# OPS-NF-002 — 제품 단계 전환·마이너 진입

- 상태: **Accepted — 1.1.0 selected-read 진입**
- 작성일: 2026-09-09
- 결정 Phase: 1.0.12 점검 및 1.0.14 P5, 1.1.0 P1
- 승인: 2026-09-12 사용자가 1.1.6까지 각 버전의 전체 Phase와 개별 릴리스를 지시했다. 착수 전에 알린 권장 owner/actor/resource-grant 해석에 따라 1.1.0 selected-read 진입을 승인한다. 공개 링크와 쓰기 확장은 해당 버전 P1에서 재판정한다.

## 해결할 질문

패치 우선 운영에서 무엇을 실제 제품 단계 전환으로 승인할 것인가?

## 검토한 대안

1. 현재 자료 계약을 재사용하되 새 동작의 경계를 명시한다.
2. 모든 상태/권한/형식을 일괄 교체한다. 영향·이행 비용이 크므로 사전 검증 없이 선택하지 않는다.
3. 외부 의존 또는 구현 가능성이 확인되지 않으면 범위를 숨기지 않고 사용자에게 대안·차단 이유를 제시한다.

## 권장 선택과 이유

패치 수·UI·플랫폼 개수 대신 owner/actor·인가/데이터 계약의 변화를 판단한다. 조건 미충족이면 다음 1.0.x를 사용한다.

## 영향과 검증

개인 흐름 회귀·공유 ADR·권한/복구·현재 운영 인수·발행 불변·user major 지시 없음. 실제 source SHA·변경 파일·schema·자동/수동 증거를 해당 Phase 인수표에 기록한다. 새 문서가 있다는 사실만으로 기존 Accepted 결정을 폐기하지 않는다.

## 1.0.14 P5 재판정

1.0.12 개인 창작 흐름의 owner 격리·원문/copy·정렬·Suno 수동 링크와 1.0.14 폰트 선택·fallback은 자동/공개 회귀를 통과했다. 그러나 이 결과는 여러 사용자의 공유 actor 모델을 검증하지 않는다. 초대/철회, 읽기/쓰기 role, 기존 owner와 actor의 RLS/API/capability, offline 변경 충돌, 탈퇴·삭제·복원·export, 감사·사고 대응의 승인안이 없으므로 **NO-GO**다. 다음 patch도 이 gate를 우회하지 않으며 1.1.0 P1은 명시적 권한 모델 승인 후에만 착수한다.

## 1.1.0 P1 재판정

1.0.14의 개인 기능 인수와 정식 릴리스가 완료됐고, 사용자 승인에 따라 owner 유지·별도 actor·자료별 grant 모델 및 최소 공개 필드·즉시 회수·owner-only rollback 계약을 확정했다. 따라서 1.1.0 selected-read 구현은 **GO**다. P2~P5가 실제 RLS/API/WS/브라우저 회귀와 동일 SHA 개발 인수를 통과하기 전에는 정식 릴리스하지 않는다.

## 되돌림·비용

새 기능을 중단해도 기존 원문·owner 데이터·정식 버전 기록을 유지한다. 형식/권한을 되돌릴 때 추가 쓰기·미전송 자료·구버전 client의 호환을 확인하고 destructive rollback은 별도 승인한다.

## 범위 밖

미선택 Future 아이디어·원문 외부 전송·운영 배포·메이저 증가의 자동 승인은 포함하지 않는다.
