# LyricsCloud 1.0.12 — 개인 창작 흐름 통합 안정화

상태: 정식 릴리스 완료. source/main/tag `b051d5d8a5593fba25d35c8d12a994f689525250`, main CI `34638724606`, tag CI `34641693226`, schema `1003_song_suno_workspaces.sql`.

## 주요 변경

- 곡·라임 노트·프롬프트 목록의 pin 그룹 위치 계산을 결과 동등 O(n) 공통 경로로 바꿔 큰 목록 비용을 낮췄다.
- desktop/mobile에서 곡 생성부터 가사·연결 라임·문장형 프롬프트 exact copy·Suno 수동 모델과 링크·재진입까지 한 흐름으로 검증했다.
- 다른 owner 자료는 404로 숨기고 작업 자료 실패는 현재 원문을 유지한 채 재시도할 수 있다.
- 서비스 재시작 뒤 가사·프롬프트·순서·Suno 링크가 PostgreSQL에서 그대로 복구된다.

## 검증

실제 PostgreSQL 18 전체 Vitest 330건이 PASS했고 조건부 beta signup 4건은 환경상 skip됐다. P4 Actions push `34632758817`과 PR `34632766602`는 전체 verify를 통과했다. 동일 SHA 개발 환경에서 desktop/mobile 수직 흐름, owner 격리, PWA 경계, web·collaboration·worker 재시작 지속성을 확인하고 합성 자료를 제거했다.

P5 후보 전체 CI 뒤 최종 main CI와 tag CI가 통과했고 네 정식 이미지의 서명·provenance·SBOM을 확인했다. 릴리스 서버에는 exact digest로 migrate 후 배포했으며 공개 HTTPS에서 원문 저장·문장 exact copy·연결 자료·owner 격리·Suno 작업공간·서비스 재시작 영속성을 재확인하고 합성 자료를 제거했다. GitHub Release는 [v1.0.12](https://github.com/parking-place/LyricsCloud/releases/tag/v1.0.12)이다.

## 알려진 제한과 운영 위험

- 자동 Suno metadata는 공식 허가 경로가 없어 제공하지 않는다. 수동 모델과 링크를 유지하며 scraping하지 않는다.
- 여러 사용자의 공동 편집·actor/capability·공유 RLS는 시작하지 않았다.
- 실제 Windows/iOS/Android 물리 입력은 이 후보에서 새로 수행하지 않았다.
- 공식 릴리스 서버의 외부 암호화 backup·24시간 RPO·실제 복원 훈련은 `OPS-100-001` 사용자 승인 예외로 미구축이다.
