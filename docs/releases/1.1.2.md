# LyricsCloud 1.1.2 — 지정 사용자 공동 편집

상태: **Phase 5 정식 릴리스 후보**. 동일 SHA 개발 인수 뒤 승인된 main·annotated `v1.1.2` tag·exact digest 운영 배포와 GitHub Release를 실행한다.

## 주요 변경

- owner는 읽기 권한이 있는 지정 사용자의 가사 본문 쓰기를 켜거나 읽기 전용으로 낮출 수 있다.
- owner와 writer의 동시 입력은 CRDT로 수렴하고 reader도 실시간 본문을 받는다. 서버가 확인한 cursor와 online/idle 상태만 표시한다.
- 강등·회수 경계에서 거부된 로컬 원문은 범위가 분리된 복구함에 남아 복사·다운로드할 수 있고, 재허용 뒤 자동으로 본문에 적용되지 않는다.

## 설치와 업그레이드

`v1.1.2`의 네 서비스 이미지를 같은 source SHA의 exact digest로 고정하고 migrate를 먼저 실행한다. 최신 schema는 `1120_selected_lyric_write.sql`이다. application-first rollback으로 1.1.1 image를 먼저 복원하며 DB volume은 삭제하지 않는다. schema나 자료 무결성이 의심되면 쓰기를 중단하고 격리 restore한다.

## 공동 편집과 보안

쓰기 권한은 활성 selected-read의 부분집합이다. writer는 본문 외 ACL·메타데이터·revision·삭제·소유권·계정 권한을 얻지 않는다. 각 update의 actor와 permission/write epoch를 서버에서 검증하고, 처리 receipt는 중복 재전송을 안전하게 ACK하되 강등·회수 뒤 새 update를 거부한다. public-link write와 guest identity는 제공하지 않는다.

## 알려진 제한과 운영 위험

- 실제 OS/물리 기기는 1.1.2 P4/P5에서 새로 실행하지 않았다. Linux에서 Chromium·Firefox·WebKit desktop과 Chromium·WebKit mobile viewport 자동화를 수행했다.
- 거부 원문 복구함은 자동 병합 도구가 아니다. 현재 서버 본문을 확인한 뒤 필요한 부분만 직접 반영해야 한다.
- public-link write·guest 표시 이름/수명주기·익명 공동 cursor는 후속 1.1.3~1.1.4 범위이며 별도 보안 승인이 필요하다.
- `OPS-100-001` 외부 암호화 backup·24시간 RPO·복원 훈련은 사용자 승인 예외로 미구축이다.

## 릴리스 검증

P4 제품 후보 `b79722428c5836e794b74c38c63c404114e00b62`에서 Actions push `34721549799`·PR `34721572892`의 전체 검증, 네 dev image 게시·서명, 실제 PostgreSQL 권한/복구 통합, 5-browser selected-write 행렬을 통과했다. 동일 SHA 개발 서버 `1.1.2/dev/p4`, schema `1120_selected_lyric_write.sql`에서 3계정 live 수렴·writer 강등/회수·offline rejected 복구·재허용 비자동 적용·메모 격리와 서비스 재시작을 확인하고 합성 fixture를 제거했다.

P5 최종 후보·main/tag CI·운영 exact digest와 공개 smoke 결과는 실행 뒤 이 절에 추가한다.

## 지원과 보안

미해결 P0/P1은 0건이다. W⊆R 위반, 다른 사용자 자료 노출, writer 권한 확대, 강등·회수 뒤 새 update ACK, 거부 원문 유실·교차 노출은 배포 중단 조건이다. 일반 문제와 보안 문제는 각각 [지원 정책](../support.md)과 [비공개 보안 보고](../../SECURITY.md)를 따른다.
