# LyricsCloud 1.1.3 — 공개 링크 비로그인 공동 편집

상태: **정식 릴리스 후보**. P1~P5와 동일 SHA 개발 인수를 완료했고 승인된 main·annotated tag·exact digest 운영 배포를 수행한다.

## 주요 변경

- owner는 기존 공개 읽기 링크에서 별도 위험을 확인한 뒤 비로그인 guest의 가사 본문 쓰기를 켜거나 즉시 중지할 수 있다.
- 각 브라우저 탭은 서버가 발급한 별도 guest session과 표시 이름으로 구분되며 두 guest와 owner의 본문이 CRDT로 수렴한다.
- 거부된 자기 입력은 범위가 분리된 복구함에 남아 복사·다운로드할 수 있고, 재허용 뒤 자동으로 본문에 적용되지 않는다.

## 설치와 업그레이드

`v1.1.3`의 네 서비스 이미지를 같은 source SHA의 exact digest로 고정하고 migrate를 먼저 실행한다. 최신 schema는 `1130_public_lyric_guest_write.sql`이다. application-first rollback으로 1.1.2 image를 먼저 복원하며 DB volume은 삭제하지 않는다. schema나 자료 무결성이 의심되면 쓰기를 중단하고 격리 restore한다.

## 공개 guest 공동 편집과 보안

공개 쓰기는 active public-read의 부분집합이며 기본 off다. selected reader가 있는 자료와 동시에 켤 수 없고 UI와 API가 기존 ACL을 보존한 채 거부한다. guest는 본문 외 workspace·목록·제목·상태·메모·연결 자료·revision·ACL·삭제·소유권·계정 권한을 얻지 않는다. 각 update의 link·resource·guest session·permission/write epoch를 서버에서 검증하고 guest/link 지속 budget, socket 상한과 owner 중지·전체 회수를 적용한다.

## 알려진 제한과 운영 위험

- 실제 OS/물리 기기는 1.1.3 P4/P5에서 새로 실행하지 않았다. Linux에서 Chromium·Firefox·WebKit desktop과 Chromium·WebKit mobile viewport 자동화를 수행했다.
- guest rejected 복구함은 자동 병합 도구가 아니며 현재 탭 session의 자기 입력만 남는다. 현재 서버 본문을 확인한 뒤 필요한 부분만 직접 반영해야 한다.
- 장시간 절전·반복 네트워크 전환·복원 중 offline writer와 다음 로그인 계정으로의 초안 격리는 1.1.4에서 추가 안정화한다.
- `OPS-100-001` 외부 암호화 backup·24시간 RPO·복원 훈련은 사용자 승인 예외로 미구축이다.

## 릴리스 검증

P4 제품 후보 `3fd9f0d9ebde0a58c653c94e46f8549643e3a194`에서 Actions push `34769556924`·PR `34769560151`의 전체 검증과 네 dev image 게시·서명, 실제 PostgreSQL 358 PASS·4 skip, 5-browser guest-write 5/5를 통과했다. 동일 SHA 개발 서버 `1.1.3/dev/p4`, schema `1130_public_lyric_guest_write.sql`에서 selected/public 충돌·두 guest 수렴·private 격리·offline rejected 복구·비자동 replay·회수와 실제 서비스 재시작 전후 지속성을 확인하고 합성 fixture를 제거했다.

P5 최종 후보 `8abf21a7e7d35cbd9a041e042836da0bb1305b6d`에서 Actions push `34771639925`·PR `34771648925`의 전체 검증, Vitest 358 PASS·4 skip, 전체 E2E 348 PASS·40 skip, 공유 전용 행렬과 release 10 PASS, 네 dev image 게시·서명을 통과했다. 동일 SHA 개발 서버 `1.1.3/dev/p5`에서 selected/public 충돌·두 guest 수렴·private 격리·presence·offline rejected-only 복구·비자동 replay·전체 회수와 실제 서비스 재시작 전후 지속성을 확인하고 합성 fixture를 제거했다. 정식 main/tag/운영 결과는 릴리스 완료 뒤 이 절에 추가한다.

## 지원과 보안

미해결 P0/P1은 0건이다. W⊆R 위반, 다른 자료·private 필드 노출, guest identity 위조, 제한·중지·회수 뒤 새 update ACK, 거부 원문 유실·교차 노출은 배포 중단 조건이다. 일반 문제와 보안 문제는 각각 [지원 정책](../support.md)과 [비공개 보안 보고](../../SECURITY.md)를 따른다.
