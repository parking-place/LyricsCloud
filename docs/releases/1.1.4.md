# LyricsCloud 1.1.4 — 공유 안정성·복구 동선

상태: **정식 릴리스 완료**. main·annotated `v1.1.4` tag·exact digest 운영 배포와 GitHub Release를 완료했다.

## 주요 변경

- 가사·상위 곡을 삭제하면 기존 selected/public 공유를 함께 끝내고, 휴지통 복원 뒤 과거 grant/link를 자동 부활시키지 않는다.
- owner revision 복원 중 같은 쓰기 권한의 offline writer가 재접속하면 복원 목표와 writer 신규 원문을 모두 보존해 공동 편집이 수렴한다.
- actor별 저장·복구 상태를 구분해 안내하고, 계정 전환 뒤 이전 actor의 로컬 자료·초안·복구 원문·presence를 다음 계정에 노출하지 않는다.
- capability별 browser outbox를 64건 또는 1 MiB bounded queue 안에서 lossless compact하고 재연결 ACK 뒤 비운다.

## 설치와 업그레이드

`v1.1.4`의 네 서비스 이미지를 같은 source SHA의 exact digest로 고정하고 migrate를 먼저 실행한다. 최신 schema는 `1140_sharing_stability.sql`이다. application-first rollback으로 1.1.3 image를 먼저 복원하며 DB volume·accepted update·receipt·revision을 삭제하지 않는다. schema나 자료 무결성이 의심되면 쓰기를 중단하고 격리 restore한다.

## 공유 복구와 보안

삭제는 자료 visibility와 capability 회수·epoch 증가를 한 transaction으로 처리한다. 복원은 편집 사건이므로 유효한 같은 epoch writer update와 수렴한다. 복원 전 입력을 강하게 끊으려면 owner가 먼저 write를 끄거나 grant/link를 회수해야 한다. bounded queue는 서로 다른 actor/resource/capability/epoch나 in-flight update를 섞지 않는다. 로그아웃·계정 전환은 이전 owner-hash browser store를 제거한다.

## 알려진 제한과 운영 위험

- 실제 장시간 wall-clock soak와 실제 OS 절전/복귀는 1.1.4 P4/P5에서 새로 실행하지 않았다. 가속 offline/online 반복과 실제 서비스 재시작을 S2/S3 증거로만 기록했다.
- 물리 Windows/Linux/macOS/Android/iOS와 실제 OS IME는 새로 실행하지 않았다. Linux의 Chromium·Firefox·WebKit desktop과 Chromium·WebKit mobile viewport 자동화는 실제 기기를 대신하지 않는다.
- 복원 중 강한 편집 절단은 자동 정책이 아니다. owner가 먼저 쓰기 중지·권한 회수를 완료해야 한다.
- `OPS-100-001` 외부 암호화 backup·24시간 RPO·복원 훈련은 사용자 승인 예외로 미구축이다.

DB volume·secret·HMAC allowlist·beta code는 보존됐고 GitHub Release `v1.1.4`를 발행했다.
