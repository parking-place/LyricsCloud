# 1.1.7 P1 실제 과제·동선 관찰

## 기준과 관찰 경계

- 정식 runtime 기준은 main/annotated `v1.1.6` source `f8d24c610ce24a1ff926e77204783473b936da88`, 운영 `1.1.6/release`, schema `1140_sharing_stability.sql`이다. 1.1.6 릴리스 기록이 병합된 문서 기준은 `5a727804d7a668bf38c51b6513e3da3cb257eb6e`다.
- 합성 제목·본문과 disposable `_test` PostgreSQL만 사용했다. 실제 이메일·창작물·행동 분석은 수집하지 않았다.
- PC는 Linux Chromium 1440×1000 실제 자동화다. `chromium-mobile` 390×844는 Android 작업의 browser/touch 대리, `webkit-mobile` 390×844는 iOS 작업의 browser/touch 대리일 뿐 실제 Android/iOS·safe-area·가상 키보드·TalkBack/VoiceOver 증거가 아니다.
- 정식 tag Actions `34871969616`의 인증/소유권·selected/public read·selected/public guest write·sharing stability·release 매트릭스를 같은 runtime source의 기존 증거로 재사용했다. 이번 관찰은 가입 오류 보존과 수직 창작 흐름 6건만 새로 실행해 중복 full suite를 만들지 않았다.

## 코드·화면 대조 결과

1. `QuickAdd`는 새 곡·새 가사에 현재 `pathname+search`를 `returnTo`로 전달하지만 새 라임·새 프롬프트 link에는 전달하지 않는다.
2. `/rhymes/new`는 `searchParams`를 읽지 않고 `RhymeNewScreen`도 `returnTo`를 받지 않는다. 생성 성공은 항상 `/rhymes/:id`, 취소는 항상 `/rhymes`다.
3. `/prompts/new`는 `template`만 읽고 `PromptNewScreen`도 `returnTo`를 받지 않는다. 생성 성공은 항상 `/prompts/:id`, 취소는 항상 `/prompts`다.
4. 기존 `safeWorkspaceReturnTo`는 same-origin 허용 route만 통과시키고 외부/`//` 입력을 fallback하므로 새 open redirect 규칙을 만들 필요가 없다.
5. NAVER 한·영·일 사전 tooltip은 1.0.13 P1 no-go 상태로 runtime에 없다. P1의 `라임/사전` 관찰은 실제 라임 노트와 현행 내부 prompt suggestion까지만 포함하며, 외부 사전 기능을 존재하거나 PASS한 것으로 기록하지 않는다.

## P2로 확정한 작은 개선 범위

- `QuickAdd`의 새 라임·새 프롬프트에도 현재 안전한 `returnTo`를 전달한다.
- 두 new page와 new screen이 `safeWorkspaceReturnTo` 결과를 받아 생성 성공 뒤 editor URL과 취소/back에 유지한다. 생성 resource·API payload·DB·초안 key는 바꾸지 않는다.
- 원래 가사 editor로 돌아온 뒤 동일 CodeMirror/Yjs·selection·undo·draft/outbox·현재 권한이 보존되는지 desktop/mobile에서 확인한다. keyboard focus와 browser/mobile back의 반환 위치도 회귀로 고정한다.
- 공유 설명·권한 종류·공개 쓰기 위험 확인, 사전/provider, 새 route·migration·native shell은 P2 범위가 아니다.

## 중단·rollback 조건

외부 `returnTo` 허용, 다른 owner route 노출, 생성 중복, 초안 삭제, 원래 editor의 본문/selection/undo 손실, 저장 전 성공 안내가 생기면 중단한다. 변경은 query 전달과 안전한 반환에 한정하며 application rollback은 1.1.6 exact image다. DB rollback은 필요하지 않다.

## P1 판정

`AC-1.1.7-01`을 충족한다. 관찰 환경·정확한 source·과제별 단계·막힘·복구와 P2 성공 기준을 연결했고 기능/데이터 변경은 분리했다. 실제 Android/iOS·OS IME·screen reader·물리 touch·OAuth callback은 미실행이며 이후 Phase에서도 실제 증거 없이 PASS로 승격하지 않는다.
