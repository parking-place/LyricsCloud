# 1.1.4 공유 안정성·복구 최종 추적

이 문서는 1.1.4 P1~P5의 `NF-REQ-034`, `NF-REQ-035`, `NF-REQ-036` 부분 범위와 `AC-1.1.4-01`~`04`를 source·migration·검증 증거에 연결한다.

## 변경·데이터 경계

- 가사·상위 곡 삭제 transaction은 selected grant와 public link를 회수하고 permission/write epoch를 증가시킨다. 휴지통 복원은 본문을 복구하지만 old capability를 부활시키지 않는다.
- owner revision 복원은 같은 read/write epoch의 offline writer update와 수렴해 복원 목표와 writer 신규 원문을 모두 보존한다. 강한 절단은 쓰기 중지·회수로 먼저 epoch를 올린다.
- browser outbox와 IME remote queue는 actor·resource·capability·epoch별 64건 또는 1 MiB bounded queue 안에서 lossless compact한다. 서로 다른 경계와 in-flight update를 섞거나 원문을 임의 ACK하지 않는다.
- owner/writer/reader/guest의 서버 ACK·기기/탭 보관·권한 종료 복구 상태를 분리해 안내한다. 로그아웃·계정 전환 시 이전 owner-hash IndexedDB·snapshot·outbox·rejected draft·selection/presence를 제거한다.
- 최신 schema는 `1140_sharing_stability.sql`이며 29개 migration 이름·checksum을 `config/migrations.1.1.4.json`에 봉인한다.

| 기준 | 증거 | 결과 |

| `AC-1.1.4-01` | offline/online 4주기, browser outbox 64건 이하·ACK 뒤 0건, 실제 web/collaboration/worker 재시작 | PASS |
| `AC-1.1.4-02` | owner revision 복원 중 selected writer 90회 초과 offline 편집·재접속, 복원 목표와 writer 원문 보존 | PASS |
| `AC-1.1.4-03` | reader 회수와 writer→다음 계정 전환 뒤 이전 IndexedDB·본문·권한·메모 비노출 | PASS |

P5 최종 후보 `081117d264aff2c4507e9992908a1f2b8fbe89eb`는 Actions `34786159783` 전체 verify·네 dev image 게시/서명과 동일 SHA 개발 인수에서 공개 복원/offline writer 병합·bounded/drained outbox·회수/계정 전환 격리·서비스 재시작을 통과했다. 합성 계정·자료는 0건으로 정리했다.
