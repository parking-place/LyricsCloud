# 0.3.1 동일 owner CRDT 동기화 계약

## 식별자와 책임

editable resource 하나는 서버가 발급한 opaque `document_key` 하나에 대응한다. 이 키는 resource UUID와 다르고 URL·로그에 원본 resource ID와 함께 기록하지 않는다. PostgreSQL mapping은 `owner_id`, `resource_id`, `document_key`를 유일하게 묶는다. 클라이언트가 owner ID를 전달해 권한을 주장할 수 없고 인증 session의 내부 user ID만 사용한다.

가사 본문은 Yjs `Y.Doc` 안의 `Y.Text("body")`가 병합 원본이다. 제목·status·favorite·pin·memo는 ADR-0004에 따라 관계형 명령과 `rowVersion`으로 유지한다. 평문 projection은 관계형 현재 제목과 서버가 적용한 Y.Text 본문을 LF UTF-8 문자열로 결합한다. 같은 CRDT state와 관계형 version은 언제나 같은 바이트를 만들며 projector가 CRDT 원본을 수정하지 않는다.

## 접근과 wire envelope

연결 시작, 재연결, 최대 5분마다의 재인증, snapshot 요청과 모든 update 수신에서 session과 resource를 다시 조회한다. 인증 owner와 resource owner가 같고 session이 유효하며 resource가 활성일 때만 허용한다. 미인증·다른 owner·만료 session·없는/삭제된 문서는 모두 `SYNC_DOCUMENT_UNAVAILABLE`로 닫아 존재 여부를 구분할 수 없게 한다. awareness도 같은 검사 뒤 메모리에만 두고 영속화하지 않는다.

각 client update는 client가 생성한 UUID `update_id`, opaque document key, binary Yjs update를 갖는다. 단일 update는 1 MiB, projection 본문은 400,000 UTF-8 byte 이하로 제한한다. 서버는 `(document_key, update_id)` unique key로 먼저 중복을 제거하고 같은 ID의 다른 payload는 protocol violation으로 연결을 닫는다. ACK는 raw update와 projection outbox가 한 transaction에 기록된 뒤에만 보낸다.

## 역전·오프라인·snapshot

Yjs update는 교환 법칙·결합 법칙·멱등성을 이용하므로 수신 순서로 의미를 만들지 않는다. 장시간 오프라인 client는 snapshot state vector를 받은 뒤 부족한 update만 교환하며, 이미 compact된 update ID의 ACK ledger는 보존 기간 동안 유지한다. 서버는 최신 snapshot과 그 snapshot 이후 committed update만으로 재시작한다.

압축은 update 수 또는 byte budget 임계값에서 문서별 advisory lock 아래 수행한다. 현재 state를 새 immutable snapshot으로 쓴 뒤 그 snapshot sequence 이하 raw update를 제거할 수 있지만, 연결된 client의 state vector와 update ID ACK를 무효화하지 않는다. snapshot 저장 실패 시 기존 snapshot/update를 유지하고 ACK나 projection 완료 상태를 앞당기지 않는다.

## editor adapter와 오류

CodeMirror의 확정 `EditorDocumentTransaction`을 Y.Text transaction으로 변환한다. `composing: true`인 IME 중간 상태는 wire update로 확정하지 않는다. 원격 delta는 `applyTransaction`으로 적용하고 `origin: external` event는 다시 송신하지 않는다. 로컬 저장, 전송 중, 서버 ACK, projection 지연은 별도 상태이며 하나의 “저장 완료”로 합치지 않는다.

오류·성능 지표에는 document key의 일방향 운영 hash, update byte 수, 지연, retry count와 오류 code만 남긴다. 제목·본문·binary payload, resource ID와 owner ID의 결합값은 남기지 않는다. 여러 사용자 공유·presence UI·작성자 표시는 이 계약 밖이다.

## 검증 fixture

- 같은 seed에서 서로 다른 위치를 편집한 두 client update를 양방향 역순·3회 중복 적용해 최종 projection byte가 같은지 검사한다.
- snapshot만으로 복구한 뒤 후속 delta를 적용해 원래 state vector와 본문이 같은지 검사한다.
- 다른 owner, null/만료 session과 삭제 문서를 같은 오류로 거부한다.
- 한글·emoji·CRLF 입력을 LF 평문으로 반복 projection해 같은 결과인지 검사한다.

Phase 2는 이 계약의 owner/document key를 IndexedDB compound key로 사용하고, Phase 3은 mapping·raw update·snapshot·projection outbox를 실제 migration과 collaboration 서버에 구현한다.
