# 0.3.0 가사 현재본 API

모든 요청은 서버 세션의 내부 user ID를 사용한다. 변경 요청의 Origin은 앱 origin과 같아야 한다. 응답은 private/no-store이며 다른 owner·없음·삭제 상태의 GET/PATCH/복제는 같은 404다. DELETE 재전송은 `{deleted:false}`를 반환한다.

| HTTP | 경로 | 입력·결과 |
|---|---|---|
| GET | `/api/songs/:songId/lyrics` | 활성 소속 가사의 최근 수정·ID 내림차순 `{items}` |
| POST | `/api/songs/:songId/lyrics` | requestId, title, body, memo, status → `{lyric,replayed}` 201/200 |
| GET | `/api/lyrics/:lyricId` | `{lyric}` |
| PATCH | `/api/lyrics/:lyricId` | rowVersion 및 title/body/memo/status/isFavorite/isPinned/pinOrder → `{lyric}` |
| DELETE | `/api/lyrics/:lyricId` | `{deleted}` |
| POST | `/api/lyrics/:lyricId/duplicate` | requestId → `{lyric,replayed}` 201/200 |

제목은 trim 후 1~200 Unicode scalar, 본문은 0~100000, 메모는 0~10000이다. 본문·메모의 공백과 줄바꿈은 API에서 변경하지 않는다. NUL과 단독 surrogate는 PostgreSQL UTF-8 text로 손실 없이 저장할 수 없어 validation 오류다. 상태는 `draft`, `revising`, `final`, `on_hold`이며 기본은 `draft`다. 사용자 HTML은 항상 텍스트다.

PATCH는 관계형 명령 하나로 원자 적용하며 서버 rowVersion과 불일치하면 `VERSION_CONFLICT` 409로 거부한다. 같은 생성·복제 requestId는 owner 안에서 한 문서만 만들며 다른 부모·원본·작업 종류로 재사용하면 충돌이다. resource와 subtype 생성 및 부모 활성 검사는 같은 transaction에서 진행한다.

곡 삭제는 당시 활성 소속 가사에 같은 deletion_batch_id를 기록한다. 이전에 개별 삭제한 가사는 다시 삭제하거나 작업 ID를 바꾸지 않는다. 가사 수는 같은 owner의 활성 부모·가사만 계산한다. 가사 검색·카드 UI는 Phase 5에서 연결한다.
