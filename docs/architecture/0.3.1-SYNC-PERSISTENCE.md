# 0.3.1 동기화 서버 영속화와 평문 투영

가사 하나는 `resources.id`와 다른 opaque `sync_documents.document_key` 하나에 대응한다. 브라우저는 세션 cookie로 `POST /documents/{resourceId}`를 호출해 key를 받고 `/sync/{documentKey}` WebSocket에 연결한다. 서버는 연결·snapshot 전송·모든 update마다 세션, owner, soft-delete 상태를 다시 조회한다. 존재하지 않음, 다른 owner, 만료·취소 세션과 삭제 자료는 모두 `SYNC_DOCUMENT_UNAVAILABLE`로 처리한다.

client update는 UUID `updateId`와 Base64 Yjs binary payload다. 서버는 1 MiB 제한을 검사하고, `(document_key, update_id)` receipt와 SHA-256으로 동일 재전송은 같은 ACK를 반환하며 ID가 같은 다른 payload는 protocol violation으로 닫는다. raw update, receipt, 관계형 `lyrics.body` projection과 projection 상태는 문서 advisory lock 아래 한 transaction에서 처리한다. ACK에는 `projection: current|pending`을 포함하며, 실패 상태는 5초 주기 projector가 재처리한다.

재시작은 최신 snapshot에 `snapshot_sequence` 이후 raw update를 순서대로 적용한다. 문서당 raw update 100개 또는 1 MiB에서 새 snapshot을 저장하고 이전 raw update를 제거하되 receipt ledger는 유지해 오프라인 재전송 ACK 기준을 보존한다. 제목은 ADR-0004에 따라 관계형 현재본이며 본문만 `Y.Text("body")`에서 LF UTF-8 평문으로 투영한다.

운영 출력은 연결 수, update byte 수, 중복 여부, projection pending·지연과 document key의 16자리 SHA-256 운영 hash만 포함한다. owner/resource ID, 제목·본문, binary/Base64 payload는 로그에 출력하지 않는다. `/metrics` 역시 집계값만 반환한다.

0.3.1 Phase 4는 현재 CRDT snapshot과 평문 projection을 revision의 원본으로 사용하고, 복원 전 현재본 snapshot을 먼저 생성해야 한다.
