# 0.9.0 반응형 셸·편집 패널 계약

이 문서는 Phase 1 UI 감사의 `GAP-01`~`GAP-07` 중 Phase 2 범위를 닫고 Phase 3 이후가 유지해야 할 반응형·초점·자료 보존 계약을 기록한다. 보호된 목업은 변경하지 않는다.

## 전환점과 셸

| 범위 | 셸 | 편집 보조 기능 | 탐색 |
|---|---|---|---|
| 0~720px | 모바일 header·하단 dock | 가사 송폼/자료, 라임 설정을 modal sheet로 표시 | 곡·라임·프롬프트·검색·즐겨찾기와 `더보기` |
| 721~960px | 11.5rem rail·가로 스크롤 가능한 단일 행 topbar | 숨긴 desktop side를 같은 mobile dock/sheet로 대체 | 전체 desktop rail·topbar |
| 961~1200px | desktop rail·압축 topbar | 가사 3열 또는 화면별 desktop panel | 전체 desktop rail·topbar |
| 1201px 이상 | 넓은 desktop shell | 전체 desktop panel | 전체 desktop rail·topbar |

`packages/ui/src/tokens.css`의 mobile 720px, tablet 960px가 의미 기준이다. CSS media query는 custom property를 사용할 수 없으므로 같은 값을 명시하고 뷰포트 회귀가 불일치를 감시한다. `main-shell`은 `minmax(0, 1fr)` 열을 가져 자식의 최소 콘텐츠 폭이 문서 전체를 늘리지 않으며, topbar 항목은 줄바꿈하지 않고 내부에서 가로 이동한다.

모바일 `더보기`는 최근 작업·템플릿·휴지통·설정을 항상 노출한다. 따라서 특정 route가 하단 세 번째 항목을 대체하던 동작 없이 모든 15개 화면으로 이동할 수 있다.

## modal·sheet 초점 계약

- 열리면 첫 유효 조작 요소로 초점을 이동한다.
- `Tab`과 `Shift+Tab`은 열린 modal 내부를 순환한다.
- `Escape`, 닫기 버튼, backdrop 직접 선택으로 닫을 수 있다.
- 탐색 sheet와 확인 dialog를 닫으면 초점은 열었던 버튼으로 돌아간다. 가사 자료 패널의 명시적 닫기와 backdrop 닫기는 편집 연속성을 위해 본문으로 돌아가고, `Escape`는 열었던 자료 버튼으로 돌아간다.
- sheet 전환은 편집 컴포넌트와 CRDT/IndexedDB sync 인스턴스를 재생성하지 않는다.

이 계약을 모바일 `더보기`, 가사 송폼, 가사 자료 패널, 라임 설정, 프롬프트 템플릿·삭제 확인에 적용한다. 가사와 라임 dock 버튼은 44px 이상의 터치 높이를 유지한다.

## 곡 작업 조건

곡 목록 `work` query는 `all`, `has_linked_resources`, `no_lyrics`만 허용한다.

- `has_linked_resources`: 현재 owner 곡에 연결되고 soft delete되지 않은 라임 노트 또는 프롬프트가 하나 이상 있는 곡이다.
- `no_lyrics`: 현재 owner 곡에 속한 soft delete되지 않은 가사가 하나도 없는 곡이다.
- 검색·상태·정렬·cursor와 조합하며 count와 page query에 같은 조건을 사용한다.
- 다른 owner 자료와 삭제된 자료는 조건 판정에 포함하지 않는다.

## 프롬프트 템플릿·삭제

- 편집 중 템플릿 적용은 기존 occurrence를 교체하지 않고 선택한 태그를 현재 순서 뒤에 추가한다.
- 적용 전에 revision checkpoint를 만들고 200개 태그 제한을 넘으면 어떤 태그도 바꾸지 않는다.
- 삭제는 로컬/서버 동기화와 `leave` checkpoint가 성공한 뒤 same-origin `DELETE`를 보낸다.
- API는 인증 owner만 soft delete하며 다른 owner에는 존재 여부를 노출하지 않고 `deleted: false`를 반환한다.
- 실패하면 현재 제목·태그와 화면을 그대로 유지하고 복구 문구를 표시한다.

## 자동 회귀

- Chromium 320×700, 360×800, 390×844, 768×1024, 1280×900, 1440×1000에서 문서 overflow와 조작 요소 가림을 검사한다.
- 390×844 → 844×390 회전에서 Chromium과 WebKit으로 가사 초안을 입력한 뒤 자료 sheet를 열고 닫아 서버 projection과 현재 본문이 유지되는지 검사한다.
- 모바일/desktop에서 프롬프트 템플릿 추가, 초점 순환·복귀, owner 격리, 삭제·휴지통 노출을 검사한다.
- 기존 편집기 회귀가 한글 IME, 100,000자 본문, 오프라인·다중 탭, 커서·송폼 이동을 계속 담당한다.

Phase 3은 이 전환점과 초점 계약을 바꾸지 않고 온라인·오프라인·오류·재시도 표현을 공통 상태 체계로 통합한다.
