## Phase 5 수직 흐름

- `creative-flow.spec.ts`는 빈 곡 목록에서 UI로 곡·가사를 만들고 송폼 구간을 복사한 뒤, 같은 곡에 연결된 라임을 현재 CRDT cursor에 삽입하고 프롬프트 원문 전체를 가사 화면 안에서 복사한다.
- 프롬프트가 panel preview 길이를 넘더라도 상세 owner API에서 정확한 `plainText`를 읽으며, clipboard 거부 시 동일 원문을 수동 복사 dialog에 보존한다.
- 모바일 자료 sheet 위에 수동 복사 dialog가 쌓이고 닫기·재시도에 접근할 수 있다. 복사 전에 자료가 삭제되면 현재 가사를 바꾸지 않고 stale 카드를 잠근다.
- 기존 `song-flow`, `lyric-flow`, `lyric-resource-panel`, `cursor-quick-add`, 동기화·오프라인·owner 공격 suite가 부분 실패와 두 탭·기기 회귀를 담당한다.

## 0.7.0 소비 계약

- 통합 검색은 `resources.owner_id`, 활성 상태와 각 subtype의 기존 평문 projection을 사용한다. 다른 owner·soft-deleted row의 제목, count, 존재 여부를 반환하지 않는다.
- 결과 카드는 기존 곡·가사·라임·프롬프트 deep link를 사용한다. 열기 전에 대상 생존을 재검사하고 편집 화면의 `returnTo`와 미전송 초안을 보존한다.
- 최근 작업은 `updated_at`과 별도 열람 시각을 구분하고, 0.6.0 panel의 마지막 탭·검색·너비 및 editor cursor·송폼 위치를 문서/owner 단위로 확장한다.
- 통합 즐겨찾기·핀은 subtype 원본을 복제하지 않고 공통 resource metadata를 읽는다. 사용자 순서 변경은 owner 범위의 안정적 식별자와 멱등 transaction을 사용한다.
- 검색 결과에서 라임 삽입은 현재 살아 있는 가사 편집 대상이 있을 때만 0.6.0 상대 위치 검증을 호출하고, 그 외에는 exact copy를 제공한다.
