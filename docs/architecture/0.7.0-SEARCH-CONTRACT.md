# 0.7.0 통합 검색 계약

## 범위와 원본 경계

통합 검색은 PostgreSQL 안에서 현재 사용자의 활성 `song`, `lyrics`, `rhyme_note`, `prompt`만 조회한다. 외부 색인, 오타 교정, 초성 검색, 형태소 분석과 다른 사용자 자료는 범위 밖이다. 작성한 제목·본문·태그는 변경하지 않으며, 검색에는 NFKC·영문 소문자화·연속 공백 축약을 적용한 생성 열만 사용한다. 생성 열은 화면에 원문으로 렌더링하지 않는다.

| 자료 유형 | 제목 | 태그 | 본문 | 관련 곡 ID |
|---|---|---|---|---|
| 곡 | `resources.search_title` | — | — | 자기 ID |
| 가사 | `resources.search_title` | — | `lyrics.search_body` | 부모 곡 ID |
| 라임 노트 | `resources.search_title` | 활성 owner `tags.search_value` | `rhyme_notes.search_body` | 활성 연결 곡 ID |
| 프롬프트 | `resources.search_title` | `prompts.search_text` 평문 토큰 | — | 활성 연결 곡 ID |

## 입력과 문자 그대로 검색

`q`는 정규화 뒤 1~200자, `type`은 `all|song|lyrics|rhyme_note|prompt`, `limit`은 1~50이며 기본값은 20이다. `cursor`는 이전의 같은 `q`·`type`·`limit` 응답에서 받은 opaque 값만 허용한다. `%`, `_`, 역슬래시는 `LIKE ... ESCAPE` 패턴을 만들 때 이스케이프하고 따옴표를 포함한 모든 값은 query parameter로 전달한다.

## 출력과 정렬

각 결과는 `id`, `type`, 작성 원문 `title`, `matchField(title|tag|body)`, 최대 240자 미리보기, 활성 관련 곡 ID 배열, `score`, `updatedAt`을 반환한다. 점수는 제목 완전 일치 600, 제목 시작 500, 제목 포함 400, 태그 300, 본문 200이다. 같은 점수는 `updatedAt DESC`, `type ASC`, `id ASC`로 고정하고 커서는 이 네 키의 PostgreSQL 마이크로초 정밀도를 보존한다.

## 권한과 삭제

서비스는 transaction 안에서 `lyricscloud_app` role과 `app.user_id`를 설정한다. 각 분기에도 `owner_id`와 `deleted_at is null`을 명시해 RLS와 애플리케이션 조건을 겹쳐 둔다. 가사는 활성 부모 곡만, 라임·프롬프트의 관련 곡은 활성 곡만 반환한다. 삭제 자료의 제목·태그·본문은 어느 분기에서도 결과가 되지 않는다.

## 인덱스와 짧은 검색어

`0700_search_foundation.sql`은 baseline의 `pg_trgm` 존재를 다시 보장하고 제목·본문·태그 생성값의 GIN trigram 인덱스를 만든다. 세 글자 이상 부분 문자열은 planner가 trigram 후보 축소를 선택할 수 있다. 1~2글자는 trigram 선택성이 낮아 owner 범위 선형 검사가 가능하며, 합성 긴 가사 fixture의 `EXPLAIN ANALYZE` 결과를 Phase 검증 기록에 남긴다. 0700 rollback은 baseline 소유의 확장을 제거하지 않는다.
