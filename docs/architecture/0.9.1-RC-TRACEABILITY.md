# 0.9.1 RC 요구사항 추적과 동결 판정

## 판정 기준

이 문서는 1.0 후보의 동결 시점 상태를 기록한다. [`Requirements-Traceability.md`](../../0.Plans/1.%20Dev-phase/Requirements-Traceability.md)의 §49 요구사항 71행을 행 단위 원본으로 사용하고, 각 행의 `최초 구현·확장`과 `주 검증·완료 증거` 열을 구현·자동/수동 검증·문서 증적 연결로 소비한다. [`0.9.0 UI 감사`](./0.9.0-UI-AUDIT.md)는 15개 화면과 목업 제안의 화면 증적 원본이다.

- 기준 source: 0.9.0 완료 SHA `713f3113b6db07f9a444291e23d32f961839c3e2`
- 자동·시각·실기기 기준: 71개 기능 구현 및 선행 검증 완료, 15개 화면과 8개 source 제안 구현·검증 완료
- Phase 2~5의 보안·성능·관측·복원 검증은 구현 누락이 아니라 RC 재검증 gate다.
- 현재 미구현·부분 구현·검증 증적 없음: 0행
- 현재 미해결 P0/P1: 0건

## 결함 등급과 동결 한도

| 등급 | 정의 | 대표 사례 | RC 처리 |
|---|---|---|---|
| P0 | 데이터 손실, 교차 사용자 노출, 인증 우회, 복원 불가, 서비스 전체 불능 | 다른 owner export 노출, 정상 backup 복원 불가 | 즉시 차단·rollback, 예외 승인 불가 |
| P1 | 우회 없는 핵심 흐름 실패, 무음 저장 충돌, 주요 모바일 사용 불가, 삭제/내보내기 오류 | 한글 저장 유실, iOS/Android 편집 불가 | 1.0 차단, 수정·전체 영향 회귀 필수 |
| P2 | 안전한 우회가 있는 기능·성능·접근성 저하 | 중복 Yjs import 경고, budget 안의 국소 지연 | 영향·우회·후속 버전 기록 후 release owner 판정 |
| P3 | 데이터·보안·핵심 흐름에 영향 없는 polish 또는 증거 품질 | 실기기 상세 버전 미기록, 문구·fixture 정리 | backlog 또는 RC 문서 수정 허용 |

RC 한도는 미해결 P0 0건, 미해결 P1 0건이다. P0/P1을 알려진 제한으로 낮추거나 일정만을 이유로 예외 승인할 수 없다.
