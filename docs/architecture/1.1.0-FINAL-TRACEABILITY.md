# 1.1.0 지정 사용자 읽기 공유 최종 추적

이 문서는 1.1.0 P1~P5의 `NF-REQ-034`, `NF-REQ-036`, `NF-REQ-042` 부분 범위와 `AC-1.1.0-01`~`04`를 source·migration·검증 증거에 연결한다.

## 변경·데이터 경계

- 기존 resource owner를 유지하고 별도 sharing identity와 자료별 `lyric_read_grants`를 둔다. 공유 대상은 로그인 계정의 비열거 sharing ID로 선택하며 이메일을 공개 API나 화면에 노출하지 않는다.
- selected-read가 공개하는 필드는 지정 가사의 제목·본문·상태, owner의 제한된 표시 이름, 최소 presence뿐이다. 곡 메모·가사 메모·연결 라임/프롬프트·다른 가사·revision·owner API는 포함하지 않는다.
- reader의 owner route·목록/회수·삭제·CRDT write와 stranger의 API/URL/WS 접근은 서버와 forced RLS에서 거부한다. 회수·만료 시 permission epoch가 증가하고 열린 socket과 이후 API를 차단한다.
- 최신 schema는 `1100_selected_lyric_sharing.sql`이며 25개 migration 이름·checksum을 `config/migrations.1.1.0.json`에 봉인한다. public link·guest·selected write는 1.1.0에 없다.

## 수용 추적

| 기준 | 증거 | 결과 |
|---|---|---|
| `AC-1.1.0-01` | owner가 A에게 한 가사만 grant; 공개 필드·presence·다른 자료/메모/revision 격리 | PASS |
| `AC-1.1.0-02` | reader/stranger의 owner URL·API·삭제·WS write 직접 조작, forced RLS와 비열거 404 | PASS |
| `AC-1.1.0-03` | live reader 권한 회수, offline 중 변경 비수신, reconnect와 이후 API 차단 | PASS |
| `AC-1.1.0-04` | 사용자 minor 승인 전 1.0.14 유지, 승인·P1 계약 뒤 1100 적용, 하위 migration 복구 순서 | PASS |

P2 후보 `046a98c`는 grant/RLS/API/read-only WebSocket 기반, P3 후보 `e315d4b`는 desktop/mobile owner/reader 흐름, P4 제품 후보 `3e20728`은 owner 판정 결함 수정과 실제 DB·5-browser·서비스 재시작/오프라인 회귀를 통과했다. P5 최종 후보는 별도 전체 CI와 동일 SHA 개발 인수로 봉인한다.

미해결 제품 P0/P1은 0건이다. 실제 OS/물리 기기는 P4/P5에서 새로 실행하지 않았고, 자동화 브라우저 엔진·viewport를 실기기 증거로 확대하지 않는다. `OPS-100-001` 외부 backup 예외는 사용자 승인대로 열려 있다. `NF-REQ-034` public-link read, `NF-REQ-036`의 이후 write 부분, 다중 편집/cursor는 1.1.1~1.1.4가 담당한다.
