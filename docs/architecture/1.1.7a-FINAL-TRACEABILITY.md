## 변경·자료 경계

P1은 한 번짜리 버전 경계/계약, P2는 `packages/database/migrations/1151_profile_customization.sql`, `packages/database/src/owned.ts`·`auth.ts`·`beta-signup.ts`, profile/photo API·input/Sharp·export/탈퇴 경계, P3는 `profile-settings.tsx`·`settings-screen.tsx`·`app-shell.tsx`와 화면/홈 guard, P4는 공유 가사의 실제 URL 판정과 권한·복구 회귀, P5는 사용자·운영 문서·30개 migration checksum·환경/license/release manifest·최종 CI Phase metadata를 담당한다. 상세 파일은 P1~P4 Phase PR diff와 P5 최종 commit tree로 추적한다. 사용자 데이터, 사진 원본, 비공개 환경값은 source artifact에 넣지 않는다.

기존 CodeMirror/Yjs editor·CRDT 원문, undo·selection·copy/export·공유 capability는 1.1.7a 프로필/홈 변경의 비대상으로 유지하고 전체 E2E에 포함한다.

`1151`은 기존 29개 migration에 추가한 additive 이행으로 legacy 효과 이름/URL을 지우지 않는다. owner 사진은 인증된 현재 owner URL과 force RLS PostgreSQL bytea로만 제공하고 공유·공개 링크에 자동 노출하지 않는다. 현재 닉네임은 기존 공유 owner 이름 보이기 설정이 켜진 신규 조회에만 반영하며 과거 revision actor 기록은 소급 수정하지 않는다. 완전 탈퇴는 owner FK cascade로 사진을 삭제하고 사용자 export는 현재 재인코드 WebP를 개인 ZIP에 넣는다. 호환성 롤백은 **application-first rollback**으로 검증된 `v1.1.7` exact digest를 되돌린 뒤 `1151` schema와 사진 자료는 보존한다. destructive down migration/사진 수동 삭제는 신규 쓰기 중지·별도 백업·승인 전 금지다. 이전 앱에서는 새 DB 사진 override가 fallback/미표시일 수 있다.

## 출시 게이트·위험

최종 `동일 SHA 개발 인수`는 P5의 새 후보에서 다시 수행한다. P4에서 검증한 SHA를 P5의 새 SHA 결과로 오인하지 않는다.

P4 첫 CI #35043201011은 기존 성능 revision 라운드 CV 83.327% > 75%로 FAIL/image skipped였고, 같은 SHA·기준 재실행 #35043634916은 전체 verify·네 signed dev image PASS다. Unit 393 PASS/5 조건부 skip, E2E 393 PASS/43 조건부 skip, release browser matrix 10 PASS. P5의 별도 최종 SHA CI·동일 SHA 개발 공개 인수와 release branch/tag CI·서명 digest·운영 smoke는 아직 완료로 적지 않는다. 현재 미해결 제품 P0/P1은 0건이며 신규 원문 유실·인증 우회·타인 사진 접근이 발견되면 배포를 중단한다.

실제 Windows Edge/IME, iOS·Android 물리 기기, screen reader·OS zoom/native SDK·스토어는 이번 버전의 새 PASS 증거가 없다. 브라우저 Linux 대리를 물리 기기 결과로 대체하지 않는다. `OPS-100-001` 외부 암호화 backup·일일 timer·격리 restore 미구축은 사용자가 명시적으로 유예했으며 24시간 RPO/호스트 손실 복구 지점이 없다. 승인자는 사용자 2026-09-16의 정확한 `1.1.7a`·별도 release branch/tag·P5 뒤 릴리스 지시이고, 실제 go/no-go는 최종 SHA·운영 결과에 따른다.
