# 0.7.0 최근 작업·가사 위치 계약

이 문서는 [PROD-0007](../product/PROD-0007-recent-work.md)의 사용자 동작을 HTTP·PostgreSQL·CodeMirror 경계로 고정한다.

## 최근 활동 의미

- 목록 대상은 현재 owner의 active `song | lyrics | rhyme_note | prompt`다. 가사는 active 부모 곡이 있어야 한다.
- 수정 시각은 `resources.updated_at`, 열람 시각은 `recent_items.last_opened_at`이다. 열람 기록은 resource의 수정 시각·row version을 변경하지 않는다.
- 정렬 시각은 `greatest(updated_at, coalesce(last_opened_at, epoch))`이며 내림차순 뒤 자료 유형·ID로 안정 정렬한다.
- `last_opened_at > updated_at`이면 `최근 열람`, 아니면 `최근 수정`으로 표시한다.
- 열람 행이 없는 기존 자료도 최근 수정 자료로 나타난다. soft delete 자료와 삭제된 부모의 가사는 query에서 제외한다.

## 응답 경계

`GET /api/recent?type=<all|song|lyrics|rhyme_note|prompt>&limit=1..50`은 다음 표시 정보만 반환한다.

- 자료 ID·유형·제목·상태, 수정/열람/활동 시각과 활동 종류
- 가사의 active 부모 곡, 라임·프롬프트의 대표 active 연결 곡과 연결 곡 수
- 곡 작업 메모 또는 가사 메모의 존재 여부 boolean
- 가사의 content-free 위치

본문·메모 원문·위치 주변 문자열은 응답에 포함하지 않는다. 모든 응답은 private/no-store이고 인증 owner transaction과 강제 RLS를 함께 적용한다.

## 위치 행

`recent_items`는 `(owner_id, resource_id)`당 하나이며 resource의 owner·type 복합 FK를 가진다. 위치 열은 `lyrics`에만 허용한다.

- `cursor_offset`: 0..100,000 code-unit offset
- `songform_label`, `songform_occurrence`: 본문 발췌가 아닌 인식된 marker label과 같은 label의 순번
- `scroll_top`: 0..10,000,000 정수 CSS pixel
- `viewport`: `desktop | mobile`
- `position_saved_at`: 서버 수신 시각
- `position_basis_updated_at`: 저장 당시 resource 수정 시각

label·occurrence는 둘 다 null이거나 둘 다 유효해야 한다. 위치 전체는 없을 수 있지만 일부 열만 남을 수 없다.

## 저장과 복원

- client는 선택·viewport 변화를 2초 debounce하고 연속 변화는 최대 15초마다 저장한다. 한 탭의 쓰기는 직렬화하며 최신 값만 후속 저장한다.
- `PUT /api/recent/:resourceId/position`은 same-origin mutation만 허용하고 active owner 가사와 부모 곡을 다시 확인한다.
- page hide와 편집 화면 전환 전에 마지막 위치를 best-effort flush한다. 위치 실패는 본문 CRDT·metadata 자동 저장을 막지 않는다.
- 검색 `find`가 있으면 검색 위치가 저장 위치보다 우선한다.
- 저장 viewport와 현재 viewport가 같고 본문 수정 시각도 같으면 clamp한 cursor와 scroll을 복원한다.
- viewport가 다르거나 본문이 변경되면 일치하는 송폼 label+occurrence 시작을 우선한다. marker가 사라졌으면 문서 길이로 clamp한 cursor로 복원한다.

## 비노출·삭제 경계

- 다른 owner, 잘못된 ID, soft delete, 삭제된 부모 곡은 위치 저장·열람 갱신에서 동일한 `404` 결과다.
- 최근 행 자체는 soft delete 동안 남아 복원 정책과 결합되지 않는다. 목록에서는 보이지 않고 resource hard delete 시 FK cascade로 제거된다.
- 오류 응답·운영 log·성능 event에는 title·body·memo·songform 주변 문장을 기록하지 않는다.
