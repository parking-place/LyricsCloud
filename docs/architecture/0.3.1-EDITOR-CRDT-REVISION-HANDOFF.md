# 0.3.1 Editor·CRDT·revision 인계

## 0.3.0 기준선

가사 하나는 독립 resource ID와 PostgreSQL 현재본 `title`, LF 순수 텍스트 `body`, `memo`, `status`, favorite·pin metadata를 갖는다. `SerializedSaveController<LyricEditorDraft>`가 이 값을 하나의 직렬 큐와 `rowVersion` CAS로 저장한다. 409나 네트워크 실패 때 CodeMirror document를 교체하지 않으며 사용자가 재시도하기 전까지 오류 상태를 유지한다.

CodeMirror DOM과 extension은 `CodeMirrorTextEditor` 내부에만 있다. 화면은 다음 port만 소비한다.

```ts
interface EditorTextChange { from: number; to: number; insert: string }
interface EditorDocumentTransaction {
  changes: readonly EditorTextChange[]
  selection?: { anchor: number; head: number }
  origin: "user" | "external"
  composing: boolean
}

interface CodeMirrorTextEditor {
  readonly value: string
  readonly selection: { from: number; to: number }
  readonly visibleRange: { from: number; to: number }
  applyTransaction(transaction: Omit<EditorDocumentTransaction, "origin" | "composing">): void
}
```

로컬 CodeMirror 변경은 `onTransaction`으로 전달된다. `applyTransaction`으로 적용한 외부 변경은 `origin: external`로 다시 관찰되므로 adapter는 이를 원격 재전송하지 않는다. offset은 transaction 적용 전 document 기준이며 insert의 줄 끝은 LF로 정규화한다. 송폼 parser·복사는 적용 후 현재 `value`와 section offset만 읽고 CRDT 자료 구조를 원본으로 삼지 않는다.

## 0.3.1 연결 순서

1. 기존 PostgreSQL `body`를 빈 Yjs document의 최초 `Y.Text` 값으로 한 번만 가져온다. 이미 update 또는 snapshot이 있으면 현재본을 다시 삽입하지 않는다.
2. 같은 owner의 인증된 기기·탭만 opaque document key로 연결하고, 연결과 재인증마다 resource owner를 검사한다.
3. 확정된 로컬 transaction만 Yjs update로 변환한다. `composing: true`인 한글 IME 중간 상태는 전송·revision 기준점으로 사용하지 않는다.
4. 원격 Yjs delta를 offset transaction으로 바꿔 `applyTransaction`에 전달한다. selection은 로컬 사용자 선택을 강제로 덮지 않는다.
5. raw update append와 압축 snapshot을 순서·중복 안전하게 저장한 뒤, 서버가 적용한 상태의 평문 projection을 같은 transaction/outbox 경계로 현재 검색 본문에 반영한다.
6. IndexedDB queue는 계정 ID와 opaque document key로 격리하고 로그아웃·계정 전환·탈퇴 시 해당 계정 데이터만 정리한다.
7. revision은 update log와 별도인 불변 복구 snapshot이다. 복원 전 현재본을 새 revision으로 남긴 뒤 과거 내용을 새 최신 상태로 적용한다.

## 충돌·실패 불변조건

- `rowVersion`은 0.3.0 단일 세션 저장 충돌 token이며 CRDT clock이나 revision 번호가 아니다.
- 초기 이관 중 0.3.0 현재본을 무음 덮어쓰기 하지 않는다. 양쪽에 데이터가 있으면 동기화를 중단하고 비교 가능한 충돌 상태를 만든다.
- 원격 update, 평문 projection 지연, revision 생성 실패를 “저장 완료” 한 상태로 합치지 않는다.
- 제목·본문·메모를 WebSocket, worker, 오류, 성능 로그에 기록하지 않는다.
- 다른 사용자의 document, awareness, 검색 projection과 revision은 존재 여부도 노출하지 않는다.

## 필수 회귀 fixture

0.3.0의 한글·emoji·리터럴 HTML, 10만 자, 반복 Hook, 전체·복수 구간 복사, 현재 미저장 입력, 다른 가사 전환·복제·삭제 fixture를 유지한다. 0.3.1은 여기에 두 탭 동시 입력, 한글 composition, offline queue 재연결, duplicate/out-of-order update, collaboration 재시작, projection 재구축, revision 생성·복원과 A/B owner 차단을 추가한다.

관련 결정은 Accepted `ADR-0004`, `ADR-0005`, `PROD-0004`다. 특정 CRDT package 코드는 이 인계 문서가 아니라 0.3.1 구현 Phase에서 adapter 뒤에 추가한다.
