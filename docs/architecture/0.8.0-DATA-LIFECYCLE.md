# 0.8.0 자료·계정 수명주기

## 자료 상태

| 상태 | 진입 | 읽기·연결 | 다음 상태 |
|---|---|---|---|
| 활성 | 생성 또는 복원 | owner의 일반 API에서만 노출 | soft delete |
| 휴지통 | DB 시각의 `deleted_at`, `purge_at = deleted_at + 30 days` | 일반 목록·검색·연결 후보에서 제외, 휴지통 API에서만 노출 | 복원, 사용자 확인 hard delete, worker purge |
| 완전 삭제 | 확인된 즉시 삭제 또는 `purge_at <= worker clock` | 없음 | 없음 |

`0802_lifecycle.sql`의 제약과 trigger가 자료와 owner 템플릿의 정확한 30일 deadline을 강제한다. 애플리케이션은 남은 날을 자정 단위 정책으로 다시 계산하지 않고 이 절대 시각과 현재 시각의 차이를 올림해 표시한다.

곡 soft delete는 하나의 `deletion_batch_id`를 현재 활성 소속 가사에 함께 기록한다. 곡 복원은 같은 batch의 가사만 함께 복원하며, 곡보다 먼저 독립적으로 삭제된 가사는 그대로 휴지통에 남긴다. 삭제된 부모에 속한 가사를 단독 복원하려면 다음 중 하나를 명시해야 한다.

- 부모 곡 복원: 부모 곡과 같은 삭제 batch의 가사를 함께 복원한다.
- 활성 곡 이동: 현재 owner의 활성 곡을 잠그고 선택한 가사의 `song_id`를 바꾼 뒤 복원한다.

라임 노트·프롬프트의 곡 연결과 즐겨찾기·핀은 soft delete 동안 보존한다. 곡 hard delete는 소속 가사와 그 종속 관계·수정 기록을 함께 제거하지만 독립 라임 노트·프롬프트는 제거하지 않는다.

## 권한과 원자성

휴지통 목록·복원은 `SET LOCAL ROLE lyricscloud_app`과 `app.user_id`가 설정된 transaction에서 수행한다. `lyricscloud_app`에는 `resources`·`templates` 직접 `DELETE`를 주지 않는다. 완전 삭제는 현재 owner와 휴지통 상태를 다시 검사하는 `SECURITY DEFINER` 함수만 호출할 수 있다.

다중 복원·완전 삭제는 먼저 모든 대상 row를 잠그고 대상 수와 화면에서 확인한 제목을 다시 비교한다. 하나라도 사라졌거나 owner·제목·복원 위치가 달라졌으면 전체 transaction을 rollback한다. 본문이나 제목은 purge 실행 기록과 worker 로그에 넣지 않는다.

## 계정 상태

| 상태 | 자료 접근 | 세션 | 전이 |
|---|---|---|---|
| `active` | 허용 | 일반 세션 허용 | 탈퇴 요청 |
| `withdrawal_pending` | 일반 API 즉시 차단 | 요청 당시 모든 세션 폐기, 이후 Google 재인증 세션은 철회 화면만 허용 | 7일 안 철회 또는 worker purge |
| 삭제 | 없음 | cascade 삭제 | 없음 |

탈퇴 요청은 현재 session이 요청 시각 기준 10분 안에 만들어졌는지 확인한다. 성공 transaction은 `withdrawal_requested_at`, 정확히 7일 뒤인 `withdrawal_purge_at`을 기록하고 해당 사용자의 미폐기 세션을 전부 폐기한다. 브라우저는 `Clear-Site-Data`와 계정 prefix의 local/session storage·IndexedDB·개인 Cache Storage를 함께 정리한다.

탈퇴 계정의 Google 재인증 callback은 일반 return path를 무시하고 `/account/withdrawal`로 보낸다. 이 세션은 일반 `AuthStore.readSession`에서 계속 거부되고, 철회 endpoint만 별도 최소 resolver로 확인한다. 사용자가 `철회`를 입력하면 같은 transaction에서 계정을 `active`로 되돌리며 현재 재인증 세션은 이후 일반 세션으로 사용할 수 있다.

## 자동 purge와 백업 경계

worker는 시작 직후와 설정 간격마다 다음 순서로 최대 100개씩 처리한다.

1. 5분 넘게 `running`인 이전 실행을 내용 없는 `WORKER_INTERRUPTED` 실패로 마감한다.
2. 실행 row를 만들고 transaction advisory lock을 얻는다.
3. `withdrawal_purge_at <= now` 계정, `purge_at <= now` 자료와 템플릿을 안정된 deadline·ID 순서로 잠가 삭제한다.
4. 성공 개수 또는 정규화된 실패 코드만 기록한다.

같은 시각으로 재실행하면 이미 삭제된 행은 다시 선택되지 않으므로 결과는 0이고 다른 owner의 미도래 자료는 바뀌지 않는다. 애플리케이션 삭제는 live DB와 사용자 화면에서의 제거를 뜻한다. 인프라 백업에는 운영 보존 기간 동안 암호화된 사본이 남을 수 있으며, 일반 사용자 복원 경로와는 분리한다.
