# 0.8.0 템플릿 데이터·적용 계약

## 저장 경계

- `templates`는 `lyrics | prompt` 중 한 유형과 그 유형에 맞는 원문 하나만 저장한다. 가사는 최대 100,000 codepoint의 순수 텍스트, 프롬프트는 최대 200개의 순서형 표시 토큰이다.
- `owner_id is null`인 네 기본 행은 읽기 전용이다. `owner_id`가 있는 행은 강제 RLS와 명시적 owner 조건을 함께 적용한다.
- 즐겨찾기·사용 횟수·최근 사용 시각은 `template_preferences`에 owner별로 둔다. 따라서 기본 원문을 바꾸지 않고도 개인 정렬을 제공한다.
- `template_requests`는 생성·복제·적용의 owner별 요청 UUID와 payload hash를 보존한다. 같은 요청과 같은 payload는 기존 결과를 반환하고 다른 payload 재사용은 충돌로 거부한다.

## 적용 transaction

1. 인증 owner에게 보이는 active 템플릿을 읽는다.
2. 요청의 `targetType`과 템플릿 유형이 다르면 쓰기 전에 거부한다.
3. 가사는 같은 owner의 active 부모 곡을 잠그고, 프롬프트는 표시 토큰을 정규화한 평문 projection과 함께 새 resource를 만든다.
4. 새 subtype, owner별 사용 기록과 멱등 결과를 같은 transaction에 기록한다.
5. 어느 단계든 실패하면 resource·subtype·사용 기록·요청 기록을 모두 rollback한다.

적용 결과는 템플릿 ID를 참조하는 live 문서가 아니라 적용 시점의 값 복사본이다. 이후 양쪽 수정은 독립적이며 기존 자료에 덮어쓰기·추가 병합은 하지 않는다.

## HTTP·화면 경계

- `/api/templates`와 하위 mutation은 인증, `no-store`, same-origin 검사를 적용한다. 다른 owner·삭제된 사용자 템플릿과 기본 템플릿 수정은 공통 404다.
- `/templates`는 가사/프롬프트 유형과 기본/사용자 출처를 독립 필터로 제공한다. 미리보기는 `<pre>` 또는 React text child만 사용하고 사용자 HTML을 해석하지 않는다.
- `/lyrics/new`와 `/prompts/new`는 빈 자료 또는 템플릿 선택을 명시한다. 적용 취소는 현재 선택·로컬 초안을 유지하며 서버 자료를 만들지 않는다.
