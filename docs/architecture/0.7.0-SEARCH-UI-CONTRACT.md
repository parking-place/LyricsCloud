# 0.7.0 통합 검색 화면·딥링크 계약

## URL과 요청 상태

통합 검색 진입점은 `/search`다. 정규화된 검색어는 `q`, 자료 유형은 `type=all|song|lyrics|rhyme_note|prompt`로 직렬화한다. `all`은 생략하며 알 수 없는 유형은 화면에서 `all`로 처리한다. 입력은 300ms 뒤 요청하고, 검색어나 유형이 바뀌면 이전 `fetch`를 취소한다. 각 요청에 증가하는 sequence를 부여해 취소 신호가 늦게 전달돼도 이전 응답이 현재 결과를 덮어쓰지 못한다.

로딩·빈 결과·실패·추가 페이지 실패는 별도 상태다. 추가 페이지 실패는 이미 받은 결과를 유지한다. URL은 `router.replace(..., { scroll: false })`로 갱신해 새로고침과 브라우저 뒤로 가기에서도 검색어와 필터를 복구한다. 결과를 열기 직전 문서 또는 검색 영역의 스크롤 위치를 `lc:<internal-user-id>:search-scroll:<search-url>` session storage에 저장하고 결과 목록이 다시 준비된 뒤 복원한다. 이 namespace는 공통 계정 캐시 삭제 계약으로 로그아웃 때 제거된다.

## 결과 표시와 키보드

서버 결과의 `title`과 `preview`는 React 텍스트 노드로만 렌더링한다. NFKC·영문 소문자·공백 축약 기준의 첫 일치 범위를 원문 UTF-16 offset으로 다시 매핑해 그 범위만 `<mark>`로 감싼다. 서버 HTML, `dangerouslySetInnerHTML`, 검색어로 만든 selector는 사용하지 않는다.

검색 입력에서 `ArrowDown`은 첫 결과로 이동한다. 결과에서 `ArrowUp`·`ArrowDown`은 인접 결과로, 첫 결과의 `ArrowUp`과 `Escape`는 입력으로 돌아간다. modifier 또는 IME composition 중인 키는 가로채지 않으며 `Enter`는 anchor의 기본 이동을 사용한다.

## 자료와 가사 위치 딥링크

모든 결과 링크는 현재 `/search?...`를 `returnTo`로 가진다.

| 결과 | 경로 | 추가 상태 |
|---|---|---|
| 곡 | `/songs/<id>` | `returnTo` |
| 가사 | `/lyrics/<id>` | `returnTo`; 본문 일치이면 정규화된 `find` |
| 라임 노트 | `/rhymes/<id>` | `returnTo` |
| 프롬프트 | `/prompts/<id>` | `returnTo` |

가사 편집기는 `find`의 첫 문자 일치 범위를 CodeMirror selection으로 만들고 가운데로 스크롤한 뒤 포커스한다. 협업 초기화가 읽기 전용 상태를 편집 가능으로 바꿀 때 포커스가 사라지지 않도록 최초 전환 직후 한 번만 selection과 포커스를 재적용한다. 잘못된 ID, 삭제된 자료와 다른 owner의 ID는 모두 제목이나 존재 여부 없이 같은 “요청한 자료를 열 수 없습니다” 화면을 사용한다.

## 최근 검색어

`0701_recent_searches.sql`은 owner, NFKC 정규화 검색어, 유형 조합을 하나로 유지하고 최근 실행 시각을 갱신한다. 사용자당 최신 8개만 남기며 강제 RLS를 적용한다.

- `GET /api/search/recent`: 현재 owner의 최신 목록
- `POST /api/search/recent`: 성공한 검색어·유형 기록 또는 갱신
- `DELETE /api/search/recent/<id>`: 현재 owner의 항목 삭제; 없거나 다른 owner여도 동일한 204
- `DELETE /api/search/recent`: 현재 owner 목록 전체 삭제

변경 요청은 공통 same-origin 정책을 적용한다. 최근 검색어는 추천·인기 검색·분석 자료로 사용하지 않고 다른 사용자에게 반환하지 않는다.
