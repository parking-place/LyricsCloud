## Phase 5 통합 결과

- `navigation-release.spec.ts`는 검색 결과의 Hook을 열고 편집한 뒤 최근 작업 카드로 돌아와 같은 저장 cursor에 다시 입력한다.
- 별도 모바일 BrowserContext가 type·scope·song·status가 포함된 핀 URL과 동일한 한 건을 복원한다.
- 같은 검색어를 가진 두 owner와 soft-deleted 부모/가사를 한 묶음으로 검사해 검색·최근·saved 어디에도 외부 또는 삭제 행이 나타나지 않게 고정한다.
- PC·모바일의 검색 loading·empty·error·retry, 최근 작업 empty, 즐겨찾기 empty를 열 개의 screenshot 기준으로 고정한다.
- 0.6.0의 마지막 migration인 `0501_prompt_usage.sql`까지 적용한 DB와 빈 DB 모두에 0700~0702를 두 번 적용했다. 원문, owner, favorite·pin 값과 여섯 검색 index가 보존됐다.

## 0.8.0 소비 계약과 남은 위험

- 통합 자료 링크는 활성 owner 범위의 기존 resource ID와 `returnTo`만 전달한다. 제목·본문·존재 여부를 URL이나 오류에 넣지 않는다.
- 검색 filter, 최근 type filter, saved type/song/status/scope filter는 URL을 상태 원본으로 유지한다. 0.8.0 템플릿 화면이 이를 재사용해도 새 filter 의미를 기존 값에 섞지 않는다.
- 최근 위치에는 본문을 저장하지 않는다. 같은 viewport는 cursor를, 기기 크기 또는 본문 revision이 다르면 송폼을 우선하고 범위를 clamp한다.
- 즐겨찾기와 핀은 독립 값이며 pin order는 owner의 전역 exact set이다. 템플릿을 네 기존 자료 유형처럼 포함할지는 0.8.0 범위에서 별도로 결정한다.
- 2,000개 합성 resource에서 saved 480개 전체 목록의 p95는 개발 컨테이너 기준 15ms 미만이었다. 현재 비공개 베타에는 비차단이지만 목록 pagination은 운영 규모와 `OPS-0003` 성능 budget이 정해질 때 다시 판단한다.
