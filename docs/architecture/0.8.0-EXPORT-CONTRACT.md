# 0.8.0 전체 내보내기 계약

## 묶음 형식

인증된 사용자는 `GET /api/export`에서 `lyricscloud-export-YYYYMMDD.zip`을 받는다. 응답은 `application/zip`, `no-store`, `nosniff`이며 세션의 현재 owner만 읽는다. ZIP은 다음 항목을 UTF-8로 담는다.

- `README.md`: schema version, 생성 시각과 포함·제외 경계
- `lyricscloud-export.json`: `lyricscloud.export.v1` 기계 판독 snapshot
- `songs/*.md`, `lyrics/*.txt`, `rhymes/*.txt`, `prompts/*.txt`, `templates/*.txt`: 사람이 읽을 수 있는 자료별 파일
- `settings.md`: 계정 표시 설정과 가사별 재정의

JSON 최상위는 `schemaVersion`, ISO 8601 `exportedAt`, `records[]`로 고정한다. 각 record는 `section`과 `data`를 가지며 section은 account, profile, identities, resources, songs, lyrics, rhymeNotes, prompts, promptDictionary, promptTokens, tags, resourceTags, songResourceLinks, templates, templatePreferences, settings, lyricDisplaySettings, recentItems, recentSearches, lyricRevisions 중 하나다. 내부 session token·요청 receipt·검색 projection·본문 hash·CRDT update는 포함하지 않는다.

관계 ID는 같은 JSON 안의 resource, tag, prompt dictionary 또는 template ID를 가리킨다. 사용자 기본 템플릿 환경설정이 있으면 참조 대상 built-in template도 `source: built_in`으로 포함한다. 이미 완전 삭제된 자료와 애플리케이션 밖 인프라 백업은 포함하지 않는다. 휴지통 자료와 owner 템플릿은 삭제·purge 시각과 함께 포함한다.

## 일관성과 대용량 경계

서버는 전용 PostgreSQL 연결에서 `REPEATABLE READ READ ONLY` transaction을 열고 export 시각과 최소 계정 메타데이터를 owner ID 조건으로 읽는다. 이후 `lyricscloud_app` 역할과 transaction-local owner context를 적용해 모든 창작 자료를 강제 RLS 아래 읽는다. JSON과 가독 파일을 만드는 여러 cursor는 모두 같은 transaction snapshot을 사용하므로 다운로드 도중 편집된 값이 일부 파일에만 섞이지 않는다.

본문은 50행 cursor batch와 ZIP chunk로 전송한다. 전체 계정 본문이나 완성 ZIP을 메모리·임시 파일에 모으지 않는다. ZIP 중앙 색인에는 파일별 이름·CRC·크기·offset의 작은 metadata만 보존하며 ZIP32 한도 또는 65,535개 entry를 넘으면 불완전 묶음을 성공 처리하지 않는다. 브라우저 취소·stream 오류 시 generator `finally`가 transaction을 rollback하고 연결을 반환한다. 서버 임시 산출물이 없으므로 성공·취소·실패 후 정리할 export 파일도 없다.

## 파일명과 내용 안전성

자료 제목은 NFKC 정규화 후 제어 문자와 Windows·POSIX 경로 구분자·예약 문자를 `_`로 바꾸고, 끝의 점·공백을 제거하며 72 codepoint로 제한한다. Windows 예약 이름은 `_`를 붙인다. 같은 제목도 UUID 앞 8자를 suffix로 붙여 충돌하지 않는다. archive 경로는 고정된 유형 폴더 아래에서만 생성한다.

사용자 본문은 앱 HTML로 렌더링하거나 로그에 쓰지 않고 ZIP entry의 UTF-8 bytes로만 전달한다. JSON schema validator는 version·section·record 형태와 관계 대상 존재를 검사한다.
