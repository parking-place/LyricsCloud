# 0.5.0 프롬프트 토큰 계약

이 문서는 0.5.0 Phase 1의 parser·CRDT 원본·PostgreSQL 읽기 투영 경계를 고정한다. 사용자 간 공유나 템플릿은 포함하지 않는다.

## 제한

| 항목 | 제한 | 적용 위치 |
|---|---:|---|
| 제목 | Unicode code point 200자 | domain, `resources`, API 입력 |
| 토큰 표시 값 | Unicode code point 200자 | domain, dictionary, projection |
| 편집 sequence | 200개 | domain과 CRDT 입력 경계 |
| 직렬화 문자열 | Unicode code point 40,398자 | domain, `prompts.plain_text` |

토큰 200개가 각각 200자이고 구분자 `, `가 199개인 최댓값을 직렬화 한도로 사용한다. 빈 프롬프트 sequence는 허용하지만 제목은 비어 있을 수 없다.

## 쉼표 parser와 표시 값

- 모든 `,`는 구분자다. 따옴표나 escape 문법은 없으므로 토큰 내부 쉼표는 표현할 수 없고 둘 이상의 토큰으로 나뉜다.
- 연속 쉼표와 문자열 양끝의 쉼표가 만든 빈 항목은 버린다.
- 토큰 양끝 공백은 제거한다. 토큰 내부 공백, 대소문자, 호환 문자와 이모지는 표시 값에 그대로 보존한다.
- 직렬화는 현재 표시 값의 순서대로 정확히 `, `를 사이에 넣는다.
- NUL, 짝이 맞지 않는 surrogate와 제한 초과 입력은 저장하지 않는다.

## 중복 비교와 정리

중복 키는 표시 값에 `NFKC → 연속 Unicode 공백 한 칸 → 소문자화`를 순서대로 적용한 값이다. 이 키는 비교와 검색에만 쓰며 표시 값을 덮어쓰지 않는다.

편집 중 CRDT sequence는 서로 다른 occurrence ID가 가진 중복 표시 값을 보존한다. 그래야 사용자가 중복 위치를 확인하고 개별 제거 또는 일괄 정리를 선택할 수 있다. PostgreSQL 읽기 투영은 sequence의 첫 occurrence를 대표 표시 값으로 유지하고 같은 정규화 키의 뒤 항목을 제외한다. `prompt_tokens`의 owner·prompt·정규화 키 unique constraint가 이 읽기 모델의 무중복을 재확인한다.

## CRDT와 PostgreSQL 책임

- Yjs 원본: 제목, occurrence ID, 표시 값과 순서를 보존하고 같은 owner의 탭·기기 update를 수렴시킨다.
- `prompts.plain_text`: 무중복 읽기 sequence를 결정적으로 직렬화한 검색·복사용 문자열이다.
- `prompt_tokens`: 무중복 읽기 sequence의 ordinal, 표시 값, 정규화 값과 owner dictionary 연결이다.
- `prompt_token_dictionary`: owner별 최초 대표 표시 값, 누적 사용 횟수와 최근 사용 시각이다. 다른 owner의 후보는 RLS와 owner query 양쪽에서 차단한다.

같은 occurrence ID의 재전송은 CRDT adapter에서 무시한다. 생성·복제·업데이트는 owner+request ID와 payload hash를 기록해 같은 요청은 재생하고, 같은 ID의 다른 payload는 `REQUEST_REUSED`로 거부한다.

## 곡 연결과 삭제

곡 연결은 `song_resource_links`의 독립 관계다. unlink는 해당 관계 하나만 지우고 프롬프트, 토큰 dictionary, 곡과 다른 연결은 보존한다. 프롬프트 삭제는 `resources.deleted_at`만 설정하는 soft delete이며 이후 읽기와 새 연결 후보에서 제외된다. 토큰 사용 이력은 자동완성을 위해 유지된다.
