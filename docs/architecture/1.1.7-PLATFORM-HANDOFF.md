# LyricsCloud 1.1.7 웹 동선·플랫폼 개발안 인계

## 승인 입력과 공통 계약

승인 입력은 B-1 통합 작업공간, 1.1.7 P2의 명시적 `returnTo`, P3의 exact 목록 복귀·focus 복원·보호된 새 탭·비-pointer 대안, P4의 reduced transparency/contrast/forced-colors fallback이다. Windows/Linux/macOS/Android/iOS 개발안은 같은 곡·가사·라임·프롬프트 URL 의미와 API·DB·CodeMirror/Yjs 원문, owner/actor/capability/epoch, copy/export 형식, 계정별 draft/outbox/rejected recovery 경계를 유지한다.

새 자료 생성은 호출 화면이 명시적으로 전달한 내부 경로로만 돌아가며 임의 referrer나 외부 URL을 소비하지 않는다. 목록→곡→가사→공유·Suno→목록 복귀는 원래 filter·sort·view query를 보존한다. 저장 완료는 서버 ACK 뒤에만 표시하고 editor가 입력 가능하고 초기 동기화가 끝나기 전에는 사용자의 쓰기를 허용하지 않는다. pointer gesture에는 보이는 버튼·키보드 대안이 있고 dialog/sheet는 닫힌 뒤 trigger로 focus를 돌려준다.

## 플랫폼별 차이와 최초 검증 입력

| 플랫폼 | 유지할 제품 흐름 | 최초 실제 검증·결정 |
|---|---|---|
| Windows | desktop rail·keyboard/focus, 외부 브라우저 OAuth, CodeMirror/Yjs 호환 원문 | [ADR-NF-004](../adr/ADR-NF-004-windows-native.md)의 WinUI 3/WebView/Avalonia spike, Microsoft IME·selection·undo·protocol·MSIX/서명 |
| Linux | desktop URL/focus와 system font fallback | [ADR-NF-008](../adr/ADR-NF-008-linux-platform.md)의 toolkit, Wayland/X11, IBus/Fcitx, keyring·패키징 |
| macOS | desktop 복귀·보호 새 탭·Keychain 후보 | [ADR-NF-009](../adr/ADR-NF-009-macos-platform.md)의 SwiftUI/AppKit/WebView, Korean IME·sandbox·notarization·update |
| Android | bottom navigation·More sheet, system/predictive back, keyboard inset | [ADR-NF-005](../adr/ADR-NF-005-android-native.md)의 Kotlin/Compose/WebView spike, Gboard/Samsung Keyboard·회전/복원·Credential Manager·APK/AAB |
| iOS | bottom navigation·More sheet, safe area·keyboard inset | [ADR-NF-010](../adr/ADR-NF-010-ios-platform.md)의 SwiftUI/UIKit/WebView spike, Korean IME·scene 복원·Keychain·서명/TestFlight |

browser 자동화의 Chromium mobile은 Android, WebKit mobile은 iOS의 반응형 대리일 뿐 native 앱 합격이 아니다. 실제 SDK 설치, 기술 선택, 패키징, 서명, 스토어 등록, 물리 기기, OS IME와 보조 기술은 각 후속 버전에서 별도 증거를 가져야 한다. 웹 client secret을 binary에 넣거나 embedded WebView Google 로그인을 만들지 않는다.

## 중단과 rollback

원래 목록 query·가사 원문·selection/undo·미전송 입력·권한 경계가 바뀌거나 저장 성공을 거짓 표시하면 해당 플랫폼 작업을 중단한다. 웹의 시각 문제는 같은 image의 `LC_UI_VARIANT=classic`, application 문제는 직전 `v1.1.6` exact image로 먼저 되돌리며 DB volume과 `1140_sharing_stability.sql`을 삭제하거나 down-migrate하지 않는다.
