# 0.9.0 PWA 설치·캐시·업데이트 계약

## 제품 경계

LyricsCloud는 설치 가능한 온라인 우선 웹 앱이다. 설치 여부와 서비스 워커 지원 여부는 곡·가사·라임·프롬프트 기능의 사용 가능 여부를 바꾸지 않는다. 완전 오프라인 자료 탐색은 범위 밖이며, 이미 열린 편집기의 계정별 IndexedDB 초안과 재전송 queue만 연결 중단을 견딘다.

## 설치 계약

- `/manifest.webmanifest`는 이름, 짧은 이름, `/workspace` 시작 URL, `/` scope, `standalone`, 색상, 한국어와 192×192 일반·512×512 maskable 아이콘을 제공한다.
- `beforeinstallprompt`를 지원하는 브라우저에서는 공통 shell에 명시적인 `앱 설치` 버튼을 표시한다. 취소하거나 이벤트를 지원하지 않아도 일반 반응형 웹은 그대로 동작한다.
- 서비스 워커는 HTTPS 또는 localhost 계열 secure context에서만 등록하며 `/sw.js`를 HTTP cache에 의존하지 않고 갱신한다.

## 캐시 허용 목록

서비스 워커의 Cache Storage 대상은 같은 origin의 `/_next/static/` 아래 content-addressed 파일이며 다음 조건을 모두 만족해야 한다.

1. GET 정적 URL이고 query가 없다.
2. Next build가 생성한 8자 이상 식별 segment가 있다.
3. 응답이 성공했고 `Cache-Control`에 `public`과 `immutable`이 있다.
4. `Set-Cookie`가 없다.

HTML, `/api/**`, `/collaboration/**`, 가사·라임·프롬프트·검색 결과, manifest와 임의 public 파일은 fetch handler가 가로채거나 Cache Storage에 기록하지 않는다. 인증·계정·창작 route에는 `private, no-store`를 적용하며 collaboration HTTP 응답도 `no-store`를 유지한다. 따라서 shell cache 이름은 계정 식별자를 포함하지 않고 로그아웃 뒤 남아도 개인 데이터가 아니다.

## 로컬 초안과 schema

0.3.1의 owner hash DB 이름 `lyricscloud-draft-<sha256>-sync-v2`는 유지한다. Dexie schema 2는 기존 `documents`와 `updates` store를 변경하지 않고 `metadata` store와 schema marker만 추가한다. 첫 shell 진입에서 기존 schema 1을 제자리 upgrade하고 문서 snapshot과 안정적인 update ID queue를 보존한다. 기존 ACK·500ms~30s 재연결·중복 제거·owner 검증은 서비스 워커와 독립적으로 그대로 작동한다.

로그아웃·계정 전환은 owner prefix의 local/session storage와 IndexedDB를 제거한다. 탈퇴는 여기에 개인용 Cache Storage까지 제거한다. 서버 `Clear-Site-Data`는 이 브라우저 정리를 보강한다.

## 업데이트 상태 기계

- 새 worker가 `waiting`이어도 스스로 `skipWaiting`하지 않는다.
- shell은 닫힌 탭의 queue와 라임·프롬프트·빠른 생성 초안을 포함하는 `hasOwnerPendingDrafts`를 확인한다.
- 미전송 초안이 있으면 적용 버튼을 비활성화하고 현재 worker와 화면을 유지한다.
- 초안이 비워진 뒤 사용자가 `업데이트 적용`을 눌러야 waiting worker가 활성화된다.
- `controllerchange`는 같은 탭의 승인 marker가 있을 때만 한 번 reload한다. 최초 설치나 다른 탭의 변경은 강제 reload하지 않는다.

## 회귀 계약

`scripts/verify-0903-pwa.mjs`는 production manifest·standalone worker·아이콘·URL allowlist·no-store route 선언을 검사한다. `tests/e2e/pwa.spec.ts`는 실제 Chromium worker에서 schema 1 자료 보존, immutable shell cache, 개인 응답 비저장, offline cache hit, dirty update 차단·승인 reload, offline 편집 복구와 로그아웃 정리를 검증한다. 기존 전체 E2E는 worker 차단 환경에서도 일반 웹 기능이 유지됨을 계속 확인한다.
