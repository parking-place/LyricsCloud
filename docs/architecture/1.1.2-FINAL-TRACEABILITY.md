# 1.1.2 지정 사용자 공동 편집 최종 추적

이 문서는 1.1.2 P1~P5의 `NF-REQ-035`, `NF-REQ-036` 부분 범위와 `AC-1.1.2-01`~`04`를 source·migration·검증 증거에 연결한다.

## 변경·데이터 경계

- owner는 활성 selected-read grant의 지정 사용자에게만 가사 본문 쓰기를 켤 수 있다. W⊆R은 별도 역할 이름이 아니라 실제 활성 read grant로 구조화한다.
- writer는 본문 CRDT update만 보낼 수 있고 ACL·제목·상태·메모·연결 자료·revision·삭제·소유권·계정 관리는 권한을 상속하지 않는다.
- 각 update는 인증 actor·resource·grant·permission/write epoch를 서버에서 확인한다. durable receipt는 같은 update의 재전송에 같은 ACK를 주지만 강등·회수 뒤 새 update는 거부한다.
- 서버 확인 presence/cursor만 공유하고 public reader에는 identity presence를 노출하지 않는다. 거부 원문은 계정·actor·resource·grant·epoch별 local 복구함에 남기며 재허용 뒤 자동 replay하지 않는다.
- 최신 schema는 `1120_selected_lyric_write.sql`이며 27개 migration 이름·checksum을 `config/migrations.1.1.2.json`에 봉인한다. public-link write와 guest identity는 1.1.2에 없다.

## 수용 추적

| 기준 | 증거 | 결과 |
|---|---|---|
| `AC-1.1.2-01` | 존재하지 않는 reader에 write 부여 시도, ACL snapshot 비교와 실제 PostgreSQL 제약 | PASS |
| `AC-1.1.2-02` | owner/writer 동시 한글 update, reader live 수신, 서버·복사·재접속·재시작 수렴 | PASS |
| `AC-1.1.2-03` | 강등 전후 epoch 경쟁, duplicate ACK·stale 거부, offline rejected 원문 보존·재허용 비자동 적용 | PASS |
| `AC-1.1.2-04` | writer의 ACL·메타데이터·revision·삭제 요청과 다른 자료·메모 접근 | PASS |

P2 후보 `41db8ff`는 1120 schema·원자 actor/epoch ACK·rejected queue와 collaboration 기반, P3 후보 `f8f2dbd`는 PC/mobile owner·writer·reader 흐름과 awareness 복구, P4 제품 후보 `b797224`는 실제 DB·5-browser·offline/reconnect·권한 강등/회수·서비스 재시작 회귀를 통과했다. P5 최종 후보는 별도 전체 CI와 동일 SHA 개발 인수로 봉인한다.

미해결 제품 P0/P1은 0건이다. 실제 OS/물리 기기는 P4/P5에서 새로 실행하지 않았고 자동화 브라우저 엔진·viewport를 실기기 증거로 확대하지 않는다. `OPS-100-001` 외부 backup 예외는 사용자 승인대로 열려 있다. `NF-REQ-035`, `NF-REQ-036`의 public-link/guest write 범위는 1.1.3~1.1.4가 명시적 보안 경계 승인 뒤 담당한다.
