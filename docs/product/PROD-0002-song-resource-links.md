# PROD-0002 — 곡과 라임 노트·프롬프트 연결

- 상태: Accepted
- 결정 Phase: 0.2.0 Phase 1
- 승인자: 사용자(0.2.0 Phase 1 진행 지시), 2026-09-05

## 해결할 질문

하나의 라임 노트나 프롬프트를 여러 곡에서 재사용할 수 있는지, 같은 연결의 중복과 연결 해제가 원본 자료에 어떤 영향을 주는지 정한다. 실제 연결 테이블·API·화면 구현은 0.6.0 범위이며 이 Phase에는 넣지 않는다.

## 검토한 대안

1. 라임 노트·프롬프트가 한 곡에만 속하는 1:N 관계
2. 곡과 독립 자료를 여러 번 연결할 수 있는 N:M 관계
3. 연결할 때마다 자료를 곡 안으로 복제

## 선택과 이유

- 곡과 라임 노트·프롬프트는 N:M이다. 같은 자료를 여러 곡에서 재사용하는 기획 흐름을 보존한다.
- 연결 양쪽은 항상 같은 `owner_id`여야 한다.
- `(owner_id, song_resource_id, linked_resource_id)` 한 쌍은 하나만 존재하며 같은 연결 요청은 중복 행을 만들지 않는다.
- 연결 해제는 관계만 없애고 라임 노트·프롬프트 원본을 수정하거나 삭제하지 않는다.
- 연결 대상이 soft delete되면 활성 곡 대시보드에서만 숨긴다. 관계는 유지하므로 대상을 복원하면 다시 보인다.
- 대상이 완전 삭제될 때만 해당 연결 행을 제거한다. 다른 곡과 연결된 독립 자료 자체는 곡 삭제의 cascade 대상이 아니다.
- 사용자 정의 연결 순서는 1.0 범위에 없으며 기본 표시는 연결 시각과 자료 제목을 사용한다.

## 영향과 검증

- 영향 작업: `LC-020-P1-01`, 0.6.0 Phase 2의 연결 schema·명령
- 영향 화면: `04-song-dashboard`, 라임 노트·프롬프트 목록과 보조 패널
- 미래 schema: `song_resource_links`, 양쪽 resource와 owner를 함께 검증하는 FK 또는 동등한 지연 제약, 쌍 unique
- 자동 검증: 교차 owner 연결 거부, 중복 연결 1건 유지, 해제 뒤 원본 유지, 어느 한쪽 soft delete·복원 시 가시성 전환
- 대체 비용: 1:N으로 바꾸면 기존 다중 연결을 복제하거나 하나만 선택해야 하므로 데이터 migration과 UI 의미 변경이 필요하다.
