# PROD-0008 — 템플릿 적용과 기존 내용 보호

- 상태: Accepted
- 결정 Phase: 0.8.0 Phase 1
- 승인 근거: 사용자의 1.0.0까지 단계별 진행 지시, 2026-09-07

## 해결할 질문

가사 구조 또는 프롬프트 템플릿을 적용할 때 기존 자료를 덮어쓸지, 내용을 추가할지, 별도 자료를 만들지와 취소 시 보호 범위를 확정한다.

## 검토한 대안

- 열린 기존 자료를 템플릿 내용으로 덮어쓴다. 빠르지만 저장·동기화된 창작물을 의도치 않게 잃을 위험이 크다.
- 열린 자료 끝에 템플릿을 추가한다. 가사 송폼과 프롬프트 토큰의 중복·순서 충돌 의미가 불명확하다.
- 템플릿은 새 자료 생성에서만 선택하고, 적용 시점의 원문 스냅샷을 한 transaction에서 새 자료로 복사한다.

## 선택과 이유

- 템플릿 적용은 빈 새 가사 또는 새 프롬프트를 만드는 흐름에서만 제공한다. 기존 자료에는 덮어쓰기나 병합을 제공하지 않는다.
- 선택 화면의 취소는 자료나 템플릿을 변경하지 않는다. 적용 요청이 성공하기 전에는 부분 자료를 남기지 않는다.
- 가사 템플릿은 UTF-8 순수 텍스트 본문을, 프롬프트 템플릿은 표시 문자열의 정규화된 무중복 순서를 보존한다. 미리보기는 두 형식을 모두 사용자 HTML이 아닌 텍스트로 렌더링한다.
- 적용은 요청된 대상 유형과 템플릿 유형이 정확히 같아야 한다. 가사는 같은 owner의 활성 부모 곡까지 확인하고, 실패하면 새 자료·사용 횟수·요청 기록을 모두 되돌린다.
- 적용 시점의 템플릿 값을 새 자료에 복사한다. 이후 새 자료 또는 사용자 템플릿을 수정해도 서로 영향을 주지 않는다.
- 기본 템플릿의 내용은 모든 로그인 사용자에게 읽기 전용이다. 즐겨찾기와 최근 사용은 템플릿 원문과 분리된 owner별 선호 행으로 기록한다.
- 사용자 템플릿은 owner만 읽기·수정·복제·soft delete할 수 있다. 다른 owner의 ID는 모든 읽기·적용 경로에서 존재 여부를 드러내지 않는 404로 처리한다.

## 영향과 검증

- 영향 작업: `LC-080-P1-01`~`LC-080-P1-09`, `templates`, `template_preferences`, `template_requests`, 템플릿 API/UI와 새 가사·프롬프트 흐름.
- 유형 혼동과 다른 owner ID의 원자 거부, 요청 재시도, 적용 후 양쪽 독립 수정, 기본 원문 불변, 순수 텍스트 미리보기를 단위·DB·E2E에서 검증한다.

## 되돌림 비용

기존 자료 병합을 추가하려면 CRDT 변경과 복구 UX가 함께 필요하므로 별도 제품 결정과 revision 기반 되돌림 설계 없이는 이 결정을 바꾸지 않는다.
