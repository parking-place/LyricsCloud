# PROD-0010 — soft delete, cascade와 복원

- 상태: Accepted
- 결정 Phase: 0.2.0 Phase 1
- 승인자: 사용자(0.2.0 Phase 1 진행 지시), 2026-09-05

## 해결할 질문

곡을 삭제·복원할 때 공통 resource, 곡에 소속된 가사, 독립적으로 연결한 라임 노트·프롬프트가 어떻게 보이고 복원되는지 정한다. 휴지통 UI, 30일 뒤 완전 삭제 작업과 가사 schema는 후속 Phase 범위다.

## 검토한 대안

1. 곡만 숨기고 모든 자식과 연결 자료는 계속 노출
2. 곡과 소속 가사, 연결된 독립 자료를 전부 cascade 삭제
3. 곡과 소속 가사만 함께 숨기고 독립 자료와 연결 관계는 보존

## 선택과 이유

- `resources.deleted_at`이 soft delete의 단일 기준이다. subtype 행은 보존하며 활성 조회는 항상 `deleted_at is null`을 포함한다.
- 같은 삭제 요청은 이미 삭제된 자료의 시각을 바꾸지 않는 idempotent 동작이다.
- 곡이 삭제되면 당시 활성 상태인 소속 가사만 같은 작업 단위에서 숨긴다. 이미 휴지통에 있던 가사는 곡 복원으로 되살리지 않는다.
- 곡 복원은 그 곡 삭제 작업 때문에 숨겨진 가사만 복원한다. 후속 가사 schema는 삭제 원인 또는 삭제 묶음을 식별할 수 있어야 한다.
- 연결된 라임 노트·프롬프트는 독립 resource이므로 곡 삭제로 숨기거나 삭제하지 않는다. 연결 행도 유지하지만 삭제된 곡 화면에서는 노출하지 않는다.
- 곡을 복원하면 보존된 연결 관계가 다시 나타난다.
- 30일 뒤 완전 삭제는 곡 subtype, 곡 소속 가사와 연결 행을 제거하되 연결된 독립 자료는 제거하지 않는다.

## 현재 Phase 적용

0.2.0 Phase 1에는 아직 가사와 연결 테이블이 없으므로 `soft_delete_song`이 소유자가 가진 song resource의 `deleted_at`만 한 트랜잭션에서 기록한다. `resources`와 `songs` 행은 모두 남으며 직접 hard delete 권한은 애플리케이션 역할에 주지 않는다.

## 영향과 검증

- 영향 작업: `LC-020-P1-08`, 0.3.0 가사 schema, 0.6.0 연결, 0.8.0 휴지통
- 영향 화면: 곡 목록·대시보드, 휴지통, 연결 자료 영역
- 자동 검증: soft delete 뒤 활성 조회 제외와 원본 두 행 유지, 재삭제 무변경, 교차 owner 삭제 무변경
- 후속 검증: 곡 cascade로 숨긴 가사만 복원, 독립 연결 자료 유지, hard purge 뒤 orphan 없음
- 대체 비용: 연결 자료까지 cascade하는 정책은 공유 자료 손실 위험과 복원 migration이 커 새 PROD 결정이 필요하다.
