## 인증·세션 판정

- OIDC authorization은 Google issuer, 고정 same-origin callback, `code_challenge_method=S256`, random state·nonce·verifier를 사용한다.
- callback은 sealed HttpOnly SameSite=Lax transaction cookie의 state를 constant-time 비교하고 DB의 one-time hash를 소비한다. 변조·만료·재사용·취소·invalid grant는 session을 만들지 않는다.
- verified email이 invite allowlist에 없으면 거부한다. provider token은 저장하거나 client/log에 노출하지 않는다.
- session은 opaque random token의 hash만 DB에 저장하고 idle 30일·absolute 90일·7일 전 renewal window를 적용한다. logout·탈퇴는 같은 owner의 모든 session을 즉시 폐기한다.

## 제한값과 응답

| 경계 | 값 | 실패 계약 |
|---|---:|---|
| API POST/PUT/PATCH/DELETE body | 1,048,576 bytes | 413 `PAYLOAD_TOO_LARGE`, no-store |
| 로그인·callback | 40 tokens / 5분 / Cloudflare·trusted proxy client key | 429 `RATE_LIMITED`, `Retry-After` |
| 통합 검색 | 120 tokens / 1분 / authenticated user | 동일 |
| 전체 export | 6 tokens / 1분 / authenticated user | 동일 |

title/body/tag/query/export의 제품별 더 작은 의미 제한은 기존 domain parser와 DB constraint가 계속 적용된다. 외부 client key는 Cloudflare가 덮어쓰는 `CF-Connecting-IP`를 우선하고 trusted reverse proxy의 `X-Real-IP`·첫 `X-Forwarded-For`를 차례로 사용하며, 고유 key 저장은 10,000개를 넘으면 오래된 항목을 8,000개까지 제거한다. rate limiter는 단일 Node instance 메모리 token bucket이다. 개발 서버 단일 replica 기준에는 정확하며, 다중 replica 전환 시 공용 limiter 또는 reverse-proxy global limit가 필요하다는 P2 운영 제한을 Phase 3에 넘긴다.
