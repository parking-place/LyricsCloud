# 1.0.2 Phase 2 저장·서버 인수

## 수정 범위

- 런타임을 `1.0.2`로 전환하고 package/Compose/Next 기본 version을 함께 맞췄다.
- 편집기의 volatile 상태(`metadata dirty/saving/error`, IndexedDB `saving-local/error`)를 `data-pending-input`으로 노출한다. PWA manager는 이 동기 신호가 남아 있으면 브라우저 직접 이탈을 경고하고 worker update reload를 막는다.
- root가 공개 `BUILD_ID` meta를 렌더링하고 service worker registration URL과 cache namespace를 동일 ID로 묶는다. 사용자·인증 데이터는 URL/cache에 포함하지 않는다.
- beta signup 응답 유실은 새 intent로 같은 principal이 재시도할 때 기존 active grant를 반환하며 code/grant/receipt를 중복 생성하지 않는 실제 DB 회귀로 고정했다.
- schema/API/Yjs wire/IndexedDB schema 변경은 없다.

## 호환·복구

- migration 추가 없음. 기존 `0901_beta_signup.sql`이 최대 schema이며 fresh/repeat migration만 재확인한다.
- worker는 새 build가 활성화될 때 `lyricscloud-shell-*` 중 현재 namespace 외 cache만 제거한다. 정적 content-addressed asset 외 응답은 저장하지 않는다.
- 실패 시 v1.0.1 application image로 먼저 되돌린다. DB/volume/tag를 삭제하거나 이동하지 않는다.
- 물리 Windows/Android/iOS IME를 이번 후보에서 새로 실행하지 않았다. 동일 입력 경계의 1.0.1 인수는 과거 증거로만 보존한다.
