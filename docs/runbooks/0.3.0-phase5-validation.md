# 0.3.0 Phase 5 검증

2026-09-05, Node 24.20.0 / pnpm 11.25.0 / 별도 PostgreSQL `lyricscloud_test`와 공개 개발 서버에서 검증했다. 실제 사용자 본문과 릴리스 환경은 사용하지 않았다.

## 범위와 결과

LC-030-P5-01~11을 완료했다. 곡 대시보드는 owner의 활성 가사를 최근 수정순 카드와 실제 개수로 표시하며 0개 빈 상태, 새 가사, 열기, 복제, favorite와 개별 soft delete를 제공한다. 편집기는 제목·본문·메모·상태·favorite·pin을 한 `rowVersion` 직렬 저장 큐로 보존하고 저장 완료 뒤 다른 가사 전환·복제·삭제를 수행한다. PC의 세 열과 모바일의 송폼·복사·다른 가사·집중 모드 dock은 같은 자료와 명령을 사용한다.

곡 검색은 owner가 같은 활성 lyric resource의 제목과 현재 본문을 부분 문자열로 찾는다. 삭제된 가사와 다른 owner의 내용은 결과와 미리보기에 노출하지 않는다. CodeMirror는 offset transaction과 `user`/`external` origin을 전달하는 port를 추가했으며 Yjs·WebSocket·IndexedDB·revision은 [0.3.1 인계](../architecture/0.3.1-EDITOR-CRDT-REVISION-HANDOFF.md)에만 정의했다.

## 복구와 0.3.1 인계

schema 변경은 없다. 문제가 생기면 이전 검증 SHA로 앱만 되돌릴 수 있다. 0.3.1은 현재 PostgreSQL body를 최초 CRDT 문서에 한 번만 이관하고, `EditorDocumentTransaction` port 뒤에서 같은 owner의 기기·탭 동기화, update 영속화·평문 projection, offline queue와 revision을 추가한다. 0.3.0 현재본을 무음 덮어쓰거나 `rowVersion`을 CRDT clock으로 재사용하지 않는다.
