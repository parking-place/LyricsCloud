# 0.2.0 Phase 2 검증 기록

검증일: 2026-09-05

## 결과

곡 resource와 subtype을 한 transaction에서 만드는 명령, owner별 생성 요청 멱등성, 상세·수정·공통 메타데이터·soft delete 명령, 검색·상태·다섯 정렬·keyset cursor 목록을 구현하고 통과했다. 가사와 연결 자료는 값 `0`과 `available: false`로 구분해 아직 지원하는 것처럼 보이지 않는다.

## 자동 검증

```text
docker compose --profile test run --rm migrate_test
docker compose --profile test run --rm migrate_test pnpm test:migration:0200
docker compose --profile test run --rm migrate_test pnpm test:migration:0201
docker compose --profile test run --rm -e AUTH_DATABASE_INTEGRATION=true migrate_test sh -lc 'pnpm check && pnpm test'
docker compose --profile test run --rm -e NODE_ENV=production migrate_test pnpm build
docker compose --profile test run --rm -e E2E_DATABASE_URL=... migrate_test pnpm test:e2e
docker compose --profile test run --rm migrate_test pnpm check:secrets apps/web/.next
```

- migration 전체 적용과 재적용 통과
- 0200 의존 rollback·재적용과 0201 단독 rollback·재적용 통과
- architecture boundary, TypeScript 검사 통과
- 14개 파일, 57개 단위·PostgreSQL 통합 테스트 통과
- Next.js production build 통과
- desktop·mobile 30개 E2E 통과
- production build secret scan 통과

## 확인한 경계

- 동일 owner·request UUID 동시 재전송은 최초 song 한 개와 같은 ID만 반환한다.
- title·description·work notes·상태와 favorite·pin·color 명령은 필드별 validation을 적용한다.
- `%`, `_`, 한글과 영문 대소문자를 포함한 검색을 wildcard 주입 없이 문자 그대로 처리한다.
- 다섯 정렬은 핀 우선과 UUID tie-breaker를 포함한다.
- 테스트 중 PostgreSQL 마이크로초 시각이 JavaScript 밀리초로 줄어 cursor 항목이 재등장하는 결함을 발견했고, cursor 전용 원시 시각을 보존하도록 수정한 뒤 전 정렬 다중 페이지를 재검증했다.
- 사용자 B는 사용자 A의 상세·수정·메타데이터·삭제에서 제목이나 존재 여부를 확인하지 못한다.
- 곡 API E2E는 다른 인증 시나리오의 세션 만료 조작과 실행 순서가 결합되지 않도록 프로젝트별 합성 사용자·세션을 격리한다.
- soft delete 재호출은 서버 오류나 추가 변경 없이 `deleted: false`로 끝난다.
- 변경 API는 앱 origin을 요구하고 응답과 오류는 `no-store`다.

## 후속 범위

Phase 3은 [`곡 API와 cursor 계약`](../architecture/0.2.0-SONG-API.md)을 소비해 카드, URL 검색·필터·정렬, cursor 추가 로드를 구현한다. 가사 본문 검색과 연결 자료 필터는 capability가 활성화되는 후속 버전까지 표시하지 않는다.
