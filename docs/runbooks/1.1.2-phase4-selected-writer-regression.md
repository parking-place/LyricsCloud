# 1.1.2 Phase 4 — 지정 공동 작성 권한·복구 회귀

## 후보와 범위

- 제품 후보는 `b79722428c5836e794b74c38c63c404114e00b62`다.
- 1120 schema의 active read grant 안에서만 write를 허용하는 W⊆R, actor·permission/write epoch, durable receipt/ACK와 local-only rejected 원문 계약을 변경하지 않고 실패·재시작 경계를 확대했다.
- owner·writer·reader 3계정은 같은 본문을 실시간으로 보되 owner와 지정 writer만 작성한다. writer 강등은 읽기를 유지하고 reader grant 회수는 열린 연결과 재접속을 모두 차단한다.

## 자동 검증

- Node 24.20.0에서 `pnpm check`와 production build가 PASS했다.
- 실제 PostgreSQL sharing/collaboration 집중 회귀 5건이 PASS했다. 존재하지 않는 reader의 write 전환 거부와 ACL 불변, owner/writer 동시 한글 update, actor audit·duplicate ACK, stale epoch 거부, collaboration 실제 process restart 뒤 owner/write/read snapshot 수렴, writer 강등 뒤 읽기 유지, reader 회수 격리를 확인했다.
- Chromium·Firefox·WebKit desktop과 Chromium·WebKit mobile의 3계정 5/5가 PASS했다. owner/writer 동시 입력을 reader가 수신하고, writer ACL·삭제 차단, reader 완전 회수, writer offline 입력의 강등 뒤 로컬 복구와 재승격 비자동 적용을 확인했다.
- 후보 Actions push `34721549799`와 PR `34721572892`는 전체 verify를 통과했다. push는 Vitest 353 PASS·4 조건부 skip, 전체 E2E 347 PASS·38 조건부 skip, selected-read 5 PASS, public-link 11 PASS·4 skip, selected-write 5 PASS, release matrix 10 PASS와 네 development image 발행·서명을 완료했다.

## 동일 SHA 개발 인수

- 공개 live/ready는 `1.1.2`·`dev`·`p4`, schema `1120_selected_lyric_write.sql`과 후보 SHA를 반환했고 postgres/web/collaboration/worker는 모두 healthy였다.
- 합성 owner·writer·reader·stranger로 3계정 live 수렴, writer 강등 뒤 읽기 유지, reader 회수와 재접속 차단, writer의 ACL 차단, offline rejected 복구함, 재허용 뒤 rejected 원문 비자동 적용, writer 회수와 메모 격리를 PASS했다.
- web/collaboration/worker를 실제 재시작한 뒤 writer/read access와 본문, 무관 계정·메모 격리가 유지됐다. 합성 곡·가사·grant·계정은 인수 직후 제거했다.
- 실제 Windows Chrome/Edge·Firefox, iOS, Android 물리 기기는 P4에서 새로 실행하지 않았다. 자동 브라우저 엔진·viewport와 구분해 P5 release 위험으로 인계한다.

P5는 이 후보를 요구 추적·사용자/지원/보안/자가호스팅 문서와 release manifest에 연결하고, 최종 후보의 전체 CI·동일 SHA 개발 인수 뒤 승인된 정식 릴리스 gate를 판정한다.
