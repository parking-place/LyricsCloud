구현 후보는 `565ed50335197855b7d3c14f3ea9e5519e1f838f`이며, 인수 기록을 포함한 개발 배포 SHA는 `3b05a34468874877043b3c36abdacf216a092565`이다. Node 24.20.0, pnpm 11.25.0, PostgreSQL 18, production standalone과 digest 고정 기반 image에서 권한·동시성·저장·복구를 다시 인수했다. 제품 P0/P1은 0건이며 `RC-091-001`은 현재 후보에서 해소됐다.

P9 검증 중 아래 회귀 검사 공백을 발견해 닫았다.

- 0901 이후 관리자 CLI fixture가 `claimed_code_digest`를 만들지 않아 현재 schema에서 실패하던 문제를 수정했다.
- production image와 backup product smoke에 P4 가입용 index key fixture가 없어 session 검사가 503이 되던 문제를 보완했다.
- rollback 검사가 application rollback 뒤 최신 forward-compatible schema를 유지하는 계약 대신 과거 schema 이름을 기대하던 기준을 수정했다.

- P7 브랜드 적용 뒤 전역 이미지 0개와 모바일 보조 로고 표시를 가정하던 XSS/UI 검사를 실제 콘텐츠 경계에 맞게 고쳤다.
- 설치 가능한 PWA의 정확한 192/512 아이콘을 새 브랜드 `any` 자산과 함께 manifest에 복구했다.

성능은 동일 격리 runner에서 `measure-0913-performance.ts`를 세 번 재실행했다. 각 실행은 전체 budget을 통과했고 save p95는 2.963/3.838/3.512ms, save CV는 33.221/4.181/29.814%였다. 과거 병합 CI의 130.793%는 절대 save p95 4.319ms·오류 0인 상태에서 runner 편차가 증폭된 실패로 보며 현재 세 번의 재측정에서 재현되지 않았다. 75% 예산은 완화하지 않았다.

## 남은 운영 예외

`OPS-100-001`은 **열린 상태**다. 사용자가 이번 1.0.1 작업에서 외부 backup 구축은 나중에 하며 릴리스 진행을 승인했으므로 P9/P10의 현재 배포 예외로 기록한다. 격리된 암호화 backup/restore 도구의 PASS는 공식 릴리스 서버의 외부 저장소·일일 timer·24시간 RPO를 뜻하지 않는다. 호스트 손실 징후가 있으면 신규 쓰기와 배포를 중단하고, 후속 운영 작업에서 별도 저장소·identity·timer·실제 restore 훈련을 구축한다.

원격 Phase 브랜치와 PR #21, 개발 서버 checkout·공개 build metadata는 `3b05a34468874877043b3c36abdacf216a092565`로 일치했다. 공개 live/ready/auth·favicon·manifest, schema `0901_beta_signup.sql`, postgres·web·collaboration·worker healthy를 확인했다. P9 동안 main, 정식 tag, moving release alias와 릴리스 서버는 변경하지 않았다. P10에서 최종 SHA의 전체 원격 CI·개발 공개 smoke를 동결한 다음, 이미 받은 릴리스 승인 범위 안에서만 main 병합·정식 image·릴리스 서버 배포를 수행한다.
