## 공식 근거 재검토

2026-09-15에 다음 공식/원문 자료를 확인했다.

- [Microsoft Windows 개발 경로](https://learn.microsoft.com/en-us/windows/apps/get-started/): 신규 native Windows 앱의 권장 경로는 WinUI 3 + Windows App SDK다.
- [Windows App SDK stable lifecycle](https://learn.microsoft.com/en-sg/windows/apps/windows-app-sdk/stable-channel): P2에서 지원 중 stable channel의 exact version을 잠가야 한다.
- [Microsoft WebView2 보안](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security): hosted web content와 native bridge는 불신 입력으로 취급하고 origin/message를 제한해야 한다.
- [RFC 8252](https://www.rfc-editor.org/info/rfc8252/): native auth는 external user-agent, PKCE와 desktop loopback redirect를 사용한다.
- [Google installed app OAuth](https://developers.google.com/identity/protocols/oauth2)와 [loopback 안내](https://developers.google.com/identity/protocols/oauth2/resources/loopback-migration): desktop loopback은 지원되며 distributed secret은 기밀로 볼 수 없다.
- [Windows Data Protection](https://learn.microsoft.com/windows/uwp/security/data-protection): `LOCAL=user` DPAPI 보호를 WinUI 앱에서 사용할 수 있다.
- [Yjs update API](https://docs.yjs.dev/api/document-updates): update binary와 state-vector/적용 의미를 native interop fixture의 기준으로 삼는다.
- [Windows packaging](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/packaging/)과 [접근성](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessibility-overview): test package와 정식 서명, 자동 검사와 실제 Narrator/keyboard 검사를 분리한다.

## reference spike

합성 fixture `tests/native/windows/fixtures/1.1.8-read-copy-yjs-v1.json`을 추가했다. 실제 창작물은 포함하지 않으며 다음 입력을 고정한다.

- `바라봐`, `마냥`, `마땅한`, emoji가 포함된 UTF-8/Yjs `body`
- CRLF/CR→LF, 송폼 tag/빈 줄, 전체 copy의 exact Extend 행 제거
- 부분 송폼 copy의 Extend 보존
- Unicode code point 3,000 초과 경고

실행 명령:

```sh
docker run --rm -v "$PWD:/workspace" -w /workspace node:24.20.0-bookworm-slim \
  sh -lc 'corepack pnpm exec vitest run tests/new-feature/1.1.8.contract.test.ts packages/editor/src/copy.test.ts packages/editor/src/crdt.test.ts packages/auth/src/service.test.ts'
```

결과: **4 files, 34 tests PASS**. 신규 fixture 3건, 기존 copy 7건, CRDT 9건, 인증 15건이다. 첫 실행에서 workspace package alias를 root test가 해석하지 못한 실패를 재현했고, 기존 root test 관례인 source-relative import로 고쳐 같은 명령을 재실행했다.

이 결과는 JavaScript reference, 기존 서버 auth 취소/잘못된 state/session 비생성 동작과 합성 원문의 근거다. Windows clipboard, C# decoder, native callback, 실제 IME/selection/undo/보조 기술의 PASS가 아니다.

## 최초 소비 전 인터페이스 결정

- native auth는 first-party HTTPS broker + system browser + loopback PKCE이며 URL에는 single-use code만 둔다. native opaque session은 back-channel exchange 성공 때만 만든다.
- native session은 `DataProtectionProvider("LOCAL=user")`로 보호한다. Google/server client secret은 binary에 넣지 않는다.
- 기존 API JSON, RLS, owner/actor/capability/permission/write epoch, Yjs `body`, copy 알고리즘을 유지한다. bearer transport 외에 parallel domain protocol을 만들지 않는다.
- owner cache와 selected/shared cache를 구분한다. shared cache는 매번 온라인 권한 확인 전 화면·clipboard에 노출하지 않는다.
- DB migration은 P1에 없다. P2가 single-use grant 저장을 추가하면 forward migration, 최소 grant column, 60초 이하 TTL, digest-only code, consume-once, RLS/role, cleanup과 rollback/forward-fix를 함께 제출한다.

rollback은 native feature/배포 채널을 끄고 웹·서버·DB 원문을 유지하는 방식이다. copy 불일치, auth 오류 session 생성, account/cache 교차 노출, 공유 회수 뒤 stale 표시, Yjs 원문 훼손 중 하나라도 나오면 해당 Phase를 중단한다. volume 삭제나 기존 migration down은 rollback이 아니다.

P2 진입에 필요했던 다음 범위는 사용자가 승인했다: **WinUI 3/.NET, 1.1.8 read/copy-only, WebView2 미포함, system browser + first-party loopback PKCE, 계정별 DPAPI cache, 1.1.9 native editor/Yjs는 별도 gate**. 승인 검토 proposal source는 `e26fe58c49c1d67b5435bab6018148bb8a75eca0`이며, P1 승인 기록 commit은 결정 내용의 bookkeeping만 추가한다. `NF-REQ-040` 전체는 Windows 구현·실기기·서명 인수 전까지 미완료다.
