# 0.3.0 Phase 2 검증

2026-09-05, Node 24.20.0 / pnpm 11.25.0 / 별도 PostgreSQL `lyricscloud_test`와 공개 개발 서버에서 검증했다. 실제 사용자 본문과 릴리스 환경은 사용하지 않았다.

## 범위와 결과

LC-030-P2-01~10을 CodeMirror 6 어댑터, 직렬 자동 저장 controller와 `/lyrics/[lyricId]` 화면으로 연결했다. 편집기 경계 밖에는 제목·본문 문자열만 전달하며 DOM·selection·decoration은 저장하지 않는다. 한글 composition 중간본은 저장하지 않고, 마지막 입력 후 약 1초 또는 최초 변경 후 최대 5초에 요청한다. 같은 문서의 쓰기는 직렬화하고 sequence와 `rowVersion`을 함께 확인하며 실패 시 현재 문서와 명시적 재시도를 유지한다.

본문은 CRLF를 LF로 정규화하고 HTML도 실행하지 않는 문자 그대로의 텍스트로 왕복한다. 60 KiB 이하 요청에만 브라우저 `keepalive`를 사용해 64 KiB 전송 한도를 넘는 10만 자 문서도 일반 fetch로 정상 저장한다. PC 편집 폭은 54rem으로 제한하고 모바일은 `100dvh`·safe-area와 본문 우선 높이를 적용했다. CRDT, 수정 기록, 송폼 decoration은 완료 기능으로 노출하지 않았다.

- `pnpm check`: workspace 경계와 전체 TypeScript 통과.
- `AUTH_DATABASE_INTEGRATION=true pnpm test`: 20개 파일, 75개 테스트 통과. 신규 자동 저장 controller 4개와 CodeMirror 원문 계약 1개를 포함한다.

## 복구와 Phase 3 인계

이 Phase는 schema를 변경하지 않는다. 문제가 생기면 개발 서버에 이전 검증 SHA를 배포해 앱만 되돌릴 수 있다. 미저장 편집을 서버 재조회로 덮지 않으며 실패 상태에서 문서가 남는다.

Phase 3은 `createCodeMirrorTextEditor`가 노출한 현재 문자열, visible range, selection, replace와 focus를 사용한다. 송폼 parser와 decoration은 editor DOM을 직접 수정하지 않고 문서 변경 transaction에서 파생하며, 긴 문서에서 전체 DOM 렌더를 강제하지 않는다.
