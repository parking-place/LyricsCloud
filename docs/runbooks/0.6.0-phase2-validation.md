# 0.6.0 Phase 2 곡 연결 자료 관리 검증

## 구현 결과

- 곡 대시보드 연결 자료를 라임 노트·프롬프트 유형 탭과 연결 목록으로 확장하고, 같은 화면에서 PC modal 또는 모바일 bottom sheet로 연결을 관리한다.
- owner의 활성 자료만 제목과 라임 본문 또는 프롬프트 토큰으로 검색하며 전체·연결됨·미연결 필터와 cursor 추가 로드를 제공한다.
- 최대 50개 변경을 한 transaction으로 적용하고 요청 ID를 정규화해 중복 관계를 만들지 않는다. 같은 요청을 반복해도 `song_resource_links` 기본 키와 `ON CONFLICT DO NOTHING`이 한 관계만 유지한다.
- 연결 해제 전에 곡과 자료 이름, 자료 원본이 라이브러리에 남는다는 문구를 표시한다. 저장 실패 시 선택과 재적용 행동을 보존한다.
- 연결 적용 뒤 dashboard count와 유형별 목록을 다시 조회하며 기존 라임·프롬프트 편집기와 곡 필터 API가 같은 owner N:M 관계를 사용한다.
- 자료 또는 곡을 soft delete하면 관계 행을 보존한 채 후보·목록·집계에서 숨기고, 복원하면 기존 관계가 다시 표시되는 `PROD-0010` 정책을 통합 테스트로 고정했다.
- 조회 오류와 저장 오류 상태를 분리해 검색 debounce가 연결 저장 실패 안내를 지우지 않도록 했다. 적용·취소 뒤에는 연결 관리 행동으로 focus를 복원한다.

## Phase 3 인계

- Phase 3은 `/api/songs/:songId/links`의 owner 범위 `rhyme_note|prompt`, `linked|unlinked|all`, 검색·cursor 계약을 가사 편집 보조 패널에서 재사용한다.
- 곡 전환과 다른 가사 목록은 기존 곡·가사 owner API를 공통 결과 계약으로 정리하되, 미저장 CRDT 초안·cursor·selection을 잃지 않아야 한다.
- PC 접이식 패널과 모바일 sheet는 마지막 탭·검색·스크롤과 editor focus를 복원하고, 탭별 실패가 다른 탭 사용을 막지 않게 한다.
