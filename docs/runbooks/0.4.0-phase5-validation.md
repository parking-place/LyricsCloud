# 0.4.0 Phase 5 검증

## 구현·통합 결과

- [0.4.0 라임 노트 증적과 인계](../architecture/0.4.0-RHYME-HANDOFF.md)에 Phase 1~4의 32개 고유 작업 ID를 구현·테스트·검증 문서와 연결했다.
- 라임 목록의 favorite·pin·color 명령을 자료·필드별 직렬 queue로 바꿨다. 첫 응답이 느린 동안 반복 입력은 마지막 의도로 합쳐지고, 서로 다른 필드의 오래된 전체 resource 응답이 다른 선택을 덮어쓰지 않는다. 마지막 요청 실패 시에는 확인된 서버 상태로 돌아가고 오류를 알린다.
- PC·모바일에서 신규 offline 초안 → 생성 → 제목/CRDT 본문 편집 → 태그 → 곡 연결 → tag/song 목록 필터 → 두 탭 병합 → revision 복원 → 전체/선택/수동 복사 → 이름 확인 삭제를 하나의 흐름으로 검증했다.
- 10만 자에 가까운 한글 본문을 연 뒤 끝 위치에 편집하고, 태그 30개와 한도 초과 실패 보존, 마지막 tag의 키보드 focus, 모바일 가로 overflow 없음을 검증했다.
- 실제 가사 cursor 삽입은 활성화하지 않았다. 0.6.0은 `PROD-0006`의 동일 owner source/target·Yjs relative position·멱등 request ID 계약을 소비한다.

## 로컬 검증

- migration을 두 번 적용하고 `0200`, `0201`, `0300`, `0310`, `0311`, `0400`의 rollback guard·복구 검사를 모두 통과했다.
- architecture boundary와 모든 TypeScript project, `33 files / 122 tests`, Next.js production build, build artifact secret scan을 통과했다.
- Playwright production 전체 suite는 PC·모바일 합계 `138 passed / 2 intentional skipped`다. 빈 화면·무결과·server retry·offline·저장 상태·Clipboard 거부·삭제 modal·A/B owner·soft delete·다중 탭/기기 복구를 포함한다.
- 네 production image로 신규 DB migration, web·collaboration·worker readiness, DB·서비스 재시작, WebSocket 수렴, pending projection·revision 복구를 통과했다.
- 계획 구조 검사 결과는 `13 versions / 65 phase documents / 576 task IDs / 71 requirements`다.

## 0.5.0·0.6.0 인계

- 0.5.0은 공통 resource 표시 속성, owner/RLS, soft delete, 문자 그대로 검색, cursor·URL 목록 상태, 명령 queue와 오류/복사 상태를 프롬프트에 재사용한다.
- 0.6.0은 라임 source 선택 snapshot과 열린 가사 target을 명시적으로 묶고, 동일 owner/활성 resource/document를 서버에서 재검증한 뒤 하나의 CRDT transaction·undo 단위로 삽입한다.
