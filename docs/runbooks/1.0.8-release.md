# 1.0.8 정식 릴리스 실행

## 승인과 source

사용자는 2026-09-11 현재 요청에서 1.0.14까지 각 버전의 Phase 완료와 정식 배포를 승인했다. 1.0.8 P1~P5 후보 SHA와 CI·개발 인수는 [최종 후보 인수](./1.0.8-phase5-final-acceptance.md)와 [추적표](../architecture/1.0.8-FINAL-TRACEABILITY.md)에 연결한다. 외부 backup 미구축 `OPS-100-001`은 명시적 위험 예외이며 성공으로 기록하지 않는다.

## 불변 순서

1. 1.0.8 environment·migration·license·manifest와 P0/P1 0건을 검증한다.
2. Phase PR을 순서대로 `main`에 병합하고 최종 main SHA CI를 통과한다.
3. 같은 main SHA를 개발 서버에서 확인한 뒤 annotated `v1.0.8` tag를 만든다.
4. 정확한 tag에서 `publish=true`, `release=true` workflow를 실행한다.
5. 네 서비스 각각 `1.0.8`·전체 SHA·`Release`·`latest`·`Release-latest`가 같은 digest인지 확인한다.
6. manifest의 exact digest만 릴리스 서버에 적용하고 migrate 뒤 세 app을 갱신한다.
7. 공개 live/ready·auth, 합성 계정의 곡 이동·재진입·stale 복구·owner 격리와 안정 구간을 확인한다.

DB volume·secret·기존 tag를 삭제하거나 재사용하지 않는다. 실패하면 직전 1.0.7 digest로 application-first rollback하고 호환 schema는 유지한다. 파괴적 down migration은 수행하지 않는다.
