# 1.1.1 Phase 2 공개 링크 기반 인수

## 결과

후보 `571398d700f606a5778d13500364eeae564a79b7`에서 공개 읽기 capability의 저장·API·실시간 읽기 기반을 인수했다. 링크 원문은 URL fragment로 한 번만 전달되고 서버에는 domain-separated SHA-256 digest만 남는다. 한 가사당 활성 링크는 하나이며 재발급·회수·만료·자료 삭제 뒤에는 API와 WebSocket 모두 일반화된 거부로 전환된다.

## 구현 경계

- `packages/auth/src/public-share.ts`: 256-bit base64url token 생성·검증·digest.
- `packages/database/migrations/1110_public_lyric_read_links.sql`: 링크·멱등 요청, owner-only RLS, public 최소 projection와 read-only document/update/access 함수.
- `packages/database/src/public-lyric-sharing.ts`: owner 발급·목록·회수, rotation, 공개 projection.
- `apps/web/src/app/api/lyrics/[lyricId]/public-link`: owner 발급·목록·회수.
- `apps/web/src/app/api/public/shared-lyric`: same-origin 고정 POST, 4 KiB body, bounded rate limit, no-store/noindex 응답.
- `apps/collaboration/src/server.ts`: 첫 WebSocket frame token 인증, public-read snapshot/update만 허용, write·presence·identity 차단, 주기적 회수/만료 재검증.
- `infra/docker/Dockerfile.service`: collaboration production bundle이 auth workspace를 포함하도록 정렬.

## 검증

- Node 24 관련 계약 4건, 실제 PostgreSQL public sharing 통합, collaboration 통합 3건, 1110 및 영향 migration 복구, security ownership matrix, `pnpm check`, production build를 통과했다.
- GitHub Actions push `34692185838`와 PR `34692188575`가 같은 SHA에서 전체 verify와 web·worker·collaboration·migration 개발 이미지 게시·서명을 완료했다.
- 개발 서버 공개 live/ready는 `version=1.1.1`, `channel=dev`, `phase=p2`, 동일 build SHA와 schema `1110_public_lyric_read_links.sql`을 반환했고 네 서비스가 healthy였다.
- 공개 합성 smoke는 fragment-only URL, DB digest-only, 허용 필드 projection, 다른 owner 차단, rotation 뒤 이전 링크 차단, revoke 뒤 새 링크 차단, generic page no-store/noindex를 확인했다. 합성 사용자·자료·링크는 종료 시 제거했다.

## 잔여 범위

P2는 서버 기반만 완료했다. owner 확인 UI, fragment 즉시 제거와 탭 한정 보관, 비로그인 reader 화면, PC·모바일·오프라인·재시작 브라우저 흐름은 P3/P4가 담당한다. public write와 guest identity는 1.1.3 이전에 활성화하지 않는다. 실제 물리 iOS/Android는 이 Phase에서 새로 실행하지 않았다.
