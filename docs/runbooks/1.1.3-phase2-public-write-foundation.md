## 저장·순서·남용 제한

1. raw link/session secret은 URL query·DB·log에 저장하지 않고 서로 다른 digest domain을 사용한다.
2. receipt lookup을 먼저 수행해 ACK 유실 retry가 update 또는 budget을 중복 차감하지 않게 한다.
3. 새 update는 active link/read, write enabled, 미만료 link/session, 같은 resource와 두 epoch를 link/session row lock에서 확인한다.
4. PostgreSQL minute bucket이 guest 240건/4 MiB, link 1,200건/16 MiB를 원자 차감한다. 초과 update는 원문·projection·receipt에 반영하지 않는다.
5. document lock 아래 Yjs update·guest attribution·평문 projection·receipt를 commit한 뒤 ACK/broadcast한다. 기존 1 MiB update·100,000자 본문 제한도 유지한다.
6. owner write off는 write epoch를 올려 writer를 public-read로 낮춘다. revoke/expiry/rotation은 permission 경계에서 read/write를 모두 끝낸다.

## 잔여 범위

P2는 저장·서버 기반이다. owner의 공개 읽기/쓰기 비교·위험 확인 UI, guest CodeMirror 편집/저장 상태, 계정 데이터와 분리된 rejected recovery와 PC/mobile 흐름은 P3가 담당한다. P4가 대량 병렬 update·restart budget·session spoof·지원 브라우저 전체 회귀를 보강한다. 실제 OS/물리 기기와 `OPS-100-001` 외부 backup 예외는 미실행 위험으로 유지한다.
