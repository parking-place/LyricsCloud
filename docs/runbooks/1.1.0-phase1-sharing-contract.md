## 확정한 권한과 자료 경계

1. `owner_id`는 자료의 실제 소유자로 유지하고 요청 주체는 별도 `actor_id`로 판정한다. 타인을 owner로 가장시키지 않는다.
2. 1.1.0은 `private`와 로그인한 지정 사용자 `selected-read`만 제공한다. 공개 링크·선택/공개 쓰기는 생성·API·UI 모두 비활성이다.
3. grant는 특정 가사 resource와 grantee의 실제 집합이다. owner는 항상 읽고 관리하며, grantee는 활성 read grant가 있는 가사만 읽는다.
4. 공유 응답 필드는 가사 제목·본문·상태·수정 시각과 owner가 공유용으로 허용한 표시 이름으로 제한한다. 작업 메모, 곡/다른 가사, 라임, 프롬프트, Suno 링크, revision, 개인 설정, 이메일과 내부 사용자 ID는 포함하지 않는다.
5. 개인 목록·검색·내보내기·revision·복제는 owner-only를 유지한다. 공유 가사 접근은 전용 화면/API/실시간 구독에서만 허용한다.
6. 존재하지 않는 가사·수신자·grant와 권한 없는 요청은 외부에서 구분하지 못하는 일반화된 응답을 사용하고 공유 응답은 `private, no-store`로 제공한다.

## 저장·API·실시간 인터페이스

### 저장

- 사용자에게 이메일 대신 무작위·비열거형 `sharing_id`를 발급한다. 이 값으로 수신자를 지정하며 이메일/내부 PK 조회 API를 제공하지 않는다.
- `lyric_read_grants`는 `resource_id`, `owner_id`, `grantee_id`, 활성/회수 상태, `permission_epoch`, 생성·회수 시각을 보관한다.
- 중복 grant 생성은 멱등하게 처리한다. 같은 owner/resource/grantee에 활성 grant는 하나뿐이다.
- RLS는 owner 관리와 활성 grantee 읽기를 분리하고, grantee의 수정·삭제·ACL 변경은 항상 거부한다.

### HTTP

- owner 관리: `GET/POST /api/lyrics/:lyricId/shares`, `DELETE /api/lyrics/:lyricId/shares/:grantId`
- viewer 읽기: `GET /api/shared/lyrics/:lyricId`, `/shared/lyrics/:lyricId`
- 회수·삭제·차단 계정은 다음 요청부터 일반화된 unavailable 응답이다.

### WebSocket

- 연결 문맥은 `actorId`, 실제 `ownerId`, `resourceId`, `accessMode`, `permissionEpoch`를 분리한다.
- reader는 snapshot/update와 서버 검증 presence만 수신하고 CRDT update·revision 생성은 거부한다.
- subscribe, reconnect, 각 client message와 broadcast 직전에 현재 권한/epoch를 확인한다. 회수 시 socket을 종료하고 presence를 제거한다.
- presence는 서버가 인증한 공유 표시 이름과 일시 색상/상태만 포함한다. 이메일·내부 ID와 클라이언트가 주장한 타인 identity는 전달하지 않는다.

## 정상·오류·권한·복구 입력표

| 분류 | 입력 | 기대 결과 | P2/P3/P4 검증 |
|---|---|---|---|
| 정상 | owner가 A의 `sharing_id`로 가사 한 개를 공유 | A 전용 읽기 API/화면과 reader socket만 허용 | DB+API+browser |
| 정상 | 같은 grant 요청을 같은 멱등 키로 반복 | 활성 grant 하나와 같은 결과 | DB 경쟁 시험 |
| 오류 | 잘못되거나 존재하지 않는 `sharing_id` | 사용자 존재 여부를 드러내지 않는 동일 오류 | API 계약 |
| 권한 | B가 lyric/grant/document key를 변조 | HTTP·RLS·WS 모두 거부, 다른 자료/참가자 미노출 | DB+API+WS |
| 권한 | A가 본문 update·revision·export/search 호출 | 모두 거부, owner 원문 불변 | DB+API+WS |
| 범위 | A가 공유 가사를 읽음 | 제목/본문/상태/수정 시각 외 메모·연결 자료·다른 버전 미노출 | API+browser |
| 회수 | A가 보는 동안 owner가 grant 회수 | 다음 내용·presence 수신 중단, socket 종료, 이후 HTTP 거부 | WS+browser |
| 계정 | grantee가 차단/탈퇴됨 | grant가 남아도 접근 거부 | DB+API |
| 복구 | 기능 flag off 또는 애플리케이션 rollback | owner-only 개인 기능과 원문 유지, 신규 공유만 중단 | restart+rollback |

## 호환과 되돌림

- 기존 owner API, 개인 화면, CRDT document key와 원문 저장 형식은 바꾸지 않는다. 신규 viewer 경로만 actor/grant 판정을 소비한다.
- 기능 flag를 끄면 owner-only 동작으로 즉시 복귀한다. grant 행은 감사/재가동을 위해 보존한다.
- migration 역삭제는 활성 grant와 reader session이 없음을 확인한 별도 승인 때만 수행한다. 가사·revision·sync update를 파괴하는 rollback은 금지한다.
- 이미 읽거나 복사한 내용의 회수는 보장하지 않는다. 회수는 이후 서버 접근과 신규 수신을 차단한다.

## 미실행과 잔여 위험

P1은 설계-only라 runtime, migration, CI, 서버 배포를 실행하지 않았다. 다중 계정 PostgreSQL/RLS, socket 회수 지연, 브라우저 cache, 실제 화면은 P2~P4에서 검증한다. 외부 백업 미구축 `OPS-100-001` 예외는 사용자의 기존 지시에 따라 유지하되 migration 전 DB volume과 secret을 보존한다.
