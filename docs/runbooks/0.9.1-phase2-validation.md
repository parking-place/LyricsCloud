# 0.9.1 Phase 2 검증 기록

## 범위

- `LC-091-P2-01`~`LC-091-P2-09`
- OAuth/OIDC·session, 60개 Web API와 collaboration, 32개 DB table의 사용자 격리
- 저장·반사·DOM XSS, CSRF/Origin, no-store, body size와 요청 빈도
- dependency·Git history·빌드 산출물·네 production image의 runtime·취약점·secret

상세 판정은 [보안 감사 보고서](../security/0.9.1-security-audit.md)와 [API·데이터 소유권 행렬](../security/0.9.1-api-ownership-matrix.md)에 기록한다.

## 수정과 방어선

- OIDC S256 challenge와 callback verifier, nonce binding을 자동 검증했다.
- 53개 POST/PUT/PATCH/DELETE handler에 exact `APP_ORIGIN` 검사를 적용하고 profile·logout도 공통 helper로 통일했다.
- 모든 API mutation body를 stream 기준 1 MiB에서 선차단한다.
- 로그인·callback은 Cloudflare/trusted proxy IP별 40회/5분, 검색은 사용자별 120회/분, export는 사용자별 6회/분으로 제한하고 429·`Retry-After`·no-store를 반환한다. client bucket은 최대 10,000개에서 오래된 key를 제거한다.
- 요청별 nonce CSP를 적용하고 고정 theme bootstrap 외 `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function` production sink가 없음을 정적으로 고정했다.
- production runtime을 고정 digest Distroless Node 24 Debian 13 nonroot로 전환하고 rootfs read-only·tmpfs·내장 healthcheck를 검증했다.
- 개발 배포 Compose도 네 production target과 절대 `/app` entry path·Distroless health probe를 사용하고, 배포 검사는 shell 유틸리티 대신 image metadata와 `/nodejs/bin/node`를 사용한다.
- `drizzle-orm`을 advisory 수정 버전 `0.45.2`로 올렸고 runtime의 `tsx`·package toolchain을 제거했다.
