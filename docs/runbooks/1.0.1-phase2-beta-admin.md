# 1.0.1 P2 베타코드 관리자 인수

## 명령과 권한 경계

`bin/LyricsCloud`는 저장소의 고정된 관리자 진입점이다. `pnpm`이 있는 관리 호스트에서는 TypeScript 원본을 실행하고, 없는 서버에서는 `compose.admin.yaml`의 격리된 관리자 컨테이너만 실행한다. 일반 web·collaboration·worker 서비스에는 `BETA_CODE_AEAD_KEY_FILE`이나 관리자 테이블 권한을 주지 않는다.

관리 서비스 계정으로 아래 순서를 사용한다. 전역 설치가 필요하면 저장소 밖의 사용자 전용 bin 디렉터리에 `bin/LyricsCloud`의 symlink를 만들고, 복사본을 만들지 않는다.

```bash
node scripts/provision-beta-code-keys.mjs
chmod 600 .private/runtime/beta_code_index_key .private/runtime/beta_code_aead_key
ln -sfn "$PWD/bin/LyricsCloud" "$HOME/.local/bin/LyricsCloud"
LyricsCloud betacode -n 7
LyricsCloud betacode ls
LyricsCloud betacode refresh
```

키 준비 스크립트는 기존 파일을 덮어쓰지 않고 값도 출력하지 않는다. `.env`에는 `BETA_ENVIRONMENT`, `BETA_CODE_INDEX_KID`, 1~168 범위의 선택적 `BETA_CODE_TTL_HOURS`만 둔다. 키 파일은 Git·image·웹 runtime·로그에 포함하지 않는다. 관리자 컨테이너는 호출한 서비스 계정과 같은 UID/GID로 실행해 mode 600 bind mount를 읽는다.

`refresh`는 현재 환경명을 대화형으로 다시 입력해야 한다. 자동화에서는 `--confirm-environment development|release|test`를 명시한다. 먼저 commit한 발급/refresh 순서를 PostgreSQL advisory transaction lock이 결정한다. refresh는 unused code와 pending intent만 폐기하며 사용 receipt, admission grant와 사용자 자료는 변경하지 않는다.

## 검증과 복구

- migration `0900_beta_access.sql`은 코드 epoch·batch·digest tombstone·가입 intent·grant·receipt·실패 budget을 추가한다.
- `LyricsCloud betacode -n 7`은 batch 전체 commit 뒤 7개 코드만 표준 출력에 쓴다. `0`, 음수, 소수, 비숫자, `101` 이상은 비0 종료하며 DB에 일부 발급을 남기지 않는다.
- `ls`는 현재 환경의 unused·unexpired·unrevoked code만 AEAD 검증 후 표시한다. 출력 장치 실패 뒤에도 이미 commit된 batch는 `ls`로 복구한다.
- 코드 원문은 사용·폐기·만료 시 ciphertext까지 제거하지만 HMAC digest tombstone은 남겨 재발급을 막는다.
- rollback SQL은 beta state가 한 건이라도 있으면 중단한다. 장애 시 schema를 유지한 application-first rollback을 우선하고, 빈 격리 DB에서만 down/reapply한다.

P2는 가입 UI나 callback을 열지 않는다. P3의 HMAC test-user 이행과 P4의 검증된 Google identity 원자 소비 전에는 신규 가입이 제공됐다고 안내하지 않는다.

원격 브랜치와 PR #14는 후보 `0dcbd643fe045048ebee000093904e63d25ae1aa`를 가리켰다. 개발 서버를 같은 SHA로 build·migration한 뒤 네 서비스 health, 관리자 1개 발급→`ls` 복구→`refresh` 폐기와 공개 live/ready/auth 200을 확인했다. 공개 ready의 build ID는 후보와 같고 schema는 `0900_beta_access.sql`이다. canary 원문은 출력하지 않고 mode 600 임시 파일을 삭제했으며 code digest tombstone과 refresh 기록만 개발 DB에 남겼다. 원격 전체 CI는 저장소 규칙에 따라 P10 최종 통합 후보에서 수행하며 P2 중간 push는 PASS로 오기하지 않는다.
