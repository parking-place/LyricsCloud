## 실제 DB·브라우저 결과

- 격리 PostgreSQL에서 domain/store 집중 회귀 10건 PASS 후, P4의 즐겨찾기 삭제·복원과 세 자료 유형 독립 상태를 포함한 store 회귀 5건을 다시 PASS했다.
- P3 코드 기준 전체 Vitest/PostgreSQL 77 files·309 tests PASS. P4는 여기에 독립 순서 상태와 즐겨찾기 복원 회귀 2건을 추가했으며 관련 파일 5건 PASS로 확인했다.
- Chromium desktop/mobile 전체 358건 중 322 PASS·환경 조건부 36 skip. 저장·오프라인 재접속·두 탭·한글 IME·가사/라임/프롬프트와 직전 버전 기능을 포함한다.
- Chromium/Firefox/WebKit desktop과 Chromium/WebKit mobile에서 1.0.9 기능 15건 PASS.
- 실제 OS/물리 기기는 새로 실행하지 않았다. 브라우저 엔진 자동화와 viewport 결과를 실기기 결과로 기록하지 않는다.

## 수용 사례와 실패 복구

- `AC-1.0.9-01`: 프롬프트 카드를 옮긴 뒤 읽은 `tokens`와 `plainText`가 이동 전과 동일하고, UI 복사와 순서 버튼이 분리된다.
- `AC-1.0.9-02`: touch pointer가 이동하면 long-press 복사 타이머가 취소되고, 이동 버튼·drag handle은 카드 복사를 실행하지 않는다.
- `AC-1.0.9-03`: 즐겨찾기 프롬프트를 수동 순서 중간으로 옮긴 뒤 삭제·복원하면 같은 rank에 한 번만 나타난다.
- `AC-1.0.9-04`: 곡·라임·프롬프트 이동은 서로 다른 owner/type 상태와 version을 각각 1만 증가시키며 다른 유형 순서를 바꾸지 않는다. cross-pin anchor와 stale cursor는 거부된다.
- 응답 유실은 낙관 순서를 원복하고 동일 요청 재시도를 제공한다. 인증 없는 고정 type API는 401이고 다른 owner 자료는 anchor가 될 수 없다.

## 남은 동일 SHA 인수

원격 전체 CI, 네 dev image, 정확한 SHA 개발 배포, 공개 HTTPS 기능 smoke와 서비스 재시작 전후 순서 보존은 후보 push 뒤 수행한다. 첫 결과가 실패하면 PASS로 기록하지 않고 원인 수정 후 같은 범위를 재실행한다.

사용자가 제외한 `OPS-100-001` 운영 백업 구축은 이 기능 회귀 범위에 포함하지 않는다. 기존 정적 backup·restore 계약 검증은 계속 유지한다.
