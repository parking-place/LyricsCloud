# 1.1.7 P4 사용성·접근성 재검토

## 범위

- P3의 exact 목록→대시보드→가사→공유/Suno→목록 복귀를 동일 입력으로 재실행해 관찰된 막힘의 전후 결과를 비교한다.
- reduced motion, forced colors/contrast 대리, 720 CSS px reflow와 390px 저사양 대리에서 navigation·dialog·editor 기능 동등성, focus와 overflow를 확인한다.
- owner/reader presence·회수, composition/selection/undo, Noto Sans KR 적용·차단 fallback을 새 탐색의 영향 회귀로 확인한다.
- API·DB schema·권한·본문·copy/export 계약은 변경하지 않는다. 외부 사전 no-go도 유지한다.

## 증거 계획

1. 실패 우선 계약으로 reduced motion/contrast/reflow fallback과 이번 Phase의 회귀 범위를 고정한다.
2. 실제 격리 PostgreSQL에서 단위·전체 Chromium 및 Chromium/Firefox/WebKit 집중 흐름을 실행한다.
3. production image 경계와 collaboration/service restart를 포함한 저장·권한·복구 회귀를 실행한다.
4. 후보의 필수 CI와 네 signed dev image를 확인한 뒤 정확히 같은 SHA를 개발 서버에 배포해 공개 흐름을 재실행한다.

UX 목업의 396페이지 정적 검토는 비교 입력일 뿐 실제 제품 수용 증거로 대체하지 않는다. 실제 Windows/macOS/Linux/iOS/Android, OS 200% zoom, NVDA/VoiceOver/TalkBack, 물리 저사양 GPU·배터리와 OS IME는 자동 browser 결과와 구분해 미실행으로 남긴다.

## 로컬 후보 결과

P3의 translucent surface가 플랫폼의 transparency/contrast 요청에서도 그대로 남는 실패 우선 계약을 추가한 뒤, semantic token과 기존 component tree 안에서 다음 fallback만 구현했다.

- `prefers-reduced-transparency: reduce`: 상단/모바일 navigation·dock의 blur를 제거하고 panel을 불투명하게 유지한다. modal backdrop도 불투명 검정으로 단순화한다.
- `prefers-contrast: more`: current/selected/pressed 상태에 currentColor border와 2px outline을 추가한다.
- `forced-colors: active`: system Canvas/CanvasText/Highlight를 사용하고 navigation blur를 제거한다.

| 검증 | 결과 | 경계 |
|---|---:|---|
| P4 contract | 6/6 PASS | fallback 선언과 기존 P2/P3 계약 |
| architecture boundaries·typecheck·production build | PASS | API/DB/schema 변경 없음 |
| 전체 Vitest, 실제 격리 PostgreSQL | 380/380 PASS | `AUTH_DATABASE_INTEGRATION=true`, beta 통합 포함 |
| Chromium desktop/mobile 전체 E2E | 379 PASS / 43 조건부 skip / 0 FAIL | 프로젝트별 미지원·조건부 항목만 skip |
| P4 5-browser 집중 행렬 | 8 PASS / 7 조건부 skip | forced colors는 Chromium, 4x CPU 대리는 Chromium mobile 한 번 |
| 공유/복구·10,000줄 editor/IME·폰트 영향 회귀 | 14 PASS / 2 조건부 skip | 선택 공유/presence 회수, 원문·selection·undo 포함 |

720 CSS px는 1440px 화면의 200% 확대 reflow 대리로 사용했고 수평 overflow 없이 exact 목록 복귀·가사 원문·공유 dialog Escape 후 trigger focus를 확인했다. Chromium mobile CDP 4x CPU throttle에서는 입력→저장 상태→API 원문 영속과 overflow를 확인했다. 외부 사전 요청은 만들지 않았다.

- 후보: `66f2f79967828ca40237a0d7a241d6da54094d37`
- 필수 CI: push `34894853203`, PR `34894869965` 모두 성공
- signed dev image exact digest: web `sha256:9de0a8f35dee6cd7d6d5180752eb7fd8f1eb891f8efe7d53b4316d912b92ead1`, collaboration `sha256:76e7ce74404e7c68183e0c6b6b6e4b4872dfefe3f0f199dd4727a859d1665c33`, worker `sha256:a3f24b61097d57e85a12300f96d68b62cdc04d2ccd7314d92b8d9562824f784b`, migrate `sha256:9d19b950716902bddbd096c580396108bb465cee42bdf7c745d48e2d70004e11`
- SHA tag와 `dev-1.1.7-p4` alias의 digest가 네 서비스 모두 일치했다.
- 개발 checkout·health build는 exact 후보, schema는 `1140_sharing_stability.sql`, PostgreSQL/web/collaboration/worker는 healthy였다.
- 공개 smoke에서 reduced motion, 720px reflow, forced colors, dialog Escape/focus, 390px Chromium mobile 4x CPU 입력을 통과했다. 입력은 저장 직후와 3초 후 API·CRDT 모두에 존재했고 web/collaboration/worker를 실제 재시작한 뒤에도 exact 원문·목록 query 복귀가 유지됐다.
- fixture 계정과 하위 자료는 FK cascade로 제거했다. PostgreSQL volume과 릴리스 서버는 변경하지 않았다.

최초 공개 시도는 `contenteditable`/동기화 준비 전에 locator만 확인해 입력 결과가 유효하지 않았고, 재시작 전 API·CRDT에도 원문이 없음을 진단했다. 최종 smoke는 `contenteditable=true`와 `방금 저장됨`을 선행조건으로 고정했으며 저장 직후·3초 후·재시작 후를 각각 확인했다. 이 준비 전 시도는 제품 저장 실패 증거로 사용하지 않는다.

## 미실행·인계

실제 Windows/macOS/Linux/iOS/Android, OS 200% zoom, NVDA/VoiceOver/TalkBack, 물리 저사양 GPU·배터리, OS IME, native SDK/서명/스토어는 실행하지 않았다. P5는 이 웹 지원 범위와 B-1/classic rollback, 플랫폼별 조건부 gate를 개발안에 그대로 인계한다.

## 중단·되돌림

- 원래 목록 query, focus, 가사 원문, selection/undo, 공유 권한 또는 미전송 상태가 달라지면 후보 배포를 중단한다.
- UI 보정이 필요하면 semantic token과 기존 component tree 안에서 최소 변경하고 B-1/classic 전환 계약을 유지한다.
- 개발 서버 rollback은 직전 exact P3 image/SHA로 되돌리며 migration 추가가 없으면 schema 역변경을 하지 않는다.
- 릴리스 서버는 P4에서 변경하지 않는다.
