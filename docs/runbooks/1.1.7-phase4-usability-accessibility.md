# 1.1.7 P4 사용성·접근성 재검토

## 범위

- P3의 exact 목록→대시보드→가사→공유/Suno→목록 복귀를 동일 입력으로 재실행해 관찰된 막힘의 전후 결과를 비교한다.
- reduced motion, forced colors/contrast 대리, 720 CSS px reflow와 390px 저사양 대리에서 navigation·dialog·editor 기능 동등성, focus와 overflow를 확인한다.
- owner/reader presence·회수, composition/selection/undo, Noto Sans KR 적용·차단 fallback을 새 탐색의 영향 회귀로 확인한다.
- API·DB schema·권한·본문·copy/export 계약은 변경하지 않는다. 외부 사전 no-go도 유지한다.

## 증거 계획

1. 실패 우선 계약으로 reduced motion/contrast/reflow fallback과 이번 Phase의 회귀 범위를 고정한다.
2. 실제 격리 PostgreSQL에서 단위·전체 Chromium 및 Chromium/Firefox/WebKit 집중 흐름을 실행한다.
3. production image 경계와 collaboration/service restart를 포함한 저장·권한·복구 회귀를 실행한다.
4. 후보의 필수 CI와 네 signed dev image를 확인한 뒤 정확히 같은 SHA를 개발 서버에 배포해 공개 흐름을 재실행한다.

UX 목업의 396페이지 정적 검토는 비교 입력일 뿐 실제 제품 수용 증거로 대체하지 않는다. 실제 Windows/macOS/Linux/iOS/Android, OS 200% zoom, NVDA/VoiceOver/TalkBack, 물리 저사양 GPU·배터리와 OS IME는 자동 browser 결과와 구분해 미실행으로 남긴다.

## 중단·되돌림

- 원래 목록 query, focus, 가사 원문, selection/undo, 공유 권한 또는 미전송 상태가 달라지면 후보 배포를 중단한다.
- UI 보정이 필요하면 semantic token과 기존 component tree 안에서 최소 변경하고 B-1/classic 전환 계약을 유지한다.
- 개발 서버 rollback은 직전 exact P3 image/SHA로 되돌리며 migration 추가가 없으면 schema 역변경을 하지 않는다.
- 릴리스 서버는 P4에서 변경하지 않는다.
