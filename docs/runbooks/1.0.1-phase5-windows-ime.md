# 1.0.1 Phase 5 — Windows 한글 IME 무손실 인수 기록

## 원인과 수정 경계

CodeMirror의 조합 중 변경은 `ChangeSet`으로 모아 중간 preedit를 Yjs에 보내지 않는다. 기존 구현은 `compositionend` 뒤 확정 transaction을 `setTimeout(0)`으로 미뤘고, 사용자가 곧바로 다른 화면으로 이동하면 React cleanup이 그 타이머를 취소했다. 화면에는 완성된 문장이 보이지만 Yjs update와 IndexedDB outbox에는 들어가지 않아 재진입 때 서버 원문으로 돌아가는 최초 손실 경계였다.

확정 처리를 같은 이벤트 턴의 microtask로 옮기고 `compositionend`가 관찰된 변경만 명시적으로 drain한다. 가사·라임은 명령 이동, `pagehide`, 컴포넌트 정리 전에 이 drain을 재사용하고, 확정 전 원격 update는 기존처럼 보류한다. 제목·메모 metadata와 프롬프트 제목도 이동·종료 전에 현재 확정값을 flush한다. 조합이 진행 중인 preedit 자체를 Yjs transaction으로 승격하지 않는다.

- 같은 즉시 이탈 회귀: Firefox 3 PASS, WebKit mobile 3 PASS

`pnpm why yjs -r`은 전체 workspace와 `y-indexeddb` peer가 단일 `yjs@13.6.32`를 사용함을 확인했다. Next.js build/SSR worker에서 보이는 중복 import 경고는 실제 두 버전 설치와 구분했고, 이번 입력 손실의 타이머 취소 원인과 무관하므로 의존성·major 버전·CRDT 포맷을 변경하지 않았다.

합성 이벤트·fill/paste는 실제 Windows Microsoft 한국어 IME를 대신하지 않는다. 개발 HTTPS에 후보를 배포한 뒤 Windows Chrome·Edge에서 `바라봐`, `마냥`, `마땅한`을 가사 본문·제목/메모·라임·프롬프트에 입력하고 즉시 이탈, 재진입, 복사, 다중 탭 결과가 문자 단위로 같은지 사용자 인수를 받는다.

## 데이터와 rollback

DB migration이나 저장 포맷 변경은 없다. 앱 rollback은 이전 immutable SHA로 되돌리며 PostgreSQL·IndexedDB·Docker volume을 삭제하지 않는다. rollback 뒤에도 이미 서버 ACK를 받은 Yjs update와 로컬 outbox는 보존한다.
