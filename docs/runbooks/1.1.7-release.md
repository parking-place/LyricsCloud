# LyricsCloud 1.1.7 정식 릴리스 실행

## 사전 조건

1. P1~P5가 complete이고 최종 후보 전체 CI·네 dev image·동일 SHA 개발 인수가 PASS여야 한다.
2. Phase PR을 main에 병합하고 main CI가 통과해야 한다.
3. main HEAD에 annotated `v1.1.7`을 만들며 tag를 이동하지 않는다.

## 발행과 배포

tag workflow를 `publish=true`, `release=true`로 실행한다. `1.1.7`, source SHA, `Release`, `latest`, `Release-latest`가 서비스별 같은 digest인지 확인하고 digest로만 배포한다. 릴리스 서버에서는 migrate를 먼저 실행한 뒤 collaboration·worker·web을 전환하고 기존 PostgreSQL volume·secret·HMAC allowlist·beta code와 전역 `LyricsCloud` CLI를 보존한다.

## 검증과 중단

live/ready의 `1.1.7/release`, exact build SHA, phase 없음, schema `1140_sharing_stability.sql`과 네 서비스 health를 확인한다. 공개 PC/mobile×dark/light B-1 root·overflow, quick-add exact 복귀·목록 query 복귀·가사 저장/재진입·공유/복구·다른 owner 격리와 서비스 재시작 지속성을 확인하고 합성 fixture를 제거한다. 불일치·원문 유실·거짓 저장 성공·권한 우회가 있으면 중단한다.

시각 결함만이면 같은 image의 `LC_UI_VARIANT=classic`을 우선 사용한다. application-first rollback은 `v1.1.6` exact digest를 복원하며 DB volume과 1140 schema를 삭제하지 않는다. `OPS-100-001` 때문에 호스트 손실 복구 지점은 보장되지 않는다.
