# 1.1.4 정식 릴리스 실행

사용자는 1.1.4 P1~P5 완료 뒤 main 병합·annotated `v1.1.4` tag·정식 image·릴리스 서버 배포를 승인했다. 최종 후보와 main 전체 CI가 통과한 같은 source SHA에 tag를 만들며 tag는 이동·재사용하지 않는다. `OPS-100-001` backup 미구축은 명시적 위험 예외다.

1. P5 PR을 main에 merge하고 main SHA의 필수 CI를 확인한다.
2. main HEAD에 annotated `v1.1.4` tag를 만들고 `publish=true`, `release=true` workflow를 실행한다.
3. web·collaboration·worker·migrate의 `1.1.4`, `Release`, `latest`, `Release-latest`가 같은 source SHA와 exact digest를 가리키며 signature·provenance·SBOM이 있는지 확인한다.
4. 릴리스 서버는 exact digest를 기록하고 migrate→collaboration→worker→web 순서로 전환한다. DB volume·secret·HMAC allowlist·beta code를 보존한다.
5. 공개 ready가 version `1.1.4`, release channel, phase `null`, schema `1140_sharing_stability.sql`과 exact SHA를 반환하는지 확인한다.
6. 삭제/복원 뒤 old capability 비부활, owner 복원과 offline writer 수렴, bounded queue·권한 회수/계정 전환 격리와 collaboration 재시작을 공개 HTTPS에서 확인하고 합성 fixture를 제거한다.
7. 실패 시 application-first rollback으로 직전 `v1.1.3` exact digest를 복원한다. schema나 자료 무결성이 의심되면 쓰기를 중단하고 격리 restore한다.

## 실행 결과

정식 main/tag CI·exact digest 운영 배포·공개 smoke·GitHub Release 결과는 실행 뒤 이 절에 봉인한다.
