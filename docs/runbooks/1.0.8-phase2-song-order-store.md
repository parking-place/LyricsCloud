## 실패 우선과 구현 경계

미구현 manual 정렬·anchor 명령 계약을 runner에 먼저 등록해 실패를 확인했다. 구현은 전체 ID 배열을 받지 않고 `itemId`, 보이는 `beforeId`/`afterId`, `expectedVersion`, `requestId`만 받는다. owner+자료유형별 order state, pin group별 sparse rank와 request ledger는 자료 본문·전역 핀 metadata와 분리되며 forced RLS가 적용된다.

동시 요청은 owner advisory lock과 state CAS로 하나만 승인한다. 동일 request/body 재전송은 저장된 결과를 replay하고 다른 body의 request ID 재사용은 거부한다. soft delete는 rank를 지우지 않아 복원 위치를 보존한다. manual paging cursor는 order version을 포함해 이동 뒤 오래된 cursor를 거부한다.
