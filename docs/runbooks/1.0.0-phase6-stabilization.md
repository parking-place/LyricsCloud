## 재현과 로컬 검사

`node --test scripts/tests/p6-*.mjs`: 90 tests, 90 pass, 0 fail/skip. 환경 Node 22.16.0 / TypeScript 5.8.3. 이는 지원 환경 Node 24의 전체 제품 검증을 대신하지 않는다.

먼저 실패를 확인한 추가 검사: publication 호환성 2 fail, export/withdrawal 13 fail, codebase audit 6 fail, unknown nested telemetry 1 fail, release phase helper 8 fail. 각 수정 후 해당 검사가 통과했다. 기존 52개 batch 검사도 현재 후보에서 재실행했다. DB·age·OpenTelemetry를 모사하는 검사는 테스트 파일에 명시하며 React handler 검사는 실제 원문 콜백을 추출한 격리 상태 전이이고 DOM 검사가 아니다.

실제 PostgreSQL 검사 3개는 `packages/database/src/export-safety.integration.test.ts`에 추가했다. `AUTH_DATABASE_INTEGRATION=true` 및 전용 `lyricscloud_test`만 허용한다. 현재 환경에는 PostgreSQL/pnpm/Docker가 없어 이 검사는 로컬 실행하지 않았다. 기존 CI의 unit/integration 단계가 실행하도록 한다.

## 제한된 최적화 측정

관측성에서 allowlist에 없는 필드의 중첩 객체 순회를 생략하고 금칙어 배열의 반복 할당·소문자 변환을 제거했다. 정상/민감/이상 입력 1,003개에서 이전 수정본과 결과가 같았다. 첫 100개 top-level 필드 제한과 redaction 깊이 제한을 유지한다.

동일 프로세스 5회 교대 측정, 회당 10,000회, 1,000회 warm-up의 중앙값:

| 합성 입력 | 이전 ms | 이후 ms |
|---|---:|---:|
| 일반 route 오류 로그 | 136.268 | 73.904 |
| 일반 저장 metric | 98.968 | 50.190 |

이 수치는 Node 22의 함수 미세 측정이다. 전체 앱·Node 24 production·사용자 체감·p95 개선으로 확대 해석하지 않는다. 알려지지 않은 중첩 객체의 극단 합성 시험은 더 큰 차이가 있었지만 제품 성능 배수로 사용하지 않는다.

## 원본과 릴리스 보존

STATUS 과거 전체 blob은 같은 디렉터리의 `STATUS-1.0.0-P5.md`로 손실 없이 보존한다. 기존 Phase 5 validator는 P5 기록 검사를 유지하면서 P6 상태를 별도로 검증한다. `--require-release`는 P6를 허용하지 않는다. 다른 개발 브랜치의 기존 발행 계약은 이번 P6 전용 수정에서 바꾸지 않는다.

## 미완료와 인수 조건

REVIEW-01~05·07·10, Yjs 경고, 전체 의미 기반 코드 리뷰·React Hooks 검사·실제 브라우저/기기·장시간 성능·의존성/컨테이너 최신화는 미완료다. 과거 PowerShell 계획 검사기는 고정 5-phase와 잘못된 current_phase 해석 등 기존 한계가 있어 P6 문서까지 검증했다고 주장하지 않는다. 전체 CI 결과 없이 성공을 선언하거나 테스트를 삭제/완화하지 않는다.

projection 실패 시 export는 보수적으로 503을 반환한다. 특히 휴지통 문서의 pending projection도 영향을 줄 수 있으므로 복구 가용성과 정확한 사용자 재시도 안내는 후속 작업이다. 백업 전체 checksum 검사는 archive I/O 비용이 있고 정상 backup/restore·운영 RPO 보장과 구분한다. 운영 백업 미구축 `OPS-100-001`은 이 코드 변경으로 닫히지 않는다.
