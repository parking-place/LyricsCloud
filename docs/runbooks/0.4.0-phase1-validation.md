# 0.4.0 Phase 1 검증

2026-09-06에 실제 사용자 자료 없이 합성 UUID와 격리 `lyricscloud_test` PostgreSQL, 로컬 개발 DB를 사용했다. 범위는 라임 노트·태그·곡 연결 데이터 계약과 0.3.1 동기화 어댑터 재사용이며 목록·편집 화면은 Phase 2·3 범위다.

## 구현 계약

- `0400_rhyme_notes.sql`은 `rhyme_note` 1:1 subtype, owner별 태그, 라임 노트-태그와 곡-연결 자료 N:M, 생성·복제 요청 식별자를 추가한다.
- 제목 200자, 본문 100,000자, 태그 50자, 노트당 태그 연결 30개 제한을 domain과 DB에 함께 둔다.
- 태그 identity는 NFC 정규화, 앞뒤/연속 공백 정리, 소문자 변환 결과이며 표시 값은 최초 활성 태그의 정리된 표기를 보존한다.
- `PostgresRhymeStore`의 모든 작업은 transaction-local owner와 강제 RLS를 사용한다. 다른 owner의 노트·태그·곡 연결은 FK/trigger와 RLS가 함께 거부한다.
- 곡 연결 해제는 연결 행만 제거하고 라임 원본·태그·다른 곡 연결을 보존한다. soft delete는 원본 관계를 보존하면서 일반 조회·새 연결·sync 접근에서 숨긴다.
- `sync_documents.resource_type`은 `lyrics | rhyme_note`로 확장됐으며 Yjs 본문, IndexedDB outbox, ACK, 평문 projector와 revision 저장 경계를 공유한다. 제목·태그·표시 속성은 관계형 자료로 남는다.
- `0400` rollback은 라임·태그·곡 연결·라임 sync 자료가 있으면 중단하고 기존 가사 문서와 revision을 보존한다.

## 로컬 검증 결과

- 0200·0201·0300·0310·0311·0400 migration을 각각 전진 적용 2회, rollback guard, 역방향, 재적용으로 검증했다.
- PostgreSQL 통합을 포함한 32개 test file에서 라임 태그 30개 한계 시험을 추가해 총 116개 테스트를 통과했다.
- architecture boundary와 8개 TypeScript project typecheck, Next.js production standalone build를 통과했다.
- 네 production image를 만들고 fresh DB migration, web·collaboration·worker readiness, DB/service 재시작, pending projection 복구, revision 복원과 owner-only 로그아웃 smoke를 통과했다.
- Playwright PC·모바일 전체 122개 중 명시적 2개 skip을 제외한 120개가 통과했다. 최초 고병렬 실행에서 기존 OAuth session 복원 1건이 한 번 실패했으나 해당 시험 단독 재실행과 전체 4-worker 재실행은 통과했다. 원격 CI 결과를 최종 판단에 포함한다.
- `apps/web/.next` secret scan과 `git diff --check`를 통과했다.
- 로컬 Compose DB에 0400을 적용하고 web·collaboration·worker를 재기동했다. live·ready는 `0.4.0`, `local-0.4.0-p1`, `0400_rhyme_notes.sql`을 반환했다.
