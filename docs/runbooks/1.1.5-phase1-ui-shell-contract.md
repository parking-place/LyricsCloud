## UI variant와 rollback

P2는 서버 환경 LC_UI_VARIANT를 classic 또는 b1로 파싱하고 RootLayout의 html data-ui-variant에 넣는 방식을 우선한다. 미설정 기본값은 b1로 하되 classic은 동일 image의 즉시 rollback 경계다. 알 수 없는 값은 startup/readiness에서 거부하거나 명시적으로 classic으로 숨기지 않고 설정 오류로 다룬다.

client localStorage/cookie, 계정별 draft key, API payload, DB row에 variant를 저장하지 않는다. 서버 렌더와 hydration이 같은 값을 소비해야 하며 UI 두 경로는 같은 React child/store/outbox를 사용한다. variant 때문에 editor를 새 key로 재마운트하면 구현을 중단한다.

P2는 config parser·root attribute·token/surface까지만, P3는 B-1 shell/list/workspace 구조를 적용한다. classic DOM을 완전히 삭제하지 않고 P4 회귀가 끝날 때까지 같은 component에서 조건부 표현 또는 CSS fallback을 유지한다.

## 파일 담당

- P2 config/root/token/test: Codex. packages/config, app layout, packages/ui token, 관련 단위/contract test만.
- P3 shell/list/workspace/E2E: Codex. app-shell, styles, 필요한 목록/dashboard class와 new-feature-1.1.5 E2E.
- P4 regression: Codex. 제품 코드 수정은 재현된 결함의 최소 범위만.
- P5 docs/release candidate: Codex. runtime/image/server는 P5 정확 SHA 인수 전 변경 금지.

한 파일은 한 Phase에서만 주 작성자를 둔다. 기존 schema/API/CRDT/auth 담당 코드는 UI 문제를 이유로 수정하지 않는다.

## 중단·되돌림

- DB migration 또는 API/capability 변경이 필요하면 UI-only 계약 위반으로 중단한다.
- editor remount, IME/selection/undo/draft 유실, 거짓 저장 성공, 계정 교차 노출은 P0/P1 후보로 즉시 variant classic 전환 후 원인을 고친다.
- old URL/returnTo/filter, theme, focus trap/return, 320 reflow가 깨지면 해당 Phase 완료로 표시하지 않는다.
- rollback은 LC_UI_VARIANT=classic과 같은 exact image 재시작을 우선하며 volume·DB·사용자 자료를 삭제하지 않는다.
