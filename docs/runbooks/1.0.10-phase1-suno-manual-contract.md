# 1.0.10 P1 수동 Suno 작업 자료 계약 인수

- 승인: 2026-09-11 사용자 1.0.14까지 전체 Phase와 버전별 정식 릴리스 실행 지시
- 출발점: v1.0.9 main/release `07efeb075ff420d5b835e345584c8023a9c1ba66`
- 현재 Phase: 설계-only. 아래 입력은 P2~P4의 실제 DB/API/browser와 동일 SHA 개발 인수 전까지 PASS가 아니다.

## 모델명과 수동 원본

곡의 Suno 모델명은 LyricsCloud 안의 선택 가능한 작업 메타데이터일 뿐 Suno 생성 요청이나 계정 설정이 아니다. 초기 후보 `v3`, `v3.5`, `v4`, `v4.5`, `v4.5+`, `v4.5-all`, `v5`, `v5.5`는 사용자 제공 예시로만 표시한다. 2026-09-11 공식 Suno 릴리스 노트에는 별도 v6 계열이 안내되어 있으므로 예시를 현행 공식 전체 목록으로 표현하지 않는다. 사용자는 미지정 또는 임의의 과거·신규 label을 저장할 수 있다.

`modelLabel`은 `null` 또는 NFC 정규화 후 양끝 공백만 제거한 1~64 Unicode code point 문자열이다. C0/C1 제어문자와 NUL을 거부하고 내부 공백·대소문자·`+`·`-`는 보존한다. 빈 입력은 `null`로 처리한다. catalog 변화가 이미 저장한 unknown/custom 값을 지우거나 숫자로 재해석하지 않는다.

1.0.10은 URL, 수동 제목, 수동 메모만 원본으로 저장하며 Suno API·HTML·thumbnail·duration을 요청하지 않는다. 1.0.11이 승인된 provider를 확보하더라도 자동 제목·시간·thumbnail·fetch 상태는 별도 파생 필드여야 하고 수동 제목/메모를 덮어쓰지 않는다.

## 링크·URL·순서 계약

한 active 곡에는 최대 20개 링크를 둔다. 링크는 UUID, 인증 owner, parent song, 정규화 URL, 선택 수동 제목, 메모, 0부터 시작하는 연속 순서, 행 version과 생성/수정 시각을 갖는다. 수동 제목은 NFC+trim 0~200 code point, 메모는 원문 줄바꿈을 보존한 0~1,000 code point다. 같은 곡의 동일 정규화 URL은 하나만 허용하고 새 링크는 끝에 추가한다.

허용 URL은 implicit 443의 `https://suno.com` 또는 `https://www.suno.com`이며 userinfo·명시 port·fragment는 거부한다. path는 현재 공식 서비스에서 확인한 `/song/<UUID>`와 공식 host의 짧은 공유 주소 `/s/<6~128 ASCII token>`만 허용한다. `/song`은 소문자 UUID canonical form으로 저장하고 short link는 token case를 보존한다. query는 link-only 공유에 필요할 수 있어 `?` 이후 1,024자 한도 안에서 보존하되 fragment는 입력 오류로 처리한다. 다른 protocol/host/path, IP literal, `localhost`, `javascript:`·`data:`와 제어문자는 거부한다. 1.0.10 서버는 URL로 outbound 연결하지 않는다.

Suno 공식 도움말은 곡이 기본적으로 Private/Link Only일 수 있고 직접 링크를 가진 사람이 볼 수 있다고 설명한다. 따라서 UI는 링크가 비공개 보관 대상임을 알리고 LyricsCloud의 향후 공유/export에 암묵적으로 공개하지 않는다. 새 탭은 native anchor의 `target="_blank" rel="noopener noreferrer"`만 사용하며 자동 재생·download·인증 대행은 하지 않는다.

## aggregate API·멱등성

P2는 기존 내부 라임/프롬프트 연결 route와 충돌하지 않는 다음 한 aggregate를 구현한다.

- `GET /api/songs/:songId/suno-workspace`: `{ modelLabel, links, rowVersion }`. 아직 행이 없으면 `null`, 빈 배열, `0`이며 read가 DB 행을 만들지 않는다.
- `POST /api/songs/:songId/suno-workspace/commands`: `{ requestId, expectedVersion, command, ...commandFields }`. `command`는 `set_model`, `create_link`, `update_link`, `remove_link`, `reorder_links`만 허용하며 성공 시 전체 aggregate를 돌려준다.

server는 body의 owner/song/ordinal/provider metadata를 받지 않는다. `create_link`는 `url,title,note`, `update_link`는 `linkId`와 하나 이상의 수동 필드, `remove_link`는 `linkId`, `reorder_links`는 현재 링크 ID 전체를 중복·누락 없이 받는다. 모든 mutation은 active parent와 인증 owner, aggregate CAS를 한 transaction에서 확인한다. foreign/deleted song 또는 link는 존재를 숨긴 404, stale version은 최신 version을 포함한 409다.

동일 owner+song+request ID와 canonical payload 재전송은 저장된 전체 결과를 `replayed: true`로 반환한다. 같은 ID의 다른 payload는 409이며 어떤 값도 바꾸지 않는다. 실제 의미 변화가 없는 명령은 version을 올리지 않지만 결과를 기록해 replay한다. 성공한 의미 변화는 aggregate version을 정확히 1 올린다. 두 탭이 같은 expected version을 쓰면 먼저 lock을 얻은 명령만 성공하고 다른 명령은 최신값을 다시 읽는다.

## schema·삭제·export·호환

P2의 migration 이름은 `1003_song_suno_workspaces.sql`이다. `song_suno_workspaces`는 owner+song별 nullable model과 aggregate version을, `song_suno_links`는 최대 20개 수동 링크를, `song_suno_command_requests`는 요청 hash와 결과 snapshot을 저장한다. parent는 기존 `resources(id,owner_id,type='song')`에 복합 FK로 묶고 모든 표는 강제 RLS와 app role의 최소 권한을 사용한다.

곡 soft delete는 workspace/link를 수정하지 않고 active API에서만 숨긴다. 같은 곡을 복원하면 링크와 순서·model이 그대로 다시 보인다. 링크 제거는 LyricsCloud 내부 행만 제거하며 Suno 원곡을 삭제하거나 변경하지 않는다. 곡 hard purge 또는 계정 삭제만 FK cascade로 workspace/link/request를 제거한다.

JSON export에는 workspace와 링크의 수동 필드를 별도 section으로 포함하고, 사용자용 곡 TXT/Markdown에는 모델명과 순서가 있는 링크 URL·수동 제목/메모를 포함한다. private/link-only 경고를 가이드에 적는다. 현재 제품에는 곡 복제 API가 없으므로 1.0.10에 새 복제 기능을 만들지 않는다. 향후 곡 복제가 생기면 새 UUID·새 aggregate로 값을 독립 복사하고 한 곡의 수정이 다른 곡에 전파되지 않아야 한다.

구버전 client는 새 table/route를 호출하지 않으므로 기존 곡·가사·라임·프롬프트 흐름을 그대로 사용한다. application-first rollback은 Suno panel/route를 숨기고 기존 image를 재배포하되 additive table과 자료는 보존한다. down migration은 수동 자료를 잃으므로 정식 환경에서 별도 승인 없이 실행하지 않는다.

## 실패 우선 입력표

| 입력 | 먼저 확인할 실패 | P2~P4 기대 |
|---|---|---|
| 서로 다른 3개 song/short link 생성·새로고침 | 마지막 하나만 저장·순서 유실 | 세 링크·수동 값·순서가 재접속 뒤 동일 |
| unknown `v6-wild` 및 `v4.5-all` | 공식 목록 강제·숫자 변환 | NFC/길이만 적용하고 문자열 그대로 보존 |
| `http`, userinfo, port, 다른 host/path, JS/data URL | 브라우저 열기·내부 주소 허용 | 400, 기존 모델/다른 링크/aggregate version 불변 |
| 다른 owner의 song/link ID | 존재 여부 또는 수동 제목 노출 | indistinguishable 404, 양 owner 자료 불변 |
| 같은 request replay·payload reuse | 링크 중복·version 이중 증가 | 동일 결과 replay, 다른 payload는 409 |
| 같은 version 두 탭 수정 | 무음 last-write | 한 성공·한 409, 재조회 후 사용자 재시도 |
| 링크 제거 | 외부 Suno 삭제 암시 | 내부 행만 삭제하고 안내 문구 유지 |
| 곡 휴지통→복원 | workspace cascade/순서 소실 | 휴지통 중 404, 복원 뒤 동일 model/links/order |
| export 중 link-only URL | 누락 또는 창작물 로그 노출 | 사용자 archive에만 포함, telemetry/log에는 없음 |
| offline/network abort | 성공 오인·입력 소실 | 입력을 dialog에 유지하고 저장 실패·재시도 안내 |
