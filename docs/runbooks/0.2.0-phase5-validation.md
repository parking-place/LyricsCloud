# 0.2.0 Phase 5 검증 보고서

## 완료 범위

- 곡 제목·설명·상태·색상·수정 시각과 미지원 0 집계 대시보드
- PC 주 영역·보조 열과 모바일 가사→연결 자료→메모 세로 흐름
- 가사 없음과 연결 자료 없음의 서로 다른 정직한 빈 상태
- 작업 메모, 곡 수정, pin·favorite 낙관적 갱신과 실패 rollback
- 실제 제목·향후 소속 가사 영향을 표시하는 soft delete 확인
- 목록 query 보존과 생성·수정·삭제 뒤 일관된 복귀
- 0.3.0 가사 count·owner·soft delete 인계

## 로컬 검증

2026-09-05에 격리된 `lyricscloud_test` PostgreSQL과 Docker Node 24 환경에서 실행했다.

```text
AUTH_DATABASE_INTEGRATION=true pnpm check
AUTH_DATABASE_INTEGRATION=true pnpm test
NODE_ENV=production pnpm build
E2E_DATABASE_URL=<disposable-test-database-url> pnpm test:e2e
pnpm check:secrets apps/web/.next
```

- architecture boundary와 전체 TypeScript 검사 통과
- unit·DB integration 59개 전체 통과
- production build와 곡 목록·폼·상세 route 통과
- desktop/mobile 전체 E2E 42개 통과
- 목록→생성→대시보드→수정→목록 반영→삭제 흐름 2개 통과
- API 실패 시 pin rollback, 삭제 취소·확정, 삭제 후 상세 404 확인
- 사용자 B 상세 404·제목 비노출·DELETE `deleted: false` 확인
- 전체 흐름 뒤 orphan song·song resource 각각 0건
- build artifact secret scan 0건

## 남은 범위

- 실제 가사 resource·목록·작성은 0.3.0에서 연결한다.
- 같은 owner 여러 탭의 CRDT 병합은 0.3.1에서 연결한다.
- 휴지통 복원 UI와 영구 삭제는 후속 버전 범위다.

가사 영역의 구체적 확장 경계는 [0.3.0 가사 영역 인계](../architecture/0.3.0-LYRICS-HANDOFF.md)를 따른다.
