## 로컬 실행 재현

Git 추적 파일과 커밋 후보 파일만 새 임시 작업 사본으로 복사하고, 별도 Compose project와 빈 named volume을 사용했다.

| 시나리오 | 결과 |
|---|---|
| 빈 작업 사본 `docker compose up --build --wait` | 5개 서비스 시작, migration 1건 적용 |
| web liveness/readiness | `200` / `200` |
| migration 재실행 | `Migrations: OK`, 적용 건수 1 유지 |
| PostgreSQL 중지 | liveness 유지, readiness `503 unavailable` |
| PostgreSQL 재시작 | readiness `200 ok`로 회복 |
| 컨테이너 재생성 | 합성 probe 유지 |
| 명시적 disposable volume 초기화 | 합성 probe 제거, baseline migration 재적용 |
| 공개 포트 | `127.0.0.1:8081→3000` 하나만 공개, DB·worker·collaboration은 내부 전용 |

새 의존성 volume에서 pnpm이 확인 입력을 요구하지 않도록 Compose 앱 환경에 `CI=true`를 고정했다. 기본 개발 주소는 Windows 제외 포트 범위를 피한 `127.0.0.1:8080`이다.

## 화면·보안 기준선

- Chromium `1440×1000`과 `390×844`에서 15개 route의 수평 overflow가 없고 모바일 safe-area token이 적용됨을 확인했다.
- 증거: [`0.0.0-desktop.png`](./evidence/0.0.0-desktop.png), [`0.0.0-mobile.png`](./evidence/0.0.0-mobile.png)
- 커밋 후보를 OAuth client secret, API token, private key, 자격 증명이 포함된 PostgreSQL URL 패턴으로 검사했다. 발견된 3건은 `.env.example`의 `CHANGE_ME`와 테스트 전용 `synthetic` 값뿐이다.
- web image의 환경·history·workspace와 전체 Compose 로그에서 합성 secret canary 및 실제 secret 형식이 0건이었다.
- `.env*`, key, DB data, backup, export, upload, log, test artifact는 Git 제외 규칙으로 보호한다. `.env.example`만 형식 예시로 추적한다.

## 0.1.0 인계

차단 이슈는 없다. `phase/0.0.0-baseline` 원격 push를 확인했으며 0.1.0 Phase 1은 다음 계약을 그대로 소비한다.

- 런타임: Node.js 24, pnpm 11, Next.js standalone, 분리된 collaboration·worker
- 인증: `openid-client`, DB opaque session, Google provider token 비저장, 비공개·초대 허용 목록
- 데이터: PostgreSQL, Drizzle query builder, 검토 가능한 SQL migration, 애플리케이션 소유권 검사와 RLS
- 환경: 실제 값은 추적하지 않는 `.env`; `NODE_ENV`, `DATABASE_URL`, PostgreSQL 키, 외부 origin 계약
- health: 프로세스 liveness와 DB 의존 readiness 분리
- UI: 공통 색상·간격·breakpoint·safe-area token과 PC·모바일 smoke 기준
- 제품 범위: Google 로그인과 실제 인증 화면, 사용자/profile schema는 0.1.0에서 시작하며 곡·가사·CRDT는 계속 제외

## Git·GitHub 인계 체크리스트

로컬 기준선은 `origin/main`과 일치하는 상태에서 `phase/0.0.0-baseline` 작업 브랜치로 분리하고 commit·push했다. 로컬과 원격 branch가 같은 commit을 가리키는지 확인했으며 직접 `main`에는 push하지 않았다.

첫 기준선 commit 후보는 다음과 같다.

- 보호된 기획 원본과 전체 Phase 계획
- ADR-0001~0009, 아키텍처·runbook 문서
- workspace manifest·lockfile, 앱·패키지 중립 골격
- Compose, Dockerfile, migration, Caddy 예시
- 정적 검사·단위 테스트·Playwright smoke와 합성 캡처

commit 대상에서 `.env`, 의존성, build 결과, DB volume, backup, export, upload, log, 실제 사용자 자료를 제외한다.

권한 보유자가 원격에서 수행할 항목:

- [x] 기준선 변경을 Phase 단위 원격 branch에 올리고 직접 `main` push를 사용하지 않는다.
- [ ] 0.1.0 Phase 1의 CI workflow가 추가된 뒤 type/check/test/build를 required checks로 지정한다.
- [ ] `main`에 PR 승인, required checks, 대화 해결, force-push·삭제 금지를 적용한다.
- [ ] GitHub secret scanning과 push protection을 활성화한다.
- [ ] 실제 OAuth·session·DB 값은 repository가 아닌 환경별 secret 저장소에 등록한다.
- [ ] 최초 PR에서 이 보고서, 작업 ID, DB 영향, PC·모바일 증거와 남은 위험을 연결한다.

원격 권한 설정은 로컬 0.1.0 구현의 차단 조건은 아니지만, 보호 규칙을 적용하기 전에는 협업 기준선이 완성된 것으로 간주하지 않는다.
