# 1.1.8 P4 웹 안정화 및 PC 갱신 기록

## 범위와 기준

2026-09-22 사용자가 기존 문제 수정·추가 결함 조사·계획 진행·PC Docker 갱신을 승인했다. 제품 코드는 Astra가 작성하고 독립 분석은 여러 모델이 맡았다. 작업 브랜치는 `phase/1.1.8-p4-web-stabilization`, 기준은 `21f5863` 및 기존 개발 기능 SHA `a7d8e4538c58202f4a1e39371517906e891ae1bf`다. 기존 Windows P4 실제 기기·신뢰 서명 인수와 P5·정식 릴리스 보류는 유지한다.

## 실제 재현과 수정

- 기존 기능 SHA의 production build와 별도 PostgreSQL 18 임시 DB·합성 OIDC 계정을 PC에 구성했다. Windows build 경로 오류는 `fileURLToPath`로 바로잡고 동일 소스 화면을 확인했다.
- 실제 내장 브라우저에서 곡/가사 생성·본문 입력·다시 열기·본문 복사·닉네임 저장을 확인했다. 노트북 1265×712의 도구 버튼은 폭 약 32px·높이 약 111px로 압축돼 한글이 세로로 줄바꿈됐다.
- 수정 전 production build에서 설정 저장 ACK 경쟁, 가사별 표시 설정 ACK 경쟁, 노트북 도구 배치, 휴지통 mutation 성공 후 목록 갱신 실패 회귀가 각각 실패했다. 첫 Playwright 설정은 기존 서버를 재사용하지 못해 시작 단계에서 중단됐고, 전용 설정을 바로잡은 뒤 제품 실패를 재현했다.
- 목록의 오래된 추가 응답·곡 favorite/pin 경쟁·검색 그룹의 키보드 순서·최근 검색 삭제 복원은 실제 컴포넌트 handler와 지연 네트워크 경계를 사용해 수정했다. 서버 cursor/API·schema는 바꾸지 않는다.
- 편집 실패 복사는 제목·가사 원문·메모 또는 라임/프롬프트 입력을 포함한다. 정상 Suno용 복사는 기존 형식을 유지한다. 조합 중 입력 및 메모리의 미저장 제목을 이탈/PWA guard에 표시하며, 기존 offline flush/checkpoint 계약은 유지한다.
- 공개 guest의 온라인 쓰기 권한 회수·stale epoch 거부 때 미승인 Yjs 입력이 본문/캐시에 남는 결함을 수정했다. 마지막 서버 승인 상태로 복원하고 해당 guest가 작성한 부분만 복구 보관하며 재허용 뒤 자동 재전송하지 않는다. 실제 Yjs 단위 3건에서 수정 전 FAIL→수정 후 PASS를 확인했다.

- guest mobile 2건은 제품 연결 실패가 아니라 desktop/mobile을 동일 fixture server에서 연속 실행해 기존 분당 IP handshake 제한의 **429**에 도달한 것이다. 제한·assertion·timeout은 그대로 두고 CI와 같은 project 분리 방식으로 mobile 2건을 재실행해 PASS했다. 실패 시도를 PASS로 소급하지 않는다.
- 실제 내장 브라우저에서 저장된 합성 가사 66자 재열기·전체 복사 원문 일치·console error 0건을 확인했다. 노트북 도구는 읽을 수 있게 개선됐지만 모바일 하단 도구의 세로 줄바꿈과 상단 상태 알림의 설정 링크 가림을 추가 발견했으므로 최종 모바일 보정·재검증 전 전체 UI 완료를 주장하지 않는다.
- 추가 모바일 보정 뒤 production build와 반응형 집중 회귀 **1 PASS**: 960/1265/1366px 노트북, 320/390px 모바일, 양 theme·기존 b1/classic 계약에서 줄바꿈/잘림·overflow 없음, 편집 공간·동일 editor instance 유지와 설정 링크 hit target을 확인했다. 실제 내장 브라우저 320px light에서도 읽을 수 있는 하단 도구와 알림 표시 중 설정 클릭→설정 페이지 이동을 확인했다. 최종 결과는 첫 실행의 8건과 영향 실패 3건 재검증을 합쳐 **집중 11 PASS / 1 조건부 skip**이며, 그중 반응형 1건은 모바일 보정 뒤 확장된 입력으로 다시 통과했다. 실제 물리 모바일 키보드/OS IME 결과는 아니다.

## 과거 결함 전체 범위로 확대한 후속 작업

- 사용자가 UI/UX를 포함한 과거·새 결함의 Astra 병렬 수정을 명시하여 기존 분석의 항목을 `ee3647d`와 다시 대조했다. 해당 후보의 Actions [35700291177](https://github.com/parking-place/LyricsCloud/actions/runs/35700291177)은 새 수정 범위를 포함하지 않으므로 실행 중 취소했다. 최종 결과는 **cancelled**이며 Windows job만 PASS다. 전체 CI·발행 완료로 기록하지 않고 PC 자동 전환도 보류했다.
- CRDT/IME·metadata 복구·복제·Suno/template/정렬/favorites·삭제/export·beta/auth/config·PWA/navigation에 파일별 단일 작성자를 배정했다. 이 작업의 재현/수정 결과는 통합 후보에서 별도로 기록한다.
- 제품 DB와 분리한 tmpfs PostgreSQL의 `lyricscloud_test`에 현재 migration을 적용했다. 데이터 회귀와 인증 회귀는 서로 다른 PostgreSQL 인스턴스를 사용해 fixture cleanup이 충돌하지 않게 했다.
- 기존 production bundle의 실제 내장 브라우저에서 창작 홈→곡 사이드바 이동은 document 요청 1건과 `performance.timeOrigin` 변경을 발생시켰다. 그 전환에서 관측한 요청 이벤트는 25건이며 API fetch 5건(목록 보기 설정·곡·프로필·설정·세션)을 포함했다. 이는 전송 바이트나 지연 시간 측정이 아니며, 수정 뒤 같은 동선으로 문서 재로드·요청 변화를 비교한다.
- 공동개발자의 비공개 리디자인 목업은 이번 수정에서 열거나 바꾸지 않는다. 현재 시각 구성 안의 동작·입력 보존·접근성·잘림을 고치고, 추후 공유된 디자인을 적용할 때 유지할 동작 계약으로 남긴다.

### 집중 재현·통합 전 결과

- 편집·동기화: 선행 자동 저장 timer가 조합 입력을 보내는 경우, 조합 교체 범위 안 원격 삽입 손실, 문장형 프롬프트의 전체 교체·지연 변환 경쟁을 재현했다. autosave·실제 Yjs·CRDT 집중 **26개 고유 사례 PASS**이며, 기존 브라우저 한글 조합 사례에 원격 내부 삽입을 추가했다. 실제 OS IME 결과는 아니다.
- 제목·메모 복구: 계정/문서/초안 revision별 영속 보관과 명시 복원, 늦은 ACK의 새 초안 보존, 복제 명령 잠금·멱등 재시도, 제목 제한·Extend 복사를 수정했다. 원래 범위 **28개 고유 사례 PASS**, 실제 metadata compositionstart와 pagehide·명령·dispose 경계는 **3 FAIL → 3 PASS**다. 계정 정리에서 현 계정 Suno 초안 보존·다른 계정/legacy 삭제 **2 PASS**를 확인했다.
- UI: 지연 Suno 응답·템플릿 형식별 입력·사용자 글꼴·자료 패널·순서 이동/재시도·즐겨찾기 복원·곡 정보 부분 저장의 **15 FAIL → 15 PASS**, 기존 목록 응답 경쟁 **17 PASS**다. 통합 검토에서 새 Suno 초안도 legacy 키를 사용해 재진입 정리에 지워지는 경계를 발견하여 인증 owner 키로 연결한다.
- 데이터: 실제 PostgreSQL에서 export 전체 schema 검증, 모든 자식 가사의 영구 삭제 영향, 라임 잠금 순서와 뒤쪽 projection 재시도를 확인해 **29 PASS**다. projection 실패는 실패 로그/지표로 남기며 interval 중복 진입 **2회 FAIL → 1회 PASS**와 예외 뒤 재진입을 확인했다. migration은 추가하지 않는다.
- 인증/설치: UTC 만료 정규화, OIDC 교환/DB lock 대기 뒤 최신 시각 확인, 과거 코드가 있을 때 새 index kid 거부, 선택 환경값 검증과 설치 안내를 보정했다. 별도 실제 DB 가입 회귀 **8 PASS**와 과거 envelope 정리 뒤 새 kid 거부 **1 PASS**, strict release gate **12 PASS**를 확인했다. 같은 kid의 secret bytes 임의 교체는 지원하지 않는 운영 경계이며 새 키 회전 기능을 주장하지 않는다.
- 탐색/PWA: guard를 유지하는 셸 전환, 동일 URL 단축키 무동작, 요청 내 사용자 조회 공유, 중첩 Escape, 구 build를 쓰는 탭의 정적 캐시 보존이 관련 **20 PASS**다. 실제 브라우저의 문서 재로드·두 service worker build·접근 이름 검증은 통합 production bundle에서 수행한다.
- 부모의 통합 `pnpm check`와 `git diff --check`는 PASS다. 동일 입력의 성공한 단위 결과를 재사용하며, 전체 회귀는 최종 CI 한 곳에서 실행한다. 브라우저 spec 등록이나 단위 PASS를 실제 화면 인수로 기록하지 않는다.

### production 브라우저 인수

- 통합 production build PASS 후 새 과거 결함 spec은 Chromium PC **10 PASS / 모바일 전용 1 skip**, 모바일 최초 **6 PASS / 1 FAIL / PC 전용 4 skip**였다. FAIL은 `toBeAttached`로 검사할 PC 메뉴가 모바일 접근 트리에서 숨겨진 시험 선택자 문제다. 숨김 포함 DOM 존재 확인으로 보정한 해당 모바일 1건 **PASS**이며 기능·문서 재로드 assertion은 유지했다. 총 **17개 고유 사례 PASS / 5 조건부 skip**다.
- 기존 가사 조합 사례에 추가한 교체 범위 내부 원격 삽입은 PC·모바일 **2 PASS**다. 실제 CodeMirror 선택 `BC → 한` 중 다른 탭이 `원격`을 삽입한 뒤 두 편집기와 서버 원문이 `A한원격D`로 수렴했다. 실제 OS IME 조작 결과와 구분한다.
- 실제 내장 브라우저에서 같은 합성 계정의 창작 홈→곡 사이드바 이동은 `timeOrigin`이 유지됐고 document 요청 **1→0**, 전체 요청 이벤트 **25→8**, API 요청 **5→4**였다. 중복 profile 요청이 사라졌고 콘솔 오류는 **0건**이었다. 전송 바이트·체감 시간·Web Vitals의 개선율을 주장하지 않는다.
