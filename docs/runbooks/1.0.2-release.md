# 1.0.2 정식 릴리스 실행

## 승인과 source

사용자는 2026-09-10 현재 요청에서 1.0.2의 정식 배포를 승인했다. P1~P5 후보 SHA와 CI·개발 인수는 [최종 후보 인수](./1.0.2-phase5-final-acceptance.md)와 [추적표](../architecture/1.0.2-FINAL-TRACEABILITY.md)에 있다. 외부 backup 미구축 `OPS-100-001`은 사용자의 기존 명시적 위험 예외를 유지하며 성공으로 기록하지 않는다.

## 불변 순서

1. release 준비 commit에서 1.0.2 environment·migration·license·manifest 계약과 P0/P1 0건을 검증한다.
2. Phase PR을 순서대로 `main`에 병합하고 최종 main SHA에서 필수 CI를 다시 통과한다.
3. 같은 main SHA를 개발 서버에서 확인한 뒤 annotated `v1.0.2` tag를 만든다.
4. 정확한 tag에서 `publish=true`, `release=true` 수동 workflow를 실행한다.
5. web·collaboration·worker·migrate 각각 `1.0.2`·전체 SHA·`Release`·`latest`·`Release-latest`가 같은 digest인지 확인한다.
6. manifest의 exact digest만 릴리스 서버에 적용하고 migrate 뒤 세 app을 갱신한다.
7. 공개 live/ready·auth, 합성 저장/재진입·copy·search·restore/export·owner 격리와 안정 구간을 확인한다.

DB volume·secret·기존 tag를 삭제하거나 재사용하지 않는다. 실패하면 직전 1.0.1 digest로 application-first rollback하고 schema는 유지한다. 파괴적 down migration은 수행하지 않는다.

## 실행 결과 기록 위치

최종 main SHA, CI run, annotated tag, 서비스별 digest, GitHub Release와 운영 smoke는 GitHub Release 및 Git에서 제외된 운영 기록에 남긴다. source commit 안에 스스로의 최종 SHA나 빌드 후 digest를 다시 넣는 순환 commit은 만들지 않는다.
