# 1.0.2 사용자 입력 복구

저장 안내는 `이 기기`의 임시 초안과 `서버` 저장을 구분한다. `방금 저장됨`이 보이지 않거나 저장 실패 안내가 남아 있으면 화면을 닫기 전에 아래 사용자 복구를 먼저 수행한다.

## 사용자가 할 수 있는 복구

1. 편집 화면에 입력이 그대로 보이는지 확인하고 `현재 입력 복사`를 눌러 별도 메모에 붙여 넣는다. Clipboard 권한이 거부되면 제품이 보여 주는 수동 복사 창의 전체 선택 문자열을 복사한다.
2. `동기화 다시 시도` 또는 `다시 시도`를 누르고 `방금 저장됨`을 확인한다. 오프라인이면 네트워크를 복구한 뒤 같은 화면에서 재시도한다.
3. 재로그인이 필요하면 먼저 현재 입력을 복사한다. 초대 가입 실패에서는 입력한 코드가 소비되지 않았다는 안내를 확인하고 `기존 사용자 로그인으로 이동`, `가입 다시 시도`, `입력 지우고 취소` 중 맞는 동작을 선택한다.
4. 업데이트 안내는 확정되지 않은 입력이 남아 있는 동안 새로고침을 강제하지 않는다. 입력을 저장하거나 복사한 뒤에만 업데이트를 적용한다.

브라우저 저장소 삭제, PWA 제거, 강제 새로고침, 다른 계정 로그인은 로컬 초안을 잃을 수 있으므로 사용자 복구 단계에서 수행하지 않는다.

## 운영자만 할 수 있는 복구

- 문의 코드와 발생 시각을 받아 인증·projection·동기화 오류 코드를 확인한다. 실제 초대 코드, Google 메일, 창작물 본문은 요청하거나 티켓에 기록하지 않는다.
- 서버 health와 schema/build ID를 확인하고, 계정 권한·가입 intent·grant 상태는 비공개 운영 도구로 조회한다. 사용자를 대신해 코드를 재사용하거나 DB row를 직접 수정하지 않는다.
- 배포 회귀라면 현재 SHA와 직전 검증 SHA를 대조하고 [개발 배포 runbook](./development-deploy.md) 또는 [upgrade·rollback runbook](./backup-restore-upgrade.md)에 따라 되돌린다. volume·브라우저 저장소·사용자 자료를 진단 편의를 위해 삭제하지 않는다.

복사본까지 만들 수 없거나 다른 사용자의 자료가 보이는 경우에는 입력을 더 진행하지 말고 보안·데이터 사고로 즉시 에스컬레이션한다.
