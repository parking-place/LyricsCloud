# 1.1.1 Phase 3 — 공개 링크 읽기 사용자 흐름

## 구현

- owner 공유 대화상자에 공개 필드, 1·7·30일 만료, 문구 상태, 명시 확인, 일회성 링크 복사, 교체와 회수를 연결했다. raw capability는 대화상자를 닫으면 지우고 다시 조회하지 않는다.
- 비로그인 `/shared/public` 화면은 URL fragment를 탭 전용 session storage로 옮긴 즉시 주소에서 제거한다. 고정 POST와 public read-only WebSocket만 사용하며 workspace·메모·연결 자료·revision·ACL 액션을 제공하지 않는다.
- 만료·회수·잘못된 링크는 자료 존재를 구분하지 않는 동일 안내로 전환하고 본문을 비운다. 페이지와 API는 no-store/noindex/no-referrer 경계를 유지한다.
- 편집기를 한 번도 열지 않은 빈 가사도 링크 발급 시 resource advisory lock 아래 sync 문서를 초기화해 REST projection과 실시간 snapshot이 일치한다.

## 자동 검증

- Node 24.20.0에서 `pnpm check`, production build와 실제 PostgreSQL public sharing 통합 검사가 PASS했다.
- Chromium desktop/mobile 공개 링크 4건과 기존 가사 편집기 20건에서 정상·빈 상태·로딩·권한 거부·한글 IME·undo/redo·초안 복원·저장 실패 재시도를 확인했다.
- 지원 행렬 Chromium·Firefox·WebKit desktop과 Chromium·WebKit mobile 10건이 PASS했다. 공통 정상/live/회수는 전 엔진, 재진입은 대표 PC, 빈 상태는 PC·mobile Chromium에서 검사해 P1의 IP당 분당 10회 handshake 예산 안에 유지했다.
- 후보 `175fd74cb0d2cff88ae7abed478b531983fc13cd`의 Actions push `34695985847`과 PR `34695987903`은 전체 verify를 통과했고 네 development image가 발행·서명됐다. 최초 후보의 전용 행렬 실패는 제품 한도를 초과한 중복 handshake가 원인이었고, 보안 한도 변경 없이 행렬 중복을 줄인 동일 재현이 통과했다.

## 동일 SHA 개발 인수

- 공개 live/ready는 `1.1.1`·`dev`·`p3`, schema `1110_public_lyric_read_links.sql`을 반환했고 postgres/web/collaboration/worker는 모두 healthy였다.
- 합성 owner와 mobile anonymous reader로 공개 확인, 선택 필드, 일회 링크, fragment 제거, private API 401, read-only live 갱신, 열린 탭 회수, 편집기 미개방 빈 가사의 최초 공개를 PASS했다.
- 합성 곡·가사·링크·계정은 인수 직후 제거했다. 실제 Windows/iOS/Android 물리 기기는 P3에서 새로 실행하지 않았으며 P4의 지원 브라우저·offline/reconnect·서비스 재시작 회귀에 남긴다.

P4는 같은 capability 계약에서 revision/메모 기본 거부, 다른 계정, offline/reconnect, 만료·회수 중 socket, collaboration 재시작과 public presence 비노출을 교차 검증한다.
