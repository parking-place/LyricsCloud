# 0.7.0 Phase 1 통합 검색 기반 검증

## 검증 범위

- 곡 제목, 가사 제목·본문, 라임 제목·본문·태그, 프롬프트 제목·평문 토큰의 공통 결과
- 원문과 분리된 NFKC·영문 소문자·공백 축약 검색 projection
- 현재 owner와 활성 자료만 반환하는 RLS + query 이중 경계
- `%`, `_`, 역슬래시, 따옴표의 문자 그대로 검색
- 제목 완전 일치 600, 시작 500, 포함 400, 태그 300, 본문 200 및 안정 keyset page
- `pg_trgm` GIN index와 빈 DB 적용·되돌림·재적용

## 로컬 결과

- `pnpm check`: architecture boundary, TypeScript 통과
- `pnpm test`: 42 files, 158 tests 통과 (`AUTH_DATABASE_INTEGRATION=true`)
- migration 복구: 0200, 0201, 0300, 0310, 0311, 0400, 0500, 0501, 0700 통과
- `pnpm build`: production build 통과. 기존 Yjs 중복 import 경고 외 실패 없음
- `pnpm test:performance:0700`: 합성 가사 1,500개, 각 약 8,000자에서 warm run 측정

| 검색어 | 길이 | 결과 | 계획 | 실행 시간 |
|---|---:|---:|---|---:|
| `가` | 1 | 1,500 | owner 범위 sequential/hash | 2.396 ms |
| `가사` | 2 | 1,500 | sequential + resource identity index | 36.779 ms |
| `needle0700` | 10 | 6 | 선택적 본문 후보 + resource identity index | 10.020 ms |

작은 단일-owner 합성 corpus에서는 planner가 trigram index보다 sequential scan의 비용이 낮다고 판정했다. 여섯 GIN index의 존재와 재생성은 0700 migration 검사로 고정했으며, 데이터 분포가 커질 때 planner가 trigram 경로를 선택할 수 있다. 1~2글자 검색은 예상대로 trigram 선택성이 낮지만 이 기준 fixture에서 50ms 안이었다. 이 수치는 개발 컨테이너의 회귀 기준이지 운영 SLO가 아니다.

## 보안·복구 결론

두 owner에게 같은 제목을 만들었을 때 자신의 결과만 반환됐고, 삭제 자료는 제목·태그·본문 어느 경로에서도 나타나지 않았다. 원문 전각 문자와 줄바꿈은 projection 생성·rollback 뒤에도 보존됐다. 0700 rollback은 파생 열·인덱스·함수만 제거하고 baseline의 `pg_trgm`과 모든 작성 자료를 남긴다.

## 원격·배포 증적

기능 커밋의 CI, 네 개발 이미지 digest, 동일 SHA 개발 배포와 공개 smoke 결과는 Phase 완료 커밋에서 이 절에 추가한다.
