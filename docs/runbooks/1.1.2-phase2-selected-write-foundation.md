# 1.1.2 Phase 2 지정 사용자 쓰기 기반 인수

## 결과

후보 `41db8ff9385a329dc960695eb054acb7c617a8b9`에서 active read grant 안의 선택 쓰기 저장·서버 기반을 인수했다. owner만 read/write를 전환할 수 있고 매 update는 grant·permission epoch·write epoch와 인증 actor를 다시 확인한다. DB update·actor receipt·projection ACK는 한 transaction으로 확정하며, 회수 경계에서 거부된 작성자 본인 원문은 서버 private snapshot과 분리된 기기 내 복구함으로 이동한다.

## 구현 경계

- `packages/database/migrations/1120_selected_lyric_write.sql`: read grant의 write 상태·epoch, access request, actor attribution, accepted sequence, 원자 authorization/receipt 함수.
- `packages/database/src/lyric-sharing.ts`: W⊆R을 유지하는 owner-only access 전환, revoke epoch, writer 최소 projection.
- `apps/web/src/app/api/lyrics/[lyricId]/shares/[grantId]`: same-origin owner PATCH와 기존 revoke 경계.
- `apps/collaboration/src`: message별 selected-writer 인가, actor/epoch receipt와 commit 뒤 ACK, duplicate ACK 복구, 권한 강등·회수, server-auth awareness/selection.
- `packages/editor/src/sync-storage.ts`: Dexie v3 capability tuple outbox와 작성자 본인 원문만 담는 rejected 복구함. read 회수 시 private projection cache 삭제.
- `tests/new-feature/1.1.2.contract.test.ts`, database/collaboration 통합 시험과 `scripts/verify-1120-migration.mjs`: 계약·실제 PostgreSQL·rollback·보안 행렬.

## 검증

- Node 24에서 typecheck/check/production build, 1.1.2 계약 3건, database sharing/collaboration 8건, collaboration server 3건, restart recovery, 1120 및 영향 migration 복구, security ownership matrix를 통과했다.
- 전체 Vitest는 351 PASS·환경 조건부 4 skip, PWA targeted는 2 PASS, 1.1.0 공유 회귀는 Chromium/Firefox/WebKit desktop과 Chromium/WebKit mobile 5 PASS였다.
- GitHub Actions push `34710725889`와 PR `34710727914`가 같은 SHA에서 전체 verify를 통과했고 push run이 web·worker·collaboration·migrate 개발 이미지 네 개를 게시·서명했다. PR 최초 시도의 수 ms revision 측정 CV 변동은 같은 SHA 실패 job 재실행에서 통과했으며 실제 지연·오류 예산은 최초에도 모두 충족했다.
- 개발 서버 공개 live/ready는 `version=1.1.2`, `channel=dev`, `phase=p2`, 동일 build SHA와 schema `1120_selected_lyric_write.sql`을 반환했고 네 서비스가 healthy였다.
- 공개 합성 smoke는 read 기본값, owner-only write 승격, writer 최소 projection와 collaboration discovery, read 강등 뒤 연결 유지, revoke, 무관 계정 격리와 access receipt를 확인했다. 합성 사용자·자료·grant는 종료 시 제거했다.

## 잔여 범위

P2는 저장·서버 기반만 완료했다. owner 권한 토글 UI, writer CodeMirror 편집과 상태, 권한 회수 뒤 복구함 사용자 동선, 두 사용자 selection/IME/undo, PC·모바일 흐름은 P3가 담당한다. public write·guest identity는 1.1.3 이전에 활성화하지 않는다. 실제 물리 Windows/iOS/Android 입력은 이 Phase에서 새로 실행하지 않았다.
