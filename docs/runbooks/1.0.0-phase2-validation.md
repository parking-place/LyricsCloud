# 1.0.0 Phase 2 불변 release artifact 검증

- 상태: 구현·로컬 검증 중
- 기준: [`OPS-0002`](../operations/OPS-0002-artifact-verification.md), [`OPS-0004`](../operations/OPS-0004-final-release-gate.md)
- 계약 검사: `pnpm test:release:1002`

## 봉인 입력

| 입력 | 계약 |
|---|---|
| 제품·workspace package | `VERSION`과 11개 package manifest, runtime·Compose 기본값이 모두 `1.0.0` |
| dependency | `pnpm-lock.yaml` SHA-256을 release manifest와 license inventory에 고정 |
| migration | [`migrations.1.0.0.json`](../../config/migrations.1.0.0.json)에 17개 파일의 정렬 순서·SHA-256·호환 범위·rollback 제약 고정 |
| 환경 | [`environment-schema.1.0.0.json`](../../config/environment-schema.1.0.0.json)에 서비스별 필수 값·형식·secret/file 경계 고정 |
| license | [`licenses.1.0.0.json`](../../config/licenses.1.0.0.json)에 production dependency 65개의 SPDX 분류와 재배포 주의사항 고정 |
| image | [`release-manifest.1.0.0.json`](../../config/release-manifest.1.0.0.json)에 네 repository·Dockerfile target·nonroot UID·health·attestation·digest 자리 고정 |

tracked release manifest는 source SHA와 digest를 변수로 둔다. image digest는 그 source를 빌드한 뒤에만 결정되므로 digest 값을 source commit에 다시 commit하는 순환을 만들지 않는다. CI가 같은 template에 commit·ref·build 시각·네 검증 digest를 주입해 write-once 승인 목록을 만들며, [`generate-1002-release-manifest.mjs`](../../scripts/generate-1002-release-manifest.mjs)는 기존 파일 덮어쓰기를 거부한다. 기술 gate 통과는 production 배포 승인이 아니며 `OPS-0004`의 별도 명시적 사용자 승인이 계속 필요하다.

## 실행 명령

```bash
pnpm test:release:1002
bash scripts/verify-1002-reproducible-images.sh "$(git rev-parse HEAD)"
bash scripts/verify-production-images.sh "$(git rev-parse HEAD)"
bash scripts/verify-0915-upgrade-rollback.sh "$(git rev-parse HEAD)"
```

CI는 dependency audit, Git history secret scan, 모든 migration, unit/build/E2E, fresh DB image smoke, 이전 RC upgrade·rollback, fixable High/Critical container scan, image layer secret canary, BuildKit SBOM/SLSA와 keyless signature를 같은 source SHA에서 수행한다.

## 원격·개발 인수

- 구현 commit·CI·네 signed digest: 대기
- 같은 SHA 개발 서버 배포와 공개 health/auth/metrics smoke: 대기
- release server, `main`, 정식 tag와 GitHub Release: 변경하지 않음
