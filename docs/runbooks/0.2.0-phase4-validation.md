# 0.2.0 Phase 4 검증 기록

## 검증 대상

- `/songs/new`와 `/songs/:songId/edit` 공통 폼
- domain과 같은 제목·설명·작업 메모 길이 계약
- 아이디어·미고정·미즐겨찾기·무색 기본값과 전체 상태·색상
- 생성 멱등성 key, 중복 submit 잠금, 오류 후 입력 보존
- dirty 링크·새로고침 이탈 확인과 owner 범위 수정 로드
- PC 2열·모바일 1열 및 safe-area 완료 행동

## 로컬 검증

2026-09-05에 격리된 `lyricscloud_test` PostgreSQL과 Docker Node 24 환경에서 실행했다.

```text
pnpm --filter @lyricscloud/web check
NODE_ENV=production pnpm build
pnpm exec playwright test tests/e2e/song-form.spec.ts
```

- production route `/songs/new`, `/songs/[songId]`, `/songs/[songId]/edit` 생성 통과
- 빈 제목·200자 초과 오류를 입력 바로 아래에서 확인
- 두 번 연속 submit에도 POST 1건만 발생하고 정확한 새 ID로 이동
- 생성한 모든 값을 수정 폼에서 복원하고 변경 뒤 같은 상세 ID로 이동
- dirty 취소 링크에서 이탈 취소, 320px 수평 overflow 없음
- 다른 계정의 edit route는 404이며 제목·메모가 HTML에 노출되지 않음

전체 unit·DB integration, migration recovery, 기존 auth·song E2E와 secret scan은 Phase 브랜치 필수 CI에서 함께 실행한다.

## Phase 5 인계

상세 성공 목적지 `/songs/:songId`는 owner가 확인된 곡 제목과 수정 링크만 제공한다. Phase 5가 이 route를 실제 요약·메모·가사·연결 자료 빈 상태와 삭제 흐름으로 교체한다.
