## 권한 집합과 owner 확인

1. 공개 write는 별도 capability가 아니라 기존 active·미만료 공개 read link의 기본 false 상태다. 같은 link ID, resource ID, token digest, permission epoch와 expiry 안에서만 write가 가능하므로 W⊆R이다.
2. owner가 공개 읽기와 분리된 위험 문구를 확인한 요청만 write를 켠다. API는 확인 버전과 request ID를 요구하고, 누락·구버전·다른 resource·selected-read와 조합한 요청을 일반 거부하며 기존 ACL을 바꾸지 않는다.
3. write만 끄면 공개 read는 유지하고 `write_epoch`를 증가시켜 열린 writer socket과 구 epoch queue를 차단한다. link 회수·만료·교체는 permission epoch 경계에서 read와 write를 함께 먼저 끝낸다.
4. guest는 계정이나 beta 가입자가 아니다. 해당 가사의 본문 CRDT update와 제한된 cursor/online 상태만 사용할 수 있고 workspace·목록·다른 자료·검색·export·복제·메모·연결 자료·revision·ACL·metadata·삭제·소유권·계정 API는 사용할 수 없다.

## guest session과 신원

- raw public token으로 유효 link를 확인한 뒤 서버가 최대 12시간의 256비트 opaque guest session secret을 발급한다. link expiry가 더 이르면 그 시각에 함께 만료한다. DB에는 SHA-256 digest만 저장한다.
- guest session은 한 link/resource/permission epoch에 묶고 rotation·회수 뒤 재사용하지 못한다. browser는 raw session secret을 탭 session storage에만 보관하고 URL, referrer, service-worker cache, analytics, log에 넣지 않는다.
- DB update/receipt는 로그인 `actor_id`와 분리된 `guest_session_id`를 기록한다. 표시 이름은 서버가 생성한 `게스트-XXXX`와 connection-local participant ID만 사용하고 client의 actor/name/owner 주장은 무시한다.
- 같은 탭의 reconnect는 같은 guest session으로 attribution하고 새 탭/새 session은 다른 guest다. 링크 토큰만 가진 방문자가 새 guest session을 만들 수 있다는 사실은 링크 공개 위험 문구에 포함한다.

## 저장·API·원자 순서

- additive `1130_public_lyric_guest_write.sql`은 public link에 `write_enabled`, 양의 `write_epoch`, 확인 시각을 추가하고 guest session, owner access request, durable minute budget과 public update attribution을 추가한다. 1.1.1/1.1.2 link는 모두 read-only 기본값으로 유지한다.
- owner API는 같은 활성 공개 link의 `read|write` access를 멱등 변경한다. public session API는 link token을 body로 받아 opaque guest session을 한 번 반환한다. WebSocket 최초 auth frame은 link token, link ID와 guest session을 받고 이후 각 update에서 서버가 link/session/resource/두 epoch를 transaction 안에서 재확인한다.
- public update는 기존 Yjs envelope의 update ID/payload에 permission/write epoch를 결합한다. receipt, update, projection, guest attribution과 durable budget 차감을 commit한 뒤에만 ACK하고 그 뒤 authorized peer에 broadcast한다. 같은 update ID/hash retry는 동일 ACK, 다른 hash는 거부한다.
- 존재하지 않음·다른 resource·잘못된 token/session·회수/만료/epoch 불일치는 모두 같은 unavailable 계열 응답으로 target 존재를 구분시키지 않는다. raw token/session, 본문, cursor 문자열은 log/metric에 기록하지 않는다.

## 남용 예산과 owner 중지

| 예산 | 확정값 | 집행 위치 |
|---|---:|---|
| update 절대 크기 | 기존 `1,048,576` byte | protocol parser/WS max payload |
| 병합 문서 텍스트 | 기존 `400,000` byte | DB update transaction |
| guest 분당 | `240` update, `4 MiB` | PostgreSQL minute bucket |
| link 분당 | `1,200` update, `16 MiB` | PostgreSQL minute bucket |
| 동시 socket | guest `4`, link `20` | current server sockets + session/link key |
| guest session | 최대 `12시간`, link expiry 우선 | DB expiry + 매 message 재검사 |

분당 budget은 PostgreSQL에서 원자 증가해 collaboration 재시작이나 여러 process에서도 초기화되지 않는다. 초과는 원문을 적용하지 않고 retry 시각을 알려준다. owner는 공개 read를 유지한 채 write kill switch를 즉시 끌 수 있고, 완전 회수/교체도 가능하다. 제한·kill switch는 accepted 과거 원문을 삭제하지 않으며 owner checkpoint/revision 비교 흐름을 유지한다.

## 입력·복구·표시

- guest editor는 기존 CodeMirror 한글 IME, local-origin undo, relative selection, 약 1초 저장/최대 5초 flush를 재사용한다. 서버 ACK 전 update는 capability fingerprint+guest session ID+resource+permission/write epoch로 IndexedDB에 격리한다.
- write off, link 회수/만료, budget 거부, session 만료 때 자동 전송을 멈추고 자기 working copy와 local update만 rejected 복구함에 남긴다. 새 서버 원문·다른 참가자 원문을 추가로 내려받지 않으며 재허용 후 자동 replay하지 않는다.
- 화면은 `공개 읽기`와 `공개 읽기 + 비로그인 쓰기`를 비교하고 불가능한 selected-read/public-write 조합을 설명한다. guest는 저장됨/로컬 보관/제한/권한 종료를 텍스트로 구분하고 자기 입력 복사·다운로드·폐기를 제공한다.

## 호환·되돌림·파일 담당

- 기능 flag를 끄면 모든 공개 link를 read-only로 취급하고 public update/session 발급을 거부한다. 1.1.2 애플리케이션으로 먼저 rollback할 수 있으며 새 열·guest audit·budget·복구함과 accepted 원문은 보존한다.
- destructive down migration은 실행하지 않는다. rollback SQL은 write가 모두 꺼졌고 public writer socket이 없으며 별도 DB 복원본이 있을 때만 신규 함수/권한을 비활성화한다. DB volume·update·receipt·revision·가사·link를 삭제하지 않는다.

## 미실행과 P2 인계

P1은 설계-only라 runtime version, migration, CI, 개발/운영 배포를 실행하지 않는다. P2는 먼저 실패 계약을 추가하고 additive 1130 schema, guest session/durable budget, owner toggle과 public write store/ACK의 최소 기반을 구현한다. P3는 owner 확인 UI와 guest PC/mobile editor·rejected recovery를 연결하고 P4는 실제 PostgreSQL 병렬 예산·다른 resource·spoof·restart·지원 브라우저를 검증한다. 실제 OS/물리 기기와 `OPS-100-001` 외부 backup 예외는 미실행 위험으로 유지한다.
