# 1.1.1 Phase 4 — 공개 공유 권한·복구 회귀

## 후보와 범위

- 제품 후보는 `b920049f5b00bbe44809d1d96bec0f5fd7650c4c`다.
- 공개 capability는 지정 필드의 읽기만 허용한다. revision·메모·연결 자료·export·write·ACL·presence는 권한을 상속하지 않는다.
- 권한 만료·회수는 열린 WebSocket에도 적용되며, collaboration 재시작 뒤에도 digest 기반 capability와 공개 projection이 유지된다.

## 자동 검증

- Node 24.20.0에서 `pnpm check`, 실제 PostgreSQL 공개 공유/재시작 통합 5건, 1.1.1 지원 행렬 11 PASS·의도된 중복 4 skip, 0.9.1 성능 예산을 통과했다.
- 새 통합 회귀는 공개 방문자가 owner presence에 나타나지 않고 다른 참가자 정보를 받지 않는 것, 공개 write/revision frame의 4403 거부, 만료 socket의 4404 종료, 재시작 뒤 capability 복원과 raw token 비출력을 확인했다.
- Chromium 대표 offline/reconnect는 offline 중 안전한 본문 유지, owner 변경 미수신, 재연결 수렴, 회수 후 재접속 거부를 확인했다. 익명 private resource/export API는 401을 유지했다.
- Actions push `34697600730`과 PR `34697608114`은 최종 단독 재실행에서 전체 verify를 통과했고 네 development image가 발행·서명됐다. 앞선 push 두 실행의 save/revision CV와 PR 첫 실행의 기존 1.1.0 WebKit 대화상자 5초 지연은 절대 성능 예산·로컬 동일 재현·후속 단독 전체 실행이 모두 통과해 환경 변동으로 판정했다.

## 동일 SHA 개발 인수

- 개발 서버는 `1.1.1`·`dev`·`p4`, schema `1110_public_lyric_read_links.sql`을 반환했고 postgres/web/collaboration/worker는 모두 healthy였다.
- 합성 공개 링크는 collaboration 실제 재시작 뒤 동일 projection을 반환했고, 회수 후 접근 차단과 익명 private API 401을 확인했다.
- 실제 Chromium PC/mobile 공개 UI에서 owner 확인, 일회 링크, fragment 제거, 비로그인 읽기, private 차단, live update, 열린 탭 회수, 편집기 미개방 빈 가사 최초 공개를 다시 통과했다. 모든 합성 자료와 계정은 제거했다.

실제 Windows·iOS·Android 물리 기기는 P4에서 새로 실행하지 않았고 자동 5-project 결과를 실기기 증거로 표시하지 않는다. P5는 같은 SHA를 요구·사용자·지원·보안·자가호스팅 문서와 봉인 artifact에 연결하고 최종 후보를 다시 인수한다.
