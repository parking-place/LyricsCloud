## 실패 먼저와 최소 구현

첫 `packages/auth/src/native-service.test.ts` 실행은 `./native-service.js` 부재로 suite import가 실패했다. 이후 다음 경계만 구현해 같은 테스트 4건을 통과시켰다.

1. 앱은 `127.0.0.1`의 명시적 임의 port와 `/lyricscloud/oauth/<nonce>`만 callback으로 등록한다. `localhost`, HTTPS loopback, query/hash, 짧은 PKCE challenge는 거부한다.
2. 서버는 10분 transaction을 digest로 저장하고, 기존 Google OIDC가 만든 인증된 first-party browser session에 대해서만 60초 single-use code를 exact callback으로 보낸다.
3. code·state·PKCE verifier가 모두 맞는 back-channel 교환 한 번에서만 별도 `native_sessions` token을 만든다. URL에는 session token을 넣지 않는다.
4. native token scope는 DB check와 전용 GET route 양쪽에서 `read`로 고정한다. 기존 cookie 기반 쓰기 route는 native bearer를 인증으로 받지 않는다.

Google client secret, server session secret, DB 비밀은 Windows 프로젝트에 없다. Windows app은 system browser launcher와 단일 IPv4 loopback listener를 사용하고, token 및 account cache는 `DataProtectionProvider("LOCAL=user")`로 보호한다.

## API와 저장 계약

- 공개 협상: `GET /api/native/v1/capabilities`
- broker: `POST /api/native/v1/auth/transactions`, browser `GET /api/native/v1/auth/authorize`, `POST /api/native/v1/auth/token`, `POST /api/native/v1/auth/logout`
- read session: `GET /api/native/v1/session`
- owner read: songs/list/detail, lyrics/detail, rhyme/list/detail, prompt/list/detail, song linked-resource metadata, Suno workspace model/link metadata
- selected read: `GET /api/native/v1/shared/lyrics/{id}`; 기존 grant/permission epoch/RLS를 다시 조회하며 회수 뒤 `404`

`1150_native_read_sessions.sql`은 transaction digest와 read-only native session hash만 저장한다. code/verifier/session 원문과 Google token은 저장하지 않는다. 두 테이블은 `lyricscloud_app` role에 직접 권한이 없으며 server-side auth store만 사용한다. rollback은 native route를 먼저 끄고 table/record를 보존하는 forward-fix 방식이다.

계정 cache namespace는 `SHA-256(origin + NUL + serverUserId)`다. owner cache는 offline 표시가 가능하지만 shared cache는 해당 실행에서 온라인 권한 재검증 전 표시·복사를 금지한다. `401/403/404`, permission epoch 변화, account 전환은 purge 신호다. 파일명에는 원문·제목·계정 ID를 넣지 않는다.

## 중단·rollback

- wrong state/verifier/callback/replay에서 `native_sessions`가 생기면 즉시 중단한다.
- native bearer가 기존 resource mutation에 통과하거나, 다른 owner 자료가 보이거나, shared revoke 후 원문이 반환되면 즉시 중단한다.
- C# copy가 `lyricscloud.windows.contract.v1`과 다르면 Windows 배포를 중단한다.
- server rollback은 native route를 비활성화하고 기존 web/OIDC/API/DB/Yjs를 유지한다. `1150` table과 audit record를 drop하거나 운영 volume을 삭제하지 않는다.
