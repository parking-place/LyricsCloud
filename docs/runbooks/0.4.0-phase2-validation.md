# 0.4.0 Phase 2 검증

## 구현 결과

- owner 범위 라임 노트 목록에 제목·본문 문자 그대로 검색, 태그·연결 곡 조합 필터, 다섯 정렬과 불투명 pagination cursor를 연결했다.
- 목록 응답은 카드의 태그와 활성 연결 곡 이름, 현재 계정에서 실제 라임에 쓰이는 필터 후보만 반환한다. soft delete 노트·태그·곡과 다른 owner 자료는 count·카드·필터 후보에서 제외한다.
- `/rhymes`는 검색·태그·곡·정렬을 URL에 보존하고 형식이 잘못되었거나 현재 계정에 없는 필터 ID를 기본값으로 되돌린다.
- PC 2열·모바일 1열 카드, 모바일 가로 태그 chip, 핀·즐겨찾기·색상 명명 상태, 독립된 카드 열기·메타데이터·복사 hit target을 구현했다.
- 클립보드 허용 시 원문 본문만 쓰고 성공 상태를 표시한다. 거부되거나 API가 없으면 같은 원문 전체가 선택된 수동 복사 대안을 제공한다.
- 최초 빈 화면, 검색 결과 없음, skeleton 로딩, 의존성 실패와 재시도를 서로 구분했다.

## 로컬 검증

- architecture boundary와 모든 TypeScript project 검사를 통과했다.
- PostgreSQL integration을 포함한 `32 files / 118 tests`가 통과했다. `%`·`_` 문자 검색, 조합 필터, cursor 서명, owner/휴지통 격리를 포함한다.
- Next.js production build와 standalone asset 준비를 통과했다.
- Playwright production 환경에서 PC·모바일 `124 passed / 2 intentional skipped`를 통과했다. 360·390px, PC 2열/모바일 1열, URL 새로고침, 메타데이터 키보드 조작, 정확한 본문 복사, Clipboard 거부, API 실패·재시도, 추가 로드를 검사했다.
- 모바일 메뉴 확장 후 곡 목록의 320px·200% 확대 회귀에서 발견한 가로 넘침을 수정하고 해당 회귀와 전체 suite를 다시 통과했다.

## Phase 3 인계

- 새 라임 노트와 카드 링크는 `/rhymes/new`, `/rhymes/:id`를 사용한다. Phase 3은 기존 목록 query와 owner 경계를 유지하며 생성·편집·동기화 화면을 이 경로에 연결한다.
- 목록의 정확한 본문 복사와 메타데이터 command는 편집기 저장 상태와 별개이므로 Phase 3에서도 독립 동작을 유지한다.
