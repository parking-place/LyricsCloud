## 저장·오류·권한 계약

1. nickname은 공백 trim 뒤 비어 있지 않으며 기존 상한 120 Unicode 문자/저장 구조를 넘지 않는다. 입력 중 한글 IME 조합값은 최종 저장으로 처리하지 않는다. 사용자가 지정한 값과 Google provider 기본값을 분리한다. 재로그인, OAuth 가입 재시도, 다른 탭·기기·서버 재시작은 override를 지우지 않는다. 명시적 기본값 복귀만 override를 없앤다. Google 이메일, issuer/subject, `sharing_id`는 수정하지 않는다.
2. 사진은 로컬 PNG/JPEG/WebP 파일만 선택할 수 있다. 입력 최대 2 MiB, 해독 가능한 픽셀 최대 16 MP, 서버의 실제 decode 후 256×256 WebP로 재인코드하며 EXIF·스크립트·파일명 metadata를 버린다. 이미지 처리 의존성은 현재 lock의 `sharp 0.35.4`를 web에 직접 선언한 뒤 frozen install/build로 검증한다. SVG/GIF/외부 URL 입력과 위장/손상 파일은 거부한다. 생성 결과는 200 KiB 이하로 제한한다.
3. 사진은 owner 키의 새 RLS PostgreSQL 테이블에 bytea와 content hash로 저장해 기존 DB 볼륨/backup·탈퇴 삭제 경계에 포함한다. 서버 생성 사진 URL은 cookie 인증·owner 확인을 하는 `/api/profile/avatar`이고 private/no-store·`nosniff`로 제공한다. 공유 페이지·로그·분석에는 사진을 넣지 않는다. 기존 Google URL은 override가 없을 때 fallback으로 남는다. 입력 실패와 취소는 기존 사진을 변경하지 않는다.
4. PATCH에서 필드 **생략 = 그대로 유지**, 명시 `null`/remove = provider 기본값으로 복귀를 분리한다. 사진 업로드는 서버 검증·owner 저장 완료 뒤 프로필 참조를 갱신한다. nickname/사진은 서로 독립적이다. 두 탭의 충돌은 row version 비교로 409를 반환해 최신 서버 값을 노출하고 사용자의 입력을 보존한다. 중복 요청은 같은 결과 또는 명시 충돌로 처리한다.
5. 공유 owner 표시명은 변경 성공 이후 신규 조회에 현재 닉네임을 반영하되 과거 revision/actor 감사 기록은 소급 변경하지 않는다. 공개 링크에서 owner 이름 보이기 설정이 꺼져 있으면 nickname을 새로 노출하지 않는다. 사진은 공개·선택 공유에 자동 표시하지 않는다.

## 홈 이동

현재 셸의 브랜드는 데스크톱 좌측, 모바일 좌측이고 모바일 우측은 원형 avatar다. P3에서는 **데스크톱 topbar 우측 홈 mark**, **모바일 우측 상단 홈 icon**, 기존 rail/헤더 Brand를 같은 `/workspace` 링크로 만든다. 추가 mark/icon은 기존 설정/도움말/로그아웃을 이동시키지 않고 좁은 폭에서도 보인다. 모든 링크의 이름은 “창작 홈으로 이동”이고 키보드 focus/터치 target을 제공한다. 우측 상단의 실제 목표 요소는 P3 수용 스크린샷에서 확인한다. 로그인 페이지 장식 브랜드는 홈 이동으로 바꾸지 않는다.

링크는 현재 문서의 저장 이탈 guard를 통과해야 하며 dirty·saving·offline·IME 조합·저장 오류에서 무조건 hard navigation하지 않는다. 취소 시 selection/원문/초안과 기존 `returnTo`를 보존한다. 홈에서 다시 눌러도 편집 데이터 손실이나 reload loop가 없다.

## 실패 입력과 롤백

| 입력 | 기대 결과 |
|---|---|
| 닉네임만 변경/사진만 변경/사진 제거 | 다른 필드는 유지, 제거는 Google 기본값 복귀 |
| 두 사용자 교차 읽기·업로드·URL 재사용 | 서버 owner 검사+RLS 차단, 사진/닉네임 cache 격리 |
| 잘못된 이미지·과대 파일·서버 중단 | 새 사진 제공/참조 없음, 이전 사진·사용자 입력 보존 |
| Google 재로그인/가입 재시도·이름/사진 변경 | 사용자 override 유지, 기본값만 최신 provider 값 반영 |
| 공유 owner 표시 on/off | on에서 성공 후 현재 닉네임, off에서는 비노출, 사진은 비공개 |
| 편집 중 홈 icon 클릭·IME 조합 | 기존 안전한 flush/확인 전 이동 없음, 취소 시 문서 유지 |

새 migration은 기존 컬럼/행/URL을 삭제하지 않는 additive 단계로 만들고 롤백은 **앱 우선**으로 이전 `v1.1.7` image/digest에 돌아간 뒤 추가 컬럼·사진 자료는 보존한다. DB 역방향은 신규 업로드/쓰기 중지와 자료 백업·명시 승인 후 수행한다. 기존 `v1.1.7` tag/image/볼륨은 이동하지 않는다.

## 한 번짜리 버전 예외

`1.1.7a`만 `VERSION`, `APP_VERSION`, Git tag `v1.1.7a`, Docker version tag, health/display에 허용한다. 다른 문자 접미사는 그대로 거부한다. private npm package version `1.1.7`은 SemVer 전제상 그대로 두고 앱 제품 버전과 다른 이유를 release validator에서 이 예외에 한해 검사한다. shell/Node validators, CI workflow, runtime defaults, 환경 schema, release manifest 및 runbook의 참조가 같은 제품 버전으로 봉인돼야 한다. 숫자-only 검증을 삭제해 테스트가 통과한 것처럼 만들지 않는다.

P1의 문서/설계 검증은 관련 경로·입력/권한/복구 표·rollback과 계획 링크 확인으로 구분한다. 구현/실제 DB/E2E/CI·개발/운영 배포는 P2~P5의 별도 증거다.
