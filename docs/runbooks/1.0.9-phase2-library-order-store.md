## 실패 우선과 구현 경계

미구현 라임·프롬프트 manual 정렬과 고정 자료 유형 이동 API 계약을 먼저 등록해 실패를 확인했다. 기존 `1002_library_manual_order.sql`의 owner+자료유형별 state/rank/request ledger를 재사용하고, 자료 본문·프롬프트 token occurrence·전역 pin metadata는 변경하지 않는다. 요청은 `itemId`, 보이는 `beforeId`/`afterId`, `expectedVersion`, `requestId`만 받는다.

동시 요청은 owner advisory lock과 자료 유형별 CAS로 하나만 승인한다. 동일 request/body 재전송은 저장된 결과를 replay하고, 다른 body의 request ID 재사용과 오래된 cursor/version은 거부한다. create·duplicate는 같은 pin group 끝, soft delete/restore는 보존 rank 한 곳, pin 변경은 대상 group 끝으로 이동한다.
