# 1.1.2 정식 릴리스 실행

사용자는 1.1.2 P1~P5 완료 뒤 main 병합·annotated `v1.1.2` tag·정식 image·릴리스 서버 배포를 승인했다. 최종 후보와 main 전체 CI가 통과한 같은 source SHA에 tag를 만들며 tag는 이동·재사용하지 않는다. `OPS-100-001` backup 미구축은 명시적 위험 예외다.

1. P5 PR을 main에 merge하고 main SHA의 필수 CI를 확인한다.
2. main HEAD에 annotated `v1.1.2` tag를 만들고 `publish=true`, `release=true` workflow를 실행한다.
3. web·collaboration·worker·migrate의 `1.1.2`, `Release`, `latest`, `Release-latest`가 같은 source SHA와 exact digest를 가리키며 signature·provenance·SBOM이 있는지 확인한다.
4. 릴리스 서버는 exact digest를 기록하고 migrate→collaboration→worker→web 순서로 전환한다. DB volume·secret·HMAC allowlist·beta code를 보존한다.
5. 공개 ready가 version `1.1.2`, release channel, phase `null`, schema `1120_selected_lyric_write.sql`과 exact SHA를 반환하는지 확인한다.
6. owner·writer·reader의 live 수렴, writer 강등/회수, rejected 원문 복구·재허용 비자동 적용, private 격리와 collaboration 재시작을 공개 HTTPS에서 확인하고 합성 fixture를 제거한다.
7. 실패 시 application-first rollback으로 직전 `v1.1.1` exact digest를 복원한다. schema나 자료 무결성이 의심되면 쓰기를 중단하고 격리 restore한다.

## 실행 결과

main/tag `eb949b59022cdd3185dae7349570439eca96b879`, main CI `34724875009` 재실행, tag CI `34726392136`의 전체 검증과 네 정식 image 발행·서명을 통과했다. 서비스별 네 정식 alias의 동일 digest를 확인하고 운영 서버에 migrate 우선 exact digest 배포했으며 공개 ready의 version·channel·phase·schema·SHA와 네 서비스 health가 일치했다. owner/writer/reader live 수렴, writer 강등 뒤 읽기, reader/writer 회수, ACL·메모 격리, offline rejected 복구·재허용 비자동 적용과 서비스 재시작 지속성이 PASS했고 합성 fixture를 제거했다. DB volume·secret·allowlist·beta code를 보존하고 GitHub Release `v1.1.2`를 발행했다.
