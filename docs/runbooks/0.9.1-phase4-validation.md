## 데이터 경계와 구현

관측 모듈은 허용 필드를 먼저 넓게 받지 않는다. 입력 전체를 최대 깊이·배열·객체 크기가 제한된 재귀 redaction에 통과시킨 뒤 `TELEMETRY_ALLOWED_FIELDS`에 있는 key만 남기며 각 값도 enum 또는 제한된 정규식으로 다시 검사한다. 제목·본문·검색어·URL·payload·header·cookie·OAuth token·오류 message/stack/cause와 임의 field는 모두 삭제된다.

브라우저 자동 계측, session replay, 페이지뷰·클릭 이벤트는 추가하지 않았다. collaboration의 연결·연결 해제·성공 update 건별 로그와 공개 `/metrics`도 제거해 개인별 창작 흐름을 재구성할 표면을 없앴다. 서버는 실패·서비스 상태·정기 projection/revision/purge/migration 같은 운영 작업만 구조화해 기록한다.

공개 오류는 `packages/domain/src/error-contract.ts`가 구조화 형식과 과도기 문자열 형식에서 제한된 대문자 code만 읽는다. 실제 구현 중 collaboration이 구조화 오류로 전환된 뒤 편집기 standalone 번들이 기존 문자열만 처리해 stale revision 복원이 일반 오류가 되는 회귀를 발견했고, 가사·프롬프트 공용 parser 적용과 production rebuild 후 해당 desktop E2E를 통과시켰다.

## canary·경보·장애 격리

고유 합성 문자열을 title/body/search query, raw URL, request body/header, nested error message/stack/cause/payload, breadcrumb와 DOM snapshot 자리에 넣었다. memory transport, console JSON, alert와 집계 dashboard를 직렬화해 검색한 결과 canary 0건이었다.

5개 경보는 임계값을 넘긴 snapshot에서 5/5 생성되고 정상 snapshot에서는 0건이었다. 각 결과에는 고정 metric·severity·repository runbook anchor만 남는다. 동기 transport throw와 비동기 exporter rejection을 주입해도 저장 operation의 반환값과 예외 의미가 바뀌지 않았다.
