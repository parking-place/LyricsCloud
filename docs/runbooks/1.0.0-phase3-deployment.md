## 사용자 승인과 운영 예외

2026-09-08 사용자는 앞선 배포 유예를 해제하고 Phase 5까지 연속 진행하도록 승인했다. 이어서 릴리스 전용 Google OAuth·DB 자격 증명은 개발 서버와 같은 값을 사용하고, backup은 Phase 5까지 신경 쓰지 말고 이후 구축하도록 명시했다.

- 동일 OAuth client·DB credential 사용은 원래 환경 분리 권고의 사용자 승인 예외다. 값 자체는 Git·로그·증적에 남기지 않는다.
- production은 개인정보·개발 fixture를 이관하지 않은 빈 신규 DB로 시작했다.
- 외부 backup repository·일일 timer·restore 훈련은 실행하지 않았다. 24시간 RPO가 보장되지 않는 남은 운영 위험으로 1.0.1+ 보완 목록에 넘긴다.
- 실제 Google 계정 비밀번호 입력은 자동화하지 않았다. OAuth authorization endpoint 도달, client·callback·PKCE/state/nonce 일치와 redirect mismatch 0건을 확인했고 제품 권한 흐름은 합성 session 두 계정으로 검증했다.

앞선 유예 기록은 승인 이력으로 보존하며 현재 실행 권한은 가장 최근 사용자 지시를 따른다.

## 2026-09-08 read-only release server 점검

- 개발 서버와 분리된 릴리스 호스트에 SSH 접속됨
- Docker service active, Docker Compose 사용 가능
- Cloudflare Tunnel service active, ingress 설정 유효
- root filesystem 여유 공간 35 GiB 이상
- loopback `8080` listener 없음, 공개 health는 기존 예상 상태인 HTTP `502`
- release checkout과 애플리케이션 `.env`/allowlist가 아직 구성되지 않음
- `lyricscloud-backup.timer`가 아직 설치되지 않았고 실행 중이 아님
- 어떠한 파일·서비스·컨테이너·DB·DNS·Tunnel·OAuth 설정도 변경하지 않음

이는 기존 0.9.1 production의 in-place upgrade가 아니라 신규 production bootstrap임을 뜻한다. 따라서 빈 운영 DB로 시작할지, 기존 개발 환경의 데이터를 승인된 암호화 backup/restore로 이관할지 사용자 결정 없이 가정하지 않는다.

## 실행한 고정 배포 순서

1. 배포 창과 중단 조건을 확인하고 사용자를 rollback 결정권자·운영 인수 책임자로 기록한다.
2. 릴리스 전용 checkout, mode `600` 환경 파일·허용 목록, release OAuth client와 공개 origin 일치를 구성한다. 개발 credential은 재사용하지 않는다.
3. checkout·PostgreSQL volume과 분리된 외부 backup repository, storage marker, 최소 권한 secret과 일일 timer를 구성한다.
4. 선택한 data source에 따라 다음 중 하나만 수행한다.
   - 빈 신규 운영 환경: 빈 PostgreSQL에 봉인 migration을 적용하고 공개 traffic 연결 전에 암호화 baseline backup과 RPO 검사를 통과한다.
   - 기존 데이터 이관: 원본 환경에서 배포 직전 암호화 backup을 생성·checksum 검증하고 릴리스의 새 빈 DB에 복원한 뒤 count·revision·검색·관계 fingerprint를 비교한다.
5. 네 image를 tag가 아닌 위 digest로 pull하고 source revision·version·provenance를 다시 확인한다.
6. 동일 DB에 연결된 비공개 loopback canary에서 live/ready, session 지속, owner 격리와 합성 CRUD·한글 자동 저장·검색·복사·삭제/복원·export·PWA update smoke를 수행한다.
7. health failure를 주입해 canary 제거와 직전 승인 digest 복귀를 검증한다. migration 오류, 권한 이상, 저장 실패, P0/P1 또는 data canary 불일치는 즉시 중단 조건이다.
8. canary 통과 뒤 동일 digest를 공개 instance에 전개하고 오류율·p95·저장 실패·DB·backup 지표의 안정 구간을 관찰한다.
9. 공개 smoke와 데이터 무결성 재대조 후에만 운영 인수로 판정하고, 릴리스 변경 기록과 rollback 결과를 비공개 인벤토리에 남긴다.
