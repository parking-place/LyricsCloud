# 0.3.0 Phase 4 검증

2026-09-05, Node 24.20.0 / pnpm 11.25.0 / 별도 PostgreSQL `lyricscloud_test`와 공개 개발 서버에서 검증했다. 실제 사용자 본문과 릴리스 환경은 사용하지 않았다.

## 범위와 결과

LC-030-P4-01~10을 완료했다. 전체 복사는 저장 응답이 아닌 현재 CodeMirror document를 사용한다. 구간 복사는 Phase 3 parser의 tag 포함 `from`·`to` 범위를 사용하고, 화면에서 선택한 순서와 관계없이 원문 순서로 정렬한다. 앞 slice가 LF로 끝나지 않을 때만 LF 하나를 추가하므로 기존 빈 줄은 그대로 남는다. CRLF와 단독 CR은 editor 계약과 동일하게 LF로 정규화한다.

PC 목차와 모바일 시트는 키보드 접근 가능한 checkbox, 선택 수, 전체 해제와 선택 복사를 공유한다. Clipboard 쓰기는 click 또는 `Alt+Shift+C` key activation에서 바로 시작한다. 성공 toast는 전체 가사, 단일 label 또는 선택 구간 수를 알리고, 거부되거나 API가 없으면 같은 문자열을 focus·전체 선택된 읽기 전용 textarea 대화상자에 제공한다.

집중 모드는 편집기를 다시 만들지 않고 CSS 상태만 전환한다. PC에서는 송폼 영역을 숨기고 본문 최대 폭과 저장 상태를 유지한다. 모바일에서는 문맥·제목·footer를 접고 본문을 우선하되 송폼·전체 복사·집중 종료 dock을 유지한다. `Alt+Shift+F`로 전환하며 IME 조합 중 key event는 무시한다.

## 검증

- `pnpm migrate` 2회와 `test:migration:0200`, `0201`, `0300`: 적용·rollback·복구 계약 통과.
- `pnpm check`: workspace 경계와 전체 TypeScript 통과.
- `AUTH_DATABASE_INTEGRATION=true pnpm test`: 22개 파일, 84개 테스트 통과. 신규 문자 단위 테스트는 CRLF/LF, tag 포함 범위, 기존 빈 줄, 반복 Hook, 마지막 구간, 역순 선택과 빈 선택을 확인한다.
- `NODE_ENV=production pnpm build`: production standalone build 통과.
- `E2E_DATABASE_URL=<disposable lyricscloud_test> pnpm test:e2e`: Chromium desktop/mobile 70개 전체 통과. 현재 미저장 document 전체 복사, 역순 다중 선택의 원문 순서, Clipboard 허용·거부·비지원, 수동 textarea의 동일 문자열·전체 선택, pointer 없는 checkbox, 집중 전후 입력·focus·scroll, 단축키·IME와 700×390 회전·390×520 가상 키보드 축소 상태를 확인했다.
- 1440×1000 PC와 390×844 모바일을 실제 캡처해 본문 최대 폭, 선택 도구, 모바일 시트·하단 navigation 간 겹침과 가로 overflow를 확인한 뒤 임시 캡처를 제거했다.
- production build 비밀 누출 검사 통과.

## 복구와 Phase 5 인계

schema 변경은 없다. 문제가 생기면 이전 검증 SHA로 앱만 되돌릴 수 있다. Phase 5는 `copyWholeLyric`, `copySongFormSections`, 선택 ID와 focus mode가 현재 editor instance를 유지한다는 계약을 보존하면서 대시보드와 다른 가사 전환·복제·삭제 흐름을 연결한다. Suno, 라임·프롬프트 복사와 CRDT selection은 계속 범위 밖이다.
