# 0.1.0 Phase 5 통합 검증 기록

- 검증일: 2026-09-05
- 범위: `LC-010-P5-01`~`LC-010-P5-09`
- 환경: Node.js 24.20.0, pnpm 11.25.0, Next.js 16.3.4, PostgreSQL 18, Playwright 1.62.1 Chromium
- 테스트 데이터: 실제 Google 계정과 분리된 로컬 OIDC 및 A/B 합성 fixture

## 결과

| 검사 | 결과 |
|---|---|
| migration·정적 검사 | 격리 tmpfs DB migration 2회, architecture boundary, 9개 workspace TypeScript 검사 통과 |
| 단위·통합 테스트 | 10 files, 41 tests 통과. OIDC 서명·nonce·state·PKCE·callback 재사용, 세션 갱신·만료·폐기, RLS·owner context 포함 |
| 허용 로그인 | 브라우저가 로그인 시작→로컬 OIDC authorization→callback→보호 셸을 통과하고 `issuer + subject` identity와 profile이 각각 한 번만 생성됨 |
| 세션 복원 | 새 browser context와 새로고침에서 동일 내부 사용자 ID 복원, 만료 1분 전 세션의 30일 idle 갱신 확인 |
| 거부·취소 | 미허용 이메일은 `AUTH_NOT_ALLOWED`, 사용자 취소는 `AUTH_CANCELLED`; 둘 다 session cookie와 보호 셸 접근 없음 |
| 로그아웃 | 서버 session 폐기, cookie 삭제, `Clear-Site-Data: "cache", "storage"`, 현재 `lc:<user-id>:` local/session storage 정리, 뒤로가기·직접 URL 재진입 차단 확인 |
| A/B 격리 | B가 A의 UUID를 path·query·body에 넣어도 A profile 비노출·불변, B 자신의 context만 사용 확인 |
| 시각·접근성 | 1440×1000·390×844 기준 4장과 Playwright pixel regression 생성, 320px·큰 글자·200% 확대 상당 viewport overflow 검사 통과. OS별 한글 대체 글꼴 차이는 최대 6%만 허용 |
| HTTP 정책 | private route/API `no-store`, HttpOnly·SameSite=Lax·Max-Age, HTTPS용 `__Host-`·Secure, nosniff·DENY frame·no-referrer·Permissions-Policy 확인 |
| 비밀 비노출 | 브라우저 request/response, E2E 서버 로그, standalone build에서 client secret·session secret·provider token marker 0건 |
| clean build·재실행 | production standalone build와 Docker 서비스 재시작 뒤 health 및 전체 E2E 재현 |

브라우저 E2E는 desktop·mobile 두 project에서 26개가 통과했다. Google 실계정 로그인은 Phase 2에서 별도 확인했으며, 이 Phase는 실제 credential 없이 같은 OIDC 프로토콜 경계를 결정적으로 반복 검증한다.

## 실행

```bash
pnpm migrate
pnpm migrate
pnpm check
AUTH_DATABASE_INTEGRATION=true pnpm test
pnpm build
E2E_DATABASE_URL=<disposable-test-database-url> pnpm test:e2e
GOOGLE_CLIENT_SECRET=<marker> SESSION_SECRET=<marker> E2E_PROVIDER_TOKEN=<marker> \
  pnpm check:secrets apps/web/.next <captured-e2e-log>
```

`E2E_DATABASE_URL`의 인증·profile 데이터는 global setup에서 삭제된다. 개발·릴리스 DB를 절대 지정하지 않는다.
