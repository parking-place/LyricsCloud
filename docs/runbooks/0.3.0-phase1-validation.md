# 0.3.0 Phase 1 검증

2026-09-05, Node 24.20.0 / pnpm 11.25.0 / 별도 PostgreSQL `lyricscloud_test`에서 검증했다. 실제 사용자 데이터와 릴리스 환경은 사용하지 않았다.

## 범위와 근거

LC-030-P1-01~10: `0300_lyrics.sql`, `PostgresLyricStore`, `lyric-contract.ts`, 가사 API, PROD-0003/0004와 API 계약을 연결했다. 가사 1:1 subtype·동일 owner 부모·활성 부모 잠금, 현재본 CAS, 생성·복제 멱등성, 삭제 batch와 실제 가사 수를 구현했다. CRDT·revision·가사 UI는 다음 Phase 범위다.

## 로컬 검증 결과

- `pnpm check`: 모듈 경계·전체 TypeScript 통과.
- `AUTH_DATABASE_INTEGRATION=true pnpm test`: 18개 파일, 70개 테스트 통과.
- UUID 대소문자 재전송 보정 후 가사 DB 통합 7개 재검증 통과.
- `pnpm test:migration:0200`, `0201`, `0300`: 깨끗한 DB 반복 적용, rollback·재적용 통과. 0300은 가사가 존재하면 rollback을 거부하고 원문을 보존하며, 빈 가사 상태에서 기존 곡 metadata를 보존한다.
- `NODE_ENV=production pnpm build`: 가사 API를 포함한 production build 통과.
- `E2E_DATABASE_URL=<disposable *_test DB> pnpm test:e2e`: Chromium desktop/mobile 52개 전체 통과(신규 가사 API 10개 포함).
- `pnpm check:secrets apps/web/.next`: 비밀 값 누출 검사 통과.
- production Docker web image build 및 runtime smoke: health/version/schema, auth/CSS, 미인증 가사 요청 401 검증. 최초 smoke의 synthetic 설정이 production origin/client ID 계약을 위반해 거부된 것을 수정 후 재검증했다.
- 배포 script가 target VERSION을 APP_VERSION에 반영하도록 보정하고 `bash -n`과 diff whitespace 검사를 통과했다.

## 원격·개발 배포

CI, 네 Docker Hub repository 발행, 정확한 SHA의 개발 배포와 공개 smoke는 로컬 수용 검증 후 수행한다. 완료 SHA와 CI 증거는 아래에 추가하고, 최종 개발 배포 SHA·시각은 Git 제외 서버 인벤토리에도 기록한다.

## 복구와 다음 인계

배포 실패 시 기존 사용자 데이터는 유지한다. 0300 down은 가사가 비어 있는 disposable DB에만 허용하며, populated 환경은 forward 수정 또는 별도 백업 복원으로 복구한다. Phase 2는 가사 현재본 API와 rowVersion 충돌, 원문 계약을 사용해 CodeMirror와 직렬 저장을 연결한다.
