- 승인: 2026-09-11 사용자 1.0.14까지 전체 Phase와 버전별 정식 릴리스 실행 지시
- 출발점: v1.0.6 main/release `f3147689bb57cbd681866adeda1b63d3b37f2a2a`
- 현재 Phase: 설계-only. 아래 입력은 P2~P4의 실제 DB/API/browser와 동일 SHA 개발 인수 전까지 PASS가 아니다.

## 저장·API 계약

`library_view_settings`는 `(owner_id, resource_type)` 기본 키, `view_mode`, `row_version`, `updated_at`만 가진 별도 개인 설정이다. `resource_type`은 `songs|rhymes|prompts`, `view_mode`는 `list|grid-small|grid-medium|grid-large`다. `owner_id`는 account를 참조하고 cascade delete하며 강제 RLS와 `app_current_user_id()` owner 정책을 적용한다.

행이 없을 때 GET은 `{ resourceType, viewMode: "list", rowVersion: 0, updatedAt: null }`을 반환하고 insert하지 않는다. PUT body는 `{ viewMode, rowVersion }`만 받으며 owner와 resource type은 인증 문맥/route에서 온다. version 0은 충돌 없는 최초 insert, 양수는 정확한 현재 행 CAS update다. 잘못된 enum/body는 400, 인증 없음 401, 다른 origin mutation은 403, CAS 충돌은 409다. 모든 응답은 private/no-store와 기존 인증 갱신 cookie 규칙을 따른다.

별도 행을 선택한 이유는 기존 `user_settings` 전체 snapshot 갱신과의 결합을 피하기 위해서다. 다른 탭이 글꼴을 저장하는 동안 보기 mode를 저장해도 서로 다른 table/row/version이므로 어느 쪽도 무관한 필드를 되돌리지 않는다. 유형별 행도 서로 독립이다.

## 불변 상태·UI 경계

보기 전환은 이미 불러온 item 배열을 다시 정렬하거나 초기화하지 않는다. 검색·필터·정렬·URL query·cursor/page·누적 load-more·scroll key는 그대로이고 API에는 포함하지 않는다. optimistic 전환 저장 실패는 직전 mode를 복원하고 `보기 설정을 저장하지 못했습니다. 다시 시도해 주세요.`를 status로 알린다. 같은 유형 CAS 충돌은 GET 재조회 후 서버 mode를 표시하고 충돌 안내를 낸다.

mode는 저장된 열 수가 아니다. CSS가 사용 가능한 폭에 따라 small/medium/large 카드 최소 폭을 적용하고 320px·200%에서는 모두 1열까지 줄인다. 긴 한글 제목 링크는 전체 accessible name을 보존한다. 모든 주요 action은 보이는 버튼으로 남고, mode 선택기는 label이 있는 네 button과 `aria-pressed`를 쓴다. 모바일도 hover나 drag 없이 전환 가능해야 한다.

## 실패 우선 입력표

| 입력 | 먼저 확인할 실패 | P2~P4 기대 |
|---|---|---|
| 검색/필터 후 네 mode 연속 전환 | item 재조회·순서 변경·URL 초기화 | 같은 ID/순서/query/cursor, mode만 변경 |
| owner A songs=list, B songs=grid-large | owner 누락/공유 local key | DB/API/RLS와 재로그인 후 서로 다른 값 |
| owner A songs=small, rhymes=large | 유형 key 누락 | 유형별 독립 복원 |
| 글꼴 rowVersion N과 songs view version M 동시 PUT | 전체 settings snapshot overwrite | 둘 다 성공하고 최종 font/mode 보존 |
| 같은 songs version으로 두 탭 PUT | last-write silent overwrite | 하나 성공, 하나 409 후 최신 GET |
| PUT 500/network abort | 낙관 mode만 남음 | 직전 mode rollback·재시도 문장 |
| 320px·200%·매우 긴 한글 제목 | action 겹침/이름 소실 | 1열·wrap/ellipsis 허용·전체 접근 이름·키보드 가능 |
| 구버전 client | 새 table/schema 의존 crash | 기존 list와 display settings 정상 |

## 담당·이행·되돌림

| 영역 | P2/P3 담당 | 증거 |
|---|---|---|
| enum/parser/default | `packages/domain/src/library-view-settings-contract.ts` | invalid/default/version 단위 fixture |
| schema/RLS/CAS | `packages/database/migrations/1001_library_view_settings.sql`, rollback, schema/store | fresh/repeat/owner/concurrency PostgreSQL fixture |
| 인증 API | `apps/web/src/app/api/library-view-settings/[resourceType]/route.ts`, `apps/web/src/lib` | 400/401/403/409/no-store |
| 공통 선택기·세 목록 | `apps/web/src/components`, `apps/web/src/app/styles.css` | PC/mobile/a11y/필터·순서 불변 E2E |

P2는 실패 fixture와 저장/API까지만 구현하고 runtime version을 1.0.7 P2로 맞춘다. P3가 목록 UI를 연결한다. P4가 실제 PostgreSQL, 전체 Chromium, 지원 browser, 두 owner/두 탭, 320px·200%를 교차 검증한다. 실제 물리 기기를 수행하지 않으면 자동 browser 결과를 실기기 PASS로 기록하지 않는다.

기능 rollback은 mode selector/API를 숨기고 기본 list 렌더링으로 돌아간다. 별도 table을 남겨도 기존 client에 영향이 없다. rollback SQL은 table만 삭제하지만 저장된 개인 선호가 사라지므로 정식 운영에서는 별도 승인 없이 실행하지 않는다. 자료·원문·`user_settings`를 수정하거나 migration을 역으로 덮어쓰지 않는다.
