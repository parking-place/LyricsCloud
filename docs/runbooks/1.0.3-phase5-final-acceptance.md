# 1.0.3 Phase 5 최종 후보 인수

- 상태: **진행 중** — 후보 문서·환경 계약 준비, 전체 CI와 동일 SHA 개발 인수 대기
- 범위: P1~P4 증거 통합, 사용자·지원·보안·자가호스팅 문서, 1.0.3 환경 schema, 최종 후보 CI·개발 환경 인수
- 정식 경계: 이번 Phase 완료만으로 `main`, `v1.0.3`, 숫자·`Release`·`latest` 별칭과 릴리스 서버를 변경하지 않는다.

## Source와 migration

P1~P4의 최종/구현 SHA와 네 수용 사례는 [1.0.3 후보 추적](../architecture/1.0.3-FINAL-TRACEABILITY.md)에 동결한다. P5 후보 SHA와 GitHub Actions run은 최종 push 후 이 문서에 기록한다.

1.0.3은 append-only `1000_prompt_modes.sql`을 추가한다. 기존 prompt row는 `tags` mode로 backfill하고 문장 raw는 별도 column/CRDT field에 저장한다. 1.0.2 application으로 돌아가야 하면 문장형 쓰기를 먼저 중단하고 1.0.3 application rollback을 우선하며 migration이나 volume을 삭제하지 않는다.

## P5 후보 검증

후보 commit 전 P4 제품 검증을 재사용하고 다음 문서·환경·release 봉인 검사를 실행한다.

```bash
pnpm check
pnpm build
pnpm test:environment:101
pnpm test:release:1001
pnpm test:release:1002
pnpm test:release:1004
pnpm test:release:1005
```

최종 push는 `[skip ci]` 없이 수행한다. CI의 migration·unit/integration·production build/image·backup/restore·취약점/secret·전체 Playwright와 browser matrix, web·collaboration·migrate·worker 개발 image 게시가 모두 성공해야 한다. 1.0.2의 release manifest·migration/environment/license checksum은 sealed historical artifact로 유지한다.

## 개발 환경 인수

CI를 통과한 정확한 P5 SHA만 개발 서버에 배포한다. PostgreSQL volume과 secret을 보존하고 공개 ready에서 다음을 확인한다.

```text
version=1.0.3
build.id=<정확한 후보 SHA>
channel=dev
phase=p5
database.schemaVersion=1000_prompt_modes.sql
```

네 상시 서비스 health, `/auth`, production 정적 asset, 보안 header와 합성 문장형 prompt의 저장·복제·capability 연결을 확인한다. 실패하면 P4 최종 SHA `38d0231fe4773a0e9ddb0c751128b976e651d15f`로 application-first rollback하고 volume/down migration은 수행하지 않는다.

## 안전성·잔여 위험

- P5까지 확인된 범위의 새 P0/P1, 원문 유실, 인증 우회, 교차 사용자 노출, 무음 저장 실패가 0건이어야 한다.
- `OPS-100-001` 외부 backup 미구축과 `RC-091-002` 실제 모바일 상세 기기 정보 부재는 계속 남는다.
- 1.0.4는 표시 카드·길이 안내만 후속하며 1.0.3의 raw 저장·구버전 차단·명시 변환·복구 안전성을 미루지 않는다.
