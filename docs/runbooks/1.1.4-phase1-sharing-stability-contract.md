# 1.1.4 Phase 1 — 공유 안정성·복구 사건 순서 계약

- 기준 source SHA: `35fa482e31b13a96ed0f4b53754ebe672d23634d` (`v1.1.3`, 정식 운영 인수 완료)
- P1 착수 main SHA: `0b265d6b7aaf686e83f895949d52ad030db8add2`
- 상태: **Accepted for 1.1.4 stabilization**. 이 문서는 사건 순서와 증거 등급을 고정하며 runtime·migration·배포 완료를 뜻하지 않는다.

## 불변 조건

1. `owner_id`는 소유자를, 로그인 `actor_id` 또는 public `guest_session_id`는 행위자를 뜻한다. 복원·삭제·재접속이 이 경계를 바꾸지 않는다.
2. 쓰기는 같은 시점에 유효한 읽기 capability 안에서만 가능하다. 현재 `permission_epoch`와 `write_epoch`가 맞지 않는 새 update는 적용하지 않는다.
3. 입력은 브라우저의 document snapshot과 동일 transaction의 durable outbox에 기록된 뒤에만 `이 기기에 임시 저장됨`으로 간주한다. 서버 저장은 update와 receipt가 commit된 ACK 뒤, 검색·export 반영은 평문 projection 완료 뒤로 구분한다.
4. ACK 유실 재전송은 같은 update ID와 payload를 사용한다. 서버는 기존 receipt가 있으면 현재 권한으로 새 쓰기를 허용하지 않고도 동일 commit의 ACK만 복구할 수 있다.
5. 공유가 끝난 actor의 미전송 자료는 그 actor가 작성한 텍스트만 복구함에 남긴다. 다른 actor의 snapshot·메모·연결 자료·ACL·revision은 남기거나 다음 계정에 표시하지 않는다.

## 사건 순서

### 절전·네트워크 전환·서버 재시작

1. 편집 transaction을 Yjs 문서에 적용한다.
2. 현재 snapshot과 update envelope를 IndexedDB 한 transaction에 기록한다. 이 단계가 실패하면 저장 성공을 표시하지 않는다.
3. 연결 중에는 document별 한 건만 in-flight로 보내며 8초 안에 ACK가 없으면 socket을 닫고 재연결한다.
4. 재연결은 서버 snapshot을 먼저 병합하고 기존 durable update ID를 다시 보낸다. 이미 commit된 ID는 duplicate ACK, 미commit ID는 한 번만 commit된다.
5. 서버는 document advisory lock 안에서 update·receipt·actor/guest attribution을 commit한 뒤 ACK한다. 평문 projection 실패는 accepted CRDT를 버리지 않고 `projection pending`으로 분리해 worker가 재처리한다.
6. 서버 update log는 100건 또는 1 MiB에서 snapshot으로 압축한다. P2는 browser outbox와 IME 중 remote buffer도 같은 capability 경계를 섞지 않는 병합 방식으로 제한한다. 제한 때문에 원문 update를 버리거나 임의 ACK 처리하지 않는다.

### owner revision 복원과 offline writer 재접속

1. owner는 자기 pending update를 먼저 flush하고 현재 body hash를 조건으로 복원을 요청한다.
2. 서버는 document lock 안에서 복원 직전 본문을 immutable revision으로 남기고, 기존 Yjs identity history 위에서 목표 본문으로 교체한 뒤 projection과 request receipt를 원자 commit한다.
3. 복원은 권한 회수가 아닌 **수렴 가능한 편집 사건**이다. 여전히 같은 read/write epoch로 허가된 offline writer의 기존 Yjs update는 복원 뒤 병합하며, 목표 revision 본문과 writer가 새로 작성한 원문을 모두 보존한다.
4. owner가 복원 시점 이전 writer update를 받지 않는 강한 절단을 원하면 먼저 write를 끄거나 grant/link를 회수해 epoch를 올린 뒤 복원해야 한다. 구 epoch update는 rejected 복구함으로 보내고 자동 replay하지 않는다.
5. 같은 restore request ID 재시도는 이후 편집을 다시 덮지 않고 기존 receipt만 반환한다. 다른 request ID의 stale expected hash는 충돌로 거부한다.

### 삭제·휴지통 복원

1. 가사 또는 부모 곡 삭제 transaction은 자료를 숨기는 것과 동시에 selected grant와 public link를 회수하고 read/write epoch를 증가시키는 capability fence여야 한다.
2. 열린 socket은 다음 재인가에서 종료한다. ACK 전 writer update는 서버에 적용하지 않고 actor별 rejected 복구로 전환하며 private projection을 화면과 local document cache에서 제거한다.
3. 검색·목록·export·revision·공개/selected 조회는 삭제 자료를 반환하지 않는다. worker projection 재시도도 삭제 자료를 되살리지 않는다.
4. 휴지통 복원은 기존 문서와 원문은 복구하지만 과거 grant/link를 자동 재활성화하지 않는다. owner가 새 capability를 명시적으로 발급해야 한다.

### 회수 뒤 다른 계정 로그인

1. 로그아웃은 열린 editor와 durable outbox를 먼저 flush한다. 실패하면 명시적 다운로드/강제 폐기 선택 전에는 세션을 끝내지 않는다.
2. 완료 시 현재 계정 prefix의 local/session storage와 owner-hash IndexedDB를 삭제하고 다른 탭에 종료를 알린다.
3. 새 로그인 시 새 actor prefix 외 `lc:*`와 다른 owner-hash DB를 정리한다. public guest recovery DB는 계정 자료가 아니며 guest recovery ID별로만 접근하고 계정 화면에 합치지 않는다.
4. 다음 계정은 이전 actor의 cached snapshot, outbox, rejected draft, selection/presence를 볼 수 없다.

## queue·연결·메모리 계약

| 경계 | 현재/목표 한도 | 초과 처리 |
|---|---:|---|
| server update log | document별 100건 또는 1 MiB | 같은 transaction에서 snapshot compact |
| browser durable outbox | document+capability별 64건 또는 1 MiB 목표 | 미전송 Yjs update를 한 envelope로 lossless merge; in-flight/서로 다른 epoch는 섞지 않음 |
| IME remote buffer | 64건 또는 1 MiB 목표 | Yjs update merge로 한 항목화; composition 확정 전 UI 적용은 보류 |
| public socket | guest 4, link 20 | 새 연결 거부, 기존 durable 자료 불변 |
| public update budget | guest 240건/4 MiB, link 1,200건/16 MiB per minute | transaction 전 거부, rejected recovery·비자동 replay |
| update/document | update 1 MiB, 병합 문서 400,000 byte | protocol/transaction 거부, 기존 원문 불변 |

count와 byte는 관찰 가능한 metric/test assertion으로 남긴다. 단순 반복 횟수를 실제 시간·메모리 증거로 확대하지 않는다.

가속 24시간 상당 반복은 `S1`이며 `S4 24시간 PASS`가 아니다. Playwright composition event는 `S1/S2`일 수 있으나 실제 한국어 IME `S5`를 대신하지 않는다.

## 인터페이스·호환·되돌림

- P2는 `SyncStorage`의 document+capability별 lossless outbox compact와 삭제 capability fence를 additive하게 구현한다. 필요 schema는 `1140` 한 개로 추가하고 과거 update/receipt/revision을 삭제하지 않는다.
- WebSocket envelope·ACK·permission message의 기존 필드는 유지한다. 새 client metric/상태가 필요하면 optional로 추가하고 1.1.3 client의 read/write를 깨지 않는다.
- rollback은 1.1.3 앱으로 먼저 내릴 수 있게 한다. 1140 data/schema는 보존하고 새 trigger/function만 별도 rollback에서 비활성화한다. DB volume·accepted update·receipt·revision·복구 draft를 삭제하지 않는다.
