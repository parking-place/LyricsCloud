## 브라우저·PWA·복구

- 정확한 후보의 원격 두 전체 verify는 migration 반복, unit/integration, production build/image, fresh DB, encrypted restore, previous RC upgrade/rollback, vulnerability·secret scan, auth/ownership E2E, Chromium/Firefox/WebKit release matrix를 통과했다. push run의 네 dev image도 게시·서명됐다.
- P3에서 등록한 desktop/mobile 개인 수직 흐름과 owner 404·작업 자료 503 복구가 전체 browser suite에 포함됐다. 공개 Chromium 1440×1000 dark와 390×844 mobile에서 연결 라임 삽입·재진입 저장, 문장형 exact copy, Suno `_blank`·`noopener`, overflow 부재를 다시 확인했다.
- PWA는 build별 cache namespace·인증 페이지 network-only·HTML navigation network-first·정적 asset stale-while-revalidate와 구 worker 정리를 정적/브라우저 회귀에서 확인했다. 실제 설치형 OS PWA는 새로 실행하지 않았다.

## 성능·서비스 재시작

- P2와 같은 결과 동등 O(n) 구현을 유지했다. 20회 측정에서 2,500개 median 0.4099 ms / p95 0.8904 ms, 10,000개 median 1.6463 ms / p95 3.2895 ms였다. 구현 전 10,000개 p95 482.97 ms와 동일한 위치 결과였으며, 이는 순수 계산 microbenchmark다.
- 개발 서버 checkout·build metadata는 후보와 일치했고 schema `1003_song_suno_workspaces.sql`, 네 서비스가 healthy였다. web·collaboration·worker를 실제 재시작한 뒤 위 가사 원문, 문장 원문, 연결 자료, Suno aggregate와 owner 격리가 그대로 유지됐다.
- 합성 계정·session·곡·가사·라임·프롬프트는 모든 공개 검사 종료 시 제거했다.
