# 1.1.3 Phase 4 — 공개 게스트 작성 권한·복구 회귀

## 후보와 범위

- 제품 후보는 `3fd9f0d9ebde0a58c653c94e46f8549643e3a194`다.
- 실제 개발 인수 중 연결 snapshot 준비 전에 편집기가 먼저 열려 초기 입력이 동기화 객체에 전달되지 않는 유실 경계를 발견했다. editor는 문서 초기화와 sync 준비를 모두 확인하기 전까지 읽기 전용이며, 연결 이후와 초기화된 offline 상태에서만 guest 입력을 허용한다.
- selected-read와 public-write는 같은 자료에서 상호 배타적이다. 두 방향 전환 모두 같은 advisory lock 안에서 거부하고 기존 ACL·public access·write epoch를 보존한다.

## 자동 검증

- Node 24.20.0에서 `pnpm check`와 production build가 PASS했다.
- 실제 PostgreSQL 집중 회귀는 358 PASS·4 조건부 skip이었다. 다른 자료 link/session 재사용, owner·displayName actor 위조, guest별 socket 상한, 병렬 durable budget, collaboration restart 뒤 제한 지속, owner write 중지와 승인 본문 보존을 확인했다.
- Chromium·Firefox·WebKit desktop과 Chromium·WebKit mobile의 전용 흐름 5/5가 PASS했다. 선택 독자/public-write 충돌과 ACL 보존, 연결 준비 전 편집 차단, 두 guest 수렴, private API·메모 격리, presence, offline rejected-only 복구, 재허용 뒤 비자동 적용과 전체 회수를 확인했다.
- 후보 Actions push `34769556924`와 PR `34769560151`은 전체 verify를 통과했고 네 development image가 발행·서명됐다. 이전 main 재실행 `34767147131`도 동일 코드의 기존 0.9.1 성능 절대 예산을 유지한 채 PASS했다.

## 동일 SHA 개발 인수

- 공개 live/ready는 `1.1.3`·`dev`·`p4`, schema `1130_public_lyric_guest_write.sql`과 후보 SHA를 반환했고 postgres/web/collaboration/worker는 모두 healthy였다.
- 합성 owner·selected reader·두 비로그인 guest로 selected/public 충돌과 ACL 불변, guest session 분리, 두 guest·owner 수렴, private API·메모/연결 자료 격리, 인증 presence, offline rejected-only 복구, 재허용 뒤 비자동 적용, 전체 링크 회수를 PASS했다.
- web/collaboration/worker를 실제 재시작한 뒤 같은 공개 흐름을 다시 PASS했다. 합성 계정·곡·가사·grant·guest session은 인수 직후 제거했고 application log에 token·본문·합성 identity가 기록되지 않음을 확인했다.
- 실제 Windows Chrome/Edge·Firefox, iOS, Android 물리 기기는 P4에서 새로 실행하지 않았다. 자동 브라우저 엔진·viewport와 구분해 P5 release 위험으로 인계한다.

P5는 이 후보를 요구 추적·사용자/지원/보안/자가호스팅 문서와 release manifest에 연결하고, 최종 후보의 전체 CI·동일 SHA 개발 인수 뒤 승인된 정식 릴리스 gate를 판정한다.
