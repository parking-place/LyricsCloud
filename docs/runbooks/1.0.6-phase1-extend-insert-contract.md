# 1.0.6 P1 Extend·송폼 삽입 계약 인수

- 승인: 2026-09-11 사용자 1.0.14까지 전체 Phase와 버전별 정식 릴리스 실행 지시
- 출발점: v1.0.5 main/release `4411bc1eb74c90a6a1c47f7e3315de2d5ff39edb`
- 현재 Phase: 설계-only. 아래 입력은 P2~P4에서 실제 테스트·개발 서버 인수 전까지 PASS가 아니다.

## 결정된 출력 경계

`copyWholeLyric`의 Suno용 최종 payload만 base label이 exact-case `Extend`인 정식 full-line marker를 제거한다. CRLF는 기존 정책대로 LF로 먼저 직렬화한다. marker 뒤 LF가 있으면 그 LF 하나까지 제거하고, 파일 끝 marker면 marker 텍스트만 제거한다. 주변 빈 줄·다음 가사·다른 송폼은 trim하지 않는다. 부분/구간 copy, raw CRDT, revision, 검색 원문, JSON/TXT/Markdown recovery export와 backup은 marker 및 불투명 suffix를 그대로 보존한다.

| 입력 | Suno 전체 copy 기대 | 원문/부분 copy 기대 |
|---|---|---|
| `[Extend: 3:00:24]\n첫 줄\n둘째 줄` | `첫 줄\n둘째 줄` | 입력 그대로 |
| `앞\n[Extend]\n뒤` | `앞\n뒤` | 입력 그대로 |
| `앞\n[Extend]` | `앞\n` | 입력 그대로 |
| `[extend]\n뒤` | 입력 그대로 | 입력 그대로 |
| `문장 [Extend]\n뒤` | 입력 그대로 | 입력 그대로 |
| `[Extend\n뒤` | 입력 그대로 | 입력 그대로 |

최종 payload code point가 3,000자를 초과할 때만 기존 비차단 경고를 낸다. 따라서 marker 제거 후 길이를 센다.

## 삽입 명령 경계

기본 marker source는 `Intro`, `Verse`, `Pre-Chorus`, `Chorus`, `Hook`, `Bridge`, `Outro`다. 우클릭, 키보드 메뉴키/`Shift+F10`, 모바일 보이는 버튼은 같은 source와 command를 사용한다. 우클릭은 브라우저 기본 context를 강제로 없애지 않고 삽입 메뉴를 준비한다.

메뉴를 열 때 selection의 head caret을 Yjs relative position으로 캡처한다. 선택 범위 본문은 삭제하지 않는다. 선택 실행 때 현재 document에서 그 위치를 해석하고 marker가 독립 줄이 되도록 앞뒤에 부족한 LF만 더해 한 transaction으로 정확히 한 번 삽입한다. 실행 후 한 번 undo는 그 삽입만 취소해야 한다. relative position을 해석할 수 없거나 resource/document가 바뀌었거나 IME composition 중이면 입력을 바꾸지 않고 메뉴를 닫은 뒤 재시도 안내를 낸다. Escape도 메뉴만 닫고 조합·원문을 보존한다.

## 담당과 검증 입력

| 영역 | 담당 경로 | P2~P4 증거 |
|---|---|---|
| copy/parser/relative insertion | `packages/editor/src` | marker/CRLF/경계 길이·remote edit·실패 무변경 단위 테스트 |
| editor transaction/IME | `packages/editor/src/codemirror.ts` | 한 transaction/undo·composition guard |
| PC/mobile menu와 안내 | `apps/web/src/components`, `apps/web/src/lib` | 우클릭·키보드·보이는 버튼·Escape E2E |
| 권한/복구/통합 | `tests/e2e` | 다른 owner 비노출, offline/reconnect, revision/export 원문 보존 |

새 schema, migration, 저장 API, server 권한 변경은 없다. P2는 editor package의 실패 fixture를 먼저 추가하고 copy/relative insertion 기반을 구현한다. P3가 UI를 연결하고 P4가 실제 PostgreSQL·지원 browser·IME/재접속을 교차 검증한다. 실제 Windows/macOS/Linux/mobile OS IME가 준비되지 않으면 합성 이벤트를 실제 기기 PASS로 기록하지 않는다.

## 되돌림

Suno copy filter를 기존 serializer로 되돌리고 삽입 UI/command를 숨길 수 있다. 저장 원문과 revision/export 형식이 변하지 않으므로 데이터 migration이나 파괴적 rollback은 없다. 중복 삽입·입력 손실·원문 export 누락이 발견되면 해당 동작을 비활성화하고 P1 계약 위반으로 재개방한다.
