# 0.3.1 Phase 5 로컬 통합 검증

2026-09-06, `phase/0.3.1-p5-resilience`, 구현·원격 인수 기준 `5a4816c25208422560fc57c2e46f544195539e95`.

이 보고서는 로컬 Goal 종료 시점의 구현·검증과 이후 원격·개발 서버 인수를 기록한다. **Phase 상태는 review이며 실제 물리 기기까지의 전체 인수 완료가 아니다.** Phase 3~5의 원격 push·CI·Docker Hub 발행·동일 SHA 개발 배포·공개 Chromium smoke는 완료했다. 현재 상태는 [STATUS](<../../0.Plans/1. Dev-phase/STATUS.md>)와 각 Phase PR·Actions의 현재 SHA를 따른다. 0.4.0 기능은 시작하지 않았다.

## 수정한 실제 결함

- 로그아웃이 한 세션만 폐기하던 경로를 ADR-0002의 동일 계정 전체 세션 폐기로 맞췄다. 다른 계정은 유지하고 이미 폐기·만료된 토큰으로 새 로그인을 끊지 못한다. UI는 기대한 owner를 요청에 포함해 중간 계정 변경으로 다른 계정을 로그아웃시키지 않는다.
- 현재 metadata·본문과 다른/닫힌 탭의 전송 대기열을 확인하기 전에 `Clear-Site-Data`가 초안을 지우던 경로를 고쳤다. 각 탭의 Web Lock, 준비 방송, 입력 일시 정지, 저장, 배타 잠금, 대기열 확인 뒤 서버 로그아웃한다. 저장·잠금 대기에 제한 시간을 두고 실패 시 편집을 재개한다.
- 개시 탭이 준비 중 닫혀 결과를 방송하지 못해도 나머지 탭은 30초 뒤 공유 편집 잠금을 다시 얻어 복구한다. 실제 진행 중인 로그아웃의 배타 잠금은 계속 존중한다. 모바일에서 초안 보관 안내가 편집기 아래로 밀리던 배치와 버튼 대비도 실제 캡처 확인 후 수정했다.
- 세션 만료 401은 초안을 자동 삭제하거나 화면을 바꾸지 않는다. 같은 계정으로 다시 로그인하고 재시도하면 owner·삭제 상태를 다시 검증한 뒤 전송한다. 다른 계정 진입은 이전 계정 캐시를 정리한다.
- 삭제된 문서의 전송 불가능한 초안이 로그아웃을 영구 차단하지 않도록 로컬 초안 내려받기와 명시적인 삭제 확인을 제공한다. 내려받기는 전송 대기 본문과 현재 화면의 메모리 입력을 위한 비상 보관이며 일반 자료 내보내기·백업 기능은 아니다.
- 실제 DB 컨테이너 재시작으로 유휴 `pg.Pool`의 미처리 error가 collaboration 프로세스를 종료하는 것을 재현했다. 공통 pool 생성 함수에서 끊어진 유휴 연결을 처리하고 내용 없는 이벤트만 남긴다. 실행 중인 query 오류는 기존 transaction rollback과 호출자 오류 처리로 전달된다. auth·profile·song·lyric·collaboration store와 readiness에 공통 적용했다.
- readiness의 schema 기준을 실제 사용 중인 `0311_lyric_revisions.sql`로 맞췄다. 신규 DB migration은 없다.
- 초기 동기화 중 읽기 전용 편집기에서 목차 이동 뒤 포커스를 받지 못하는 것을 trace의 `contenteditable=false`로 확인했다. 본문을 키보드로 탐색할 수 있도록 tabindex를 지정하고, 편집 가능 여부가 같을 때 불필요한 재설정을 생략한다.
- 원격 문서 후속 commit의 전체 E2E가 다중 탭 로그아웃 한 건에서 성공한 200 응답과 쿠키 폐기 뒤 `Clear-Site-Data` 때문에 fetch를 `ERR_ABORTED`로 관측하는 경합을 드러냈다. 세션 API가 401로 재확인될 때만 성공으로 확정해 다른 탭에도 완료를 전파하고, 실제 네트워크 장애면 기존처럼 편집을 재개한다. 재현 시 3회 중 2회 실패했으며 수정 후 5개 병렬 반복과 로그아웃 PC·모바일 18개를 통과했다.

실패를 포함한 전체 실행을 최종 전체 성공으로 바꾸어 보고하지 않는다. 수정 후 직접 영향 범위를 재검증했고, 무관한 기존 성공은 재사용했다. 모바일 제외 2개는 이미 하나의 테스트 안에서 PC 두 탭과 모바일을 함께 실행하는 매트릭스의 중복 실행이다.

10만 Unicode 문자에서 한 글자 교체를 측정했다. 로컬 Chromium 세 화면 수렴 관측값은 약 **76.9ms**, 전송 update 합계 **34bytes**, DB snapshot **298,019bytes**, receipt부터 평문 projection까지 **4.485ms**였다. UI 검증 도구의 왕복이 포함된 단일 로컬 관측이며 실제 인터넷·물리 모바일 성능 보장이 아니다. 수치 외 창작물 본문은 성능 증적에 넣지 않는다. 측정만을 근거로 adapter를 교체하거나 추가 최적화하지 않았다.

증거는 Git에서 제외한 `.private/p5-*.log`, `p5-metrics-report.json`, `p5-browser-evidence`, `p5-focus-evidence`, `p5-banner-evidence`에 있다. production 검증은 `scripts/verify-production-images.sh`와 `verify-production-recovery.mjs`로 CI에도 연결된다.

## 검증 환경에서 구분한 문제

- 최초 restart 실험의 tmpfs DB는 컨테이너 재시작 시 내용이 사라졌다. 이는 앱의 DB 내구성 문제가 아니다. 임시 DB에 migration을 다시 적용하고 실제 restart 검증 스크립트는 자신이 만든 일회성 named volume으로 변경했다. 종료 시 그 volume만 제거한다. 개인 DB volume은 건드리지 않았다.
- production auth smoke는 production 설정의 HTTPS 제약 때문에 처음 503이었다. 기존의 loopback OIDC fixture 옵션과 합성 설정으로 검증 환경을 맞췄으며 운영 인증 제한을 완화하지 않았다.
- worker의 Playwright `test.use` 위치 오류는 파일 최상위로 고쳤다. 함수 구문 검사만으로 E2E 실행 성공을 주장하지 않았다.
- 탭 종료 회귀의 최초 가상 시간 이동은 로그아웃 요청의 제한 시간까지 진행시켰다. 닫힌 페이지의 가로챈 fetch도 검증을 불확실하게 해, 서버가 로그아웃을 받기 전 checkpoint 준비에서 탭을 닫고 세션 200·실제 30초 경과·재입력 저장을 확인하도록 격리했다.
- GLM 5.3 Flash의 범위 제한 검토에서 발견한 세션 만료·삭제된 초안·로그아웃 중 입력 경계는 부모가 직접 수정하고 위 E2E로 검증했다.

- 개발 이미지 `lyricscloud-local-dev:p5-resilience`, build ID `phase5-local`. 기존 개인 OAuth, `.test_users`, DB와 session secret을 보존한다.

## 남는 인수

- 사용자는 이전 단계에서 실제 개인 Google 로그인과 workspace 진입을 확인했다. 이번 자동 로그아웃 검증은 합성 세션·OIDC fixture이며 실제 Google 계정의 새 로그아웃 수용을 대신하지 않는다.
- 실제 Android/iOS, OS 한글 IME·가상 키보드, 서로 다른 물리 네트워크와 브라우저 프로세스/OS 강제 종료는 미검증이다. 현재 증거는 Chromium 모바일 viewport·합성 composition, 닫힌 탭 초안 복구와 Docker 프로세스 장애다.
- ADR-0005의 초기 binding·awareness 서술과 현행 transaction adapter/presence 미구현을 문서로 구분했다. 공유 편집이나 새 CRDT 라이브러리로 범위를 바꾸지 않았다.
- 원격에는 Phase 3 → Phase 4 → Phase 5 순서의 별도 PR이 열려 있다. `main` 직접 반영이나 release는 하지 않았다.
- 실제 Android/iOS·OS 한글 IME·서로 다른 물리 네트워크와 실제 Google 로그아웃 수용 증거 전에는 Phase를 complete로 바꾸지 않는다.
