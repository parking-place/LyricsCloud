# 0.4.0 Phase 4 검증

## 구현 결과

- 라임 편집 설정에서 owner의 활성 곡을 제목의 문자 그대로 부분 문자열로 검색하고, 현재 연결을 먼저 표시한다. 연결·해제는 재시도해도 중복 관계를 만들지 않으며 실제로 관계가 달라질 때만 라임의 수정 시각을 갱신한다.
- 태그 pill은 저장 대기 중인 제목·본문을 먼저 반영한 뒤 해당 태그가 활성인 라임 목록으로 이동한다. 목록의 태그·곡 조합 필터와 count는 같은 관계를 사용한다.
- 전체 본문과 현재 CodeMirror 선택 영역 복사를 구분했다. 빈 선택에는 먼저 선택하라는 안내를, Clipboard 거부에는 원문과 동일한 선택 가능한 수동 복사 dialog를 제공한다.
- 독립 라임 화면에서는 열린 가사 대상을 추측하지 않고 삽입 행동을 비활성으로 표시한다. `PROD-0006`은 source/target resource·document key, Yjs 상대 위치, 멱등 request ID와 순수 텍스트 snapshot을 0.6.0 소비 계약으로 확정한다.
- 곡 연결은 같은 owner의 활성 라임·곡만 허용한다. 한 관계를 해제해도 라임, 곡, 태그와 다른 곡 연결은 보존한다.

## 로컬 검증

- 깨끗한 PostgreSQL test container에서 migration을 두 번 적용했다. architecture boundary·모든 TypeScript project와 `32 files / 122 tests`, Next.js production build가 통과했다.
- Playwright production 전체 suite는 Phase 4 테스트 추가 전 `132 passed / 2 intentional skipped`였고, 곡 후보 실패·재시도·빈 상태까지 추가한 Phase 4 편집 흐름 PC·모바일 6개가 별도로 통과했다. 최종 원격 suite는 `134 passed / 2 intentional skipped`다.
- PC·모바일에서 새 라임 → 태그 → 곡 연결/해제/재연결 → 태그 필터 count → 재편집 → 동일 owner 두 탭 병합 → revision 복원 → 전체/선택 복사 → Clipboard 거부 → 삭제 흐름을 검증했다.
- 다른 owner 곡 연결, 잘못된 Origin, 인증 없음, 삭제된 라임 접근을 차단하고 문자 `%_`를 검색 wildcard가 아닌 원문으로 처리했다.
- 네 production image로 새 DB migration, web·collaboration·worker readiness, DB·서비스 재시작, WebSocket 수렴, pending projection·revision 복구를 통과했다.
- build artifact 비밀 검사와 계획 구조 검사(`13 versions / 65 phase documents / 576 task IDs / 71 requirements`)를 통과했다.

## Phase 5 인계

- Phase 5는 Phase 1~4 구현을 새 계정부터 삭제까지 하나의 PC·모바일 시나리오로 다시 실행하고, 느린 메타데이터 응답의 최종 상태·다수 태그·장문·접근성 상태를 보강한다.
- 0.5.0은 라임과 같은 owner/resource·목록·복사·오류 상태 패턴을 프롬프트에 재사용할 수 있다.
- 0.6.0은 [`PROD-0006`](../product/PROD-0006-rhyme-lyric-insertion.md)과 domain/editor 상대 위치 codec을 소비하되, 명령 시점에 살아 있는 같은 owner target을 다시 확인하고 삽입을 한 CRDT transaction·undo 단위로 처리해야 한다.
