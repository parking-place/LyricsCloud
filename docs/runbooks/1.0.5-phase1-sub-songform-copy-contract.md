# 1.0.5 Phase 1 서브 송폼·가사 복사 계약

## 인수 기준

- 출발 source: `508833e5aee43ebcc9d7aecaae1592b655a5460a` (1.0.4 P5 최종 문서·개발 인수)
- 범위: `NF-REQ-024`, `NF-REQ-025`, `AC-1.0.5-01`~`04`
- 성격: 설계-only. runtime·schema·운영 환경을 변경하지 않는다.
- 담당: Codex. P2/P3 구현 경계는 `packages/editor/src/{songform,copy,codemirror}.ts`, 관련 단위 테스트, `apps/web/src/components/lyric-editor.tsx`, `apps/web/src/app/styles.css`, `tests/e2e/new-feature-1.0.5.spec.ts`다.

## 승인 계약

1. 기존 한 줄 전체 `[label]` 인식 문법을 유지한다. 내부 첫 ASCII `:` 앞의 trim된 문자열이 비어 있지 않을 때만 이를 탐색용 `label`로 쓰고, occurrence·목차·최근 위치 복원도 그 주 이름을 기준으로 한다. 이후 콜론은 모두 suffix 일부다.
2. parser projection은 전체 내부 `rawLabel`, 주 이름 `label`, 콜론부터 닫는 대괄호 직전까지의 `subtag`와 절대 `subtagFrom/subtagTo` 범위를 제공한다. `[Verse: a:b]`의 주 이름은 `Verse`, 낮출 표시 범위는 `: a:b`다.
3. 콜론 앞이 공백뿐인 기존 label은 일반 본문으로 강등하지 않는다. 해당 줄은 기존 전체 내부 label로 인식하고 subtag 범위는 만들지 않는다. 잘못된 괄호·본문 중간 대괄호 처리도 기존 계약을 유지한다.
4. suffix decoration은 selection·cursor·undo·composition·CRDT transaction을 만들지 않는 표시 projection이다. DB/API/CRDT/revision/search/export와 전체·구간 copy는 현재 순수 텍스트를 유지한다.
5. 공통 lyric copy builder는 기존 `copyWholeLyric`의 CRLF/CR→LF 직렬화가 끝난 payload를 기준으로 Unicode code point 수와 `> 3000` 상태를 함께 반환한다. 2999·3000은 경고하지 않고 3001부터 경고하되 저장·자동/수동 복사를 막거나 자르지 않는다.
6. desktop/mobile 전체 복사, 단축키, 저장 실패의 현재 입력 복사, clipboard 실패의 수동 dialog는 같은 최종 payload와 경고 판정을 쓴다. 구간 복사는 이번 경고 대상이 아니며 1.0.6 Extend 필터를 미리 구현하지 않는다.

## 실패·권한·복구 입력표

| 입력·상황 | 현재 경로와 위험 | P2/P3 기대 결과 |
|---|---|---|
| `[Verse: whisper]`, `[Verse: a:b]` | parser가 전체 내부를 label로 써 서로 다른 목차 항목이 된다. | 주 이름은 모두 `Verse`, raw와 추가 콜론은 보존한다. |
| `[ Verse : whisper ]`, `[ :legacy]` | 공백/빈 base 처리에 따라 기존 구간이 사라질 수 있다. | 첫 줄은 `Verse`로 탐색하고, 빈 base는 기존 전체 label 호환을 유지한다. |
| 같은 주 이름·다른 suffix 반복 | occurrence와 resume가 suffix 편집 때 바뀔 수 있다. | occurrence는 주 이름과 문서 순서로 고정하고 suffix-only 편집은 같은 구간을 유지한다. |
| 2999/3000/3001 code point, emoji·분해 한글·CRLF | JS code unit 또는 원문 길이를 세면 실제 clipboard와 다르다. | LF 최종 payload의 code point를 세고 3001만 비차단 경고한다. |
| clipboard 거부·저장 오류 | 수동 대안이나 복구 copy에서 경고·payload가 달라질 수 있다. | 같은 payload·경고를 제공하고 편집/저장 상태를 바꾸지 않는다. |
| 다른 계정·삭제·404 | 표시 기능이 서버 소유권 경계를 우회할 위험이 있다. | 기존 owner 검사와 404를 유지하며 타인 원문을 노출하지 않는다. |
| IME·두 탭·offline·재접속 | decoration 재계산이 composition/remote transaction과 섞일 수 있다. | 현재 snapshot의 읽기 전용 projection으로 계산하고 cursor·undo·원문을 변경하지 않는다. |

## 인터페이스·호환·되돌림

- P2는 `SongFormSection`에 `rawLabel`, nullable `subtag`, nullable `subtagFrom/subtagTo`를 추가한다. 기존 `label`, `tagFrom/tagTo`, `from/to`는 유지하며 `label`만 주 이름 의미로 좁힌다.
- incremental `SongFormIndex`는 marker에 같은 projection을 보존하고 변경 line 주변만 다시 읽는다. suffix-only 변경으로 offset이 이동하지 않으면 section id와 occurrence도 바뀌지 않는다.
- P2는 `LYRIC_COPY_WARNING_LIMIT = 3000`과 `buildLyricCopyPayload`를 추가하며 기존 `copyWholeLyric`을 호환 wrapper로 유지한다.
- migration은 없다. UI rollback은 subtag mark·보조 label·경고 표시를 제거하고 기존 parser/copy wrapper로 돌아가면 되며 저장 원문 변환이나 데이터 복구가 필요 없다.

## 검토 증거와 남은 작업

- 조사한 실제 경로: `songform.ts` parser/index/find, `codemirror.ts` line decoration/resume, `copy.ts` LF serializer/구간 slice, `lyric-editor.tsx` 목차·전체/복구 copy·feedback, 기존 unit/E2E.
- P1은 수용 결과를 실행 완료로 주장하지 않는다. P2가 실패 fixture·순수 parser/builder·증분/장문 단위 회귀, P3가 PC/mobile UI·접근성·IME 흐름, P4가 실제 DB·브라우저·권한·offline/restart 교차 검증, P5가 문서·최종 CI·동일 SHA 개발 인수를 담당한다.
- 실제 Windows/iOS/Android 입력은 새로 수행하지 않았고 자동 브라우저 결과로 대체하지 않는다. `OPS-100-001` 운영 백업 예외와 1.0.0 P6 review를 유지한다.
