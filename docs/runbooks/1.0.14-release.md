# 1.0.14 정식 릴리스 실행

사용자는 1.0.14 P1~P5 완료 뒤 main 병합·annotated `v1.0.14` tag·정식 image·릴리스 서버 배포를 승인했다. 최종 후보와 main 전체 CI가 통과한 같은 source SHA에 tag를 만들며 tag는 이동·재사용하지 않는다.

1. P5 PR을 merge commit으로 main에 병합하고 main 전체 CI를 통과시킨다.
2. main HEAD에 annotated `v1.0.14` tag를 만들고 `publish=true`, `release=true` workflow를 실행한다.
3. web·collaboration·worker·migrate의 `1.0.14`, `Release`, `latest`, `Release-latest`가 같은 source SHA와 exact digest를 가리키며 signature·provenance·SBOM이 있는지 확인한다.
4. 릴리스 서버에 migrate exact digest를 먼저 실행하고 나머지 세 서비스를 exact digest로 교체한다. DB volume·secret·초대 자료는 보존한다.
5. ready의 version/SHA/channel/schema와 공개 HTTPS 저장·재진입·font/fallback·owner 격리·서비스 재시작을 확인하고 합성 자료를 제거한다.

중단 기준은 CI/image 서명 실패, SHA·digest·schema 불일치, migration 실패, ready 실패, 원문 손실·owner 노출이다. schema-compatible 오류는 application-first rollback으로 직전 1.0.12 exact digest를 복원한다. schema 복구가 필요하면 쓰기를 중단하고 유효 backup을 새 DB에 restore한다. 현재 `OPS-100-001` 예외로 운영 backup이 미구축이므로 DB 복구 지점은 보장되지 않으며 이 위험을 숨기지 않는다.
