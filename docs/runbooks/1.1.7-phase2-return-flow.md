# 1.1.7 P2 생성·복귀 흐름 인수

## 범위

- 새 라임·새 프롬프트를 빠른 추가에서 열 때 현재 workspace 경로를 `returnTo`로 전달한다.
- 생성 성공 뒤 편집 화면과 목록 복귀 버튼이 같은 안전한 경로를 유지한다.
- `returnTo`는 같은 origin의 workspace 경로만 허용하며 외부 URL과 계정 경로는 각 자료 목록으로 되돌린다.
- 빠른 추가가 아닌 기존 직접 생성·템플릿 진입에는 새 query를 붙이지 않아 기존 URL·초안 복구 계약을 유지한다.
- API·DB schema·권한·본문 저장·copy 형식은 변경하지 않는다.

첫 원격 후보는 명시되지 않은 기본 복귀 경로까지 편집 URL query로 붙여 기존 생성·템플릿 회귀 14건을 실패시켰다. 명시적 `returnTo`가 있을 때만 query를 전달하도록 보정하며 같은 전체 CI를 다시 실행한다.

Android/iOS 항목은 browser mobile 대리 환경이며 실제 Android/iOS 앱·물리 기기·OS IME·AT 검증이 아니다.

## 공개 개발 인수

후보 commit의 필수 CI와 네 dev image가 성공한 뒤 정확히 같은 SHA를 개발 서버에 배포한다. 다음을 확인하기 전 P2를 완료하지 않는다.

1. `/api/health/ready`의 version/channel/phase/build가 후보 `1.1.7/dev/p2/SHA`와 일치한다.
2. 가사 화면에서 새 라임과 새 프롬프트를 생성하고 편집 화면을 거쳐 원래 가사 URL·본문으로 복귀한다.
3. desktop/mobile에서 focus 가능한 편집기와 가로 overflow 없음이 유지된다.
4. schema는 `1140_sharing_stability.sql`로 유지되고 모든 서비스가 healthy다.
5. 합성 fixture를 제거하며 DB volume·secret·allowlist를 보존한다.

## 중단·되돌림

- 외부 URL이 허용되거나 원래 가사 본문·권한 상태가 달라지면 배포를 중단한다.
- 개발 서버 rollback은 직전 exact dev image/SHA로 되돌리며 migration 추가가 없으므로 schema 역변경은 하지 않는다.
- 릴리스 서버는 P2에서 변경하지 않는다.
