# 0.6.0 Phase 1 곡 대시보드 검증

## 구현 결과

- 곡 hero에 제목·설명·상태·색상·핀·즐겨찾기·최근 수정과 수정·삭제 행동을 PC·모바일에서 같은 의미로 표시한다.
- owner의 활성 자료만 대상으로 가사·연결 프롬프트·연결 라임을 각각 집계하며, 곡 핵심 조회와 영역 조회를 분리해 일부 실패가 이미 받은 곡 정보를 지우지 않는다.
- 가사 카드에 제목·두 줄 preview·상태·즐겨찾기·현재 작업·수정 시각을 표시하고 새 가사·열기·멱등 복제·대상 이름 확인 삭제를 연결한다.
- 곡과 각 가사의 작업 메모를 본문과 별도로 추가·편집·삭제하고, 연결 라임·프롬프트의 제목과 본문/토큰 preview 및 전체 목록 진입을 제공한다.
- 곡 목록의 검색·상태·정렬 query, 추가 로드 수와 window/내부 scroll 위치를 저장해 대시보드와 가사 편집기를 왕복한 뒤 복원한다.
- 다른 owner 또는 삭제된 곡은 HTTP 404를 유지한다. route 전역 loading boundary가 404 응답을 streaming 200으로 바꾸는 문제를 발견해 owner 확인 뒤의 내부 Suspense boundary로 교정했다.

## Phase 2 인계

- Phase 2는 현재 preview와 독립 영역 재시도 패턴을 유형 탭·전체 목록·owner 검색·다중 연결·확인 해제로 확장한다.
- 기존 `song_resource_links`의 owner N:M·중복 방지·unlink 원본 보존 계약을 유지하고, 삭제 자료·삭제 곡은 후보 및 집계에서 제외한다.
- PC modal과 모바일 bottom sheet는 적용·취소·오류 뒤 원래 연결 행동으로 focus를 복원해야 한다.
