## 복구 절차

[`0200_resources_songs.sql`](../../packages/database/rollback/0200_resources_songs.sql)은 `resources`와 `songs` 데이터 및 0200 migration 이력을 제거한다. 자동 rollback이 아니며 다음 조건을 모두 확인한 경우에만 수동 실행한다.

1. 대상 DB 이름과 환경을 다시 확인하고 백업을 만든다.
2. 0200 이후 migration 또는 업무 데이터가 없음을 확인한다.
3. disposable DB나 백업 복원본에서 먼저 down과 전체 forward migration을 반복한다.
4. 운영 데이터가 있으면 down SQL로 되돌리지 말고 검증된 백업 복원 또는 forward 보정 migration을 사용한다.

## Phase 2 인계

- 생성은 resource와 song을 한 transaction에서 삽입해야 하며 owner는 session의 내부 UUID만 사용한다.
- 활성 조회는 `owner_id`, `type='song'`, `deleted_at is null`을 모두 포함한다.
- 상태·색상·길이 값은 [`resource-contract.ts`](../../packages/domain/src/resource-contract.ts)를 사용하고 DB check와 다르게 확장하지 않는다.
- `soft_delete_song`은 원본 두 행을 보존하고 재호출 시 `false`를 반환한다.
- 생성 idempotency key, CRUD repository, 검색·정렬 cursor는 Phase 2 범위로 남겨 두었다.
