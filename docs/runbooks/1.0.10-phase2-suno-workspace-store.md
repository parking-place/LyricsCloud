## 실패 우선과 구현 경계

미구현 model/URL 제한, owner 격리, aggregate CAS·멱등 replay, 곡 삭제/복원과 export 수용 사례를 먼저 등록했다. 공통 domain parser는 모델명을 NFC·trim 후 최대 64 code point의 nullable 값으로 처리하며 제안 목록을 강제하지 않는다. URL은 HTTPS의 `suno.com`/`www.suno.com`과 `/song/<UUID>` 또는 `/s/<token>`만 허용하고 userinfo·port·fragment·내부 주소·outbound 조회를 거부한다.

`1003_song_suno_workspaces.sql`은 곡별 model/state, 최대 20개의 ordered link, request ledger를 owner 정책으로 추가한다. GET과 `set_model`, `create_link`, `update_link`, `remove_link`, `reorder_links` 명령은 owner·active parent를 확인하고 `expectedVersion` CAS와 `requestId` replay를 적용한다. soft delete는 숨기고 복원은 같은 자료를 다시 보이며 영구 삭제는 cascade한다. JSON과 읽기용 Markdown export에 model·URL·수동 title/note/order를 포함하지만 외부 Suno 원곡은 변경하지 않는다.
