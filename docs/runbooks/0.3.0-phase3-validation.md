# 0.3.0 Phase 3 검증

2026-09-05, Node 24.20.0 / pnpm 11.25.0 / 별도 PostgreSQL `lyricscloud_test`와 공개 개발 서버에서 검증했다. 실제 사용자 본문과 릴리스 환경은 사용하지 않았다.

## 범위와 결과

LC-030-P3-01~10을 하나의 순수 송폼 parser와 CodeMirror view plugin, PC 목차와 모바일 시트에 연결했다. 앞뒤 공백을 제외한 한 줄 전체가 비어 있지 않은 `[label]`일 때만 인식하며 표준 영문·번호·Final·한글·사용자 label을 원문대로 보존한다. 빈 태그, 닫히지 않은 태그, 중첩 대괄호와 문장 안 대괄호는 일반 본문으로 남는다.

반복 label은 문서 순서 occurrence와 현재 tag offset을 조합한 고유 ID를 갖는다. section 범위는 tag 줄 시작부터 다음 tag 직전 또는 문서 끝까지다. line decoration은 원문과 undo history를 바꾸지 않는다. cursor·viewport 갱신은 animation frame당 한 번만 React 상태로 전달하며, PC 목차와 모바일 시트 모두 같은 plugin section 배열을 사용한다.

`SongFormIndex`는 입력마다 전체 10만 자를 다시 읽지 않는다. 변경된 줄과 인접 줄만 재파싱하고 나머지 marker offset은 CodeMirror `ChangeDesc`로 매핑한 뒤 section 순서와 occurrence를 재계산한다.

## 검증

- `pnpm check`: workspace 경계와 전체 TypeScript 통과.
- `AUTH_DATABASE_INTEGRATION=true pnpm test`: 21개 파일, 80개 테스트 통과. 송폼 신규 5개 테스트는 표준·한글·사용자·반복 label, 오탐 방지, 정확한 tag 포함 범위, tag 추가·제거와 장문 증분 갱신을 확인한다.
- 500개 section·약 10만 자 fixture의 한 글자 변경에서 증분 결과가 전체 재파싱 결과와 동일하고 재검사량이 600자 미만임을 확인했다.
- `NODE_ENV=production pnpm build`: production standalone build 통과.
- `E2E_DATABASE_URL=<disposable lyricscloud_test> pnpm test:e2e`: Chromium desktop/mobile 64개 전체 통과. 400개 section 문서를 5초 안에 열고 마지막 section 이동·focus 복원을 확인했다.
- 1440×1000 PC와 390×844 모바일을 실제 캡처해 목차·본문 최대 폭, 활성 표시, 모바일 sheet·하단 navigation 간 겹침과 가로 overflow를 확인한 뒤 임시 캡처를 제거했다.
- production build 비밀 누출 검사 통과.

## 복구와 Phase 4 인계

schema 변경은 없다. 문제가 생기면 이전 검증 SHA로 앱만 되돌릴 수 있다. Phase 4는 editor port의 현재 `value`, 문서 순서 `songForm.sections`, 각 section의 `from`·`to`, `selection`을 사용해 복사 문자열을 만든다. 저장 응답이나 초기 서버 값으로 복사 원본을 대체하지 않는다.
