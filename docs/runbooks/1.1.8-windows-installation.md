# 1.1.8 Windows 개발 빌드·설치 인계

1.1.8 Windows 앱은 **읽기·복사 전용**이다. 곡·가사·라임 노트·프롬프트의 서버 원문을 읽고 클립보드에 복사하지만 편집, 로컬 초안, Yjs update, 서버 쓰기를 제공하지 않는다.

## P3 개발 artifact

P3 후보 `b96200cb4adf967401df1e7bf3bab8ff853d709a`의 CI는 고정된 .NET 10.0.401과 Windows App SDK 2.4.0으로 x64 WinUI 앱을 빌드했고, `windows-x64-read-only-b96200cb4adf967401df1e7bf3bab8ff853d709a` artifact를 7일 보관한다. 이 artifact는 코드·XAML·의존성 결합을 검토하기 위한 framework-dependent 개발 빌드이며 서명 installer나 정식 배포물로 표시하지 않는다. 실행 PC에는 지원되는 Windows와 Windows App Runtime 2.4가 필요하다.

정식 서명 전 개발 artifact를 일반 사용자에게 배포하거나 릴리스 서버의 다운로드 링크로 연결하지 않는다. P5는 승인된 publisher identity와 비공개 signing key, 신뢰 가능한 timestamp를 사용한 MSIX를 별도 생성해야 한다. 인증서·암호·token은 저장소나 CI log, artifact에 넣지 않는다.

## P5 설치·업데이트·제거 수용 순서

1. 같은 최종 source SHA의 x64 MSIX와 SBOM/provenance를 생성하고 서명한다.
2. 격리된 Windows 사용자에서 `Get-AuthenticodeSignature`의 `Status`와 signer subject가 승인값인지 확인한다.
3. 깨끗한 PC에서 `Add-AppxPackage`로 설치하고 시작 메뉴 실행, system-browser 로그인, 곡/가사·라임·프롬프트 읽기와 exact copy를 확인한다.
4. 같은 publisher/package identity의 이전 1.1.8 시험 패키지 위에 최종 패키지를 업데이트하고 계정·서버 origin 결합 저장소가 다른 origin으로 노출되지 않는지 확인한다.
5. 프로세스 강제 종료 뒤 다시 열어 만료되지 않은 같은 계정 session만 복원되고, 공유 회수·401/403/404에서 cache와 화면이 닫히는지 확인한다.
6. `Remove-AppxPackage`로 제거하고 재설치해 앱 제거 시 로컬 DPAPI token/cache가 복구 수단이 아님을 확인한다.

## 실제 Windows에서만 판정할 항목

GitHub Windows runner build나 정적 계약은 실제 UI 인수를 대신하지 않는다. Microsoft 한국어 IME, Tab/Shift+Tab/Enter/Escape, Alt+Shift+C, Narrator, high contrast, 200% scaling, 창 폭 720/900/1440, 다중 모니터와 다른 DPI 사이 이동, 실제 clipboard, system browser 취소/callback, DPAPI/프로세스 종료는 P4/P5의 실제 Windows 증거로만 PASS 처리한다.

서명 실패, publisher 불일치, update 중 package identity 변경, 원문 변형, 다른 origin/account token 노출, 쓰기 요청 발생 중 하나라도 관찰되면 배포를 중단한다. 설치 전 패키지와 기존 서버는 보존하고 원인을 수정한 새 SHA로 처음부터 검증한다.
