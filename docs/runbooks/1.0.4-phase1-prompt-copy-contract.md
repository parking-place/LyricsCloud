## 승인 계약

1. 문장형 표시 parser는 ASCII 마침표 `U+002E`가 나올 때마다 그 마침표까지를 하나의 span으로 반환하고, 마지막 미완성 구간도 그대로 반환한다. 빈 span을 임의 생성하지 않으며 모든 span의 `text`를 순서대로 연결하면 code unit까지 입력 raw와 같아야 한다. 이 기능은 문장 의미를 추론하지 않으므로 연속점·소수·URL도 같은 규칙을 적용한다.
2. 표시 span은 presentation projection일 뿐이다. PostgreSQL `sentence_text`, API `sentenceText/plainText`, Yjs `prompt-sentence`, 검색·revision·export·clipboard 원문을 바꾸거나 역직렬화 입력으로 사용하지 않는다.
3. 공통 prompt copy builder는 호출자가 복사하려는 최종 문자열을 한 번 받아 payload와 Unicode code point 수(`[...payload].length`) 및 `> 1000` 상태를 함께 반환한다. 공백·LF·CRLF·분해 한글·emoji도 최종 payload 그대로 센다.
4. 1,000자는 허용 상한이 아니라 안내 기준이다. 999·1000자는 경고하지 않고 1001자부터 경고하되 입력·저장·자동 clipboard·수동 복사를 모두 허용한다. 경고를 위해 trim, NFC/NFKC, 줄바꿈 변환, 축약을 하지 않는다.
5. 목록 버튼·모바일 길게 누르기·프롬프트 편집기·가사 자료 패널은 같은 builder 결과를 사용한다. clipboard 실패 시 수동 복사 textarea에도 동일 payload와 경고 상태를 전달한다. 최근 사용 기록 실패는 기존처럼 복사 성공과 분리한다.
6. 편집 중 표시는 현재 CRDT snapshot의 `plainText/sentenceText` 한 버전에서 계산한다. composition 중간 상태는 서버 저장을 새로 유발하지 않고, remote update 뒤에는 새 snapshot 전체로 한 번 재계산한다.

## 실패·권한·복구 입력표

| 입력·상황 | 현재 경로와 위험 | P2/P3 기대 결과 |
|---|---|---|
| `a.. b.`, `3.5`, `https://example.invalid/a.b`, 끝 미완성 | 목록은 현재 raw 한 단락만 표시한다. 의미 기반 분리 시 원문 손실 위험이 있다. | U+002E 포함 span의 연결이 raw와 정확히 같다. |
| 최종 payload 999/1000/1001 code point | 복사 경로별 공통 길이 판정이 없다. JS `length`는 surrogate pair에서 계약과 다르다. | 각각 999/1000/1001로 표시하고 1001만 비차단 경고한다. |
| emoji·분해 한글·CRLF | normalization이나 LF 변환 시 표시/복사 불일치 위험이 있다. | payload는 byte/code unit 변형 없이 같고 code point 규칙만 적용한다. |
| 목록·길게 누르기·편집기·자료 패널·수동 복사 | 현재 각 컴포넌트가 `copyText`를 직접 호출한다. | 모든 경로의 payload·길이·경고 판정이 같다. |
| clipboard 권한 거부 | `CopyFeedback`가 수동 textarea를 연다. | 원문 전체와 초과 안내를 유지하고 저장/편집 상태를 바꾸지 않는다. |
| 다른 계정·삭제·404 | API 소유권/404 경계는 기존 서버가 담당한다. | 타인 원문을 노출하지 않고 현재 편집 내용도 바꾸지 않는다. |
| 두 탭·offline·재접속·IME | CRDT snapshot과 local draft가 갱신될 수 있다. | copy 시점 최신 snapshot 하나로 계산하며 composition·cursor·undo를 변경하지 않는다. |

## 인터페이스·호환·되돌림

- P2는 domain에 순수 함수 `splitPromptSentenceDisplay`, `buildPromptCopyPayload`와 `PROMPT_COPY_WARNING_LIMIT`를 추가하고 package의 기존 barrel export를 통해 공개한다. 입력/반환은 JSON 저장 형식이 아니라 메모리 projection이다.
- 기존 prompt DB/API/CRDT schema와 `PROMPT_LIMITS.serialized`는 변경하지 않는다. 따라서 migration은 없고 구버전 클라이언트도 기존 raw를 계속 읽고 쓸 수 있다.
- P3 UI는 새 순수 projection만 제거하면 즉시 이전 단락 표시/복사 UX로 되돌릴 수 있다. rollback에서도 저장된 raw와 revision을 변환하지 않는다.
- 성능 기준은 최대 40,398 code point 입력에서 parser와 builder가 각각 선형 한 번 순회하고 render 중 중복 직렬화를 피하는 것이다. P2에서 반복 측정으로 확인한다.

## 검토 증거와 남은 작업

- 조사: `prompt-contract.ts`의 raw 검증/serializer, `crdt.ts`·`prompt-browser-sync.ts`의 snapshot projection, 네 UI copy 호출과 `CopyFeedback` fallback, 기존 prompt/editor E2E를 읽었다.
- P1에서 수용 결과를 실행 완료로 주장하지 않는다. P2가 실패 fixture·순수 함수·단위/성능 회귀, P3가 PC/mobile UI·접근성·IME, P4가 실제 DB·브라우저·권한·offline/restart 교차 검증, P5가 문서·최종 CI·동일 SHA 개발 인수를 담당한다.
- schema 추가 없음. `OPS-100-001` 운영 외부 백업 예외와 1.0.0 P6 review는 유지한다.
