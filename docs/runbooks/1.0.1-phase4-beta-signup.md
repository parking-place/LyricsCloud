# 1.0.1 Phase 4 — 베타 가입 인수 기록

## 구현 경계

- 기존 사용자의 `Google 계정으로 계속하기`와 신규 사용자의 `초대 코드로 가입`을 분리한다.
- 가입 전에 받은 이메일은 주장값일 뿐이다. OIDC 서명·issuer·audience·nonce·PKCE·만료와 `email_verified=true`를 통과한 이메일이 주장값과 일치할 때만 가입할 수 있다.
- 브라우저·URL·로그에는 원문 코드와 이메일을 넣지 않는다. OAuth cookie에는 암호화된 일회성 intent token만 보관하고 DB에는 환경·purpose가 분리된 HMAC/해시만 보관한다.
- 코드 소비, issuer+subject 접근권, 가입 intent 완료, 불변 redemption 영수증은 PostgreSQL 한 트랜잭션이다. 세션 응답이 유실돼도 다음 일반 로그인에서 이미 발급된 grant를 복구한다.
- bootstrap HMAC 허용 계정은 기존 로그인으로 복구할 수 있고, 철회 grant와 blocked 계정은 새 코드나 bootstrap으로 우회할 수 없다.
- 웹 런타임에는 코드 조회용 index key만 읽기 전용으로 제공한다. 코드 복호화 AEAD key와 관리자 권한은 제공하지 않는다.

## 실패와 재시도

| 상황 | 코드 소비 | grant | 사용자 안내 |
|---|---:|---:|---|
| OAuth 취소·provider 실패 | 없음 | 없음 | 코드가 사용되지 않았으며 다시 시작 가능 |
| 다른 Google 이메일 | 없음 | 없음 | 입력 이메일과 같은 계정으로 재시도 |
| 만료·폐기·선사용·다른 환경 코드 | 없음 | 없음 | 새 코드 확인 |
| 동일 코드 동시 callback | 승자 1건 | 승자 1건 | 나머지는 일반 실패 |
| grant commit 뒤 응답 유실 | 1건 | 유지 | 일반 로그인으로 복구 |
| principal 24시간 실패 budget 초과 | 없음 | 없음 | 대기 후 재시도 |

가입 POST는 정확한 same-origin `Origin`, 4 KiB body 상한, JSON allowlist, IP token bucket을 적용한다. preflight는 코드 존재 여부를 조회하지 않아 코드 유효성 oracle을 만들지 않는다.

## 개발 서버와 외부 인수

구현 commit push 뒤 같은 SHA를 개발 서버에 배포하고 schema `0901_beta_signup.sql`, 네 서비스 health, 공개 HTTPS live/ready/auth/signup preflight/OAuth 시작을 확인한다. 실제 Google 신규 계정 callback은 운영자 상호작용이 필요한 별도 실환경 증거로 구분한다. 완료 SHA와 결과는 배포 뒤 이 문서와 STATUS에 추가한다.

## rollback

앱 rollback은 이전 immutable SHA로 되돌린다. `0901` DB rollback은 `code_id/code_epoch`가 비어 있는 가입 intent가 하나라도 있으면 중단한다. 원문 코드, 기존 grant·receipt, 사용자 자료를 자동 삭제하지 않으며 Docker volume을 삭제하지 않는다.
