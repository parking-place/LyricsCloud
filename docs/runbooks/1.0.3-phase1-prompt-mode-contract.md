## 승인된 저장·API 계약

- 신규 migration은 `1000_prompt_modes.sql` 하나다. 기존 migration은 수정하지 않는다.
- `prompts.mode`는 `tags | sentence`, 기본값은 `tags`다. 기존 `plain_text`와 `prompt_tokens`는 태그 표현을 그대로 보존하고 `sentence_text`는 문장 원문을 별도로 보존한다.
- `templates`에도 `prompt_mode`와 `prompt_text`를 추가한다. 가사 템플릿 및 기존 프롬프트 템플릿은 각각 기존 의미와 `tags` 기본값을 유지한다.
- API record의 `mode`, `sentenceText`, `plainText`를 구분한다. `plainText`는 현재 mode의 공통 copy payload이고, 문장형 raw에는 trim·NFC/NFKC·쉼표 분해·dedup을 적용하지 않는다.
- 새 create payload는 `mode`를 명시하고 `tags`면 `tokens`, `sentence`면 `sentenceText`를 사용한다. mode를 생략한 1.0.2 payload는 `tags`로 읽는다.
- 기존 mode 전환은 두 표현을 모두 보존하는 metadata 변경이다. 구조 변환은 원문·미리보기·확인·revision checkpoint가 있는 명시 동작으로만 제공한다.
- 검색은 제목, 태그 projection, 문장 raw를 모두 대상으로 한다. raw export, 읽기 쉬운 export, 복제, 템플릿 적용, revision JSON은 mode와 두 표현을 함께 보존한다.

## CRDT와 구버전 차단

- prompt document는 `prompt-title`, `prompt-mode`, `prompt-tokens`, `prompt-sentence` 공유 타입을 사용한다. mode 변경과 필요한 초기 표현 쓰기는 단일 Yjs transaction이다.
- projection은 current mode에 해당하는 표현만 active copy로 선택한다. 다른 mode의 동시·지연 update는 보존되더라도 현재 mode의 body와 섞지 않는다.
- 브라우저는 문장형 편집 연결에 `X-LyricsCloud-Prompt-Capability: prompt-mode-v1`를 보낸다. collaboration service는 문장형 문서에 이 capability가 없으면 `409 PROMPT_MODE_CAPABILITY_REQUIRED`를 반환한다.
- 1.0.2 클라이언트의 목록·GET·export 호환 읽기는 유지한다. 알 수 없는 mode를 `tags`로 강등해 쓰거나 sentence raw를 빈 token projection으로 덮어쓰지 않는다.

## rollback

- 애플리케이션 우선 rollback은 1.0.2 이미지를 재기동한다. 새 열은 additive이며 기존 태그형 자료는 계속 읽을 수 있다.
- 1.0.2 애플리케이션은 문장형 편집 capability가 없어 문장형 쓰기가 차단된다. 따라서 rollback 동안 문장형은 읽기/복사만 허용하고 재편집은 1.0.3 복구 후 수행한다.
- schema rollback은 모든 문장형·문장 템플릿이 0건임을 검사한 뒤에만 `1000_prompt_modes.sql` rollback을 허용한다. 사용자 raw가 있으면 중단한다.
