# 0.2.0 Phase 3 검증 기록

## 검증 대상

- `/songs` PC 2열·모바일 1열 카드 목록과 공통 인증 셸
- 300ms 지연 검색과 취소·요청 순번 기반 최신 응답 보호
- 상태 필터, 다섯 정렬, URL query 복원, cursor 추가 로드
- owner 범위 favorite·pin 갱신, 카드 열기와 내부 행동 분리
- 0곡·검색 결과 없음·재시도 오류, 320px·큰 글자 대응

## 로컬 검증

2026-09-05에 격리된 `lyricscloud_test` PostgreSQL과 Docker Node 24 환경에서 실행했다.

```text
pnpm check
pnpm test
NODE_ENV=production pnpm build
pnpm exec playwright test tests/e2e/songs-ui.spec.ts
pnpm exec playwright test tests/e2e/auth-ui.spec.ts --update-snapshots
```

- architecture boundary와 전체 TypeScript 검사 통과
- unit·DB integration 57개 전체 통과
- production build와 `/songs`, `/songs/new` 동적 route 생성 통과
- 곡 목록 desktop/mobile E2E 4개 통과
- 인증 셸 desktop/mobile 회귀 E2E 14개 통과
- 0곡 첫 CTA, 30곡 cursor, 한글 연속 검색, 상태·정렬 URL, 키보드 toggle·focus 검증
- 320px와 200% 글자 크기에서 주요 행동 접근 가능, 수평 overflow 없음
- build artifact secret scan 0건

다섯 정렬의 DB 순서와 owner A/B 격리는 Phase 2의 `songs.integration.test.ts`와 `song-api.spec.ts`를 그대로 회귀 기준으로 사용한다. 전체 DB integration·E2E·secret scan은 Phase 브랜치 필수 CI에서 다시 실행한다.

## 범위 경계

- 검색은 제목·설명·작업 메모만 대상으로 하며 가사 본문 검색을 표시하지 않는다.
- 연결 자료 필터와 가사·라임·프롬프트 빠른 추가는 표시하지 않는다.
- 새 곡 행동은 `/songs/new`에 연결했으며 완전한 입력 폼은 Phase 4 인계 대상이다.
