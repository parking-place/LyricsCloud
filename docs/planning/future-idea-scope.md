# 추가 아이디어 중복·범위 확인

## 무엇을 확인했나

추가 아이디어로 적혀 있던 300개를 [원래 요구사항 41개](../../0.Plans/2.Patch-phase/Requirements-Traceability.md), [로드맵](../../0.Plans/2.Patch-phase/ROADMAP.md), [세부 기능 계약](../../0.Plans/2.Patch-phase/contracts/EDITOR-COPY.md), [공유 계약](../../0.Plans/2.Patch-phase/contracts/SHARING.md), [네이티브 개발안](../../0.Plans/2.Patch-phase/contracts/DESIGN-NATIVE.md), [품질 기준](../../0.Plans/2.Patch-phase/QUALITY-GATES.md), [P6 인수 항목](../../0.Plans/2.Patch-phase/P6-AND-BUG-INTAKE.md)과 대조했다.

| 분류 | 개수 | 처리 |
|---|---:|---|
| 별도로 선택할 후보 | 129 | 쉬운 이름·설명·사용 예시로 작성 |
| 같은 기능의 설명 또는 세부 항목 | 84 | 다른 후보 하나에 합쳐 따로 세지 않음 |
| 기존·예정 범위와 겹치거나 필수 품질·개발 조건 | 87 | 선택 목록에서 제외하고 담당 계획에 남김 |
| 검토한 원래 항목 | 300 | 각 번호의 처리 결과를 아래 표에 기록 |

**기존 300개를 모두 서로 다른 신규 기능이라고 볼 수는 없다.** 87개 전부가 현재 코드에 구현됐다는 뜻도 아니다. 이미 요구한 기능, 필수 보존·보안 조건, 개발 검증 방법, 기존 계획과 경계가 겹치는 항목을 함께 포함한다. 경계가 모호하면 신규 기능 수에 넣지 않고 착수 전에 범위를 확인하도록 했다.

이것은 전달된 계획 문서의 수동 의미 검토다. 현시점의 원격 저장소 전체나 진행 중인 로컬 Codex 코드를 새로 감사한 결과가 아니다. 후보 129개도 실제 구현 전에 현재 코드와 다시 대조한다.

## 쉽게 읽는 문서와 검토 기록의 구분

후보 129개는 공개된 [Future_Feature.md](../../0.Plans/2.Patch-phase/Future_Feature.md)에 두고 다른 작업자가 갱신한다. Phase 완료 때 [검수 인수 절차](../../0.Plans/2.Patch-phase/FUTURE-INTAKE.md)에 따라 Git 변경을 한 번 대조한다. 이 문서는 번호가 어디로 갔는지 확인할 담당자용 기록이다. 제외한 번호에 다른 새 아이디어를 배정하지 않으며, 같은 목적의 설명을 합친 경우 연결된 번호를 남긴다. 저장·복구·권한 관련 필수 조건은 선택 목록에서 빠졌어도 작업 범위에서 사라지지 않는다.

예를 들어 FF-072의 미전송 초안 복구, FF-139의 업데이트 전 원문 보호, FF-142의 배포 전 검사, FF-151의 한글 회귀 자료는 별도로 고를 신기능이 아니다. FF-022의 이름 있는 태그 조합은 기존 프롬프트 템플릿과 구분되지 않는다. FF-008·187·206·207·208·293은 표현과 제목 후보를 모아 비교하는 하나의 선택 항목으로 묶었다.
