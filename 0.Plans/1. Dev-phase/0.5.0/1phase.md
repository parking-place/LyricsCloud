# 0.5.0 Phase 1 — 프롬프트 도메인과 순서형 토큰 계약

- 상태: **완료**
- 단계 목적: 쉼표 프롬프트를 손실 없이 편집·검색·복사할 수 있는 순서형 토큰 모델을 확정한다.

## 목표

프롬프트 제목과 순서 있는 토큰, 정규화된 중복 기준, 사용 이력, 핀·즐겨찾기, 곡 연결을 owner별로 안전하게 저장하고 CRDT 원본과 쉼표 평문 투영이 결정적으로 왕복하게 한다.

## 선행조건

- [0.3.1 릴리즈](../0.3.1/)의 owner 전용 CRDT·IndexedDB·평문 projector가 완료되어야 한다.
- [0.4.0 릴리즈](../0.4.0/)의 공통 자료 속성·곡 연결 패턴을 재사용할 수 있어야 한다.
- 토큰의 정규화·순서 의미는 이 Phase의 작업·fixture로 확정하고, 같은 owner의 동시 편집 저장 방식은 [아키텍처 ADR](../../../docs/adr/README.md)의 `ADR-0005`를 따르며 세부 패키지를 임의 선정하지 않는다.

- [x] **LC-050-P1-01** 프롬프트 제목·토큰·공통 속성·곡 연결 schema와 길이·개수 제한을 정의한다.
- [x] **LC-050-P1-02** 쉼표, 앞뒤 공백, 연속 쉼표, 빈 토큰과 토큰 내부 쉼표의 처리 규칙을 문서화한다.
- [x] **LC-050-P1-03** 표시 문자열을 바꾸지 않는 중복 비교용 Unicode·대소문자·공백 정규화 규칙을 구현한다.

- [x] **LC-050-P1-06** 자동완성용 owner별 토큰 사용 횟수·최근 사용 정보를 다른 사용자와 분리한다.
- [x] **LC-050-P1-07** 곡 연결·해제와 프롬프트 삭제를 구분하고 soft delete 자료를 후보에서 제외한다.
- [x] **LC-050-P1-08** 생성·복제·업데이트 재시도가 중복 프롬프트나 토큰을 만들지 않게 한다.

## 구체적 검증

1. 한글·영문·숫자·이모지·여분 공백·연속 쉼표가 섞인 문자열의 parse→serialize 기대값을 fixture로 고정한다.
2. 정규화 값만 같은 두 토큰이 중복으로 감지되지만 사용자가 정리하기 전 표시 값은 임의 변경되지 않는지 확인한다.
3. 같은 owner 두 기기에서 서로 다른 위치에 토큰을 추가·이동해 모든 sequence가 같은 순서로 수렴하는지 검사한다.
4. 다른 owner의 과거 토큰이 자동완성 count나 suggestion에 포함되지 않는지 테스트한다.
5. 프롬프트 연결 해제가 자료 본문과 다른 곡 연결을 삭제하지 않는지 확인한다.
