# 0.7.0 Phase 4 — 통합 즐겨찾기·핀과 목록 필터

- 상태: **대기**
- 단계 목적: 자주 쓰는 자료와 현재 집중 자료를 유형과 관계없이 빠르게 찾게 한다.

## 목표

곡, 가사, 라임 노트, 프롬프트의 즐겨찾기와 핀을 일관되게 저장·표시하고, 핀 순서를 접근 가능하게 조정하며, 통합 목록과 각 자료 목록에서 필터와 딥링크 상태를 유지한다.

## 선행조건

- [0.7.0 Phase 3](./3phase.md)의 통합 자료 표시와 딥링크 규약이 완료되어야 한다.
- 자료 공통 속성의 소유권·soft delete 제약이 DB에 적용되어 있어야 한다.
- 즐겨찾기와 핀의 제품 의미가 서로 다르다는 원칙을 유지해야 한다.

## 작업 체크리스트

- [ ] `LC-070-P4-01` 즐겨찾기와 핀의 정의·표시·정렬 규칙을 문서화한다.
- [ ] `LC-070-P4-02` 네 자료 유형에서 동일한 권한 검사를 거쳐 토글되는 데이터 작업을 구현한다.
- [ ] `LC-070-P4-03` 통합 즐겨찾기 화면에 자료 유형·소속 곡 필터와 일관된 카드/행 정보를 구현한다.
- [ ] `LC-070-P4-04` 통합 핀 영역에는 사용자별 수동 순서를 적용하고, 일반 자료 목록에는 핀 우선 뒤 사용자가 고른 정렬 기준을 적용한다.
- [ ] `LC-070-P4-05` 필터 값을 URL에 저장하고 잘못된 값은 안전한 기본값으로 정규화한다.
- [ ] `LC-070-P4-06` 휴지통 이동 시 통합 목록에서 즉시 숨기고 복원 시 기존 표시 속성을 보존한다.
- [ ] `LC-070-P4-07` 연속 토글과 느린 네트워크에서도 오래된 응답이 최신 상태를 되돌리지 않게 한다.
- [ ] `LC-070-P4-08` 아이콘에 텍스트 이름·키보드 초점·선택 상태를 제공한다.
- [ ] `LC-070-P4-09` 핀 순서를 drag와 `앞으로`·`뒤로` 버튼·키보드로 바꾸고 첫째·마지막 경계를 문장으로 알린다.

## 구체적 검증

1. 각 자료 유형을 즐겨찾기·핀 처리한 뒤 통합 목록과 원래 목록의 상태가 일치하는지 확인한다.
2. 다른 사용자의 자료 ID로 토글 요청을 보내도 행 수와 존재 여부가 노출되지 않는지 검사한다.
3. 빠르게 세 번 토글했을 때 마지막 사용자 의도가 서버·화면에 동일하게 남는지 확인한다.
4. 필터 URL을 새 탭과 모바일 뷰에서 열어 같은 결과가 표시되는지 E2E로 검증한다.
5. 키보드와 스크린 리더 이름으로 즐겨찾기 추가·해제를 구분할 수 있는지 확인한다.
6. PC drag와 모바일·키보드 이동 후 새 탭에서도 같은 핀 순서가 복원되고 동시 재정렬이 자료를 누락시키지 않는지 확인한다.

## 완료 조건

- [ ] 네 자료 유형의 즐겨찾기·핀이 한 규칙으로 동작한다.
- [ ] 필터·정렬·URL 복원 테스트가 통과한다.
- [ ] 삭제·복원과 느린 네트워크에서 표시 상태가 어긋나지 않는다.
- [ ] 즐겨찾기·핀 컨트롤이 키보드와 보조 기술에서 식별 가능하다.
- [ ] 핀 수동 순서가 기기 사이에 유지되고 drag 없이도 조정된다.
