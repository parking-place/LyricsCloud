# 0.7.0 Phase 3 — 최근 작업과 마지막 위치 복원

- 상태: **대기**
- 단계 목적: 중단한 작업을 자료와 편집 위치까지 빠르게 이어간다.

## 목표

자료 종류와 관계없는 최근 작업 목록을 제공하고, 가사 편집기의 마지막 커서·송폼·스크롤 위치를 기기 간에 무리 없이 복원한다.

## 선행조건

- [0.7.0 Phase 2](./2phase.md)의 자료 및 송폼 딥링크 규약이 완료되어야 한다.
- 기존 자동 저장·동기화 모델과 DEC-06의 확정된 병합 방식이 적용되어 있어야 한다.
- 사용자별 최근 상태를 저장하는 스키마는 승인된 인증/DB ADR을 따라야 한다.

## 포함 범위

- 자료 유형 통합 최근 작업 목록
- `updated_at`과 `last_opened_at`의 분리
- 최근 작업 카드의 소속 곡과 본문과 분리된 작업 메모 문맥
- 가사별 마지막 커서, 송폼, 스크롤 위치의 제한적 저장
- 삭제·권한 변경·문서 단축에 안전한 위치 복원
- PC와 모바일 간 이어쓰기

## 제외 범위

- 사용자 행동 분석용 상세 열람 로그
- 키 입력마다 서버에 위치를 전송하는 방식
- 다른 사용자와 최근 작업을 공유하는 기능

## 작업 체크리스트

- [ ] `LC-070-P3-01` 최근 수정과 최근 열람의 의미·정렬 우선순위를 문서화한다.
- [ ] `LC-070-P3-02` 사용자·자료별 마지막 열람 위치를 저장하는 무결성 제약을 구현한다.
- [ ] `LC-070-P3-03` 커서·송폼·스크롤 갱신을 지연·병합해 불필요한 DB 쓰기를 제한한다.
- [ ] `LC-070-P3-04` 최근 작업 목록에서 자료 유형, 제목, 소속 곡, 시각을 일관되게 표시한다.
- [ ] `LC-070-P3-05` 휴지통 자료와 접근 불가능한 자료가 최근 목록에서 제외되게 한다.
- [ ] `LC-070-P3-06` 본문 변경으로 저장된 위치가 범위를 벗어나면 가장 가까운 유효 위치로 복원한다.
- [ ] `LC-070-P3-07` 모바일에서 저장한 위치를 PC에서 열 때 송폼 우선으로 자연스럽게 복원한다.
- [ ] `LC-070-P3-08` 위치 정보가 오류·성능 로그나 분석 이벤트에 본문과 함께 기록되지 않게 한다.
- [ ] `LC-070-P3-09` 최근 작업 카드에 자료 유형·소속 곡·작업 메모 여부를 혼동 없이 표시하되 가사 본문과 메모를 섞지 않는다.

## 구체적 검증

1. 동일 자료를 단순 열람했을 때 본문 `updated_at`은 바뀌지 않고 `last_opened_at`만 갱신되는지 확인한다.
2. 가사를 줄인 뒤 과거 커서 위치로 진입해도 예외 없이 유효한 위치가 선택되는지 확인한다.
3. 휴지통 이동·복원 전후 최근 목록의 노출 규칙을 통합 테스트한다.
4. 한 기기에서 Hook 위치를 저장하고 다른 뷰포트의 기기에서 해당 송폼으로 복원되는지 E2E로 확인한다.
5. 빠른 커서 이동 100회가 약속한 최대 횟수 이내의 서버 쓰기로 합쳐지는지 측정한다.
6. 같은 제목의 가사·프롬프트·메모가 있을 때 유형과 소속 곡을 올바르게 구분해 여는지 확인한다.

## 완료 조건

- [ ] 최근 열람과 최근 수정이 데이터·화면에서 구분된다.
- [ ] 마지막 위치 복원이 잘못된 커서나 다른 사용자의 위치를 노출하지 않는다.
- [ ] PC·모바일 이어쓰기와 삭제 자료 제외 테스트가 통과한다.
- [ ] 위치 저장이 편집 입력이나 자동 저장 지연을 체감 가능하게 늘리지 않는다.
