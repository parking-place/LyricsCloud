# 0.7.0 Phase 1 — 통합 검색 기반과 데이터 경계

- 상태: **대기**
- 단계 목적: DEC-05-A에 맞는 사용자별 정확·부분 문자열 검색 기반을 만든다.

## 목표

곡, 가사, 라임 노트, 프롬프트를 하나의 검색 진입점에서 찾을 수 있도록 검색 계약, 정규화 규칙, PostgreSQL 인덱스와 사용자 격리 규칙을 확정한다.

## 선행조건

- 0.6.0까지 핵심 자료와 태그·연결 데이터가 마이그레이션으로 정의되어 있어야 한다.
- 인증된 사용자 식별 방식과 PostgreSQL 접근/RLS 방식은 [0.0.0 ADR 산출물](../0.0.0/)을 따른다.
- 외부 검색 저장소는 사용하지 않으며 DEC-05-A를 변경하려면 별도 결정 갱신이 필요하다.

## 포함 범위

- 곡 제목, 가사 제목·본문, 라임 노트 제목·본문·태그, 프롬프트 제목·태그 검색
- 원문과 분리된 검색용 정규화 값
- `pg_trgm` 기반 정확·부분 문자열 검색과 GIN/GiST 인덱스
- 소유자 범위, 휴지통 제외, 결과 유형·식별자·점수 계약

## 제외 범위

- 오타 자동 교정, 한글 초성 검색, 형태소 분석
- Elasticsearch/OpenSearch 등 외부 검색 서비스
- 다른 사용자의 공개 자료나 공유 문서 검색

## 작업 체크리스트

- [ ] `LC-070-P1-01` 검색 대상 필드와 공통 결과 스키마를 문서화한다.
- [ ] `LC-070-P1-02` 원문을 보존한 채 Unicode·영문 대소문자·공백을 처리하는 검색 전용 정규화 함수를 만든다.
- [ ] `LC-070-P1-03` 선택된 PostgreSQL migration 도구로 `pg_trgm` 확장과 필요한 인덱스를 재현 가능하게 정의한다.
- [ ] `LC-070-P1-04` 검색 쿼리에 현재 소유자와 `deleted_at IS NULL` 조건을 강제한다.
- [ ] `LC-070-P1-05` `%`, `_`, 역슬래시와 따옴표가 정규식이나 와일드카드가 아닌 문자로 검색되게 한다.
- [ ] `LC-070-P1-06` 제목 완전 일치, 제목 시작, 제목 포함, 태그, 본문, 최근 수정 순의 기본 점수를 구현한다.
- [ ] `LC-070-P1-07` 한글·영문·숫자·송폼 태그·줄바꿈이 섞인 합성 테스트 자료를 준비한다.
- [ ] `LC-070-P1-08` 1~2글자 검색과 긴 가사 검색의 실행 계획·응답 시간을 측정해 기록한다.

## 구체적 검증

1. 서로 다른 두 사용자에게 같은 제목의 자료를 만들고 자신의 결과만 반환되는지 DB 통합 테스트로 확인한다.
2. 휴지통에 있는 자료가 제목·본문·태그 어느 경로에서도 노출되지 않는지 확인한다.
3. `FIRE`, `fire`, `Verse 1`, `100%`, `_air` 검색의 기대 결과를 고정 fixture로 검증한다.
4. migration을 빈 PostgreSQL에 적용한 뒤 되돌리고 다시 적용해 확장·인덱스가 재현되는지 확인한다.
5. 한국어 1글자, 2글자, 일반 검색어의 `EXPLAIN ANALYZE` 결과를 산출물에 남긴다.

## 완료 조건

- [ ] 검색 API/함수의 입력·출력·정렬·페이지 규칙이 확정되었다.
- [ ] 교차 사용자 및 휴지통 자료 노출 테스트가 모두 통과한다.
- [ ] DEC-05-A 범위를 넘어선 검색 기능이 포함되지 않았다.
- [ ] 검색 migration과 성능 기준 기록이 코드 리뷰를 통과했다.
