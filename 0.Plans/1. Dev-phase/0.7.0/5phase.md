# 0.7.0 Phase 5 — 탐색 기능 통합 검증과 릴리즈

- 상태: **대기**
- 단계 목적: 10~12번 목업 범위의 탐색 기능을 하나의 안정된 릴리즈로 묶는다.

## 목표

통합 검색, 최근 작업, 마지막 위치, 즐겨찾기·핀, 필터와 딥링크를 실제 사용자 흐름으로 회귀 검증하고 0.7.0 릴리즈 증적을 남긴다.

## 선행조건

- [0.7.0 Phase 1](./1phase.md)부터 [Phase 4](./4phase.md)까지 완료되어야 한다.
- 선택된 자체 운영 환경에서 동일한 PostgreSQL 확장과 migration을 재현할 수 있어야 한다.
- 이 내부 마일스톤의 브랜치·PR 규칙은 [기여 가이드](../../../CONTRIBUTING.md)를 따르며, 1.0 RC 고유 동결·태그 정책은 이후 `OPS-0001`에서 확정한다.

- 공개 공유·추천·사용자 간 협업

- [ ] `LC-070-P5-01` Phase 1~4의 요구사항 ID와 테스트·산출물을 추적표로 연결한다.
- [ ] `LC-070-P5-02` 검색 → 가사 구간 → 편집 → 최근 작업 → 동일 위치 복귀 흐름을 자동화한다.
- [ ] `LC-070-P5-03` 즐겨찾기/핀 → 필터 URL → 새 기기 열기 흐름을 자동화한다.
- [ ] `LC-070-P5-04` 두 사용자와 휴지통 자료를 포함한 검색·최근·즐겨찾기 격리 회귀를 수행한다.
- [ ] `LC-070-P5-05` 합성 대량 데이터에서 검색과 통합 목록의 기준 응답 시간을 측정한다.
- [ ] `LC-070-P5-06` PC·모바일의 로딩·빈 결과·실패·재시도 화면을 시각 점검한다.
- [ ] `LC-070-P5-07` migration을 신규 DB와 이전 버전 DB 양쪽에 적용해 결과를 기록한다.
- [ ] `LC-070-P5-08` 변경 기록과 [상태표](../STATUS.md)의 0.7.0 진행 상태를 갱신할 준비를 한다.

## 구체적 검증

1. CI의 단위·DB·브라우저 테스트 전체를 깨끗한 환경에서 실행한다.
2. 검색 결과 수, 정렬, 딥링크가 새로고침과 재로그인 후에도 동일한지 확인한다.
3. 모바일 느린 네트워크 조건에서 중복 결과나 오래된 상태가 나타나지 않는지 검사한다.
4. 검색·목록 응답 시간과 DB 실행 계획의 기준값을 릴리즈 증적에 기록한다.
5. 0.6.0 데이터의 migration 이후 검색 인덱스 누락 여부를 표본 검사한다.

## 완료 조건

- [ ] 0.7.0의 모든 고유 ID가 구현·테스트·문서 중 하나 이상의 증적과 연결된다.
- [ ] 사용자 격리와 삭제 자료 제외 회귀가 전부 통과한다.
- [ ] 10~12번 목업의 PC·모바일 핵심 상태가 확인되었다.
- [ ] 치명적 또는 데이터 손실 결함 없이 0.8.0 개발을 시작할 수 있다.
