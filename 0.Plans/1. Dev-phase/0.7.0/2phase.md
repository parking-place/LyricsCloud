# 0.7.0 Phase 2 — 검색 화면, 필터와 딥링크

- 상태: **대기**
- 단계 목적: 검색 결과에서 원하는 자료와 가사 구간까지 안전하게 이동하게 한다.

## 목표

통합 검색 목업을 PC와 모바일에 적용하고, 자료 유형 필터·검색 상태·키보드 이동·가사 송폼 위치 딥링크를 하나의 사용자 흐름으로 완성한다.

## 선행조건

- [0.7.0 Phase 1](./1phase.md)의 검색 결과 계약과 사용자 격리 테스트가 완료되어야 한다.
- 애플리케이션 라우팅과 목록 복귀 방식은 [0.1.0 Phase 4](../0.1.0/4phase.md)의 공통 셸과 [0.2.0 Phase 3](../0.2.0/3phase.md)의 URL 상태 계약을 재사용한다.
- 존재하지 않거나 삭제된 대상의 딥링크 처리 규칙이 합의되어야 한다.

## 포함 범위

- 통합 검색 입력, 로딩, 결과 없음, 실패, 재시도 상태
- 전체·곡·가사·라임 노트·프롬프트 유형 필터
- 결과 유형, 제목, 안전한 스니펫, 최근 수정 시각 표시
- 검색 결과에서 자료 및 특정 송폼 위치로 이동하는 딥링크
- 현재 사용자만 볼 수 있는 최근 검색어의 열기·개별 삭제·전체 지우기
- PC 키보드와 모바일 터치 탐색

## 제외 범위

- 초성·형태소·오타 교정 UI
- 서버 추천·인기 검색어, 다른 사용자 자료
- 서버가 생성한 HTML 스니펫을 그대로 렌더링하는 방식

## 작업 체크리스트

- [ ] `LC-070-P2-01` 목업의 PC·모바일 검색 레이아웃을 공통 컴포넌트로 구현한다.
- [ ] `LC-070-P2-02` 입력 디바운스, 요청 취소와 오래된 응답 무시 규칙을 구현한다.
- [ ] `LC-070-P2-03` 자료 유형 필터를 URL 상태와 동기화해 새로고침·뒤로 가기에도 유지한다.
- [ ] `LC-070-P2-04` 검색어와 필터를 안전하게 직렬화한 딥링크 규칙을 정의한다.
- [ ] `LC-070-P2-05` 가사 결과가 송폼 정보를 가질 때 편집기의 해당 위치로 이동하고 초점을 복원한다.
- [ ] `LC-070-P2-06` 스니펫은 이스케이프된 텍스트 노드로 표시하고 일치 범위만 안전하게 강조한다.
- [ ] `LC-070-P2-07` 키보드 위/아래, Enter, Escape와 포커스 이동을 브라우저 기본 단축키와 충돌하지 않게 구현한다.
- [ ] `LC-070-P2-08` 삭제·권한 없음·잘못된 ID 딥링크에 동일한 일반 오류 안내를 제공한다.
- [ ] `LC-070-P2-09` 검색 전 화면에 사용자별 최근 검색어를 제한된 개수로 표시하고 다시 검색·개별 삭제·전체 지우기를 제공한다.

## 구체적 검증

1. 느린 첫 요청 뒤 빠른 두 번째 요청이 끝나도 화면이 이전 검색어 결과로 되돌아가지 않는지 확인한다.
2. 검색 결과의 `<script>`, 따옴표, 송폼 괄호가 실행되지 않고 문자로 표시되는지 검사한다.
3. 결과 선택 후 브라우저 뒤로 가기로 검색어·필터·스크롤 위치가 복원되는지 확인한다.
4. PC 키보드와 360px 모바일 화면에서 모든 결과 유형을 열 수 있는지 Playwright로 검증한다.
5. 삭제되었거나 다른 소유자의 URL을 직접 열어도 제목·존재 여부가 노출되지 않는지 확인한다.
6. 검색 전 PC·모바일 화면에서 최근 검색어를 다시 실행하고 지운 뒤 다른 기기·다른 사용자에게 노출되지 않는지 확인한다.

## 완료 조건

- [ ] 검색의 정상·빈 결과·로딩·실패 화면이 모두 구현되었다.
- [ ] 필터 및 자료/송폼 딥링크 E2E 테스트가 통과한다.
- [ ] 키보드만으로 검색하고 결과를 열고 돌아올 수 있다.
- [ ] 사용자 입력이나 검색 스니펫에서 HTML 실행 경로가 없다.
- [ ] 최근 검색어가 사용자별로 격리되고 사용자가 제거할 수 있다.

- 최근 검색어 저장·삭제 계약과 격리 테스트
