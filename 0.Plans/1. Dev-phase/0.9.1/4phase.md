# 0.9.1 Phase 4 — 오류·성능 관측과 본문 제거 검증

- 상태: **대기**
- 단계 목적: DEC-11-A 범위에서 문제를 발견하되 사용자 창작물을 관측 시스템에 보내지 않는다.

## 목표

승인된 관측 도구에 오류·성능·운영 지표만 기록하고, 가사·라임·프롬프트·검색어·Google 토큰·내보내기 내용이 로그·trace·event에 포함되지 않게 한다.

## 선행조건

- [0.9.1 Phase 3](./3phase.md)의 성능 지표와 오류 분류가 확정되어야 한다.
- 관측 도구·보존 위치·지역은 [0.0.0 ADR 산출물](../0.0.0/)에서 선택되어야 하며 이 문서가 임의 결정하지 않는다.
- DEC-11-A에 따라 사용자 행동 분석은 포함하지 않는다.

## 포함 범위

- 구조화 오류 코드, 처리 시간, 성공/실패 수와 시스템 자원
- 자동 저장 실패·충돌 수, 검색 지연, purge/backup 작업 상태
- 요청 ID·비가역 익명 운영 식별자와 환경/버전
- 수집 전 allowlist·redaction·길이 제한
- 경보와 운영 runbook 연결

## 제외 범위

- 페이지뷰·클릭·검색어 등 사용자 행동 분석
- 가사, 제목, 메모, 라임, 프롬프트, 템플릿 본문
- OAuth code/access/refresh token, cookie, Authorization 헤더
- 관측 공급자·저장 지역의 신규 선택

## 작업 체크리스트

- [ ] `LC-091-P4-01` 허용 관측 필드와 금지 필드를 데이터 분류표로 정의한다.
- [ ] `LC-091-P4-02` 클라이언트·서버·DB 작업에 동일한 구조화 오류 코드와 요청 상관 ID를 적용한다.
- [ ] `LC-091-P4-03` 수집 SDK/transport 앞에 allowlist와 재귀적 redaction을 적용한다.
- [ ] `LC-091-P4-04` URL, query, breadcrumb, DOM snapshot, request/response body의 기본 수집을 차단한다.
- [ ] `LC-091-P4-05` 저장 실패율·검색 p95·purge/backup 실패·서비스 상태 경보를 승인 임계값에 연결한다.
- [ ] `LC-091-P4-06` 각 경보에 확인 순서, 사용자 영향, 완화와 escalation runbook 링크를 둔다.
- [ ] `LC-091-P4-07` 운영 대시보드가 오류·성능만 보여주고 개인별 창작 행동을 재구성할 수 없게 한다.
- [ ] `LC-091-P4-08` 로그 보존·접근 권한·삭제 정책을 ADR 결과와 운영 문서에 기록한다.

## 구체적 검증

1. 고유한 canary 문자열을 제목·본문·검색어·토큰 자리에 넣고 관측 수집 전체에서 검색 결과가 0인지 검사한다.
2. 오류 객체의 중첩 cause, stack context, URL과 네트워크 payload에서도 canary가 제거되는지 확인한다.
3. 자동 저장 실패, 검색 지연, purge 실패를 주입해 대응 경보와 runbook 링크가 생성되는지 검증한다.
4. 관측 도구가 중단돼도 편집·저장·로그인 기능이 계속 동작하는지 확인한다.
5. 운영 권한이 없는 계정이 로그·대시보드에 접근할 수 없는지 검사한다.

## 완료 조건

- [ ] 오류·성능 정보만 수집되며 행동 분석 이벤트가 없다.
- [ ] 창작물·검색어·인증 비밀 canary가 모든 관측 경로에서 0건이다.
- [ ] 핵심 실패 경보가 재현되고 runbook으로 연결된다.
- [ ] 관측 시스템 장애가 핵심 제품 흐름을 막지 않는다.
