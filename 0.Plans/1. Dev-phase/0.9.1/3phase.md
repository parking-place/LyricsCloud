# 0.9.1 Phase 3 — 성능 기준과 전체 회귀

- 상태: **대기**
- 단계 목적: 실제 자체 운영 기준 환경에서 핵심 흐름의 응답성과 안정성을 수치로 검증한다.

## 목표

대표 데이터 규모와 네트워크 조건에서 화면 로드, 검색, 자동 저장, 편집, 내보내기와 purge를 측정하고 전체 단위·DB·통합·브라우저 회귀를 고정한다.

## 선행조건

- [0.9.1 Phase 2](./2phase.md)의 보안 수정이 병합되고 관련 회귀가 추가되어야 한다.
- 기준 서버 사양·DB 구성·동시 작업 수와 성능 budget은 [결정 권한표](../Decision-Ownership.md)의 `OPS-0003`으로 이 Phase에서 확정한다.
- 성능 자료는 실제 사용자 본문이 아닌 결정론적 합성 fixture로 생성한다.

## 포함 범위

- 기준 환경·데이터셋·성능 budget의 문서화
- 긴 가사 편집, 통합 검색, 목록/대시보드, 자동 저장·선택된 병합 방식
- 대량 내보내기, revision 정리, 휴지통/account purge
- 단위·DB·통합·E2E·시각 회귀 전체 실행
- 느린 쿼리와 메모리·CPU·DB 연결 분석

## 제외 범위

- 승인되지 않은 고가 인프라 증설로만 문제를 숨기는 방식
- 실제 창작물·운영 토큰을 사용하는 부하 시험
- DEC-05-B/C 검색 기능

## 작업 체크리스트

- [ ] `LC-091-P3-01` `OPS-0003`에 기준 장비, 컨테이너 제한, 데이터 건수·본문 길이와 동시 작업 수를 기록한다.
- [ ] `LC-091-P3-02` `OPS-0003`에 핵심 화면 로드·검색·저장·export의 p50/p95와 오류율 budget을 승인한다.
- [ ] `LC-091-P3-03` 10,000줄 합성 가사의 입력·송폼 이동·복사·revision 성능을 측정한다.
- [ ] `LC-091-P3-04` `pg_trgm` 검색을 1~2글자와 일반 검색어로 나눠 실행 계획과 p95를 기록한다.
- [ ] `LC-091-P3-05` 자동 저장 폭주, 재시도와 선택된 동시 편집 방식에서 DB 쓰기·충돌·메모리 사용을 측정한다.
- [ ] `LC-091-P3-06` 대량 export와 30일/7일 purge가 요청 처리와 DB 잠금에 미치는 영향을 검사한다.
- [ ] `LC-091-P3-07` 단위·DB·통합·E2E·시각 회귀를 한 RC pipeline에서 반복 실행 가능하게 한다.
- [ ] `LC-091-P3-08` 느린 쿼리·N+1·누수·불필요한 실시간 연결을 수정하고 전후 수치를 비교한다.

## 구체적 검증

1. 승인된 기준 장비에서 최소 세 번 반복해 p50/p95·오류율과 분산을 기록한다.
2. 검색과 저장의 목표값은 기준 데이터에서 각각 승인된 budget을 넘지 않는지 자동 판정한다.
3. 네트워크 지연·단절·서버 재시작 중 입력이 무음으로 사라지거나 중복되는지 확인한다.
4. 24시간에 준하는 반복 편집 시험 또는 가속 반복 시험으로 브라우저·서버 메모리 증가를 확인한다.
5. 전체 회귀를 깨끗한 DB migration 상태와 이전 버전 upgrade 상태 양쪽에서 실행한다.
6. 실패 테스트를 재실행으로 숨기지 않고 flaky 원인과 허용 정책을 기록한다.

## 완료 조건

- [ ] 승인된 기준 환경과 성능 budget이 재현 가능한 문서로 남았다.
- [ ] 핵심 p95·오류율이 budget을 만족하고 미해결 P0/P1 성능 결함이 없다.
- [ ] 전체 회귀가 깨끗한 환경에서 연속 통과한다.
- [ ] 실제 사용자 창작물이나 인증 정보가 성능 fixture·결과에 포함되지 않았다.
