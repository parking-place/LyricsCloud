# 0.9.1 Phase 1 — 기능 동결과 RC 추적 기준

- 상태: **대기**
- 단계 목적: 신규 기능을 멈추고 1.0 후보의 요구사항·결함·변경 경계를 고정한다.

## 목표

Sketch 49절의 1차 출시 범위와 15개 목업 README의 추가 제안을 구현·테스트·문서 증적에 연결하고, RC 기간의 P0/P1 기준과 변경 승인 절차를 확정한다.

## 선행조건

- 0.9.0의 15개 화면, PWA와 실기기 검증이 완료되어야 한다.
- 0.0.0~0.9.0의 Phase 산출물과 상태표가 최신이어야 한다.
- 릴리즈 브랜치·태그·승인 방식은 [결정 권한표](../Decision-Ownership.md)의 `OPS-0001`로 이 Phase에서 확정한다.

- [구현 기술 스택](../../Implementation-Stack.md) — 선택 전체, 테스트·배포 원칙

## 포함 범위

- Sketch 49절 전체 기능의 요구사항 추적
- 15개 화면 README의 추가 제안 추적
- 기능 동결, RC 변경 허용 기준과 결함 등급
- 알려진 제한·P2/P3 목록과 1.0 차단 여부
- 릴리즈 후보 식별자와 재현 가능한 변경 집합

## 제외 범위

- 새 제품 기능, UI 재설계, 선택되지 않은 DEC 대안
- 오타·초성·형태소 검색 추가
- 공개 공유, AI, 미디어, 결제, 네이티브 앱

## 작업 체크리스트

- [ ] `LC-091-P1-01` Sketch 49절의 각 글머리를 고유 추적 ID로 분해한다.
- [ ] `LC-091-P1-02` 15개 목업 README의 추가 제안을 추적표에 별도 행으로 등록한다.
- [ ] `LC-091-P1-03` 모든 추적 행을 구현 경로, 자동/수동 테스트와 문서 증적에 연결한다.
- [ ] `LC-091-P1-04` 미구현·부분 구현·검증 없음 항목을 1.0 차단 여부와 함께 표시한다.
- [ ] `LC-091-P1-05` P0를 데이터 손실·교차 사용자 노출·인증 우회·복원 불가·서비스 전체 불능으로 정의한다.
- [ ] `LC-091-P1-06` P1을 우회 없는 핵심 흐름 실패·무음 저장 충돌·주요 모바일 사용 불가·삭제/내보내기 오류로 정의한다.
- [ ] `LC-091-P1-07` `OPS-0001`에 RC 브랜치, 태그 후보와 허용 변경을 결함·보안·성능·문서 수정으로 제한하는 규칙을 기록한다.
- [ ] `LC-091-P1-08` `OPS-0001`에 모든 변경의 회귀 테스트·추적표 갱신·승인자와 1.0 태그 발행 절차를 문서화한다.

## 구체적 검증

1. Sketch 49절의 글머리 수와 추적표의 대응 행 수를 독립적으로 대조한다.
2. 15개 README를 순회해 추가 제안이 누락되지 않았는지 두 번째 검토자가 확인한다.
3. 추적 행에서 구현 또는 검증 증적으로 이동할 수 없는 orphan 항목을 0개로 만든다.
4. 대표 결함 사례를 P0~P3로 분류해 등급 기준이 일관된지 점검한다.
5. RC 기준 commit/image에서 전체 추적표가 다시 생성·검증되는지 확인한다.

## 완료 조건

- [ ] Sketch 49절과 모든 목업 추가 제안이 누락 없이 추적된다.
- [ ] 미검증·부분 구현 항목마다 책임자와 1.0 차단 여부가 있다.
- [ ] P0/P1 정의와 기능 동결 예외 절차가 승인되었다.
- [ ] 이후 새 기능은 1.0 범위에 무단 추가되지 않는다.

- RC 기능 동결 및 변경 승인 규칙
- 결함 등급 정의와 알려진 제한 목록
