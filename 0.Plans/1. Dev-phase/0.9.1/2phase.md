## 포함 범위

- Google OAuth PKCE/state/redirect와 초대 사용자 제한
- 세션 발급·갱신·로그아웃·탈퇴 즉시 차단

- XSS, CSRF/Origin, 입력 크기, 요청 빈도와 오류 정보 노출

- 추가 Google API 권한
- 도구가 정해지지 않은 외부 WAF·SIEM의 임의 도입

## 작업 체크리스트

- [ ] `LC-091-P2-01` OAuth callback, state, PKCE, redirect allowlist와 초대 제한을 위·변조 테스트한다.
- [ ] `LC-091-P2-02` 서로 다른 두 사용자로 모든 테이블·API·검색·딥링크의 읽기/쓰기/삭제 행렬을 실행한다.
- [ ] `LC-091-P2-03` 수정 기록, 최근 위치, export job, purge job 등 보조 자료까지 소유권 정책을 감사한다.
- [ ] `LC-091-P2-04` 제목·본문·태그·메모·파일명에서 저장/반사/DOM XSS payload를 검사한다.
- [ ] `LC-091-P2-05` 상태 변경 요청의 CSRF/Origin 방어와 인증된 응답의 no-store 정책을 검증한다.
- [ ] `LC-091-P2-06` 본문·검색·내보내기 크기와 인증·검색 요청 빈도 제한을 부하 조건에서 확인한다.
- [ ] `LC-091-P2-07` Docker 이미지가 비루트 사용자·최소 런타임·read-only 가능 경로·health check 원칙을 만족하게 한다.
- [ ] `LC-091-P2-08` repository, image layer, build log와 오류 응답에 secret/token/창작물이 없는지 검사한다.
- [ ] `LC-091-P2-09` 의존성·컨테이너 취약점 결과를 기록하고 P0/P1 또는 이용 가능한 심각 취약점을 해소한다.

## 구체적 검증

1. 사용자 A의 모든 ID를 사용자 B의 요청에 대입하는 자동화된 negative 권한 테스트를 실행한다.
2. 탈퇴 직후 기존 탭·refresh token·직접 API 요청의 접근이 차단되는지 확인한다.
3. `<script>`, 이벤트 속성, `javascript:` 문자열을 모든 출력 위치에서 문자로만 표시하는지 검사한다.
4. OAuth callback의 변조 state, 미허용 redirect, 중복 callback을 재현해 안전하게 실패하는지 확인한다.
5. 컨테이너 이미지와 Git 이력 대상 secret scan, dependency/image scan 결과를 증적으로 남긴다.
6. 인증·권한 오류가 대상 자료의 제목·유형·존재 여부를 누설하지 않는지 확인한다.

## 완료 조건

- [ ] 탈퇴 즉시 접근 차단과 7일 철회 정책이 보안 테스트를 통과한다.
- [ ] 보안 감사 범위·도구 버전·예외와 재검증 결과가 기록되었다.
