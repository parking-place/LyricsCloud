# 0.3.0 Phase 4 — 전체·송폼 복사와 집중 모드

- 상태: **대기**
- 버전 상태: [../STATUS.md](../STATUS.md)

## 목표

가사 전체 또는 하나 이상의 송폼 구간을 원문 순서대로 복사하고, 복사 권한 실패에도 사용자가 내용을 잃지 않게 한다. PC와 모바일에서 불필요한 UI를 숨기는 집중 모드를 함께 제공한다.

## 선행조건

- 0.0.0의 관련 ADR이 모두 Accepted 상태이며 이 Phase는 승인 결과를 따라야 한다.
- 0.3.0 Phase 3의 section 배열과 정확한 원문 offset이 준비되어야 한다.
- Clipboard 실패 시 수동 복사 대안의 UI 문구가 확정되어야 한다.

## 작업 체크리스트

- [ ] LC-030-P4-01 — 전체 복사가 저장된 이전 값이 아니라 현재 editor document 전체를 사용하게 한다.
- [ ] LC-030-P4-02 — section 복사 범위에 tag 줄과 다음 section 직전까지의 본문을 포함하는 계약을 고정한다.
- [ ] LC-030-P4-03 — 복수 section 선택은 문서 원래 순서로 정렬하고 구간 사이 줄바꿈을 예측 가능하게 만든다.
- [ ] LC-030-P4-04 — PC 목차에 키보드로 선택 가능한 checkbox 또는 동등한 다중 선택 수단을 제공한다.
- [ ] LC-030-P4-05 — 모바일 시트에서도 각 section 선택, 전체 선택 해제, 선택 개수, 복사 행동을 제공한다.
- [ ] LC-030-P4-06 — Clipboard 쓰기를 실제 click·key activation 안에서 호출하고 성공 뒤 대상명이 있는 toast를 표시한다.
- [ ] LC-030-P4-07 — Clipboard 거부·비지원 때 같은 문자열을 선택된 textarea 또는 dialog로 제공한다.
- [ ] LC-030-P4-08 — PC 집중 모드는 좌우 영역을 숨기되 editor 최대 행 폭과 상단 필수 상태를 유지한다.
- [ ] LC-030-P4-09 — 모바일 집중 상태는 본문을 우선하고 송폼·복사 도구를 닫을 수 있는 dock 또는 시트로 제공한다.
- [ ] LC-030-P4-10 — 전체 복사와 집중 모드 단축키가 브라우저·IME 기본 단축키와 충돌하지 않게 한다.

## 검증 방법

- CRLF 입력, LF 저장, 빈 줄, 반복 Hook, 마지막 section이 포함된 fixture의 복사 문자열을 문자 단위로 비교한다.
- Verse 2와 Hook 1처럼 화면 선택 순서가 문서 순서와 다른 경우 최종 복사 순서를 확인한다.
- Clipboard 허용·거부·API 없음 세 환경에서 성공 안내 또는 수동 대안이 나타나는지 확인한다.
- PC와 모바일에서 키보드·터치로 다중 선택과 복사를 수행한다.
- 집중 모드 진입·해제 뒤 cursor, selection, scroll, 미저장 입력이 유지되는지 확인한다.
- 1440px, 390×844, 화면 회전, 모바일 가상 키보드 상태에서 주요 도구가 가려지지 않는지 확인한다.

## 완료 조건

- [ ] 전체·단일·복수 송폼 복사 결과가 원문 계약과 일치한다.
- [ ] Clipboard 실패에도 수동으로 같은 내용을 복사할 수 있다.
- [ ] 성공 안내에 실제 복사 대상이 표시된다.
- [ ] PC·모바일 집중 모드가 입력 상태를 보존한다.
- [ ] 다중 선택을 포인터 없이 사용할 수 있다.
- [ ] Suno나 외부 서비스와 직접 연동하지 않는다.
