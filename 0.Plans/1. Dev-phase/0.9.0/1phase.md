# 0.9.0 Phase 1 — 15개 화면 완성도 감사와 추적 기준선

- 상태: **대기**
- 단계 목적: 기능 추가 전에 모든 목업과 구현 화면의 차이를 측정 가능한 목록으로 고정한다.

## 목표

15개 화면의 PC·모바일 레이아웃, 상태, 상호작용과 추가 제안을 전수 대조해 화면별 추적표와 공통 시각 기준을 만든다.

## 선행조건

- 0.8.0까지 기획된 기능과 데이터 수명주기가 통합 환경에서 동작해야 한다.
- 구현된 라우트·컴포넌트 목록과 목업 15개를 일대일로 대조할 수 있어야 한다.
- UI 프레임워크·자산 방식은 [0.0.0 ADR 산출물](../0.0.0/)을 따르며 이 단계에서 교체하지 않는다.

## 포함 범위

- 01~15 화면의 구현/미구현/차이/추가 제안 추적
- PC·모바일 기준 뷰포트와 공통 디자인 토큰 감사
- 정상·빈 상태·로딩·오류·저장·오프라인·권한 없음 상태 목록
- 공통 헤더, 좌측 메뉴, 우측 패널, 모바일 내비게이션 기준
- 시각 회귀 캡처 기준선

## 제외 범위

- 신규 제품 기능과 목업에 없는 대규모 재설계
- UI 프레임워크 교체
- 공개 공유·AI·미디어 업로드 추가

## 작업 체크리스트

- [ ] `LC-090-P1-01` 15개 화면 각각을 라우트·컴포넌트·기획 절·목업 README와 연결한다.
- [ ] `LC-090-P1-02` 각 README의 추가 제안을 별도 추적 행으로 분리해 누락 여부를 기록한다.
- [ ] `LC-090-P1-03` PC, 좁은 PC, 태블릿, 모바일의 기준 너비와 캡처 조건을 정한다.
- [ ] `LC-090-P1-04` 색상·간격·타이포그래피·모서리·그림자·포커스 토큰의 불일치를 조사한다.
- [ ] `LC-090-P1-05` 화면별 정상/로딩/빈/오류/저장/오프라인 상태 보유 여부를 표로 만든다.
- [ ] `LC-090-P1-06` 공통 내비게이션과 편집기 좌·우 패널의 데스크톱/모바일 차이를 정의한다.
- [ ] `LC-090-P1-07` 실제 구현 캡처를 기준선으로 생성하되 계정·가사 등 개인 데이터를 사용하지 않는다.
- [ ] `LC-090-P1-08` 차이를 P0/P1/P2/P3와 접근성·기능·시각 범주로 분류한다.

## 구체적 검증

1. 추적표에 01부터 15까지 누락 없이 한 행 이상 존재하는지 자동 또는 수동 교차 확인한다.
2. 모든 목업 README의 기능 및 추가 제안 항목 수와 추적표 항목 수를 대조한다.
3. 동일 합성 계정으로 네 기준 뷰포트의 캡처가 재현되는지 확인한다.
4. 화면 상태를 강제로 전환할 수 있는 fixture/테스트 경로가 있는지 검사한다.
5. 감사 과정에서 발견한 기능 결함과 시각 차이를 구분해 우선순위 오염을 방지한다.

## 완료 조건

- [ ] 15개 화면과 목업 추가 제안이 모두 추적표에 등록되었다.
- [ ] 네 가지 기준 뷰포트와 시각 회귀 기준선이 확정되었다.
- [ ] 미구현 상태와 접근성 결함이 우선순위별로 분류되었다.
- [ ] 0.9.0에서 다룰 범위가 기능 확장 없이 승인되었다.
