# 0.9.0 Phase 4 — 접근성·빈 화면·오류·저장 상태

- 상태: **대기**
- 단계 목적: 모든 화면의 비정상·과도 상태까지 이해 가능하고 조작 가능하게 만든다.

## 목표

15개 화면의 키보드, 초점, 이름, 대비, 동작 피드백을 점검하고 빈 화면·로딩·오류·저장·오프라인·충돌 상태를 공통 패턴으로 완성한다.

## 선행조건

- [0.9.0 Phase 3](./3phase.md)의 PWA와 저장 상태 인터페이스가 완료되어야 한다.
- [0.9.0 Phase 1](./1phase.md)의 상태 행렬과 접근성 결함이 최신 상태여야 한다.
- 오류 수집 도구는 아직 선택하지 않아도 되지만 본문 제거라는 DEC-11-A 원칙을 지켜야 한다.

## 포함 범위

- 키보드 순서, 초점 표시·복원, 스크린 리더 이름
- 밝음·어두움 테마 대비와 색 외 상태 표현
- 빈 화면의 다음 행동, 로딩 지연, 재시도 가능한 오류
- 자동 저장·로컬 임시 저장·실패·충돌·오프라인 상태
- reduced motion, 확대, 긴 한국어 텍스트

## 제외 범위

- 법적 접근성 인증 획득 자체
- 외부 분석 도구 선정
- 기능을 바꾸는 대규모 화면 재설계

## 작업 체크리스트

- [ ] `LC-090-P4-01` 15개 화면의 제목 구조, landmark, 레이블과 포커스 순서를 감사한다.
- [ ] `LC-090-P4-02` 아이콘 전용 버튼과 토글에 접근 가능한 이름·현재 상태·도움말을 제공한다.
- [ ] `LC-090-P4-03` 빈 화면마다 현재 맥락에 맞는 설명과 키보드 접근 가능한 다음 행동을 배치한다.
- [ ] `LC-090-P4-04` 로딩·오류·오프라인·권한 없음·삭제됨 상태를 서로 혼동하지 않게 구분한다.
- [ ] `LC-090-P4-05` 자동 저장 상태 변경을 방해되지 않는 live region과 시각 표시로 전달한다.
- [ ] `LC-090-P4-06` 오류 후 재시도해도 사용자가 입력한 본문과 커서가 유지되게 한다.
- [ ] `LC-090-P4-07` 색상 표시에 텍스트/아이콘 대안을 두고 양 테마의 대비를 검사한다.
- [ ] `LC-090-P4-08` 모달·시트·메뉴·도움말의 초점 trap, Escape, 닫힌 뒤 초점 복원을 통일한다.
- [ ] `LC-090-P4-09` 애니메이션을 reduced motion 환경에서 제거하거나 단순화한다.

## 구체적 검증

1. 자동 접근성 검사와 키보드 수동 검사를 15개 화면의 PC·모바일 기준에서 실행한다.
2. 네트워크 오류·인증 만료·저장 충돌·서버 500을 주입해 초안과 재시도 행동을 확인한다.
3. 200% 확대와 긴 한글 제목에서 내용이나 조작 요소가 잘리지 않는지 검사한다.
4. 밝음·어두움 테마에서 텍스트, 상태, 포커스, 비활성 컨트롤 대비를 측정한다.
5. 스크린 리더로 저장 상태가 과도하게 반복되지 않으면서 실패·충돌은 즉시 식별되는지 확인한다.

## 완료 조건

- [ ] 15개 화면의 자동 접근성 중대 오류가 없다.
- [ ] 모든 빈 화면과 실패 상태에 설명·다음 행동·재시도 경로가 있다.
- [ ] 저장·오프라인·충돌 상태가 본문 손실 없이 전달된다.
- [ ] 색, 포인터, hover만으로 전달되는 필수 정보나 행동이 없다.
