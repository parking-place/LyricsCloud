# 0.9.0 Phase 3 — 설치형 온라인 우선 PWA

- 상태: **대기**
- 단계 목적: DEC-04-A 범위 안에서 설치 가능하고 개인 데이터를 잘못 캐시하지 않는 PWA를 완성한다.

## 목표

웹 앱 매니페스트, 설치 진입, 정적 앱 셸 캐시와 안전한 업데이트 흐름을 제공하고, 연결 중단 시 IndexedDB 초안을 보존해 재연결 후 전송한다.

## 선행조건

- [0.9.0 Phase 2](./2phase.md)의 모바일 셸과 저장 상태 표시가 완료되어야 한다.
- 로컬 초안과 선택된 DEC-06 병합 모델의 source of truth가 확정되어야 한다.
- 공개 origin, TLS, 프록시와 캐시 헤더 방식은 [0.0.0 ADR 산출물](../0.0.0/)을 따르며 여기서 공급자를 선택하지 않는다.

## 포함 범위

- 설치 가능한 manifest, 아이콘, 이름, 시작 URL과 표시 모드
- 해시된 정적 앱 셸 자원만을 대상으로 한 캐시
- 인증 HTML·API·가사·노트·프롬프트 응답의 네트워크 우선/비캐시
- 온라인·오프라인·로컬 임시 저장·재전송 상태
- 미전송 초안이 있을 때 강제 reload를 막는 업데이트 안내
- 로그아웃·계정 전환·탈퇴 시 계정별 로컬 데이터 제거

## 제외 범위

- 모든 자료의 완전 오프라인 탐색·편집·삭제 동기화
- 푸시 알림과 백그라운드 주기 동기화 보장
- 인증된 응답을 Cache Storage에 장기 저장하는 방식

## 작업 체크리스트

- [ ] `LC-090-P3-01` manifest 필수 항목과 각 크기 아이콘을 설치 검사 기준에 맞춘다.
- [ ] `LC-090-P3-02` 서비스 워커 precache 대상을 빌드 정적 자산 allowlist로 제한한다.
- [ ] `LC-090-P3-03` 인증 페이지·API·사용자 콘텐츠 응답에 private/no-store 정책과 캐시 제외 테스트를 적용한다.
- [ ] `LC-090-P3-04` 0.3.1에서 만든 계정별 IndexedDB schema와 재시도 큐를 PWA 업데이트 전후에 호환되게 migration하고 구버전 복구를 검증한다.
- [ ] `LC-090-P3-05` 0.3.1의 재연결·중복 방지·CRDT 병합 로직을 service worker가 있는 cold start에서도 그대로 사용한다.
- [ ] `LC-090-P3-06` 새 서비스 워커가 준비돼도 dirty 초안이 있으면 사용자 승인 전 활성 reload를 하지 않는다.
- [ ] `LC-090-P3-07` 로그아웃·계정 전환·탈퇴 뒤 IndexedDB와 개인화 캐시가 제거되는지 보장한다.
- [ ] `LC-090-P3-08` 설치 불가 브라우저에서도 일반 반응형 웹 기능이 모두 유지되게 한다.

## 구체적 검증

1. 브라우저 PWA 검사로 manifest, 아이콘, service worker와 HTTPS 조건을 확인한다.
2. Cache Storage를 열어 인증 HTML·JSON·창작물 문자열이 존재하지 않는지 자동 검사한다.
3. 오프라인에서 가사를 입력하고 브라우저를 종료·재실행한 뒤 로컬 상태와 재전송 결과를 검증한다.
4. 전송 응답을 잃은 상황을 재현해 같은 자료가 두 번 생성되지 않는지 확인한다.
5. 미전송 초안 상태에서 새 배포를 감지해도 내용이 유지되고 승인 후에만 reload되는지 E2E로 검사한다.
6. 사용자 A 로그아웃 후 사용자 B 로그인 시 A의 제목·초안·최근 위치가 보이지 않는지 확인한다.

## 완료 조건

- [ ] 지원 브라우저에서 설치 가능하고 미지원 환경에서 웹 기능이 저하되지 않는다.
- [ ] 앱 셸 외 인증·창작물 응답이 서비스 워커 캐시에 저장되지 않는다.
- [ ] 오프라인 초안·재연결·중복 방지·업데이트 테스트가 통과한다.
- [ ] 로그아웃·계정 전환·탈퇴 시 로컬 개인 데이터가 제거된다.
