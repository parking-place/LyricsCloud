# 0.4.0 Phase 5 — 라임 노트 통합 검증과 릴리즈

- 상태: **진행 중**
- 단계 목적: 06~07번 목업의 라임 보관·편집·재사용 흐름을 안정된 릴리즈로 묶는다.

## 목표

라임 노트 생성, CRDT 편집, 태그·필터·검색, 전체/선택 복사, 핀·즐겨찾기·색상, 곡 연결을 PC·모바일과 동일 owner 다중 기기 조건에서 회귀 검증한다.

## 선행조건

- [0.4.0 Phase 1](./1phase.md)부터 [Phase 4](./4phase.md)까지 완료되어야 한다.
- 로컬 동기화 서버와 PostgreSQL은 [0.0.0 ADR 산출물](../0.0.0/)에 따라 깨끗한 환경에서 재현 가능해야 한다.
- 실제 가사 cursor 삽입은 0.6.0 인계 범위임을 확인해야 한다.

## 작업 체크리스트

- [ ] **LC-040-P5-01** Phase 1~4의 고유 ID를 구현·테스트·문서 증적과 연결한다.
- [ ] **LC-040-P5-02** 새 노트 → 편집 → 태그 → 곡 연결 → 목록 필터 → 복사 흐름을 PC·모바일로 자동화한다.
- [ ] **LC-040-P5-03** 두 탭·두 기기의 제목/본문 동시 편집과 오프라인 복구 회귀를 수행한다.
- [ ] **LC-040-P5-04** 핀·별·색상 연속 변경과 느린 응답에서 최종 상태가 되돌아가지 않는지 확인한다.
- [ ] **LC-040-P5-05** 로딩·최초 빈 화면·무결과·저장 중·오프라인·오류·삭제 modal·clipboard 실패를 시각 점검한다.
- [ ] **LC-040-P5-06** 다른 owner와 휴지통 자료가 목록·검색·태그 count·곡 연결에서 노출되지 않는지 검사한다.
- [ ] **LC-040-P5-07** 키보드·스크린 리더·모바일 touch로 모든 핵심 행동에 접근 가능한지 확인한다.
- [ ] **LC-040-P5-08** 변경 기록과 [상태표](../STATUS.md)의 0.4.0 진행 상태를 갱신할 준비를 한다.

## 구체적 검증

1. 깨끗한 계정의 빈 화면에서 첫 노트를 만들고 목록으로 돌아와 다시 편집하는 전체 흐름을 확인한다.
2. 필터 결과 0건, 서버 오류, 재연결, 클립보드 거부 후에도 작성 내용과 filter 상태가 보존되는지 검사한다.
3. 모바일 긴 본문·태그 다수·가상 키보드에서 스크롤과 고정 행동이 겹치지 않는지 확인한다.
4. 같은 owner 두 기기에서 편집한 최종 CRDT, 평문 목록 preview와 수정 기록이 일치하는지 비교한다.
5. 다른 owner ID 조작과 연결 관계 조작이 내용·제목·존재 여부를 노출하지 않는지 테스트한다.

## 완료 조건

- [ ] 0.4.0의 모든 고유 ID가 증적과 연결된다.
- [ ] 06~07번 핵심 흐름과 미표현 상태가 PC·모바일에서 검증되었다.
- [ ] owner 격리와 동일 owner 자동 병합 회귀가 통과한다.
- [ ] 치명적 데이터 손실·복사·연결 결함이 없다.
- [ ] 0.5.0과 0.6.0 인계 계약이 문서화되었다.
