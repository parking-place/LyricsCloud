# 0.4.0 Phase 3 — 라임 노트 생성·편집과 저장 상태

- 상태: **대기**
- 단계 목적: 자유 형식 라임을 손실 없이 작성하고 표시 속성과 수정 기록을 관리하게 한다.

## 목표

07번 목업을 기준으로 신규·편집 모드의 제목과 자유 본문, 태그·핀·즐겨찾기·색상, 자동 저장, 수정 기록 진입과 삭제 확인을 PC와 모바일에 함께 구현한다.

## 선행조건

- [0.4.0 Phase 2](./2phase.md)의 목록 진입·복귀와 URL 상태가 완료되어야 한다.
- [0.3.1 릴리즈](../0.3.1/)의 CRDT, IndexedDB, 저장 상태, 수정 기록 어댑터를 재사용해야 한다.
- soft delete와 복원 의미는 [결정 권한표](../Decision-Ownership.md)의 `PROD-0010`을 따르고, 제목·본문 validation 문구와 경계값은 이 Phase의 작업·검증 산출물로 확정한다.

## 포함 범위

- 신규·수정 모드의 제목과 자유 형식 본문
- 자동 저장과 동일 owner 탭·기기 병합
- 태그, 핀, 즐겨찾기, 색상 편집
- 수정 기록 목록 진입·복원 결과 반영
- soft delete 확인과 목록 복귀

## 제외 범위

- 다른 사용자 공동 편집
- 독립 편집기에서 열린 가사의 cursor로 직접 삽입
- 라임 발음 자동 분석과 추천
- 휴지통 관리 화면

## 작업 체크리스트

- [ ] **LC-040-P3-01** 빈 신규 모드와 저장된 편집 모드의 초기화·취소·뒤로 가기 규칙을 구현한다.
- [ ] **LC-040-P3-02** 제목과 자유 본문을 CRDT transaction과 평문 projector에 연결한다.
- [ ] **LC-040-P3-03** 태그 추가·삭제, 핀·즐겨찾기·색상 변경을 본문 저장과 독립적으로 안전하게 처리한다.
- [ ] **LC-040-P3-04** 저장 중, 로컬 임시 저장, 동기화 중, 저장됨, 재시도 상태를 PC·모바일에 표시한다.
- [ ] **LC-040-P3-05** 제목 누락·길이 초과·빈 본문 허용 여부를 승인된 validation 문구로 처리한다.
- [ ] **LC-040-P3-06** 수정 기록 목록·미리보기·복원 후 현재 편집 상태가 갱신되게 한다.
- [ ] **LC-040-P3-07** 삭제 메뉴와 대상 이름을 포함한 확인 modal/sheet를 구현한다.
- [ ] **LC-040-P3-08** 모바일 가상 키보드가 열린 상태에서도 제목·본문과 하단 복사 행동이 가려지지 않게 한다.

## 구체적 검증

1. PC와 모바일에서 새 노트를 작성하고 오프라인 전환·강제 종료 뒤 내용과 저장 상태가 복구되는지 확인한다.
2. 같은 owner의 두 탭에서 제목과 본문을 동시에 바꿔 자동 병합되고 목록 평문도 최종 상태를 반영하는지 검사한다.
3. 제목 누락, 매우 긴 본문, 빈 줄, 한글 IME, 이모지, 대량 붙여넣기를 검증한다.
4. 수정 기록 복원 직전 상태가 보존되고 복원 후 다른 기기와 목록 미리보기가 수렴하는지 확인한다.
5. 삭제 취소·실행·실패 시 modal/sheet와 목록 상태가 실제 서버 결과와 일치하는지 테스트한다.
6. 모바일 키보드·화면 회전·긴 본문 스크롤 중 고정 행동 영역이 선택 텍스트를 가리지 않는지 시각 점검한다.

## 완료 조건

- [ ] 신규·편집·validation·삭제 흐름이 PC·모바일에서 완료된다.
- [ ] 라임 제목·본문이 0.3.1 동기화·수정 기록 규칙을 따른다.
- [ ] 모든 저장·오류 상태가 실제 데이터 상태와 일치한다.
- [ ] 긴 본문·IME·가상 키보드 회귀가 통과한다.
