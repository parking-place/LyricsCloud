# 0.3.1 Phase 1 — 동일 소유자 CRDT 동기화 계약

- 상태: **완료**
- 단계 목적: 여러 탭과 기기가 같은 창작물을 편집해도 자동 병합되는 소유자 전용 동기화 경계를 확정한다.

## 목표

0.0.0에서 승인된 ADR을 기준으로 CRDT 문서 식별자, 소유권 검증, 업데이트·스냅샷 계약과 평문 투영 경계를 정의한다. 이 버전의 자동 병합은 한 사용자의 여러 탭·기기에만 적용하며 여러 사용자의 공유·공동 편집으로 확장하지 않는다.

## 선행조건

- 0.3.0의 곡·가사 기본 편집 흐름과 순수 텍스트 저장 규칙이 완료되어야 한다.
- 인증, 자체 운영 서버·PostgreSQL, CRDT 엔진과 전송 방식은 [0.0.0 ADR 산출물](../0.0.0/)에서 승인되어야 한다.
- 세부 패키지나 네트워크 프로토콜은 승인된 ADR 없이 이 Phase에서 새로 확정하지 않는다.

## 포함 범위

- 동일 소유자의 탭·기기 사이 CRDT 자동 병합
- 문서 ID, 소유자 ID, 클라이언트·기기 세션, 업데이트 ID와 스냅샷 계약
- 서버 영속본, 클라이언트 로컬본, 검색용 UTF-8 평문 투영의 책임 분리
- 중복·순서 역전·재전송에 안전한 업데이트 처리 규칙
- 이후 가사 외 편집 자료가 재사용할 수 있는 동기화 어댑터 경계

## 제외 범위

- 다른 사용자 초대, 공유 링크, 역할·권한, 다중 사용자 공동 편집
- 댓글, 사용자별 커서·presence, 변경 작성자 표시
- CRDT 패키지나 협업 서버 제품의 임의 선정
- 수정 기록 화면과 비교·복원 UI

## 작업 체크리스트

- [x] **LC-031-P1-01** CRDT 문서, PostgreSQL 자료, 사용자 소유권 사이의 식별자 매핑을 문서화한다.
- [x] **LC-031-P1-02** 같은 owner만 문서 초기화·구독·업데이트·스냅샷 요청을 할 수 있는 권한 계약을 정의한다.
- [x] **LC-031-P1-03** 클라이언트 업데이트의 고유 ID와 중복 수신·재전송 처리 규칙을 정의한다.
- [x] **LC-031-P1-04** 순서가 바뀐 업데이트와 장시간 오프라인 업데이트의 병합 규칙을 고정한다.
- [x] **LC-031-P1-05** CRDT 원본에서 제목·본문을 UTF-8 평문으로 투영하는 결정적 변환 계약을 작성한다.
- [x] **LC-031-P1-06** 서버 재시작을 위한 스냅샷·증분 업데이트·압축 경계를 정의한다.
- [x] **LC-031-P1-07** 가사 편집기와 동기화 계층 사이 명령·이벤트·오류 인터페이스를 정의한다.
- [x] **LC-031-P1-08** 다른 사용자의 문서 ID 추측, 만료 세션, 삭제 문서 접근에 동일한 거부 규칙을 적용한다.

## 구체적 검증

1. 같은 owner의 두 클라이언트가 서로 다른 줄을 동시에 수정한 업데이트를 반대 순서로 적용해도 최종 상태가 같은지 확인한다.
2. 같은 업데이트를 세 번 전달해도 본문이 중복되거나 서버 로그가 무한 증가하지 않는지 검사한다.
3. 다른 owner가 문서 ID를 직접 요청할 때 존재 여부와 내용이 노출되지 않는지 권한 테스트한다.
4. CRDT 상태를 여러 번 평문으로 투영해 바이트 단위로 같은 제목·본문이 생성되는지 확인한다.
5. 서버 스냅샷만으로 재시작한 뒤 남은 증분 업데이트를 적용해 원래 상태를 복구하는 시험 절차를 작성한다.

## 완료 조건

- [x] 동일 소유자 자동 병합과 다중 사용자 공유 제외 경계가 명시되었다.
- [x] 업데이트 중복·역전·재전송의 기대 결과가 테스트 계약으로 고정되었다.
- [x] CRDT 원본과 평문 투영의 단일 책임자가 정해졌다.
- [x] 인증·서버·CRDT 세부 선택이 0.0.0 ADR과 충돌하지 않는다.
