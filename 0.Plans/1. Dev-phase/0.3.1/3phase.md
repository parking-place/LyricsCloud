# 0.3.1 Phase 3 — 동기화 서버 영속화와 평문 검색 투영

- 상태: **검토**
- 단계 목적: 자동 병합된 CRDT 상태를 서버 재시작 후에도 복구하고 검색 가능한 평문 읽기 모델로 투영한다.

## 목표

0.0.0 ADR에서 승인된 동기화 서버가 owner 인증을 거쳐 업데이트를 영속화하고, CRDT 제목·본문을 PostgreSQL의 최신 UTF-8 평문으로 일관되게 투영하도록 구현한다. 여러 사용자 공동 편집은 허용하지 않는다.

## 선행조건

- [0.3.1 Phase 2](./2phase.md)의 로컬 업데이트 큐와 상태 전이 테스트가 완료되어야 한다.
- 서버 런타임, 연결 방식, PostgreSQL 접근과 배포 단위는 [0.0.0 ADR 산출물](../0.0.0/)에서 승인되어야 한다.
- 문서별 owner와 삭제 상태를 검증할 수 있는 데이터 경계가 존재해야 한다.

## 포함 범위

- 인증된 동기화 연결과 문서 owner 검증
- 증분 업데이트·스냅샷의 내구성 저장과 재시작 복구
- 업데이트 수신 승인과 클라이언트 미전송 큐 제거 확인
- 제목·본문·수정 시각의 PostgreSQL 평문 투영
- 투영 지연·실패·재처리와 내용 없는 운영 지표

## 제외 범위

- 다른 owner의 동시 접속과 권한별 편집
- 전문·초성·형태소 검색과 통합 검색 화면
- 창작물 본문을 오류·성능 로그에 기록하는 기능
- 수정 기록 비교와 복원

## 작업 체크리스트

- [x] **LC-031-P3-01** 연결 수립과 갱신마다 owner·문서·삭제 상태를 검증하는 서버 경계를 구현한다.
- [x] **LC-031-P3-02** 업데이트 저장과 수신 확인이 재시도되어도 중복되지 않는 영속화 작업을 구현한다.
- [x] **LC-031-P3-03** 서버 재시작 시 최신 스냅샷과 후속 업데이트로 CRDT 상태를 복구한다.
- [x] **LC-031-P3-04** 안전한 임계값에서 업데이트를 새 스냅샷으로 압축하되 접속 중인 클라이언트의 기준점을 보존한다.
- [x] **LC-031-P3-05** CRDT 상태를 검색·목록용 제목과 본문 평문으로 결정적으로 투영한다.
- [x] **LC-031-P3-06** 평문 투영 실패를 재처리 가능하게 기록하고 마지막 성공 시각과 지연 상태를 노출한다.
- [x] **LC-031-P3-07** 삭제·복원된 문서와 만료 세션의 업데이트를 거부하거나 승인된 복원 흐름으로만 처리한다.
- [x] **LC-031-P3-08** 연결 수, 업데이트 지연, 재시도 수, 투영 지연만 관측하고 창작물 본문은 로그에서 제거한다.

## 구체적 검증

1. 서버 프로세스를 업데이트 수신 전·후·확인 전 세 지점에서 중단해도 재시작 후 본문이 손실되거나 중복되지 않는지 확인한다.
2. 같은 owner의 PC·모바일이 동시에 수정한 뒤 서버 CRDT와 양쪽 클라이언트가 같은 상태로 수렴하는지 검사한다.
3. 투영 작업을 의도적으로 실패시킨 뒤 재처리해 평문 제목·본문이 최종 CRDT와 같아지는지 확인한다.
4. 다른 owner, 만료 세션, 휴지통 문서 ID로 연결·업데이트를 요청해 동일하게 거부되는지 테스트한다.
5. 긴 한글 가사와 송폼 태그, 이모지, 줄바꿈을 투영한 뒤 원문 의미와 UTF-8 값이 보존되는지 비교한다.
6. 운영 로그와 오류 이벤트에 제목·본문·업데이트 payload가 포함되지 않는지 자동 검사한다.

## 완료 조건

- [x] 서버 재시작과 중복 재전송 뒤에도 모든 복제본이 수렴한다.
- [x] 평문 읽기 모델이 CRDT 최신 상태와 추적 가능한 시간 안에 일치한다.
- [x] 소유자·삭제·세션 경계 테스트가 모두 통과한다.
- [x] 서버와 투영기의 로그에 창작물 내용이 남지 않는다.
