# 0.3.1 Phase 4 — 수정 기록, 버전 비교와 비파괴 복원

- 상태: **대기**
- 단계 목적: 자동 병합 중에도 과거 표현을 안전하게 비교하고 현재 작업을 잃지 않은 채 복원한다.

## 목표

현재 CRDT 문서와 별개인 자동 수정 기록을 5분 간격과 중요 작업 전에 생성하고, 180일·항목당 200개 정책으로 관리한다. PC·모바일에서 기록을 비교·미리보기하고 복원할 때 현재 상태를 먼저 보존한 뒤 새 최신 상태로 적용한다.

## 선행조건

- [0.3.1 Phase 3](./3phase.md)의 서버 영속화와 평문 투영이 완료되어야 한다.
- 수정 기록 보존 정책은 [0.0.0 ADR 산출물](../0.0.0/)과 DEC-07-A 승인 내용을 따른다.
- 사용자가 만든 가사 버전과 시스템 수정 기록을 별도 자료로 취급해야 한다.

## 포함 범위

- 내용이 달라진 편집 자료의 5분 간격 자동 스냅샷
- 화면 이탈·복원·복제·대규모 붙여넣기 등 승인된 중요 작업 전 스냅샷
- 180일과 항목당 200개 한도의 정리 작업
- 현재본·가사 버전·수정 기록의 구분과 비교
- PC 나란히 비교, 모바일 전환/세로 비교, 비파괴 복원

## 제외 범위

- 여러 사용자별 작성자 추적과 승인 workflow
- 문장별 저작자 표시, 댓글, 제안 모드
- 수정 기록 무기한 보존
- 의미 기반 자동 병합이나 AI 추천

## 작업 체크리스트

- [ ] **LC-031-P4-01** 명명된 가사 버전과 자동 수정 기록의 ID·수명·표시 규칙을 분리한다.
- [ ] **LC-031-P4-02** 내용 hash가 달라진 경우에만 5분 간격 스냅샷을 생성한다.
- [ ] **LC-031-P4-03** 화면 이탈·복원·복제·대규모 붙여넣기 전 중요 스냅샷을 중복 없이 생성한다.
- [ ] **LC-031-P4-04** 180일 초과 또는 항목당 200개 초과 기록을 owner 범위에서 안전하게 정리한다.
- [ ] **LC-031-P4-05** 기록 목록의 로딩·빈 상태·실패·재시도와 시각·사유·미리보기를 구현한다.
- [ ] **LC-031-P4-06** PC 나란히 및 모바일 전환/세로 방식의 줄 단위 비교 화면을 구현한다.
- [ ] **LC-031-P4-07** 복원 전 현재 상태를 즉시 스냅샷으로 남기고 과거 내용을 새 CRDT 최신 상태로 적용한다.
- [ ] **LC-031-P4-08** 복원 후 평문 투영과 접속 중인 같은 owner의 탭·기기가 새 상태로 수렴하게 한다.

## 구체적 검증

1. 짧은 자동 저장을 반복해도 5분 창 안에서 불필요한 기록이 폭증하지 않는지 시간 제어 테스트한다.
2. 대규모 붙여넣기·복제·복원 직전에 중요 기록이 남고 실패한 작업은 잘못 완료 표시되지 않는지 확인한다.
3. 181일 된 기록과 201번째 기록을 정리하되 현재본·명명 버전·보존 대상 중요 기록 규칙이 유지되는지 검사한다.
4. PC와 모바일에서 긴 한글 가사, 빈 줄, 송폼 태그의 차이가 같은 줄 범위로 표시되는지 확인한다.
5. 과거 기록 복원 직후 두 탭이 자동 수렴하고 복원 직전 상태로 다시 되돌릴 수 있는지 E2E로 검증한다.
6. 빈 기록, 기록 조회 실패, 삭제된 자료, 정리 중 재시도 화면이 막힘 없이 안내되는지 확인한다.

## 완료 조건

- [ ] 5분·중요 작업 전·180일/200개 정책이 자동 테스트로 고정되었다.
- [ ] 명명 버전과 수정 기록이 화면과 데이터에서 혼동되지 않는다.
- [ ] 비교·복원이 PC·모바일에서 동작하고 복원 전 상태가 보존된다.
- [ ] 복원 뒤 CRDT와 평문 투영이 같은 최신 내용으로 수렴한다.
