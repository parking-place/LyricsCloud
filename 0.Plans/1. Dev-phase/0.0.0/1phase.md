# 0.0.0 Phase 1 — 요구사항 기준선과 추적표

- 상태: **완료**
- 버전 상태: [../STATUS.md](../STATUS.md)

## 목표

구현을 시작하기 전에 Sketch의 1.0 필수 범위와 15개 목업, 기술 선택 문서의 결정 상태를 하나의 추적 기준으로 고정한다. 이후 어떤 기능도 출처와 예정 버전 없이 추가되거나 빠지지 않게 한다.

## 선행조건

- 없음
- 이 Phase에서는 Implementation-Stack의 체크 상태를 읽되, 서로 결합했을 때 의미가 불분명한 선택을 구현 승인으로 해석하지 않는다.

## 포함 범위

- Sketch 1절부터 51절까지의 기능·상태·사용자 흐름 목록화
- Sketch 49절의 1차 출시 기능을 필수 수용 기준으로 표시
- 15개 화면과 공통 오버레이의 기능 소유권 매핑
- 목업에서 추가된 버전 비교, 상세 필터, 빠른 아이디어, 동기화 지연 상태, 키보드식 태그 이동의 범위 표시
- 구현 전 결정이 필요한 항목과 단순 구현 세부사항의 분리
- 0.0.0부터 1.0.0까지의 요구사항 추적 ID 규칙 정의

## 제외 범위

- 애플리케이션 코드와 데이터베이스 객체 생성
- 인증, ORM, CRDT, 리버스 프록시 패키지 선택
- Docker 이미지와 서비스 실행
- 기능 우선순위를 이유로 Sketch 49절 항목을 1.0 밖으로 임의 이동

## 작업 체크리스트

- [x] LC-000-P1-01 — Sketch의 계정, 곡, 가사, 라임, 프롬프트, 공통 기능을 각각 빠짐없이 목록화한다.
- [x] LC-000-P1-02 — 다섯 가지 명시 사용자 흐름을 시작 화면, 중간 행동, 종료 결과로 분해한다.
- [x] LC-000-P1-03 — 15개 화면별로 담당 기능과 필요한 공통 오버레이를 연결한다.
- [x] LC-000-P1-04 — Sketch 49절의 모든 불릿에 고유 요구사항 ID와 예정 버전·Phase를 지정한다.
- [x] LC-000-P1-05 — 목업 추가 기능을 원 기획 기능과 구분해 추적표에 기록한다.
- [x] LC-000-P1-06 — 화면에 있으나 동작 정의가 없는 요소와 기획에는 있으나 목업에 없는 요소를 차이 목록으로 만든다.
- [x] LC-000-P1-07 — 자동 저장, 수정 기록, 휴지통, 인프라 백업을 서로 다른 복구 계층으로 표시한다.
- [x] LC-000-P1-08 — 1.0 제외 항목과 아직 결정되지 않은 항목을 별도 목록으로 만든다.

## 검증 방법

- Sketch 49절의 각 불릿을 추적표에서 역검색해 누락이 없어야 한다.
- 목업 01부터 15까지 각 README의 주요 기능이 최소 한 개의 요구사항 ID와 연결되어야 한다.
- 새 곡 작성, 기존 곡 수정, 라임 삽입, 프롬프트 작성, 최근 작업 재개 흐름이 중간에 미정 화면 없이 연결되는지 검토한다.
- 기준 문서의 상대 링크가 현재 버전 폴더에서 모두 열리는지 확인한다.
- 패키지명이나 공급자명이 근거 ADR 없이 확정 문장으로 들어가지 않았는지 검색한다.

## 완료 조건

- [x] Sketch 49절 필수 기능의 추적 누락이 0개다.
- [x] 15개 화면과 공통 오버레이의 담당 범위가 정해졌다.
- [x] 요구사항·목업 차이 목록에 우선순위와 결정 필요 여부가 표시됐다.
- [x] 특정 인증·ORM·CRDT·프록시 패키지가 승인 없이 기준선에 고정되지 않았다.
