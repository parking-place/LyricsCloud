# 0.0.0 Phase 4 — 로컬 Docker 개발환경 구성

- 상태: **대기**
- 버전 상태: [../STATUS.md](../STATUS.md)

## 목표

Windows 개발 환경에서 반복 실행할 수 있고 이후 홈랩으로 옮길 수 있는 Docker 기반 로컬 개발환경을 실제로 구성·검증한다. 포트, 네트워크, 볼륨, 비밀 값, health, migration의 책임을 명확히 하고 기본 검사·빌드가 통과하는 상태를 만든다.

## 선행조건

- 0.0.0 Phase 3의 모듈·실행 계약이 완료되어야 한다.
- 토폴로지, 인증, 데이터 접근, 프록시 관련 ADR이 Accepted 상태여야 한다.

## 포함 범위

- 로컬 compose 서비스와 내부 네트워크의 실행 가능한 구성
- PostgreSQL 데이터와 백업의 명시적 볼륨 경계
- 개발용 포트, 컨테이너 DNS 이름, healthcheck, 시작 순서
- 환경 예시 파일과 비밀 값 주입 규칙
- migration 실행 주체와 중복 실행 방지
- 소스 hot reload와 의존성 캐시 전략
- 홈랩 이전 시 바뀌는 값과 유지되는 값의 구분
- 데이터베이스 재시작·애플리케이션 재시작 검증

## 제외 범위

- 운영 도메인과 공개 TLS 인증서 발급
- 운영 데이터 migration
- 실제 Google OAuth 운영 자격 증명
- CRDT·웹소켓 부하 구성
- 특정 프록시 제품의 설정 파일은 ADR 승인 범위를 넘어 작성하지 않음

## 작업 체크리스트

- [ ] LC-000-P4-01 — 각 컨테이너의 책임, 내부 포트, 외부 노출 필요 여부를 표로 만들고 승인된 compose 구성에 반영한다.
- [ ] LC-000-P4-02 — 데이터베이스와 백업 경로가 소스 bind mount와 섞이지 않도록 볼륨을 분리한다.
- [ ] LC-000-P4-03 — 서비스 의존 순서를 단순 시작 순서가 아니라 readiness 조건으로 표현한다.
- [ ] LC-000-P4-04 — 환경 예시에는 키 이름과 형식만 넣고 실제 OAuth·세션·DB 비밀 값은 제외한다.
- [ ] LC-000-P4-05 — migration 잠금과 재실행 안전성을 포함한 초기화 절차를 정의한다.
- [ ] LC-000-P4-06 — Windows 경로 공백과 줄바꿈에서도 hot reload가 작동하는 검증 절차를 만든다.
- [ ] LC-000-P4-07 — 컨테이너 재생성 후 PostgreSQL 데이터가 유지되는지 확인할 시나리오를 작성한다.
- [ ] LC-000-P4-08 — 홈랩 이전 체크리스트에 호스트명, 볼륨, 백업, TLS, 웹소켓, 시간대 변경점을 기록한다.
- [ ] LC-000-P4-09 — 로그에 환경 비밀 값과 사용자 본문이 출력되지 않는 기본 규칙을 설정한다.
- [ ] LC-000-P4-10 — 승인된 패키지 관리자·런타임의 manifest와 lockfile을 만들고 검사·테스트·빌드 명령을 컨테이너와 로컬에서 같은 방식으로 실행한다.

## 검증 방법

- compose 구성 정적 검증에서 누락된 변수, 중복 포트, 존재하지 않는 의존 서비스를 확인한다.
- 의존성을 새로 설치한 깨끗한 환경에서 정적 검사, 빈 단위 테스트 묶음, 기본 build를 실행하고 명령·결과를 기록한다.
- 빈 볼륨으로 최초 시작하고 migration 완료 후 readiness가 성공하는지 확인한다.
- 데이터 한 건을 넣은 뒤 애플리케이션과 데이터베이스 컨테이너를 각각 재시작해 보존 여부를 확인한다.
- 잘못된 DB 비밀번호와 닫힌 DB 포트에서 liveness와 readiness가 예상대로 달라지는지 확인한다.
- 1440px와 390px 브라우저에서 중립 골격이 같은 로컬 주소로 열리는지 확인한다.
- 로그와 compose 출력에 실제 비밀 값이 노출되지 않는지 패턴 검색한다.

## 완료 조건

- [ ] 새 개발자가 문서 순서대로 로컬 환경을 시작할 수 있다.
- [ ] 데이터 볼륨과 백업 위치가 명확히 분리됐다.
- [ ] readiness 기반 시작과 장애 진단이 가능하다.
- [ ] 실제 비밀 값이 저장소에 포함되지 않았다.
- [ ] 홈랩 이전 시 필요한 변경점이 목록화됐다.
- [ ] 깨끗한 환경에서 기본 검사·테스트·빌드가 재현됐다.
