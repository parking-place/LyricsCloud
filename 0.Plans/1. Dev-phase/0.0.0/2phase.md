# 0.0.0 Phase 2 — ADR 결정 게이트

- 상태: **완료**
- 버전 상태: [../STATUS.md](../STATUS.md)

## 목표

Implementation-Stack에서 선택된 Docker 자체 운영과 실시간 자동 병합 요구를 실행 가능한 아키텍처 결정으로 해석한다. 특히 인증, 데이터 접근, CRDT, 리버스 프록시의 제품 선택은 비교 기록과 사용자 승인을 거친 ADR로만 확정한다.

## 선행조건

- 0.0.0 Phase 1의 요구사항 추적표와 차이 목록이 완료되어야 한다.
- DEC-01-D, DEC-10-C, DEC-06-C가 체크된 현재 문서를 입력으로 사용하되 세 선택 사이의 빈칸을 임의로 채우지 않는다.

## 포함 범위

- 로컬 Docker 개발에서 홈랩 이전까지의 실행 토폴로지 ADR
- Google 인증 주체, 세션, 콜백, 계정 삭제 경계 ADR
- PostgreSQL 접근 방식, migration 소유권, ORM 사용 여부 ADR
- DEC-06-C가 같은 사용자의 여러 기기 자동 병합인지 향후 다중 사용자 공동 편집까지 뜻하는지 해석
- CRDT 문서 단위, 서버 보존 방식, 연결 실패와 압축 정책 ADR
- TLS 종료, 정적 자원, 애플리케이션 전달을 담당할 프록시 경계 ADR
- 온라인 우선 PWA의 계정별 로컬 저장과 안전한 업데이트 ADR
- 암호화 논리 백업의 저장·키·보존·복원 환경 ADR
- 오류·성능 정보에서 창작물 본문을 제거하는 관측 ADR
- ADR 승인·보류·기각 상태와 재검토 조건

## 검증 방법

- 각 ADR이 최소 두 개의 현실적인 대안과 아무것도 도입하지 않는 대안을 비교하는지 확인한다.
- 인증 패키지가 Google provider token을 불필요하게 저장하지 않는 구조인지 위협 모델로 검토한다.
- ORM 또는 데이터 접근 결정이 owner 경계, transaction, migration rollback을 표현할 수 있는지 작은 설계 예제로 확인한다.
- CRDT 결정이 여러 기기에서 동시에 한글을 편집하고 재연결하는 순서를 설명할 수 있는지 사건 흐름으로 검증한다.
- 프록시 결정이 HTTPS, 보안 헤더, 웹소켓 업그레이드, 요청 크기 제한을 담당할 위치를 명시하는지 확인한다.
- PWA 결정이 로그아웃·계정 전환과 새 service worker 적용 중 미전송 초안을 노출·손실시키지 않는지 검토한다.
- backup 결정이 운영 DB 호스트 상실과 키 상실을 각각 복구할 수 있는지 확인하고, 관측 결정의 합성 canary 본문이 수집되지 않는지 시험 계획을 만든다.
- 승인되지 않은 후보 이름이 후속 Phase의 확정 기술로 사용되지 않았는지 검색한다.
