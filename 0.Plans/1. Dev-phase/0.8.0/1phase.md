# 0.8.0 Phase 1 — 가사·프롬프트 템플릿

- 상태: **대기**
- 단계 목적: 반복되는 가사 구조와 프롬프트 구성을 안전하게 재사용하게 한다.

## 목표

기본 템플릿과 사용자 템플릿을 생성·수정·복제·삭제하고, 새 자료를 만들 때 원본 템플릿을 훼손하지 않은 채 적용할 수 있게 한다.

## 선행조건

- 0.7.0의 통합 자료 소유권·딥링크 규칙이 완료되어야 한다.
- 가사와 프롬프트의 순수 텍스트/순서 토큰 데이터 모델이 안정되어야 한다.
- 템플릿 저장 스키마와 인증 경계는 [0.0.0 ADR 산출물](../0.0.0/)을 따른다.

## 포함 범위

- 가사 구조 템플릿과 프롬프트 템플릿 구분
- 기본 템플릿 보기와 사용자 템플릿 CRUD·복제
- 새 자료 생성 시 템플릿 적용과 적용 전 미리보기
- 즐겨찾기·최근 사용 정렬 및 사용자별 격리

## 제외 범위

- 사용자 간 템플릿 공유·마켓
- 기존 가사에 템플릿을 강제 병합하는 기능

## 작업 체크리스트

- [ ] `LC-080-P1-01` 가사/프롬프트 템플릿 유형과 원문 저장 계약을 정의한다.
- [ ] `LC-080-P1-02` 기본 템플릿은 읽기 전용, 사용자 템플릿은 소유자만 변경하도록 권한을 분리한다.
- [ ] `LC-080-P1-03` 템플릿 생성·수정·복제·휴지통 이동 화면과 검증을 구현한다.
- [ ] `LC-080-P1-04` 새 가사·프롬프트 생성 흐름에서 빈 문서 또는 템플릿을 선택하게 한다.
- [ ] `LC-080-P1-05` 적용 결과를 새 자료로 복사해 이후 편집이 템플릿 원본에 영향을 주지 않게 한다.
- [ ] `LC-080-P1-06` 템플릿 미리보기에서 사용자 문자열을 순수 텍스트로 렌더링한다.
- [ ] `LC-080-P1-07` 최근 사용·즐겨찾기 정렬이 다른 자료의 통합 즐겨찾기 규칙과 일치하게 한다.
- [ ] `LC-080-P1-08` 다른 유형의 템플릿 ID를 잘못 전달했을 때 생성이 원자적으로 거부되게 한다.
- [ ] `LC-080-P1-09` 가사/프롬프트 유형과 기본/사용자 출처 필터를 독립 축으로 제공한다.

## 구체적 검증

1. 템플릿으로 만든 가사를 수정해도 템플릿 원문과 다른 가사가 바뀌지 않는지 확인한다.
2. 프롬프트 템플릿 토큰 순서와 쉼표 복사 결과가 일치하는지 검사한다.
3. 사용자 A가 사용자 B 템플릿 ID로 읽기·생성을 시도해도 존재 여부가 노출되지 않는지 확인한다.
4. 빈 템플릿, 최대 길이, 송폼 태그만 있는 템플릿의 생성 결과를 단위·통합 테스트한다.
5. 360px 모바일과 PC에서 미리보기, 선택, 취소 흐름을 E2E로 검증한다.
6. 유형·출처 필터의 모든 조합에서 잘못된 템플릿 유형이 적용 대상으로 나타나지 않는지 확인한다.

## 완료 조건

- [ ] 두 템플릿 유형의 CRUD·복제·적용 흐름이 완료되었다.
- [ ] 템플릿 적용은 항상 독립된 새 자료를 만든다.
- [ ] 권한·유형 혼동·순수 텍스트 렌더링 테스트가 통과한다.
- [ ] 목업의 PC·모바일 핵심 상태가 구현되었다.
