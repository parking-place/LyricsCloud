# 0.8.0 Phase 4 — 휴지통 30일과 탈퇴 7일 유예

- 상태: **대기**
- 단계 목적: DEC-08-A와 DEC-09-A에 맞춰 삭제·복원·탈퇴를 되돌릴 수 있고 예측 가능하게 처리한다.

## 목표

곡·가사·라임 노트·프롬프트·템플릿의 휴지통과 30일 자동 완전 삭제를 구현하고, 회원 탈퇴 즉시 접근 차단·7일 철회·이후 완전 삭제 흐름을 완성한다.

## 선행조건

- [0.8.0 Phase 3](./3phase.md)까지 설정·계정 화면과 자료 이동 명령이 완료되어야 한다.
- 인증 관리자 작업, 탈퇴 계정 차단과 purge 실행 주체는 [0.0.0 ADR 산출물](../0.0.0/)에서 확정되어야 한다.
- 외부 백업 저장소·지역·프록시는 이 단계에서 임의 선택하지 않는다.

## 포함 범위

- `deleted_at`·`purge_at` 기반 휴지통과 남은 기간 표시
- 개별·다중 선택의 원래 위치 복원과 사용자 확인을 거친 즉시 완전 삭제
- 곡과 소속 가사의 원자적 삭제·복원
- 탈퇴 즉시 접근·세션 차단, 7일 철회, 기한 후 계정·자료 purge
- 로컬 초안·PWA 개인 캐시 제거

## 제외 범위

- 30일/7일 정책 변경
- 백업 매체의 보존 기간을 무시한 즉시 물리 삭제 보장
- 운영자가 사용자 창작물 내용을 열람하는 관리 화면

## 작업 체크리스트

- [ ] `LC-080-P4-01` 자료별 삭제·복원·완전 삭제 상태 전이와 시간 기준을 문서화한다.
- [ ] `LC-080-P4-02` 곡 삭제 시 소속 가사를 한 트랜잭션으로 숨기고 복원 선택을 처리한다.
- [ ] `LC-080-P4-03` 휴지통 목록에 유형, 원래 위치, 삭제 시각과 30일 purge 예정일을 표시한다.
- [ ] `LC-080-P4-04` 영구 삭제는 자료 이름을 포함한 재확인 후 서버 권한 경계에서만 수행한다.
- [ ] `LC-080-P4-05` 탈퇴 전 Google 재인증과 전체 내보내기 안내 진입점을 제공한다.
- [ ] `LC-080-P4-06` 탈퇴 즉시 새 세션·자료 접근을 차단하고 해당 기기의 IndexedDB/개인 캐시를 제거한다.
- [ ] `LC-080-P4-07` 7일 안에 재인증한 사용자가 명시적으로 탈퇴를 철회할 수 있게 한다.
- [ ] `LC-080-P4-08` 30일 자료 purge와 7일 계정 purge 작업을 멱등·배치 방식으로 구현하고 실패 상태를 남긴다.
- [ ] `LC-080-P4-09` backup에 남을 수 있는 데이터와 실제 제거 시점을 사용자 안내 문구에 구분한다.
- [ ] `LC-080-P4-10` 다중 복원·완전 삭제 전에 부모 곡, 소속 가사와 연결 자료에 미치는 영향을 요약해 확인받는다.

## 구체적 검증

1. 경계 시각 직전·정각·직후의 30일/7일 처리 결과를 고정 시계 테스트로 검증한다.
2. purge 작업을 동일 대상에 여러 번 실행해도 오류나 다른 자료 삭제가 없는지 확인한다.
3. 삭제된 곡의 가사 단독 복원, 부모 동시 복원, 새 곡 이동 규칙을 각각 테스트한다.
4. 탈퇴 직후 기존 탭과 이미 발급된 세션으로 읽기·쓰기 요청이 차단되는지 검사한다.
5. 탈퇴 철회와 최종 purge 후 Google 재로그인의 결과를 인증 통합 테스트로 확인한다.
6. 사용자 A의 purge가 사용자 B의 동일 제목 자료·연결·수정 기록에 영향을 주지 않는지 검증한다.
7. 여러 유형을 함께 선택해 복원·완전 삭제할 때 부분 성공 없이 전체 결과와 실패 원인이 일관되게 남는지 확인한다.

## 완료 조건

- [ ] DEC-08-A의 30일 휴지통과 DEC-09-A의 7일 탈퇴 정책이 시간 테스트를 통과한다.
- [ ] 복원·완전 삭제·계정 purge가 서버 트랜잭션과 권한 경계 안에서 처리된다.
- [ ] 탈퇴 즉시 서버 접근과 로컬 개인 데이터가 차단된다.
- [ ] 실패한 purge를 식별하고 안전하게 재실행할 수 있다.
