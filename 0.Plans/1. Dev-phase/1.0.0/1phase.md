# 1.0.0 Phase 1 — 최종 요구사항·결함 게이트

- 상태: **대기**
- 단계 목적: 1.0에 들어갈 모든 기능과 추가 제안이 검증됐는지 최종 판정한다.

## 목표

Sketch 49절의 1차 출시 기능과 15개 목업 README에 기록된 추가 제안을 전부 추적해 통과 여부를 승인하고, 미해결 P0/P1이 없는 경우에만 배포 산출물 생성을 허용한다.

## 선행조건

- 0.9.1 RC의 기능 동결, 보안·성능·회귀·복원 훈련이 완료되어야 한다.
- [0.9.1 Phase 1](../0.9.1/1phase.md)의 추적표와 결함 정의가 최신이어야 한다.
- 최종 승인 권한, 예외 불가 조건과 운영 인수 책임은 [결정 권한표](../Decision-Ownership.md)의 `OPS-0004`로 이 Phase에서 확정한다.

## 포함 범위

- Sketch 49절 모든 계정·곡·가사·라임·프롬프트·공통 기능
- 01~15 목업 README의 모든 추가 제안
- 구현·자동 테스트·수동 검증·문서 증적의 최종 연결
- P0/P1 차단 결함, P2/P3 공개 가능성 판단
- 승인자와 판정 시각이 남는 release gate

## 제외 범위

- 기획·목업·승인 DEC에 없는 신규 기능
- 테스트 없이 일정만을 이유로 한 예외 승인
- P0/P1을 알려진 제한으로 낮춰 출시하는 처리

- [ ] `LC-100-P1-02` 15개 목업 README의 추가 제안마다 구현·명시적 제외·검증 결과가 있는지 확인한다.
- [ ] `LC-100-P1-03` DEC-05-A, 07-A, 08-A, 09-A, 10-C, 11-A, 12-A, 13-A의 구현 증적을 다시 연결한다.
- [ ] `LC-100-P1-04` P0 결함을 데이터 손실·교차 사용자 노출·인증 우회·복원 불가·전체 서비스 불능으로 최종 확인한다.

## 구체적 검증

1. 추적표의 모든 행이 `통과`, 승인된 `1.0 제외 범위`, 또는 차단 중 하나이고 공란이 없는지 검사한다.
2. `통과` 행을 표본 추출해 연결된 테스트와 실제 동작이 일치하는지 독립 재실행한다.
3. P0/P1 목록을 issue tracker, 보안 보고서, 실기기 목록, 운영 훈련 결과와 교차 대조한다.
4. 최신 RC commit/image에서 전체 회귀를 다시 실행해 이전 산출물의 재사용 오류를 방지한다.
5. 목업 추가 제안의 명시적 제외가 있다면 기획 승인과 사용자 영향 설명이 있는지 확인한다.

## 완료 조건

- [ ] Sketch 49절의 모든 1차 출시 기능이 추적·검증을 통과했다.
- [ ] 15개 목업의 추가 제안이 모두 추적되고 구현 또는 명시적 승인 결과를 가진다.
- [ ] 미해결 P0 결함이 **0개**다.
- [ ] 미해결 P1 결함이 **0개**다.
- [ ] 최신 RC 식별자에 대해 최종 gate가 승인되었다.
