# 1.0.0 Phase 5 — 최종 승인, 태그와 운영 전환

- 상태: **대기**
- 단계 목적: 1.0.0의 제품·데이터·운영 품질을 최종 서명하고 정식 운영 상태로 전환한다.

## 목표

프로덕션 안정 구간, 요구사항 추적, 문서·운영 인수와 P0/P1 0건을 다시 확인한 뒤 1.0.0 태그·릴리즈 기록을 발행하고 초기 운영 감시로 넘긴다.

## 선행조건

- [1.0.0 Phase 1](./1phase.md)부터 [Phase 4](./4phase.md)까지 승인되어야 한다.
- 프로덕션은 Phase 2의 승인 digest와 Phase 3의 검증된 schema를 실행해야 한다.
- 태그·릴리즈 절차는 [결정 권한표](../Decision-Ownership.md)의 `OPS-0001`, 최종 승인·운영 인수 권한은 `OPS-0004`를 따른다.

## 구체적 검증

1. 태그의 source commit과 실행 중 image label/digest를 기계적으로 비교한다.
2. 프로덕션 합성 계정으로 PC와 모바일 핵심 smoke를 실행하고 생성 자료를 안전하게 정리한다.
3. 초기 안정 구간 동안 오류율, p95, 자동 저장 실패, DB 연결, purge와 backup 지표를 확인한다.
4. canary 문자열 검색으로 관측 시스템에 창작물·검색어·토큰이 없는지 마지막 검사한다.
5. 장애 연락 테스트와 모의 rollback 판단을 수행해 운영자가 runbook 위치와 권한을 확인한다.
6. release notes의 기능·제한·정책 기간이 실제 1.0 동작과 일치하는지 독립 검토한다.
