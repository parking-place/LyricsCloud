## 미해결 항목

REVIEW-01~05, REVIEW-07, REVIEW-10의 재현 가능한 신규 초안 수명주기·PWA 메모리/IME 보호·템플릿 복구 경로를 수정했다. 합성 PostgreSQL과 Chromium PC/모바일 회귀 범위에서 검증했으며 실제 OS IME·기기·장시간 인수까지 완료한 것은 아니다. Yjs, 전체 React 훅·비동기·성능 감사와 의존성 최신화 판정은 미완료다.

## 테스트 원칙

결함을 재현하는 테스트를 먼저 실패시키고 최소 수정 후 성공을 확인한다. `node --test scripts/tests/p6-*.mjs`는 원본 함수·셸·발췌 콜백을 검사하며 외부 DB·암호화·브라우저를 모사하는 검사는 명시한다. 별도의 실제 PostgreSQL 회귀는 `packages/database/src/export-safety.integration.test.ts`이다. 테스트 삭제·skip 추가로 실패를 숨기지 않는다.

## 전체 검사

`node scripts/audit-p6-codebase.mjs`가 현재 checkout의 모든 tracked TS/JS와 Shell 파일을 문법 검사하고 명시적 any·빈 catch·대형 파일을 검토 신호로 기록한다. 검토 신호는 자동 확정 결함이 아니며 이 검사가 전체 의미 분석이나 ESLint를 대신하지 않는다.

## 발행과 환경

P6 자동 발행은 차단한다. 명시적으로 수동 candidate를 발행하는 경우에도 SHA와 candidate 전용 tag만 허용한다. 다른 개발 브랜치의 기존 계약은 유지한다. shared Dev·Dev-latest·개발 서버는 인수 전 변경하지 않는다. 운영 서버·DB·볼륨·실제 창작물·사용자 PC의 기존 폴더는 이 원격 후보 반영의 대상이 아니다.

## 호환성과 최적화

Node 24·pnpm 11의 저장소 기준을 유지하고 lockfile과 과거 migration을 바꾸지 않는다. 관측성은 allowlist·출력 동등성 테스트를 유지하며 알 수 없는 중첩 값을 탐색하지 않는다. 백업 checksum 검사는 전체 archive 읽기 비용이 있으므로 liveness와 분리해 운영 주기를 결정한다.

## 내보내기 제한

같은 owner의 미반영 projection이 있는 스냅샷은 ZIP 성공으로 반환하지 않는다. 기존 API는 이 오류를 503으로 처리한다. trash의 미반영 문서도 차단할 수 있으며, 원본 재구성·projection 복구·사용자별 재시도 안내는 후속 인수 대상이다. 성공적으로 서버에 저장된 자료를 조용히 누락하는 것보다 명시적 실패를 우선한다.

## 완료 기준

확인된 원문 유실·교차 사용자 노출·무음 저장 실패가 남아 있으면 P6를 완료 처리하지 않는다. 전체 검증과 실제 환경 인수, 제외/보류 사유, 정확한 SHA와 증거를 기록한다. 과거 릴리스의 P0/P1 0건 문구는 당시 기록이며 현재 P6의 결함 수를 뜻하지 않는다. `OPS-100-001` 운영 backup 미구축은 별도 운영 인수 전까지 계속 열려 있다.
