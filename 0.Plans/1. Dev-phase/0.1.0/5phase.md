# 0.1.0 Phase 5 — 인증·소유권·셸 통합 검증

- 상태: **완료**
- 버전 상태: [../STATUS.md](../STATUS.md)

## 목표

Google 로그인부터 개인 셸 진입, 세션 유지, 로그아웃, 다른 사용자 차단까지 하나의 흐름으로 검증하고 0.2.0의 resource·곡 기능이 안전하게 올라갈 기반을 확정한다.

## 선행조건

- 0.0.0의 관련 ADR이 모두 Accepted 상태이며 이 Phase는 승인 결과를 따라야 한다.
- 0.1.0 Phase 1부터 Phase 4까지의 완료 조건을 충족해야 한다.
- 개발용 허용 Google 계정과 분리된 두 테스트 사용자 fixture가 있어야 한다.

## 작업 체크리스트

- [x] LC-010-P5-01 — 새 허용 계정 로그인 시 profile이 한 번만 생성되고 보호 셸로 이동하는 E2E를 만든다.
- [x] LC-010-P5-02 — 기존 계정의 브라우저 재시작과 세션 갱신 후에도 같은 내부 사용자로 복원되는지 검증한다.
- [x] LC-010-P5-03 — 초대되지 않은 계정과 취소된 OAuth가 개인 셸에 도달하지 못하는지 검증한다.
- [x] LC-010-P5-04 — 로그아웃 후 쿠키, 사용자 context, 계정별 캐시가 제거되는지 검증한다.
- [x] LC-010-P5-05 — 사용자 A의 fixture를 B가 path·query·body로 요청하는 공격 테스트를 자동화한다.
- [x] LC-010-P5-06 — 로그인·셸의 1440px과 390×844 시각 기준 이미지를 저장하고 회귀 검사를 연결한다.
- [x] LC-010-P5-07 — 인증 응답의 Cache-Control, cookie 속성, 보안 헤더가 ADR 정책과 일치하는지 확인한다.
- [x] LC-010-P5-08 — 브라우저 네트워크·서버 로그·빌드 산출물에 OAuth 비밀 값과 provider token이 없는지 검색한다.
- [x] LC-010-P5-09 — 다음 버전의 resource가 반드시 owner context를 요구하도록 생성 API 계약 예제를 검증한다.

## 검증 방법

- 데스크톱과 모바일 viewport에서 로그인→셸→로그아웃 전체 E2E를 실행한다.
- 테스트 DB를 매번 초기화한 뒤 사용자 A/B 교차 접근 묶음을 반복 실행한다.
- 세션 cookie 삭제, 만료, 잘못된 서명, callback 재사용 사례를 각각 확인한다.
- 뒤로 가기, 새로고침, 직접 URL 입력에서 route 보호가 일관적인지 확인한다.
- 작은 화면·큰 글자·200% 확대에서 로그인 행동과 navigation이 가려지지 않는지 확인한다.
- clean build와 Docker 재시작 뒤 동일한 결과가 재현되는지 확인한다.

## 완료 조건

- [x] Google 로그인·유지·갱신·로그아웃 흐름이 PC·모바일에서 통과한다.
- [x] 비허용 계정과 인증되지 않은 요청이 모두 차단된다.
- [x] 사용자 A/B 교차 접근 테스트가 전부 통과한다.
- [x] 인증 화면과 셸의 시각 회귀 기준이 생성됐다.
- [x] 세션·캐시·로그에서 민감 정보 누출이 없다.
- [x] 0.2.0 resource가 사용할 owner context 계약이 확정됐다.
