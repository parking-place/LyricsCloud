# 0.1.0 Phase 1 — 승인 아키텍처의 실행 기반

- 상태: **검토**
- 버전 상태: [../STATUS.md](../STATUS.md)

## 목표

0.0.0에서 승인된 ADR만 사용해 웹 애플리케이션과 PostgreSQL을 실제로 실행하고, 인증 기능을 올릴 수 있는 설정·오류·health·테스트 기반을 만든다.

## 선행조건

- 0.0.0의 모든 Phase가 완료되어야 한다.
- 토폴로지, 인증, 데이터 접근, migration, 프록시 ADR이 Accepted 상태여야 한다.
- 이 버전부터는 ADR에서 승인된 패키지와 실행 방식만 사용한다.

## 포함 범위

- 승인된 Node.js 웹 실행 진입점과 PostgreSQL 연결
- 개발·검사·빌드·시작 명령
- 환경 설정 로더와 비밀 값 마스킹
- 애플리케이션 오류 경계와 일관된 오류 응답
- liveness, readiness, build 정보 응답
- migration 실행기와 테스트 데이터베이스 분리
- PC·모바일 공통 디자인 토큰을 불러오는 최소 루트 레이아웃
- CI에서 타입, 정적 검사, 단위 테스트, 운영 빌드 수행

## 제외 범위

- Google OAuth 요청과 callback
- profile·사용자 소유 자료 테이블
- 실제 01-auth 화면
- 인증 후 공통 메뉴와 탐색
- 곡·가사 기능

## 작업 체크리스트

- [ ] LC-010-P1-01 — Accepted ADR의 런타임과 디렉터리 구조로 웹 실행 진입점을 연결한다.
- [ ] LC-010-P1-02 — PostgreSQL 연결 성공·인증 실패·시간 초과를 구분하는 readiness 검사를 만든다.
- [ ] LC-010-P1-03 — 개발, 타입 검사, lint, 단위 테스트, build, start 명령을 각각 한 가지 공식 경로로 고정한다.
- [ ] LC-010-P1-04 — 필수 환경 값의 존재·형식을 시작 시 검증하고 값 자체는 로그에 남기지 않는다.
- [ ] LC-010-P1-05 — 공개 오류 응답에 코드와 요청 ID만 노출하고 내부 stack은 서버 로그에만 남긴다.
- [ ] LC-010-P1-06 — migration이 빈 DB에는 한 번 적용되고 같은 DB 재시작에는 중복 실행되지 않게 한다.
- [ ] LC-010-P1-07 — 루트 레이아웃에 색상, 간격, 글꼴 fallback, breakpoint, safe-area 토큰을 연결한다.
- [ ] LC-010-P1-08 — CI가 빈 테스트 DB를 준비하고 검사 종료 후 운영 데이터와 섞이지 않게 한다.
- [ ] LC-010-P1-09 — 빌드 식별자와 schema 버전을 readiness 진단 정보로 확인할 수 있게 한다.

## 검증 방법

- 빈 checkout에서 Docker 환경을 시작해 루트와 health 경로의 예상 상태 코드를 확인한다.
- DB를 중지했다가 다시 시작하며 readiness 실패·회복을 확인한다.
- 잘못된 환경 값에서 비밀 값 없이 어떤 설정이 틀렸는지만 표시되는지 확인한다.
- migration을 연속 두 번 실행해 두 번째 실행이 안전한지 확인한다.
- 1440px와 390px에서 최소 루트 레이아웃에 수평 스크롤이 없는지 확인한다.
- CI와 로컬 명령이 같은 lockfile과 동일한 검사 순서를 사용하는지 확인한다.

## 완료 조건

- [ ] 웹과 DB가 승인된 Docker 토폴로지에서 반복 실행된다.
- [ ] health가 프로세스와 의존 서비스 상태를 구분한다.
- [ ] migration과 테스트 DB가 운영 데이터 경계와 분리됐다.
- [ ] 비밀 값이 로그·빌드 산출물에 노출되지 않는다.
- [ ] PC·모바일 공통 토큰이 루트 레이아웃에 적용됐다.
- [ ] CI 기본 검사가 모두 통과한다.
