# 0.6.0 Phase 1 — 곡 대시보드 완성과 가사 버전 진입

- 상태: **진행 중**
- 단계 목적: 한 곡의 상태, 가사 버전, 메모와 연결 자료를 다음 작업의 출발점으로 완성한다.

## 목표

04번 목업의 곡 hero, 핵심 count, 가사 버전 목록, 작업 메모, 연결 라임·프롬프트와 곡 관리 행동을 PC·모바일에 함께 구현한다. 데이터가 없는 첫 곡과 부분 실패 상태에서도 새 가사 또는 연결 작업으로 이어질 수 있어야 한다.

## 선행조건

- 곡·가사 CRUD와 owner 격리는 이전 버전에서 완료되어야 한다.
- [0.4.0 릴리즈](../0.4.0/)와 [0.5.0 릴리즈](../0.5.0/)의 라임·프롬프트 카드 계약을 재사용할 수 있어야 한다.
- route, 공통 자료, count query와 상태 관리 방식은 [0.0.0 ADR 산출물](../0.0.0/)을 따른다.

## 구체적 검증

1. 가사·라임·프롬프트가 0개인 새 곡에서 빈 안내와 새 가사 행동이 PC·모바일에 표시되는지 확인한다.
2. 가사 목록만 실패하거나 연결 자료 count만 지연될 때 이미 받은 곡 정보가 사라지지 않고 해당 영역만 재시도 가능한지 검사한다.
3. 가사 복제·삭제·복원 후 dashboard count와 카드가 중복 없이 갱신되는지 확인한다.
4. 다른 owner 곡 URL과 연결 자료 ID를 직접 요청해 제목·count·존재 여부가 노출되지 않는지 테스트한다.
5. 긴 제목·긴 메모·가사 버전 다수에서 PC 스크롤과 360px 모바일 세로 흐름이 잘리지 않는지 시각 점검한다.
6. 가사 카드 열기 후 뒤로 가기로 곡 대시보드와 곡 목록의 이전 위치가 복원되는지 E2E로 확인한다.
