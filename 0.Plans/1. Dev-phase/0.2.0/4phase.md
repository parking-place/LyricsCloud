# 0.2.0 Phase 4 — 03 곡 작성·수정 폼 PC·모바일

- 상태: **완료**
- 버전 상태: [../STATUS.md](../STATUS.md)

## 목표

새 곡과 기존 곡 수정에 같은 validation 계약을 사용하고, PC와 모바일에서 제목·메모·상태·색상·핀·즐겨찾기를 명확히 편집한 뒤 대시보드로 이동하게 한다.

## 선행조건

- 0.0.0의 관련 ADR이 모두 Accepted 상태이며 이 Phase는 승인 결과를 따라야 한다.
- 0.2.0 Phase 2의 생성·조회·수정 명령이 준비되어야 한다.
- 0.2.0 Phase 3의 목록 route와 URL 복귀 규칙이 확정되어야 한다.

## 작업 체크리스트

- [x] LC-020-P4-01 — 새 곡 route는 상태 아이디어, pin·favorite 해제, 색상 미선택의 명시적 기본값으로 연다.
- [x] LC-020-P4-02 — 수정 route는 현재 owner의 곡만 불러오고 모든 필드를 서버 값으로 채운다.
- [x] LC-020-P4-03 — 제목 누락·길이 초과와 메모 길이 초과를 해당 입력 바로 아래에 표시한다.
- [x] LC-020-P4-04 — 상태 7개와 색상 선택에 텍스트 이름과 현재 선택 표시를 함께 제공한다.
- [x] LC-020-P4-05 — 저장 중 submit을 잠그고 동일 idempotency key로만 안전하게 재시도한다.
- [x] LC-020-P4-06 — 서버 validation 오류를 필드 오류로, 연결·인증 오류를 폼 상단 재시도 영역으로 구분한다.
- [x] LC-020-P4-07 — PC에서는 입력과 상태 설정을 2열로, 모바일에서는 한 열과 safe-area 위 완료 행동으로 배치한다.
- [x] LC-020-P4-08 — 수정된 폼에서 뒤로 가기·목록 이동·새로고침 전에 이탈 확인을 제공한다.
- [x] LC-020-P4-09 — 생성 성공 시 정확한 새 곡 ID의 대시보드로 이동하고 목록 캐시를 갱신한다.
- [x] LC-020-P4-10 — 아직 없는 가사 작성 CTA를 무반응 버튼으로 두지 않고 대시보드 빈 상태로 인계한다.

## 검증 방법

- 유효한 최소 입력, 모든 선택 입력, 최대 길이 경계값으로 생성·수정을 확인한다.
- submit을 빠르게 두 번 누르고 네트워크 응답을 재전송해 곡이 중복 생성되지 않는지 확인한다.
- 서버 validation, DB 중단, 세션 만료를 각각 발생시켜 오류 위치와 입력 보존을 확인한다.
- 수정 중 뒤로 가기에서 취소와 이탈을 각각 선택해 결과를 확인한다.
- PC 1440px과 모바일 390×844에서 label, 오류, 완료 버튼이 키보드와 겹치지 않는지 확인한다.
- 사용자 B의 곡 수정 URL에 접근했을 때 폼 값이 한 글자도 노출되지 않는지 확인한다.
