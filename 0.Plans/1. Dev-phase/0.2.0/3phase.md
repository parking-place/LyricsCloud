# 0.2.0 Phase 3 — 02 곡 목록 PC·모바일

- 상태: **완료**
- 버전 상태: [../STATUS.md](../STATUS.md)

## 목표

02-songs 화면을 PC와 모바일에서 동시에 구현해 사용자가 곡의 상태와 우선순위를 훑고 검색·필터·정렬·열기·빠른 생성을 수행하게 한다.

## 선행조건

- 0.0.0의 관련 ADR이 모두 Accepted 상태이며 이 Phase는 승인 결과를 따라야 한다.
- 0.2.0 Phase 2의 목록 query와 곡 메타데이터 명령이 동작해야 한다.
- 0.1.0의 PC·모바일 공통 셸과 인증 context가 준비되어야 한다.

## 포함 범위

- PC 2열 카드 목록과 모바일 1열 카드 목록
- 제목, 메모, 상태, 가사 수, 수정일, 즐겨찾기, 핀, 색상
- 제목·곡 메모 검색
- 상태 필터와 다섯 정렬 방식
- 핀·즐겨찾기 토글
- 새 곡 버튼과 빠른 추가의 새 곡 행동
- loading, 빈 목록, 검색 결과 없음, 재시도 가능한 오류
- cursor 추가 로드와 focus 유지

## 제외 범위

- 가사 본문 검색은 가사 데이터가 생기는 0.3.0에서 확장
- 연결 자료 있음·없음 필터
- 가사·라임·프롬프트 빠른 추가
- 목록에서의 영구 삭제
- 완전한 통합 검색

## 작업 체크리스트

- [x] LC-020-P3-01 — PC에서 좌측 메뉴와 상단 탭 아래 검색·필터·정렬, 2열 카드 순서로 배치한다.
- [x] LC-020-P3-02 — 모바일에서 header, 검색, 가로 상태 칩, 1열 카드, 하단 navigation, 빠른 추가를 함께 배치한다.
- [x] LC-020-P3-03 — 카드에 색상만이 아니라 상태명, 핀·즐겨찾기 아이콘과 접근 가능한 이름을 표시한다.
- [x] LC-020-P3-04 — 검색 입력을 지연 호출하고 이전 요청보다 늦게 끝난 응답이 최신 결과를 덮지 않게 한다.
- [x] LC-020-P3-05 — 정렬·필터를 URL query에 반영해 새로고침과 뒤로 가기에서 상태가 복원되게 한다.
- [x] LC-020-P3-06 — 카드 전체 열기와 내부 favorite·pin 버튼의 클릭·키보드 행동이 충돌하지 않게 한다.
- [x] LC-020-P3-07 — 빈 계정에는 첫 곡 CTA, 검색 결과 없음에는 조건 초기화를 서로 다른 문장으로 제공한다.
- [x] LC-020-P3-08 — cursor 추가 로드 뒤 현재 focus와 스크롤 위치를 유지한다.
- [x] LC-020-P3-09 — 모바일 320px 폭과 큰 글자에서도 카드 메타데이터와 주요 행동이 잘리지 않게 한다.
- [x] LC-020-P3-10 — 새 곡 행동을 03-song-form route와 연결하고 다른 미구현 빠른 추가 항목은 표시하지 않는다.

## 검증 방법

- 0곡, 1곡, 30곡 fixture로 PC·모바일 layout과 추가 로드를 확인한다.
- 모든 상태와 다섯 정렬 조합에서 첫·마지막 카드가 query 결과와 일치하는지 확인한다.
- 한글 검색을 빠르게 연속 입력해 결과 역전이 없는지 확인한다.
- 키보드만으로 검색, 필터, 카드 열기, pin, favorite, 새 곡 이동을 수행한다.
- 1440px, 1024px, 390×844, 320px에서 수평 overflow와 겹침을 확인한다.
- 사용자 B의 카드가 개수·검색·cursor 어디에도 섞이지 않는지 확인한다.

## 완료 조건

- [x] 02-songs의 PC·모바일 화면을 같은 Phase에서 완성했다.
- [x] 카드 메타데이터와 상태가 실제 API 결과와 일치한다.
- [x] 검색·필터·정렬·pagination이 URL 상태와 함께 동작한다.
- [x] 빈 상태와 오류 상태에서 다음 행동이 명확하다.
- [x] pin·favorite 행동이 카드 열기와 충돌하지 않는다.
- [x] 가사 검색 등 미구현 기능을 지원하는 것처럼 표시하지 않는다.
