# 1.0.12 — 개인 창작 흐름 통합·공유 진입 점검

상태: **P4 완료 / P5 착수**. 세 목록을 O(n)으로 최적화하고 개인 창작 desktop/mobile 수직 흐름, 실제 DB·권한·PWA·지원 브라우저·서비스 재시작 교차 인수를 마쳤다.

## 목표

여러 패치에 걸친 작성·복사·목록·Suno 흐름의 경계 결함을 정리하고 공유 도입 여부를 판정한다.

## 요구사항

`NF-REQ-022`, `NF-REQ-023`, `NF-REQ-024`, `NF-REQ-025`, `NF-REQ-026`, `NF-REQ-027`, `NF-REQ-028`, `NF-REQ-029`, `NF-REQ-030`, `NF-REQ-031`, `NF-REQ-032`, `NF-REQ-033`. 세부 의미와 완료 판정은 [요구사항 추적표](../Requirements-Traceability.md)를 따른다. 하나의 요구가 여러 패치에 걸치면 모든 담당 범위를 검증하기 전 전체 요구를 완료 처리하지 않는다.

## 선행조건과 승인

- [1.0.11 P5](../1.0.11/5phase.md)의 실제 인수와 현재 파일 담당 경계 확인.

2. [P2 — 핵심 기반·저장과 서버](2phase.md)
3. [P3 — PC·모바일 사용자 흐름](3phase.md)

## 설계의 고정 조건

- 패치 수가 12에 도달했기 때문에 마이너를 올리는 규칙은 없다.
- 개인 흐름에서 발견한 수정은 현재 1.0.x 안에서 처리하고 공유를 먼저 끼워 넣지 않는다.
- 공유의 owner/actor·RLS·capability 변경 필요와 인수 조건을 문서화한다. 결정 전 1.1.0은 조건부다.

## 대표 수용 사례

| ID | 입력·상황 | 기대 결과 |
|---|---|---|
| `AC-1.0.12-01` | 개인 창작 수직 흐름 전체 + 서버 재시작 | 최종 입력·복사·순서·링크가 보존된다. |
| `AC-1.0.12-02` | 최신 데이터로 PWA 재시작/계정 전환/복원 | 무음 원문 손실·교차 계정 노출이 없다. |
| `AC-1.0.12-03` | 합성 장문으로 최적화 전후 비교 | 결과 동등성과 실제 비용 변화가 기록된다. |
| `AC-1.0.12-04` | 공유 결정·회귀·운영 인수 중 하나 미완료 | 1.1.0을 자동 시작하지 않고 다음 가용 1.0.x로 보완한다. |

## 범위 밖

코드 변경이 없으면 확인서만 남긴다. 번호를 채우려고 인위적 수정/릴리스를 만들지 않는다.

## 계약과 인수

[세부 계약](../contracts/STABILIZATION.md) · [품질 게이트](../QUALITY-GATES.md) · [버전 규칙](../VERSIONING.md) · [릴리스 정책](../RELEASE-POLICY.md). 코드가 바뀌지 않은 연구/검증만으로 제품 tag를 발행하지 않는다. P5는 후보 인수이며 정식 main/Release/운영 변경은 별도 현재 승인 뒤 실행한다.
