# 더 추가하고 싶은 기능 고르기

이 문서는 **추가 기능 후보와 그 선택 이력**을 보존하는 곳입니다. 최신 필수 요구와 겹치는 부분은 이미 로드맵으로 이관했습니다. 마음에 드는 항목만 체크하면 됩니다.

현재 선택 후보는 **129개**입니다. 예정 기능, 반드시 해야 하는 오류·보안·복구 작업, 같은 기능을 나눠 적은 항목은 별도 아이디어 수에 넣지 않았습니다. 300개라는 숫자를 유지하기 위해 항목을 보태지 않습니다.

## 읽는 방법

각 항목은 **기능 이름 → 무엇을 하는지 → 실제 사용 예시** 순서입니다. 예시는 이해를 돕기 위한 상황이지 확정된 화면이나 작동 결과가 아닙니다.

`FF-001` 같은 번호는 개발자에게 선택한 기능을 알려줄 때 쓰는 식별자입니다. 번호가 띄엄띄엄 있는 것은 삭제·통합된 번호를 다른 기능에 재사용하지 않았기 때문입니다. 번호가 크다고 우선순위가 낮거나 일정이 늦다는 뜻은 아닙니다.

체크는 **이 기능을 더 검토하고 싶다**는 뜻입니다. 개발 완료 표시, 즉시 구현·배포 허가, 다른 서비스로 작품을 보내는 동의가 아닙니다. 체크한 기능의 세부 범위와 비용은 따로 확인합니다.

다른 작업자는 이 파일 또는 저장소 내 다른 위치의 Future 계획을 갱신할 수 있습니다. `FF-*` 번호·체크·설명·예시와 변경 의도를 보존합니다. 모든 push 직전과 Phase 완료 때 [검수 인수 절차](FUTURE-INTAKE.md)에 따라 전역 파일 탐색과 마지막 인수 commit/blob 대조를 한 번 수행합니다. 같은 변경은 반복 처리하지 않으며 체크 해제만으로 기존 구현을 삭제하지 않습니다.

## 이미 정한 계획과 구분하기

한글 입력·UI 오류 수정, 베타코드와 가입, 로고와 버전 표시, README와 현재 문서 정리는 **1.0.1 필수 계획**입니다. 프롬프트 모드, 기본 글자 수 경고, 송폼 확장, 사용자정렬·목록 보기, Suno 모델·링크, 실제 여러 사용자 동시 편집·보기와 presence/cursor, 세 언어 사전 tooltip, 무료 웹폰트, 기본 읽기·쓰기 공유, 약 5개 morphism 시안과 Windows/Linux/macOS/Android/iOS 개발안도 **이미 정한 로드맵**에서 다룹니다. 여기서 다시 선택할 필요가 없습니다.

초안 보존, 권한 검사, 백업 검증, 저장 실패 안내, 키보드 대안 같은 기본 조건은 체크 여부와 관계없이 지켜야 합니다. 아래에 관련 아이디어가 있을 때는 **기본 기능에 더하는 별도의 편의 기능**만 뜻합니다.

## 1. 가사를 쓰고 표현을 고를 때

- [ ] **한 줄에 몇 음절인지 보기** `FF-001`\
  **설명:** 가사 줄 옆에 음절 수를 표시해 줄마다 길이를 맞추기 쉽게 합니다. 실제로 부를 때의 음절 수가 다르면 직접 고칠 수 있습니다.\
  **예시:** ‘바라봐’는 3음절로 표시하고, 영어 단어는 내가 부르는 발음에 맞춰 숫자를 바꿉니다.

- [ ] **너무 자주 쓴 단어 찾아보기** `FF-002`\
  **설명:** 같은 가사에서 반복한 단어와 그 위치를 보여줍니다. 반복을 지울지, 후렴의 특징으로 남길지는 직접 결정합니다.\
  **예시:** ‘너’가 18번 나온다는 표시를 보고 일부를 다른 표현으로 바꿀지 살펴봅니다.

- [ ] **쓰는 줄을 화면 가운데 두기** `FF-004`\
  **설명:** 글을 입력할 때 현재 줄이 화면 가운데에 머물도록 화면이 따라 움직입니다. 주변 줄은 흐리게 표시할 수 있습니다.\
  **예시:** 긴 가사의 끝부분을 써도 커서가 화면 맨 아래에 붙지 않습니다.

- [ ] **내가 정한 줄 길이 알려주기** `FF-005`\
  **설명:** 한 줄의 권장 길이를 직접 정하면 너무 긴 줄에 표시를 붙입니다. 표시만 할 뿐 입력하거나 저장하는 것을 막지 않습니다.\
  **예시:** ‘한 줄은 가급적 15자 안팎’으로 정하고 긴 줄을 나눠 쓸지 판단합니다.

- [ ] **가사 옆에 나만 보는 주석 달기** `FF-006`\
  **설명:** 단어나 구간을 선택해 설명과 작업 메모를 붙입니다. 주석은 가사 본문이나 일반 가사 복사 결과에 들어가지 않습니다.\
  **예시:** 2절 옆에 ‘여기서는 이별 이유를 아직 밝히지 말기’라고 적어둡니다.

- [ ] **구간별 작업 상태 표시하기** `FF-007`\
  **설명:** 곡 전체의 상태와 별개로 1절, 후렴 같은 구간에 ‘완료’, ‘고칠 예정’, ‘보류’를 표시합니다.\
  **예시:** 후렴은 완료로 두고 2절만 ‘고칠 예정’으로 표시합니다.

- [ ] **표현·후렴·제목 후보 모아 비교하기** `FF-008`\
  **설명:** 한 구간이나 제목에 여러 후보를 달아 나란히 읽어봅니다. 채택하기 전에는 현재 원문을 바꾸지 않으며, 보류 이유도 남길 수 있습니다.\
  **예시:** ‘밤을 건너 너에게’와 ‘새벽을 따라 너에게’를 번갈아 읽어보고 한 문장만 채택합니다.

- [ ] **내가 피하고 싶은 표현 알려주기** `FF-010`\
  **설명:** 쓰지 않으려는 단어와 표현을 직접 등록하면 입력한 곳에 표시해 줍니다. 자동으로 지우거나 다른 말로 바꾸지는 않습니다.\
  **예시:** ‘영원히’를 너무 자주 쓴다고 느끼면 목록에 넣고, 다시 쓴 부분만 확인합니다.

- [ ] **꼭 남길 문장이 없어졌는지 알려주기** `FF-209`\
  **설명:** 작품의 핵심이라고 정한 어구가 편집 후 사라지면 확인 표시를 띄웁니다. 삭제를 막지는 않습니다.\
  **예시:** 후렴의 핵심 문장 ‘다시 집으로’가 빠졌을 때 의도한 수정인지 확인합니다.

## 2. 라임을 찾고 모을 때

- [ ] **발음이 비슷한 라임 찾기** `FF-011`\
  **설명:** 내 라임 노트에서 모음이나 받침이 비슷한 표현을 묶어 찾습니다. 무엇을 비슷한 소리로 볼지도 직접 정할 수 있습니다.\
  **예시:** ‘자본’처럼 모음이 ‘ㅏㅗ’인 표현을 모아보거나, 비슷한 받침끼리 찾아봅니다.

- [ ] **라임에 발음 메모 달기** `FF-012`\
  **설명:** 라임 표현마다 언어, 읽는 법, 강하게 발음할 부분을 적습니다. 사전식 발음 대신 실제로 사용할 발음을 기록할 수 있습니다.\
  **예시:** 영어 표현 옆에 한글로 읽는 법을 적고, 강세를 줄 음절에 표시합니다.

- [ ] **마음에 드는 라임만 따로 모으기** `FF-015`\
  **설명:** 여러 노트에서 고른 표현을 하나의 라임 모음에 담습니다. 어디에서 가져온 표현인지 원래 노트도 함께 연결합니다.\
  **예시:** 세 노트에서 골라낸 표현을 ‘이번 곡 후렴 후보’에 모아봅니다.

- [ ] **어떤 곡에 쓴 라임인지 기록하기** `FF-017`\
  **설명:** 라임 표현을 실제 곡에 사용했을 때 연결 기록을 남깁니다. 다음 작업에서 이미 쓴 표현인지 찾아보기 쉽습니다.\
  **예시:** ‘새벽 / 궤적’을 어느 곡의 후렴에 썼는지 확인합니다.

- [ ] **라임 후보의 검토 결과 남기기** `FF-018`\
  **설명:** 표현마다 ‘아직 안 읽어봄’, ‘입에 잘 붙음’, ‘채택’, ‘보류’를 표시하고 검토 순서를 남깁니다.\
  **예시:** 소리 내 읽어본 다섯 표현 중 두 개만 ‘입에 잘 붙음’으로 표시합니다.

## 3. 프롬프트를 시험할 때

- [ ] **프롬프트를 바꾼 전후 비교하기** `FF-021`\
  **설명:** 두 프롬프트에서 바뀐 부분과 결과 메모를 함께 봅니다. 한 요소만 바꿔 시험하거나, 왜 결과가 좋아졌다고 느꼈는지 기록합니다.\
  **예시:** 보컬 지시만 바꾼 두 안을 비교하고 ‘두 번째가 더 차분함’이라고 적습니다.

- [ ] **프롬프트 요소를 종류별로 보기** `FF-023`\
  **설명:** 프롬프트 내용을 장르, 보컬, 악기처럼 내가 정한 묶음으로 정리해 봅니다. 보기용 묶음 때문에 복사 순서가 저절로 바뀌지는 않습니다.\
  **예시:** ‘female vocal’은 보컬, ‘acoustic guitar’는 악기 묶음에 넣습니다.

- [ ] **도구별 글자 수 경고 기준 저장하기** `FF-025`\
  **설명:** 이미 계획된 기본 글자 수 경고 외에, 내가 쓰는 도구마다 원하는 경고 기준을 따로 저장합니다. 실제 서비스의 제한을 자동으로 알아낸다는 뜻은 아닙니다.\
  **예시:** A 도구용은 800자, B 도구용은 1,500자로 내가 정해 바꿔 씁니다.

- [ ] **원하지 않는 소리를 따로 적기** `FF-026`\
  **설명:** 프롬프트에 원하는 분위기와 피하고 싶은 요소를 나눠 적습니다. 복사할 때 이 제외 지시를 함께 넣을지도 선택합니다.\
  **예시:** ‘밝은 어쿠스틱 팝’과 별도로 ‘강한 왜곡 기타는 제외’를 보관합니다.

- [ ] **내가 자주 함께 쓰는 태그 추천받기** `FF-027`\
  **설명:** 내가 저장한 프롬프트에서 자주 같이 등장한 표현을 보고 다음 태그를 제안합니다. 다른 사람의 자료는 사용하지 않습니다.\
  **예시:** 내가 ‘dream pop’ 뒤에 자주 붙였던 ‘airy vocal’을 후보로 보여줍니다.

- [ ] **서로 충돌하는 프롬프트 지시 알려주기** `FF-028`\
  **설명:** 함께 쓰지 않으려는 표현 쌍을 직접 정하면 둘이 같이 들어갔을 때 알려줍니다. 내가 의도한 조합이라면 그대로 사용할 수 있습니다.\
  **예시:** ‘보컬 없음’과 ‘여성 보컬’을 함께 넣었을 때 확인 표시를 띄웁니다.

- [ ] **실험 횟수와 사용 비용 기록하기** `FF-029`\
  **설명:** 프롬프트별로 몇 번 생성했는지, 크레딧이나 비용을 얼마나 썼는지 직접 적어 합계를 봅니다. 외부 서비스의 결제를 자동으로 조회하지 않습니다.\
  **예시:** 한 곡에 12번 생성했고 60크레딧을 썼다고 기록합니다.

- [ ] **프롬프트 표현에 내 번역 붙이기** `FF-030`\
  **설명:** 영어 태그 옆에 한국어 뜻이나 내가 이해한 설명을 적어둡니다. 실제 복사에는 원래 태그가 그대로 들어갑니다.\
  **예시:** ‘breathy vocal’ 옆에 ‘숨소리가 섞인 보컬’이라고 메모합니다.

- [ ] **요소를 바꾼 프롬프트 후보 한꺼번에 만들기** `FF-212`\
  **설명:** 내가 정한 표현의 선택지를 조합해 여러 후보를 만듭니다. 외부 음악 생성까지 자동으로 실행하지는 않습니다.\
  **예시:** 보컬 두 종류와 분위기 세 종류를 조합해 프롬프트 여섯 개를 미리 봅니다.

- [ ] **제목을 가리고 생성 결과 평가하기** `FF-213`\
  **설명:** 어떤 프롬프트에서 나온 결과인지 잠시 숨긴 상태로 평가하고 나중에 정체를 확인합니다. 내가 정한 평가 항목과 선택 기록을 모아볼 수 있습니다.\
  **예시:** 결과를 A·B로만 표시하고 보컬·리듬을 평가한 뒤 어떤 설정을 썼는지 봅니다.

- [ ] **모델별로 잘 맞았던 표현 모으기** `FF-216`\
  **설명:** 어떤 모델에서 어떤 표현이 좋았는지 내 경험과 근거를 모읍니다. 모델 이름을 곡에 저장하는 기본 기능과는 다른 개인 노하우 사전입니다.\
  **예시:** 모델 A에서 ‘가까이 들리는 보컬’ 지시가 마음에 들었다는 결과 링크를 남깁니다.

- [ ] **실험에서 유지할 태그 표시하기** `FF-217`\
  **설명:** 이번 실험에서 바꾸지 않으려는 태그에 표시를 붙입니다. 수정하려 하면 한 번 더 확인하고, 허용하면 바꿀 수 있습니다.\
  **예시:** 보컬만 시험하는 동안 장르와 템포 지시를 실수로 바꾸지 않도록 표시합니다.

## 4. 곡 작업을 관리할 때

- [ ] **곡마다 할 일 목록 만들기** `FF-031`\
  **설명:** 작업 목표와 남은 일을 곡 안에 체크리스트로 둡니다. 자주 쓰는 목록을 재사용하고 완성 후 받은 수정 요청도 기록합니다.\
  **예시:** ‘2절 수정’, ‘프롬프트 두 안 비교’, ‘크레딧 확인’을 체크해 나갑니다.

- [ ] **템포·조성·박자 적어두기** `FF-032`\
  **설명:** 곡 정보에 빠르기, 조성, 박자를 직접 기록합니다. 자동으로 음원을 분석하거나 값을 추정하지 않습니다.\
  **예시:** ‘92 BPM / A minor / 4분의 4박자’를 적어둡니다.

- [ ] **가사 중 현재 기준안 지정하기** `FF-033`\
  **설명:** 같은 곡의 여러 가사 중 지금 기준으로 쓰는 안에 표시를 붙입니다. 다른 안을 삭제하거나 수정 기록으로 바꾸지는 않습니다.\
  **예시:** ‘가사 3안’을 기준안으로 정하고 1안과 2안은 비교용으로 남깁니다.

- [ ] **앨범이나 프로젝트별로 곡 묶기** `FF-034`\
  **설명:** 곡들을 앨범, EP, 행사 프로젝트 같은 묶음으로 정리합니다. 각 곡의 원본은 유지하면서 묶음 안에서 함께 찾아봅니다.\
  **예시:** ‘겨울 EP’ 안에 다섯 곡을 담아 진행 상황을 살펴봅니다.

- [ ] **이 곡을 만드는 이유 적기** `FF-035`\
  **설명:** 곡의 주제, 전달할 감정, 참고한 작품의 특징을 가사와 별도로 적습니다.\
  **예시:** ‘퇴근길의 안도감이 주제이고, 후렴은 말하듯 부드럽게’라고 적습니다.

- [ ] **가사·프롬프트·링크를 한 세트로 보관하기** `FF-036`\
  **설명:** 어느 시점의 가사와 프롬프트, 작업 링크를 함께 묶어 이름 붙입니다. 이후 각각을 수정해도 그때의 조합을 다시 확인할 수 있습니다.\
  **예시:** ‘첫 데모’에 사용한 가사와 프롬프트를 저장해 두고 최종안과 비교합니다.

- [ ] **끝낸 작업을 보관함으로 옮기기** `FF-037`\
  **설명:** 당장 쓰지 않는 곡과 자료를 삭제하지 않고 작업 목록에서 치웁니다. 여러 개를 한 번에 옮기거나 나중에 다시 꺼낼 수 있습니다.\
  **예시:** 발매가 끝난 곡을 보관함에 두고 작업 중인 곡만 평소 목록에 표시합니다.

- [ ] **내 작업 단계 이름 만들기** `FF-039`\
  **설명:** 기본 상태명 대신 자신에게 맞는 단계와 색을 만들어 사용합니다.\
  **예시:** ‘아이디어 → 가사 확정 → 생성 중 → 최종 선택’이라는 단계로 곡을 관리합니다.

- [ ] **오늘 할 작업을 홈에 모으기** `FF-113`\
  **설명:** 오늘 이어 쓸 곡과 목표, 다음에 할 일을 시작 화면에 모아둡니다. 즐겨찾기 전체와는 별개로 오늘의 작업을 고릅니다.\
  **예시:** 앱을 열면 ‘후렴 수정’이라는 메모와 어제 작업한 곡이 먼저 보입니다.

- [ ] **곡을 마친 뒤 짧은 회고 남기기** `FF-173`\
  **설명:** 좋았던 점, 아쉬운 점, 다음에 시도할 일을 곡에 따로 기록합니다.\
  **예시:** ‘후렴은 빨리 완성했지만 2절의 시점이 흔들렸다’고 적어 다음 곡에 참고합니다.

- [ ] **잊고 있던 미완성 곡 다시 만나기** `FF-178`\
  **설명:** 내 미완성 자료 중 하나를 무작위로 보여줘 이어 쓸 대상을 찾게 합니다.\
  **예시:** ‘예전에 쓰다 만 곡 보기’를 눌러 몇 달 전의 후렴을 다시 읽습니다.

## 5. 자료를 찾고 정리할 때

- [ ] **자주 쓰는 검색 조건 저장하기** `FF-041`\
  **설명:** 검색어와 필터 조합에 이름을 붙여 다시 사용합니다. 단순히 최근 검색어를 남기는 것과 달리, 내가 고른 조건을 계속 보관합니다.\
  **예시:** ‘지난달에 만든 미완성 발라드’를 저장해 한 번에 다시 엽니다.

- [ ] **여러 조건을 묶어 자료 찾기** `FF-042`\
  **설명:** 포함할 조건과 제외할 조건을 함께 정해 자료를 찾습니다. 날짜, 태그, 상태, 연결 유무 같은 조건을 조합합니다.\
  **예시:** ‘완성 상태이지만 작업 링크가 없는 곡’만 골라 정리합니다.

- [ ] **연결된 자료를 지도로 보기** `FF-043`\
  **설명:** 곡과 연결된 가사, 라임 노트, 프롬프트를 선으로 이어 보여줍니다. 목록에서 하나씩 열지 않고 관계를 파악합니다.\
  **예시:** 한 라임 노트가 어떤 세 곡에 연결되어 있는지 한 화면에서 확인합니다.

- [ ] **내 동의어 사전으로 검색하기** `FF-044`\
  **설명:** 같은 뜻으로 찾고 싶은 단어를 직접 묶어둡니다. 글에 쓰인 원래 단어는 바꾸지 않습니다.\
  **예시:** ‘새벽’을 검색할 때 내가 등록한 ‘동틀 무렵’도 함께 찾습니다.

- [ ] **검색어 오타 후보 보여주기** `FF-045`\
  **설명:** 검색 결과가 없을 때 내 자료에 있는 비슷한 표현을 제안합니다. 입력한 검색어를 몰래 바꾸지는 않습니다.\
  **예시:** ‘acustic’을 검색하면 ‘acoustic으로 찾아볼까요?’라고 묻습니다.

- [ ] **비슷하거나 겹치는 자료 정리하기** `FF-046`\
  **설명:** 제목이나 내용이 닮은 자료와 여러 노트에 반복된 표현을 모아 비교합니다. 합치거나 지울지는 내가 결정합니다.\
  **예시:** 거의 같은 라임 노트 두 개를 찾아 다른 부분을 확인하고 하나로 정리합니다.

- [ ] **같은 뜻의 태그 합치기** `FF-048`\
  **설명:** 여러 이름으로 쓴 태그를 하나로 합치거나 이름을 바꾸기 전에 영향을 받는 자료를 보여줍니다.\
  **예시:** ‘발라드’, ‘Ballad’, ‘ballad’를 하나로 묶었을 때 어떤 곡이 바뀌는지 봅니다.

- [ ] **여러 자료의 태그를 한 번에 바꾸기** `FF-051`\
  **설명:** 선택한 자료에 태그를 한꺼번에 추가하거나 뺍니다. 변경안을 모아 확인한 다음 적용할 수 있습니다.\
  **예시:** 곡 열 개를 선택해 ‘여름 프로젝트’ 태그를 붙이고 결과를 확인합니다.

- [ ] **여러 제목을 규칙대로 바꾸기** `FF-055`\
  **설명:** 여러 자료의 제목에 같은 문구를 붙이거나 번호를 매기기 전에 변경 결과를 보여줍니다.\
  **예시:** ‘데모 1, 데모 2’라는 제목 앞에 ‘겨울 EP - ’를 한 번에 붙입니다.

- [ ] **즐겨찾기와 별도로 우선순위 정하기** `FF-058`\
  **설명:** 좋아하는 자료라는 표시와 지금 먼저 해야 할 일이라는 표시를 분리합니다.\
  **예시:** 좋아하는 옛 곡은 즐겨찾기만 하고, 오늘 마감인 곡에는 높은 우선순위를 붙입니다.

- [ ] **작성한 날짜를 따라 자료 둘러보기** `FF-241`\
  **설명:** 최근 순 목록뿐 아니라 달력이나 연표에서 내가 작성한 자료를 찾아봅니다.\
  **예시:** 지난봄에 쓴 곡들을 달력에서 훑어보며 잊고 있던 아이디어를 찾습니다.

- [ ] **태그를 큰 분류와 작은 분류로 묶기** `FF-248`\
  **설명:** 태그를 한 단계로만 두지 않고 상위·하위 묶음으로 정리합니다. 기존 태그 이름이나 연결을 강제로 바꾸지 않습니다.\
  **예시:** ‘감정’ 아래에 ‘그리움’, ‘분노’, ‘안도감’을 묶습니다.

- [ ] **이번 검색에서만 결과 잠깐 숨기기** `FF-249`\
  **설명:** 지금 찾는 것과 아닌 자료를 이번 검색 화면에서만 접어둡니다. 원본을 삭제하거나 영구적으로 검색에서 제외하지 않습니다.\
  **예시:** 이미 검토한 결과 다섯 개를 접고 남은 후보만 봅니다.

## 6. 파일로 보관하거나 옮길 때

- [ ] **내보낸 파일을 앱 없이 점검하기** `FF-061`\
  **설명:** 다운로드한 자료 묶음을 오프라인에서 열어 빠진 파일, 읽기 어려운 글자, 형식 문제를 확인하는 작은 도구를 제공합니다. 서버 백업 검사와는 별개입니다.\
  **예시:** 앱 서버가 꺼져 있어도 보관한 ZIP 안의 가사가 정상적으로 읽히는지 확인합니다.

- [ ] **다른 파일의 내용을 미리 보고 가져오기** `FF-062`\
  **설명:** TXT·Markdown 가사나 LyricsCloud 자료 파일을 가져오기 전에 새로 생길 자료와 중복될 자료를 보여줍니다. 비교용 공간에서 먼저 확인할 수도 있습니다.\
  **예시:** 옛 가사 파일 다섯 개를 선택하고 기존 곡과 겹치는 두 개의 처리 방법을 고릅니다.

- [ ] **한 곡에 필요한 자료만 묶어 내보내기** `FF-063`\
  **설명:** 전체 계정 대신 고른 곡과 함께 챙길 가사·라임·프롬프트를 골라 파일로 만듭니다. 앱 없이 볼 수 있는 설명도 함께 담습니다.\
  **예시:** ‘겨울밤’ 한 곡의 작업 자료만 모아 다른 컴퓨터에 옮깁니다.

- [ ] **내 자료 파일에 암호 걸기** `FF-064`\
  **설명:** 개인이 내려받는 자료 묶음을 암호화해 보관합니다. 여는 방법과 암호를 잃었을 때의 한계도 함께 안내합니다.\
  **예시:** 공용 외장하드에 넣을 작품 파일을 암호를 알아야 열 수 있게 만듭니다.

- [ ] **휴지통에서 사라지기 전에 알림 받기** `FF-068`\
  **설명:** 기본 삭제 시각 안내와 별도로, 내가 켜 두면 완전 삭제가 가까운 자료를 알려줍니다. 휴지통 보관 기간 자체는 바꾸지 않습니다.\
  **예시:** ‘3일 뒤 완전 삭제될 곡이 있습니다’라는 알림에서 보관할 곡을 고릅니다.

- [ ] **내 화면 설정만 옮기기** `FF-069`\
  **설명:** 작품 내용 없이 글꼴, 테마, 단축키 같은 개인 설정만 파일로 저장하고 가져옵니다.\
  **예시:** 다른 서버에서 계정을 만들어도 익숙한 글쓰기 설정을 다시 가져옵니다.

- [ ] **내보낼 파일 이름을 내가 정하기** `FF-126`\
  **설명:** 다운로드할 파일 이름에 곡명, 날짜, 버전 등을 어떤 순서로 넣을지 정합니다. 같은 이름이 생기면 덮어쓰지 않도록 구분합니다.\
  **예시:** ‘2026-09-09_겨울밤_가사3안.txt’처럼 보관 규칙을 정합니다.

- [ ] **내 작품집 파일 만들기** `FF-174`\
  **설명:** 선택한 작품과 해설을 묶어 인터넷 연결 없이 볼 수 있는 작품집을 만듭니다. 웹페이지 파일이나 텍스트 책자 형태를 고릅니다.\
  **예시:** EP의 다섯 곡 가사와 작업 후기를 순서대로 담은 개인 작품집을 보관합니다.

- [ ] **두 보관 파일 사이의 변화 비교하기** `FF-251`\
  **설명:** 내가 내보낸 두 자료 묶음을 오프라인에서 비교해 새로 생기거나 바뀐 작품을 확인합니다. 파일이 정상인지 점검하는 도구와는 다른 비교 기능입니다.\
  **예시:** 지난달 ZIP과 이번 달 ZIP을 비교해 수정된 가사만 찾아봅니다.

- [ ] **시간에 맞춰 나오는 가사 파일 만들기** `FF-255`\
  **설명:** 내가 검토한 줄별 시간을 이용해 자막·가사 표시용 LRC 또는 SRT 파일을 만듭니다. 자동으로 음원을 분석해 시간을 맞추는 기능은 아닙니다.\
  **예시:** 후렴이 시작하는 시간을 직접 지정해 영상 편집기에 가져갈 자막 파일을 만듭니다.

- [ ] **개인 자료 파일을 정기적으로 보관하기** `FF-258`\
  **설명:** 사용자가 따로 허용한 위치에 자신의 암호화 자료 파일을 정기적으로 만듭니다. 서버 전체의 운영 백업을 대신하지 않습니다.\
  **예시:** 매주 내 작품 묶음을 지정한 개인 저장 위치에 보관하도록 설정합니다.

## 7. 함께 검토하고 의견을 모을 때

기본 읽기·쓰기 공유가 아니라, 그 위에 더할 댓글·검토·합의 도구입니다. 기존 공유 권한을 넘어서는 접근을 허용하는 기능은 아닙니다.

- [ ] **가사 구간에 댓글 달기** `FF-081`\
  **설명:** 함께 보는 사람이 특정 줄에 의견을 달고 해결 여부를 표시합니다. 댓글을 달아도 본문은 바뀌지 않습니다.\
  **예시:** 후렴의 한 줄에 ‘여기 표현을 더 짧게 하면 어떨까요?’라고 의견을 남깁니다.

- [ ] **특정 시점의 가사만 공유하기** `FF-083`\
  **설명:** 계속 바뀌는 최신본 대신 고른 시점의 내용을 고정해 공유합니다. 검토를 받은 뒤 현재본과 무엇이 달라졌는지도 확인합니다.\
  **예시:** ‘어제 보낸 초안’을 상대가 계속 보게 하고, 오늘 수정 중인 내용은 아직 공개하지 않습니다.

- [ ] **수정 내용을 제안으로 받기** `FF-086`\
  **설명:** 제안 참여를 허용받은 사람이 고친 문장을 제안으로 제출하면 소유자가 채택하거나 거절합니다. 본문을 직접 바꾸는 쓰기 공유와 다릅니다.\
  **예시:** 상대가 바꾼 후렴 두 줄 중 한 줄만 채택하고, 나머지에는 보류 이유를 남깁니다.

- [ ] **곡의 소유자를 다른 사람으로 바꾸기** `FF-090`\
  **설명:** 함께 작업하던 곡의 관리 책임을 다른 계정으로 넘기는 별도 절차를 제공합니다. 무엇이 넘어가는지 양쪽이 확인합니다.\
  **예시:** 팀원이 계속 관리할 곡 한 개를 넘기되 내 다른 곡과 개인 메모는 그대로 둡니다.

- [ ] **함께 작업하는 사람에게 검토 요청하기** `FF-231`\
  **설명:** 어떤 안을 언제까지 봐 달라는 요청을 보내고 검토 대기·완료 상태를 관리합니다. 단순한 읽기 권한 부여와는 다릅니다.\
  **예시:** ‘금요일까지 후렴 2안을 검토해 주세요’라는 요청을 공유한 곡에 붙입니다.

- [ ] **정해둔 질문으로 피드백 받기** `FF-232`\
  **설명:** 허용한 독자가 본문을 고치는 대신 내가 만든 질문에 답하도록 합니다. 답변자의 이름을 다른 참가자에게 숨기는 방식도 선택할 수 있습니다.\
  **예시:** ‘후렴이 기억에 남나요?’와 ‘어느 줄이 어색했나요?’에 대한 답을 모읍니다.

  **예시:** 후렴 1안과 2안 중 어느 쪽을 선호하는지 투표받고 소유자가 최종 선택합니다.

  **예시:** 25분 동안 쓰고 쉬는 방식으로 작업하되 타이머를 끄면 기록하지 않습니다.

- [ ] **작업 화면 배치 여러 개 저장하기** `FF-120`\

  **예시:** ‘가사 집중’에서는 편집기만, ‘자료 비교’에서는 라임과 프롬프트 패널을 함께 엽니다.

- [ ] **집중 중에는 덜 중요한 알림 모으기** `FF-272`\
  **설명:** 집필 중에는 부차적인 알림을 모아뒀다가 나중에 보여줍니다. 저장 실패나 보안 문제는 즉시 알려줍니다.\
  **예시:** 댓글 알림은 쉬는 시간에 보고 ‘저장 실패’는 곧바로 확인합니다.

- [ ] **용도별 글쓰기 설정 여러 개 만들기** `FF-274`\
  **설명:** 이미 있는 글꼴·줄 간격 설정에 더해 여러 조합을 이름 붙여 저장하고 가사·라임·프롬프트별로 골라 씁니다.\
  **예시:** 가사는 큰 글씨와 넓은 줄 간격, 라임 노트는 촘촘한 글씨로 된 설정을 고릅니다.

  **설명:** Android 홈 화면에 짧은 아이디어를 적는 위젯을 둡니다. 앱 화면을 여러 단계 거치지 않고 메모를 시작합니다.\
  **예시:** 잠금 해제 후 홈 화면에서 떠오른 후렴 한 줄을 바로 적습니다.

- [ ] **여러 LyricsCloud 서버를 구분해 쓰기** `FF-264`\
  **설명:** 각 서버 주소와 별칭을 저장하고 어디에 연결했는지 분명하게 보여줍니다. 다른 서버의 계정과 초안을 섞지 않습니다.\
  **예시:** ‘내 서버’와 ‘팀 서버’를 별도 연결로 저장해 구분해서 엽니다.

- [ ] **Windows에서 자료별 창 따로 띄우기** `FF-281`\
  **설명:** 여러 자료를 각기 다른 앱 창으로 열어 두고 비교합니다. 각 창이 어떤 자료를 저장 중인지 구분합니다.\
  **예시:** 한 화면에는 가사, 다른 모니터에는 라임 노트를 띄워 놓고 작업합니다.

## 12. 서버를 직접 운영할 때

- [ ] **문제 신고용 진단 파일 직접 확인하기** `FF-146`\
  **설명:** 사용자가 요청하면 앱 버전과 오류 상태를 모은 진단 파일을 만듭니다. 비밀값을 가린 내용을 먼저 보여주고, 전송할지 직접 고르게 합니다.\
  **예시:** 문제가 생겼을 때 가사 원문이나 로그인 키가 없는지 확인한 뒤 진단 파일만 개발자에게 보냅니다.

- [ ] **샘플 자료로 앱을 체험하기** `FF-160`\
  **설명:** 실제 계정 자료 대신 가짜 곡과 노트가 있는 별도 체험 공간을 만듭니다. 관리자가 이를 준비하는 명령도 제공합니다.\
  **예시:** 친구에게 앱을 보여줄 때 내 미공개 가사 대신 샘플 곡을 엽니다.

- [ ] **새 가입만 잠시 멈추기** `FF-261`\
  **설명:** 관리자가 신규 베타 가입을 일시 중단할 수 있습니다. 이미 허용된 사용자의 로그인과 작업은 계속 유지합니다.\
  **예시:** 테스터 수를 조절하는 동안 새 가입만 닫고 기존 사용자는 계속 이용하게 합니다.

- [ ] **점검 중에도 읽기와 내보내기 유지하기** `FF-262`\
  **설명:** 관리자가 쓰기를 잠시 멈춰야 할 때 가능한 읽기·내보내기는 계속 제공하는 점검 모드를 둡니다. 아직 안 보낸 입력은 보호해야 합니다.\
  **예시:** 안내된 점검 시간에는 수정 대신 기존 가사를 읽고 파일로 보관합니다.

- [ ] **기간을 정해 운영 공지 띄우기** `FF-263`\
  **설명:** 관리자가 공지의 대상 환경과 표시 기간을 정합니다. 기간이 지나면 오래된 안내가 계속 남지 않게 합니다.\
  **예시:** 개발 서버에만 ‘오늘 저녁 점검’ 공지를 표시하고 점검 후 자동으로 내립니다.

- [ ] **위험한 관리자 작업은 두 사람이 확인하기** `FF-265`\
  **설명:** 자료를 크게 바꾸거나 지우는 관리 명령에 두 관리자의 확인을 요구하는 선택 모드를 둡니다. 일상적인 작업까지 무조건 막지는 않습니다.\
  **예시:** 대규모 정리 명령을 한 사람이 요청하고 다른 관리자가 범위를 확인한 뒤 실행합니다.

- [ ] **인터넷이 없는 환경에 설치 준비하기** `FF-269`\
  **설명:** 필요한 설치 자료와 의존 파일을 미리 모아 외부 인터넷 없이 설치할 방법을 정리합니다. Google 로그인처럼 인터넷이 필요한 기능은 따로 구분합니다.\
  **예시:** 인터넷 연결이 제한된 개인 서버에 설치할 자료를 미리 준비합니다.

## 13. AI 보조 기능을 고를 때

이 절의 기능은 모두 선택 사항입니다. 외부 서비스를 쓸 때는 보낼 내용·비용·보관 조건을 먼저 확인하고 동의한 부분만 보냅니다. 원문 자동 교체나 외부 전송을 기본값으로 두지 않습니다. 이런 안전 조건을 별도 아이디어로 세지 않습니다.

- [ ] **AI에게 선택한 표현의 다른 안 받기** `FF-161`\
  **설명:** 내가 고른 부분에 대해서만 다른 표현을 제안받습니다. 결과는 후보로 남고, 내가 채택하기 전에는 원문을 바꾸지 않습니다.\
  **예시:** 후렴 한 줄을 선택해 같은 뜻의 표현 세 가지를 받아 비교합니다.

- [ ] **내 컴퓨터의 AI로 라임 후보 만들기** `FF-162`\
  **설명:** 외부 AI 서비스 대신 내 기기에서 실행하는 모델로 라임 후보를 만드는 방식을 검토합니다. 필요한 성능과 설치 부담을 먼저 확인합니다.\
  **예시:** 인터넷으로 노트를 보내지 않고 내 PC에서 ‘새벽’과 어울리는 후보를 받아봅니다.

- [ ] **뜻이 겹치는 프롬프트 표현 찾아보기** `FF-163`\
  **설명:** 철자는 다르지만 뜻이 비슷한 프롬프트 표현을 AI가 후보로 짚어줍니다. 실제로 불필요한 중복인지 직접 판단합니다.\
  **예시:** ‘soft singing’과 ‘gentle vocal’이 비슷한 지시일 수 있다고 알려주되 삭제하지 않습니다.

- [ ] **다른 자료와 닮은 표현 검토하기** `FF-170`\
  **설명:** 사용을 허용한 자료와 비교해 비슷한 표현과 근거 구간을 보여주는 보조 도구입니다. 표절 여부를 확정하거나 법적 안전을 보장하지는 않습니다.\
  **예시:** 내 이전 곡과 닮은 후렴을 발견해 의도한 반복인지 다른 표현이 필요한지 살펴봅니다.

## 14. 연작의 이야기와 설정을 관리할 때

- [ ] **연작의 인물·용어·말투 사전 만들기** `FF-181`\
  **설명:** 여러 곡이 공유하는 인물, 장소, 설정과 말투를 모아둡니다. 내가 정한 표기와 다른 이름이 등장한 곳도 확인할 수 있습니다.\
  **예시:** 한 연작에서 주인공 이름을 ‘하린’으로 정하고 다른 곡에서 다르게 쓴 곳을 찾습니다.

- [ ] **누가 누구에게 말하는 가사인지 표시하기** `FF-182`\
  **설명:** 곡이나 가사안마다 화자, 듣는 사람, 시점을 적습니다. 내용 자체를 바꾸지 않고 서술 방식의 차이를 비교합니다.\
  **예시:** 1안은 ‘내가 너에게’, 2안은 ‘제삼자가 두 사람을 회상’하는 가사라고 구분합니다.

- [ ] **반복되는 상징을 따라보기** `FF-184`\
  **설명:** 달, 기차, 겨울처럼 내가 중요하게 정한 상징이 어느 곡과 구간에 나오는지 모아봅니다.\
  **예시:** 연작에서 ‘기차’가 등장한 가사들을 살펴보고 같은 의미로 쓰였는지 비교합니다.

- [ ] **이야기 순서와 가사 순서 나눠 보기** `FF-185`\
  **설명:** 실제로 일어난 사건 순서와 노래에서 들려주는 순서를 각각 카드로 배열합니다.\
  **예시:** ‘만남 → 이별 → 재회’라는 사건을 가사에서는 ‘재회 → 만남 회상 → 이별’ 순서로 배치합니다.

- [ ] **내 다른 곡에서 가져온 구절 연결하기** `FF-188`\
  **설명:** 자기 작품의 구절을 다시 쓸 때 어느 곡에서 가져왔는지 연결해 둡니다.\
  **예시:** 첫 곡의 마지막 문장을 마지막 곡의 첫 줄로 가져오고 두 구간을 연결합니다.

## 15. 발음·가창·번안 작업을 할 때

- [ ] **부르는 방법을 가사 밖에 적기** `FF-191`\
  **설명:** 숨 쉴 곳, 늘일 모음, 애드리브와 반복마다 달라질 지시를 가사와 별도로 적습니다. 필요한 구간만 연습용 자료로 뽑을 수 있습니다.\
  **예시:** 후렴 옆에 ‘마지막 모음을 길게’, 두 번째 반복에는 ‘애드리브 추가’라고 표시합니다.

- [ ] **가사 밑에 발음 읽는 법 적기** `FF-193`\
  **설명:** 노래 가사와 별개 줄에 내가 부를 발음을 적습니다. 라임 노트의 단어 설명이 아니라 연습할 가사 전체의 읽는 법을 다룹니다.\
  **예시:** 영어 가사 아래에 실제로 연습할 한글 발음을 줄마다 적습니다.

- [ ] **랩 가사를 박자 칸에 놓기** `FF-194`\
  **설명:** 박자 칸 위에 가사의 음절을 직접 배치하고 강하게 읽을 부분을 표시합니다. 자동 박자 분석은 하지 않습니다.\
  **예시:** 네 박자 중 두 번째와 네 번째에 힘을 줄 단어를 배치해 읽어봅니다.

- [ ] **보컬 파트별 연습 가사 만들기** `FF-196`\
  **설명:** 누가 어느 줄을 부르는지 지정하고 각 파트가 볼 대본을 만듭니다. 주고받는 질문·응답 파트도 구분할 수 있습니다.\
  **예시:** A 보컬의 줄, B 보컬의 줄, 함께 부르는 후렴을 나눠 출력합니다.

- [ ] **연습·공연용 큰 글씨 화면 쓰기** `FF-200`\
  **설명:** 가사를 큰 글자로 보여주는 읽기 전용 화면을 제공합니다. 버튼으로 넘기거나 정한 속도로 자동 스크롤할 수 있습니다.\
  **예시:** 연습 중 태블릿을 세워두고 손가락 한 번으로 다음 구간으로 넘깁니다.

- [ ] **원문과 번안 가사를 나란히 작업하기** `FF-201`\
  **설명:** 직역, 뜻을 살린 번역, 노래하기 위한 번안을 따로 보관하고 원문 줄과 연결합니다. 발음·운율 메모를 달거나 두 언어를 함께 내보낼 수 있습니다.\
  **예시:** 한국어 한 줄이 영어 두 줄로 나뉘는 부분을 연결하고, 노래에 맞춘 번안은 별도 안으로 둡니다.

- [ ] **가사의 감정 흐름 표시하기** `FF-204`\
  **설명:** 구간마다 내가 느끼는 감정의 세기를 표시해 곡의 흐름을 비교합니다. AI가 감정을 단정하는 기능은 아닙니다.\
  **예시:** 1절은 차분하게 2, 후렴은 격하게 5로 표시해 고조되는 흐름을 살펴봅니다.
