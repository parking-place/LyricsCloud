# 1.0.14 Phase 5 — 고지·개발 인수·공유 진입

상태: **계획 검토 / 미착수**. `NF-REQ-044`의 이번 Phase 범위만 수행한다.

## 선행조건과 담당 경계

[P4](4phase.md)의 실제 산출물과 [결정 권한](../Decision-Ownership.md)을 인수한다. [세부 계약](../contracts/DICTIONARY-FONTS.md)을 따른다. 정확한 파일·SDK·명령은 착수 때 기존 구조 안에서 확정한다. 입력은 승인 범위·source SHA·fixture·실제 환경, 출력은 아래 산출물·수용 증거·미실행과 다음 단계 조건이다. 공통 파일은 한 작성자만 맡는다.

## 작업 체크리스트

- [ ] `LC-NF-1.0.14-P5-01` 폰트별 라이선스/저작권/배포 고지와 지원 문자·fallback·문제 해결을 문서화한다.
- [ ] `LC-NF-1.0.14-P5-02` 동일 SHA 개발 인수와 최신 Future 변경 대조를 끝내고 미완료 사전 제공 gate를 숨기지 않는다.
- [ ] `LC-NF-1.0.14-P5-03` 1.0.12의 개인 흐름 점검과 이 패치 결과를 합쳐 OPS-NF-002 공유 진입을 재판정한다. 1.1.0은 권한 모델 승인 때만 확정하며 번호 때문에 자동 시작하지 않는다.

## 수용 기준

`AC-1.0.14-05`: 개인 필수 요구와 외부 gate를 반영한 공유 go/no-go 기록이 있다.

## 검증·완료·인계

- [ ] 위 작업과 수용 기준에 실제 증거·환경·SHA를 연결하고 실패/미실행을 기록했다.
- [ ] 원문·인가·복구·기존 사용자 계약을 유지하고 [품질 게이트](../QUALITY-GATES.md)의 영향 검사만 수행했다. 같은 성공 결과를 반복하지 않았다.
- [ ] 설계/문서 단계는 검토와 결정 증거로, 구현 단계는 필수 CI·동일 SHA 개발 공개 smoke 및 플랫폼별 실제 앱 증거로 인수했다.
- [ ] [Future 검수](../FUTURE-INTAKE.md)를 push 전/Phase 완료 시 대조하고 같은 변경은 이전 기록을 참조했다.
- [ ] SDK/외부 제공·실제 OS/기기·서명/스토어·release gate의 상태를 숨기지 않았다.

[1.1.0](../1.1.0/README.md)에 산출물·지원 범위·계약·남은 gate를 전달한다. 모든 배정 Phase 인수 뒤에도 main/release 서버 변경은 [릴리스 정책](../RELEASE-POLICY.md)의 별도 현재 승인을 따른다.
