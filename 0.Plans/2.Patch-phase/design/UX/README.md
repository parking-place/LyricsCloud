## 아키텍처·기술 기준

기존 Docker/Node.js/PostgreSQL·TypeScript·CodeMirror/Yjs·온라인 우선 PWA 계약을 유지한다. 새로운 인가/자료 형식/플랫폼은 해당 Proposed ADR의 승인 범위에서만 변경한다. native 기술/편집기 선택은 spike 후 확정한다. 이 문서는 선행 설계 계획이며 앱/스키마/배포를 변경하지 않는다.

## 제외 범위

이 설계 작업에서 production UI 재작성·runtime 버전 증가·운영 배포는 하지 않는다.

## 설계 작업 완료 정의

- [ ] 다섯 Phase의 수용/완료 기준과 작업 ID 증거가 연결되어 있다.
- [ ] 현재 기능 범위에서 원문 유실·비허용 자료 노출·인증 우회·핵심 흐름 실패가 남아 있지 않다.
- [ ] 실제 실행한 검증과 모사/미실행을 구분하고 정확한 SHA를 기록했다.
- [ ] 현재 문서·사용자 안내·migration/rollback·남은 위험을 인계했다.
- [ ] 구현 버전은 전체 CI·동일 SHA 개발 smoke, 문서-only는 문서/디자인 승인 검증을 완료했다.
- [ ] 정식 배포는 완료 표시와 별개로 release 권한/manifest를 확인한다.

[요구 추적표](../../Requirements-Traceability.md)의 상태를 갱신하되 범위 삭제로 완료를 만들지 않는다. Phase 완료 때 [추가 기능 검수 인수](../../FUTURE-INTAKE.md)를 확인하며, 체크·설명·범위 변경을 현재 설계나 구현에 자동 편입하지 않는다.
