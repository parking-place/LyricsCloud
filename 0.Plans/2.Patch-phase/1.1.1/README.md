# 1.1.1 — 링크 공개 읽기·공개 범위 제어

상태: **P1 완료 / P2 진행**. public-link read의 256비트 fragment capability·digest-only 저장·명시 필드·만료/회수·cache/noindex 경계를 확정했고 서버 기반을 구현한다.

## 목표

링크 소지자가 지정한 자료만 읽도록 고엔트로피 공유 링크와 만료·회수·노출 제어를 제공한다.

## 요구사항

`NF-REQ-034`, `NF-REQ-036`. 세부 의미와 완료 판정은 [요구사항 추적표](../Requirements-Traceability.md)를 따른다. 하나의 요구가 여러 패치에 걸치면 모든 담당 범위를 검증하기 전 전체 요구를 완료 처리하지 않는다.

## 선행조건과 승인

- [1.1.0 P5](../1.1.0/5phase.md)의 실제 인수와 현재 파일 담당 경계 확인.

## 설계의 고정 조건

- 링크 공개는 개인 workspace의 공개 가입과 다르며 공유 capability만 부여한다.
- 공유 token은 6자리 beta code와 별개의 고엔트로피 값으로 생성하고 로그/referrer에 남기지 않는다.
- 링크 회수는 향후 접근을 막는 의미이며 이미 복사한 내용을 원격 삭제한다고 약속하지 않는다.

## 대표 수용 사례

| ID | 입력·상황 | 기대 결과 |
|---|---|---|
| `AC-1.1.1-01` | 비로그인 브라우저가 유효 링크를 열기 | 허용된 자료만 읽으며 private workspace 진입은 못 한다. |
| `AC-1.1.1-02` | 링크 회수 후 이전 탭/WS/API 접근 | 이후 데이터가 거부되고 새로운 수정이 전달되지 않는다. |
| `AC-1.1.1-03` | 허용 범위를 넘어 revision/메모 URL 요청 | 읽기 권한을 상속하지 않으며 기본 거부된다. |
| `AC-1.1.1-04` | crawler·OG·공용 cache 경로 | 공개 승인 범위 밖 제목·본문·share token이 노출되지 않는다. |

## 범위 밖

다른 패치의 신규 기능·사용자 미선택 아이디어·승인 없는 운영/플랫폼 변경은 제외한다.
