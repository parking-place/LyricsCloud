# 1.1.7.a — 계정 닉네임·프로필 사진 및 로고 홈 이동 추가 계획

상태: **계획 초안, 구현 미착수**. 2026-09-16 사용자 요청의 두 웹 기능을 기존 1.1.7 UX 개선과 구분해 추적한다. 현재 실행 원본은 [개발 STATUS](../../1.%20Dev-phase/STATUS.md)의 **1.1.8 P4 `review`**이며, 이 문서로 Phase를 완료하거나 Windows 보류·후속 의존성을 우회하지 않는다.

`1.1.7.a`는 사용자가 지정한 **계획 폴더/변경 요청 ID**다. [제품 버전 규칙](../VERSIONING.md)의 `major.minor.patch` 형식이 아니므로 `VERSION`, `APP_VERSION`, package version, Docker alias, Git tag `v1.1.7.a`에 쓰지 않는다. 이미 발행된 `v1.1.7`도 변경하지 않는다. 실제 구현·출시를 시작할 때 현재 배포/진행/예정 버전과 선행 조건을 재검토해 **다음 가용 숫자 patch**와 Phase ID로 재배정하고, 사용자에게 일정·의존성 및 출시 범위를 확인한다. 지금 적은 P1~P5는 그때 사용할 작업 초안이며 활성 Phase가 아니다.

## 요청 범위와 기준 화면

1. 로그인한 사용자가 계정 설정에서 **닉네임**을 수정하고 **프로필 사진을 파일로 선택·변경·제거**한다. 결과가 저장 성공 후 셸·홈 인사말·계정 화면에 반영되고, 새로고침·재로그인·Google 프로필 변화 뒤에도 사용자가 설정한 값을 유지한다. Google 계정 이메일·인증 주체·공유 ID는 바뀌지 않는다.
2. 사용자가 지목한 **우측 상단 로고/아이콘**을 클릭하거나 키보드로 실행하면 창작 홈 `/workspace`로 간다. 데스크톱 좌측 rail의 브랜드와 모바일 헤더 브랜드가 실제 후보이며, 현 우측 상단에는 설정/프로필 요소가 있으므로 [P1](1phase.md)에서 실제 PC·모바일 클릭 대상을 확인한다. 설정·로그아웃 아이콘을 홈으로 재해석하지 않는다. 저장되지 않은 편집은 기존 이탈 보호 계약을 지킨다.

기준: [설정 화면 설명](../../Mock-up/15-settings/README.md)·[정적 목업](../../Mock-up/15-settings/mockup.html), 웹 `settings-screen.tsx`, `app-shell.tsx`, `auth-screen.tsx`, `api/profile/route.ts`, `profile-input.ts`, DB `owned.ts`·`auth.ts`·`beta-signup.ts`. 원본 Sketch/Mock-up/Implementation-Stack은 이번 계획 작성에서 수정하지 않는다.

## 현재 구조에서 반드시 해결할 틈

- `user_profiles`와 인증된 `GET/PATCH /api/profile`은 존재하지만 설정 화면에는 편집 UI가 없다. 현재 입력 계약은 HTTP(S) `avatarUrl`만 받으며 로컬 사진 업로드·검증·서버 저장은 없다.
- 현재 PATCH는 `avatarUrl`을 생략하면 `null`로 정규화하므로 닉네임만 바꿀 때 기존 사진을 지울 수 있다. 이름/사진의 **독립 변경·명시적 제거** 계약이 필요하다.
- Google 인증의 `upsertIdentity`와 베타 가입 upsert가 `user_profiles` 이름·사진을 갱신한다. 사용자 지정값은 후속 로그인/가입 재시도에도 덮이지 않아야 한다.
- 공유 표시 이름은 `user_profiles`와 연결된다. 닉네임 변경이 공개/선택 공유의 표시 이름과 과거 기록에 미치는 영향·공개 범위를 P1에서 확정한다. 프로필 사진은 공유 화면에 자동 공개하지 않는다.

## 전체 수용 기준

- `AC-117A-01`: 닉네임만/사진만 변경과 사진 제거를 각각 명시적으로 저장하며, 실패 시 이전 서버 값과 사용자의 입력/미리보기를 구분한다.
- `AC-117A-02`: Google 재로그인·새 탭·다른 기기·서버 재시작 후 사용자 지정값이 유지되고, OAuth 이메일/주체/공유 ID/타 사용자 값은 바뀌지 않는다.
- `AC-117A-03`: 잘못된 형식·과대 용량·위장된 이미지·인증/소유권 실패 파일은 저장/제공하지 않고 기존 사진을 보존한다.
- `AC-117A-04`: 승인한 로고/아이콘의 마우스·터치·키보드 실행은 홈으로 가되, 미전송 입력을 강제로 버리지 않고 설정·로그아웃의 기존 기능을 보존한다.
- `AC-117A-05`: PC/모바일·light/dark·좁은 rail과 접근성 대리 검증에서 현재 이름/사진·홈 이동의 결과가 이해 가능하다.

제외: Google 계정 프로필 자체 편집, 이메일/로그인 주체 변경, 임의 원격 사진 URL을 새 입력 수단으로 홍보, 계정별 공개 프로필 페이지, Windows 네이티브 앱 수정, 이번 계획만으로 main/릴리스 서버 배포. 실제 릴리스는 [품질 게이트](../QUALITY-GATES.md)와 [릴리스 정책](../RELEASE-POLICY.md)을 적용한다.
