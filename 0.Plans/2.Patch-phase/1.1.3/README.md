# 1.1.3 — 링크 쓰기·게스트 권한 경계

상태: **비로그인 guest 쓰기 정책 명시 승인 대기 / 구현 미착수**. 번호는 미발행 작업 배정이며 배포 승인이 아니다.

## 목표

읽기 공개 범위 안에서 링크 기반 쓰기를 명시적으로 제공하되 게스트 정책·회수·남용 방어를 먼저 승인한다.

## 요구사항

`NF-REQ-035`, `NF-REQ-036`. 세부 의미와 완료 판정은 [요구사항 추적표](../Requirements-Traceability.md)를 따른다. 하나의 요구가 여러 패치에 걸치면 모든 담당 범위를 검증하기 전 전체 요구를 완료 처리하지 않는다.

## 선행조건과 승인

- [1.1.2 P5](../1.1.2/5phase.md)의 실제 인수와 현재 파일 담당 경계 확인.

## 설계의 고정 조건

- 링크를 가진 모두의 쓰기에 비로그인 guest를 포함하는 정책을 사용자에게 명시 승인받는다.
- 로그인 사용자만 허용하는 대안은 원래 공개 쓰기 요구의 동등한 완료로 처리하지 않는다.
- 쓰기 capability는 읽기 capability보다 범위가 넓을 수 없고 만료/회수 순서를 정의한다.

## 대표 수용 사례

| ID | 입력·상황 | 기대 결과 |
|---|---|---|
| `AC-1.1.3-01` | 읽기 selected + 쓰기 public-link | UI와 API가 거부하고 ACL은 유지된다. |
| `AC-1.1.3-02` | guest token을 다른 자료 ID로 재사용 | 차단되고 target 자료의 존재도 불필요하게 노출하지 않는다. |
| `AC-1.1.3-03` | 수많은 병렬 update·재시작 후 재시도 | 지속 제한과 owner 중지 기능이 동작한다. |
| `AC-1.1.3-04` | guest 정책 승인/보존 회귀가 미완료 | 공개 쓰기를 활성화하거나 충족으로 표시하지 않는다. |

## 범위 밖

다른 패치의 신규 기능·사용자 미선택 아이디어·승인 없는 운영/플랫폼 변경은 제외한다.
