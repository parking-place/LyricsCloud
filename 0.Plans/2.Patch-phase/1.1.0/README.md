# 1.1.0 — 지정 사용자 읽기 공유 기반

상태: **P1~P5 완료 / 정식 릴리스 준비됨**. selected-read 서버·UI에 자료/owner 격리, reader write 차단, offline 회수, collaboration 재시작·만료 회귀를 최종 후보 `aa4d07f`의 전체 CI·네 dev image와 동일 SHA 공개 개발 인수로 완료했다. public link·write·guest는 계속 비활성이다.

## 목표

개인 앱에서 공유 가능한 앱으로 전환하는 권한 경계를 승인받고 지정한 계정에 한정한 읽기 공유를 제공한다.

## 요구사항

`NF-REQ-034`, `NF-REQ-036`. 세부 의미와 완료 판정은 [요구사항 추적표](../Requirements-Traceability.md)를 따른다. 하나의 요구가 여러 패치에 걸치면 모든 담당 범위를 검증하기 전 전체 요구를 완료 처리하지 않는다.

## 선행조건과 승인

- [1.0.14 P5](../1.0.14/5phase.md)의 실제 인수와 현재 파일 담당 경계 확인.
- 공유 ADR와 마이너 진입 사유·호환·안전성 승인. 패치 횟수로 자동 진입하지 않는다.

## 설계의 고정 조건

- 마이너 전환은 새로운 owner/actor·인가 모델의 승인과 개인 기능 인수가 모두 끝날 때만 허용한다.
- 처음에는 private와 selected read만 제공한다. public link와 write는 기본 비활성 상태다.
- 곡 공유에 연결된 라임·프롬프트·가사 버전·메모·revision이 자동으로 포함되지 않게 공유 필드를 명시한다.

## 대표 수용 사례

| ID | 입력·상황 | 기대 결과 |
|---|---|---|
| `AC-1.1.0-01` | owner가 A에게 특정 가사만 공유 | A는 해당 가사만 읽고 연결 라임·메모·다른 버전은 읽지 못한다. |
| `AC-1.1.0-02` | 사용자 B가 ID/URL/API/WS를 직접 조작 | 서버와 RLS가 읽기/쓰기를 모두 거부한다. |
| `AC-1.1.0-03` | 읽는 도중 owner가 권한 회수 | 기존 구독과 이후 API 읽기가 차단되고 캐시로 새 자료가 새지 않는다. |
| `AC-1.1.0-04` | 마이너 전환 승인이 없음 | 현재 1.0.x를 유지하며 ACL schema를 선행 적용하지 않는다. |
