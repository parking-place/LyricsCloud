# 1.0.1 Phase 9 — 권한·동시성·복구·잔여 P6 통합 인수

상태: **계획 검토 / 구현 미착수**. 문서 작업만으로 실행 STATUS·runtime version을 바꾸지 않는다.

## 목표와 경계

기존 P6 성공 증거는 재사용하고 병합 CI의 save round CV 130.793>75 실패 원인·실제 기기·공개 인수 잔여를 닫을 근거를 연결한다.

담당 경로: 영향 테스트·복구 runbook·인수 기록. 정확한 파일·명령은 착수 당시 소스로 확정한다. 다른 Phase 기능·후속 선택 아이디어·승인 없는 운영 변경은 포함하지 않는다.

## 선행조건·입출력

- [P8](8phase.md)의 산출물·해당 구현 인수, 소비할 ADR/PROD/OPS와 파일 소유권을 확인한다.
- 입력은 정확한 SHA·계약·합성 fixture·실제 환경과 잔여 결함이다. 출력은 아래 작업의 산출물과 수용 증거·실패 복구·다음 담당자의 경계다.
- [베타 계약](../contracts/BETA-ACCESS.md), [버전 정책](../VERSIONING.md), [릴리스 정책](../RELEASE-POLICY.md), [품질 게이트](../QUALITY-GATES.md)를 소비한다.
- P2는 P1의 승인된 코드/운영 계약을 즉시 소비한다. P3/P4 전에는 신규 가입을 열지 않으며 CLI 인수를 UI·로고 최종 승인까지 기다리게 하지 않는다.

## 작업 체크리스트

- [ ] `LC-NF-1.0.1-P9-01` P6의 REVIEW-01~14를 현재 수정 SHA에서 다시 판정하고, unsent draft·PWA update·template recovery·export projection 문제의 잔여 P0/P1을 차단한다.
- [ ] `LC-NF-1.0.1-P9-02` CLI 발급/refresh와 callback·ls의 실제 PostgreSQL 경쟁 테스트, 인증 키 파일 권한, read-only 이미지 운영 및 container canary/비밀 스캔을 수행한다.
- [ ] `LC-NF-1.0.1-P9-03` 빈 설치와 P5/P6 업그레이드·rollback·실제 암호화 백업 복원을 시험한다. OPS-100-001은 구축 증거 또는 사용자 재승인 예외 없이는 닫지 않는다.
- [ ] `LC-NF-1.0.1-P9-04` 코드/DB/인증 설정·키 백업·restore·관측·지원 책임자·kill switch·rollback 절차를 릴리스 체크리스트로 정리한다.
- [ ] `LC-NF-1.0.1-P9-05` 각 기능의 성공 증거를 재사용하고 미확인 실제 OS·공개 개발환경·P6 병합 성능 실패만 영향에 맞게 추가 검증한다.

## 구체적 수용 기준

1. 기존 P6 성공 증거는 재사용하고 병합 CI의 save round CV 130.793>75 실패 원인·실제 기기·공개 인수 잔여를 닫을 근거를 연결한다.
2. 실제 PostgreSQL에서 발급/소비/refresh/ls·키 회전·탈퇴/정지·교차환경·교차계정 경쟁과 거부를 검증한다.
3. 빈 설치/업그레이드/rollback·암호화 복원을 검증한다. OPS-100-001은 실제 구축/복원 또는 현재 위험의 새 예외 승인 전 열린 상태다.

## 검증과 완료 조건

- [ ] 영향받은 실제 트리거와 결과를 기존 검사 중심으로 검증하고 명령·환경·SHA·미실행을 기록했다. 동일 입력/환경의 성공 증거를 재사용한다.
- [ ] 원문·권한·기존 사용자·복구 불변조건과 위 수용 기준에 실제 증거가 있다.
- [ ] 구현 Phase의 필수 CI·동일 SHA 개발 배포·공개 smoke와 상태 기록을 인수했다. 문서-only 변경은 링크·범위·결정 검토로 구분했다.
- [ ] [FUTURE-INTAKE](../FUTURE-INTAKE.md)에 따라 저장소 전역 Future 변경을 push 전 및 Phase 완료 때 한 번 대조하고 동일 변경은 재처리하지 않았다.
- [ ] 실제 OS/기기·Google 설정·백업·외부 승인 잔여를 숨기지 않았으며 main/release 서버 변경을 별도 현재 승인 없이 실행하지 않았다.
