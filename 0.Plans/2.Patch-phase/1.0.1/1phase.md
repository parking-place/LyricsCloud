# 1.0.1 Phase 1 — P6 인수·IME/UI 재현·베타와 릴리스 계약

상태: **진행 중**. 2026-09-09 사용자가 전체 1.0.1 실행을 승인했고 권장 베타·가입·릴리스 계약을 확정했다.

## 목표와 경계

부모가 확인한 P5 병합 SHA/동일 tree/CI 단일 실패와 실제 OS·공개 인수 미완료를 구분한다. P6 review를 임의 종료하지 않는다.

담당 경로: 계약·인수 문서, editor/auth/UI 원인 경로 읽기. 정확한 파일·명령은 착수 당시 소스로 확정한다. 다른 Phase 기능·후속 선택 아이디어·승인 없는 운영 변경은 포함하지 않는다.

## 선행조건·입출력

- [P6 인수표](../P6-AND-BUG-INTAKE.md)의 실제 선행 인수, 소비할 ADR/PROD/OPS와 파일 소유권을 확인한다.
- 입력은 정확한 SHA·계약·합성 fixture·실제 환경과 잔여 결함이다. 출력은 아래 작업의 산출물과 수용 증거·실패 복구·다음 담당자의 경계다.
- [베타 계약](../contracts/BETA-ACCESS.md), [버전 정책](../VERSIONING.md), [릴리스 정책](../RELEASE-POLICY.md), [품질 게이트](../QUALITY-GATES.md)를 소비한다.
- P2는 P1의 승인된 코드/운영 계약을 즉시 소비한다. P3/P4 전에는 신규 가입을 열지 않으며 CLI 인수를 UI·로고 최종 승인까지 기다리게 하지 않는다.

## 작업 체크리스트

- [x] `LC-NF-1.0.1-P1-01` 로컬 Codex의 P6 최종 SHA·수정/미수정 이슈·CI·DB/브라우저 증거를 인수한다. 원격 7448f47은 참고점일 뿐 최종 완료본으로 가정하지 않는다.
- [ ] `LC-NF-1.0.1-P1-02` Windows 실제 Microsoft 한국어 IME로 바라봐, 마냥, 마땅한을 직접 입력해 최초 손실 지점을 찾는다. OS·브라우저·입력기 버전, 새 문서/기존 문서, 단일/다중 탭과 연결 상태를 기록한다.
- [ ] `LC-NF-1.0.1-P1-03` 라임뿐 아니라 가사·프롬프트·제목·메모·검색·태그·템플릿 입력에 같은 검사 행렬을 적용한다. 붙여넣기와 Playwright fill 결과를 실제 IME 결과로 대체하지 않는다.
- [ ] `LC-NF-1.0.1-P1-04` localhost·개발 서버 직접 경로·dev.example.test의 SHA/정적 자산/CSP/서비스워커/콘솔 오류를 비교해 클릭 불능과 테마 누락을 별도 결함으로 등록한다.
- [x] `LC-NF-1.0.1-P1-05` 베타 가입을 코드·메일 입력→Google 검증→한 트랜잭션의 코드 소비와 앱 접근권 부여로 정의한다. 로그인 시도만으로 allowlist를 추가하는 해석은 거부한다.
- [x] `LC-NF-1.0.1-P1-06` 해시 allowlist 이행, 코드 생성/ls/refresh, 동시 사용과 OAuth 실패, 개발/릴리스 환경 격리의 ADR-NF-001·PROD-NF-001 대안을 승인받는다.
- [x] `LC-NF-1.0.1-P1-07` 1.0.1 필수 범위를 유지하고, 현재 제품 세대의 버그 수정·기능 추가·개선에는 patch를 우선하고 공유 인가 구조 같은 제품 세대 전환에만 minor를 검토하는 규칙과 major 1 고정, 다자리 버전, 릴리스 때만 main 병합, Release-latest 추가를 문서 규칙으로 확정한다.
- [x] `LC-NF-1.0.1-P1-08` 1.0.0 기존 릴리스 이력은 보존하고 1.0.1을 초대 운영을 시작하는 첫 Private Beta로 명명한다. 배포 승인과 계획 승인을 구분한다.

## 구체적 수용 기준

1. 부모가 확인한 P5 병합 SHA/동일 tree/CI 단일 실패와 실제 OS·공개 인수 미완료를 구분한다. P6 review를 임의 종료하지 않는다.
2. 라임노트에서 바라봐→바라보, 마냥→마냐, 마땅한→마ㄸㅎ를 재현하고 가사·프롬프트·제목·메모·검색·태그·템플릿 비교 행렬을 만든다.
3. P2가 소비하는 코드 상태·권한·랜덤·한도·출력 계약부터 승인하여 긴급 CLI를 뒤 UI/브랜드 작업에 종속시키지 않는다.

## 검증과 완료 조건

현재 증거와 잔여 행렬은 [P1 인수·재현 기록](../../../docs/runbooks/1.0.1-phase1-intake.md)에 남긴다.

- [ ] 영향받은 실제 트리거와 결과를 기존 검사 중심으로 검증하고 명령·환경·SHA·미실행을 기록했다. 동일 입력/환경의 성공 증거를 재사용한다.
- [ ] 원문·권한·기존 사용자·복구 불변조건과 위 수용 기준에 실제 증거가 있다.
- [ ] 구현 Phase의 필수 CI·동일 SHA 개발 배포·공개 smoke와 상태 기록을 인수했다. 문서-only 변경은 링크·범위·결정 검토로 구분했다.
- [ ] [FUTURE-INTAKE](../FUTURE-INTAKE.md)에 따라 저장소 전역 Future 변경을 push 전 및 Phase 완료 때 한 번 대조하고 동일 변경은 재처리하지 않았다.
- [ ] 실제 OS/기기·Google 설정·백업·외부 승인 잔여를 숨기지 않았으며 main/release 서버 변경을 별도 현재 승인 없이 실행하지 않았다.
