# 1.1.4 — 공유 안정성·복구 동선 정리

상태: **계획 검토 / 구현 미착수**. 번호는 미발행 작업 배정이며 배포 승인이 아니다.

## 목표

이미 제공한 읽기·쓰기 공유를 실제 장시간/다중 기기 상황에서 검증하고 경계 결함과 복구 동선을 보완한다.

## 요구사항

`NF-REQ-034`, `NF-REQ-035`, `NF-REQ-036`. 세부 의미와 완료 판정은 [요구사항 추적표](../Requirements-Traceability.md)를 따른다. 하나의 요구가 여러 패치에 걸치면 모든 담당 범위를 검증하기 전 전체 요구를 완료 처리하지 않는다.

## 선행조건과 승인

- [1.1.3 P5](../1.1.3/5phase.md)의 실제 인수와 현재 파일 담당 경계 확인.

## 설계의 고정 조건

- 이전 공유 패치의 기본 회수·인가·초안 보호는 출시 필수이며 이 단계까지 미루지 않는다.
- 소유자 복원·삭제·동시 writer 재접속의 기대 상태를 사건 순서로 정의한다.
- 자동화된 빠른 반복 시험과 실제 장시간 브라우저·절전·복귀 증거를 구분한다.

## 대표 수용 사례

| ID | 입력·상황 | 기대 결과 |
|---|---|---|
| `AC-1.1.4-01` | 기기 절전·네트워크 전환·서버 재시작 반복 | 원문·권한·영수증이 수렴하고 대기 queue가 무한 증가하지 않는다. |
| `AC-1.1.4-02` | owner가 복원 중 offline writer 재접속 | 승인된 복원/병합 정책과 서로의 원문 보존을 확인한다. |
| `AC-1.1.4-03` | 권한 회수 후 다른 계정 로그인 | 이전 actor의 자료·초안이 다음 계정에 노출되지 않는다. |
| `AC-1.1.4-04` | 가속 소크만 실행한 경우 | 실제 장시간·실기기 검증을 통과했다고 기록하지 않는다. |

## 범위 밖

문서/검증만 발생하면 별도 소프트웨어 발행 없이 기록한다.
