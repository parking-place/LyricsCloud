# 안정화·회귀·마이너 진입 계약

## 안정화의 의미

1.0.2는 실제 Private Beta 사용의 보완, 1.0.12는 개인 창작 확장의 통합, 1.1.4는 공유의 장시간/복구 동선 보완을 다룬다. 선행 버전에서 원문 유실·인증 우회·필수 복구 오류를 남긴 채 이 단계로 미루어 출시하지 않는다.

등록한 결함마다 관찰/정적 추정/격리 재현/실제 DB 재현/브라우저 재현/물리 IME 인수를 구분한다. 같은 오류를 여러 보고서에서 발견했다고 여러 건의 수정 성과로 세지 않는다. 입력된 원문과 서버/기기/복사 결과를 합성 fixture의 checksum·정확 비교로 확인한다.

## 성능 변경

같은 코드 경계·입력·기기·지원 런타임에서 baseline과 후보를 교차 측정한다. 평균 외에 p95·메모리 최대치·queue 크기·부하 후 회수 상태를 기록한다. 결과 동등성·인가·오류·재시도·데이터 보존 중 하나라도 달라지면 성능 수치만으로 반영하지 않는다.

빠른 반복 저장 함수 시험은 실제 24시간 브라우저/절전/재연결 검증과 다르다. 최종 인수에서는 어떤 검사를 수행했는지 정확히 기록한다. 성능 개선이 없으면 가독성/안전성 목적을 명시하거나 변경을 넣지 않는다.

## 릴리스 번호 사용

검토 후 앱 코드 변경이 없으면 문서/검증 산출물로만 종료한다. 빈 릴리스, 인위적 대규모 포맷 변경, 마이너 도달을 위한 patch 수 채우기는 금지한다. 후속 번호가 실제 발행과 충돌하면 [버전 정책](../VERSIONING.md)의 다음 가용 patch 규칙을 적용한다.

## 공유 진입 게이트

공유 모델을 도입하기 전 개인 입력/복사/내보내기·owner RLS·초안 복구·실제 운영 책임을 인수한다. owner/actor·R/W 집합·public capability·권한 철회·캐시/WS·백업/복구 ADR을 승인한다. 조건을 만족하면 1.1.0을 검토하며, 만족하지 못하면 1.0.x에서 보완한다. 패치 번호 크기나 달력은 진입 조건이 아니다.
