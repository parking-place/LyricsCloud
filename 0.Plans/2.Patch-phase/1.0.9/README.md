# 1.0.9 — 라임·프롬프트 사용자정렬

상태: **P1~P4 인수 완료 / P5 최종 후보 준비**. 실제 물리 기기 미실행과 `OPS-100-001` 예외를 유지한다.

## 목표

곡에서 검증한 이동 계약을 라임 노트와 프롬프트로 확장하고 목록 보기와 함께 사용한다.

## 요구사항

`NF-REQ-028`. 세부 의미와 완료 판정은 [요구사항 추적표](../Requirements-Traceability.md)를 따른다. 하나의 요구가 여러 패치에 걸치면 모든 담당 범위를 검증하기 전 전체 요구를 완료 처리하지 않는다.

## 선행조건과 승인

- [1.0.8 P5](../1.0.8/5phase.md)의 실제 인수와 현재 파일 담당 경계 확인.

## 다섯 Phase

1. [P1 — 계약·실패 사례·담당 경계](1phase.md)
2. [P2 — 핵심 기반·저장과 서버](2phase.md)
3. [P3 — PC·모바일 사용자 흐름](3phase.md)
4. [P4 — 실패·권한·복구 회귀](4phase.md)
5. [P5 — 문서·개발 인수·후속 연결](5phase.md)

## 설계의 고정 조건

- 라임·프롬프트는 각각 독립된 owner 순서를 가지며 곡이나 전역 핀과 혼합하지 않는다.
- 프롬프트 자료 카드의 순서와 한 프롬프트 안의 토큰 순서는 별개다.
- 공유 자료가 미래에 등장해도 개인 순서가 owner의 자료 metadata를 바꾸지 않게 경계를 둔다.

## 대표 수용 사례

| ID | 입력·상황 | 기대 결과 |
|---|---|---|
| `AC-1.0.9-01` | 프롬프트 카드를 이동한 뒤 전체 복사 | 자료 카드 순서만 바뀌고 토큰 순서와 출력은 같다. |
| `AC-1.0.9-02` | 라임 목록의 길게 누르기와 드래그 | 복사와 이동이 중복 실행되지 않는다. |
| `AC-1.0.9-03` | 즐겨찾기 필터에서 삭제→복원 | 자료가 중복되지 않고 계약한 개인 위치로 돌아온다. |
| `AC-1.0.9-04` | 세 자료 유형 순서를 연속 변경 | 각 유형의 순서와 전역 핀이 독립적으로 유지된다. |

## 범위 밖

다른 패치의 신규 기능·사용자 미선택 아이디어·승인 없는 운영/플랫폼 변경은 제외한다.

## 계약과 인수

[세부 계약](../contracts/LIBRARY-SUNO.md) · [품질 게이트](../QUALITY-GATES.md) · [버전 규칙](../VERSIONING.md) · [릴리스 정책](../RELEASE-POLICY.md). 코드가 바뀌지 않은 연구/검증만으로 제품 tag를 발행하지 않는다. P5는 후보 인수이며 정식 main/Release/운영 변경은 별도 현재 승인 뒤 실행한다.
