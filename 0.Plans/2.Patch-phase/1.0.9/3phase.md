## 실행·증거 기록

[공통 명령·검증](../QUALITY-GATES.md)을 먼저 읽는다. 기존 runner의 영향받은 검사를 우선 사용하고 필요할 때만 회귀를 보강한다. 지원 환경에서 관련 DB/E2E를 선택하며 동일 변경의 full suite는 로컬/CI 중 한 곳과 필수 게이트만 따른다. native은 승인된 SDK/플랫폼 명령을 기록한다. 없는 도구·실제 IME·물리 기기 검증을 모사 결과로 통과시켰다고 표시하지 않는다. 문서-only Phase는 링크·범위·결정·설계 검토로 별도 인수한다.

- 후보 `0236ee3018e00b65d634ea6ad928f60cec7d2732`, 원격 PR #61, GitHub Actions run `34575779766` 재실행의 verify·네 dev image 게시/서명: PASS.
- 실제 PostgreSQL 연속 선두 이동 회귀 3건과 전체 CI의 unit/DB·migration·production image·복원/rollback·보안 검사를 통과했다.
- 전체 Chromium 358건은 322 PASS·의도적 36 skip이다. 첫 실행에서 기존 1.0.8 HTML5 drag 1건이 일회성으로 실패했으나 같은 후보의 로컬 6회와 동일 SHA 재실행 전체가 PASS했고, 새 1.0.9 검사는 두 실행 모두 PASS했다.
- 동일 SHA 개발 서버의 `1.0.9`, `dev`, `p3`, schema `1002_library_manual_order.sql`, 네 서비스 healthy를 확인했다. 공개 desktop/mobile에서 라임·프롬프트 연속 이동→재진입, prompt 원문 불변, long-press/drag 분리, 좁은 화면 overflow 없음이 PASS했고 합성 자료를 제거했다.
- 공개 인수 중 `sort_rank::text` 출력 별칭이 공유 라임/프롬프트 조회의 numeric rank 정렬을 문자열로 가로채 연속 선두 이동을 무효화하던 결함을 발견했다. 실제 열을 qualified 정렬하고 갱신 행 수를 강제했으며 두 번 연속 이동 DB 회귀로 닫았다.
