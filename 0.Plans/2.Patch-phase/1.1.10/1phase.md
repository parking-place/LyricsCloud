# 1.1.10 Phase 1 — 계약·실패 사례·담당 경계

- 상태: **검토** (`review`, 계획 미착수)
- 단계 목적: Android 네이티브 개발안·읽기와 복사의 계약·실패 사례·담당 경계을 완료하고 다음 단계에 검증 가능한 입력을 전달한다.
- 문서 작성과 구현/배포 완료는 별개다.

> 구현 담당자는 승인된 범위에서 실패 재현→최소 구현→관련 회귀→검토 가능한 commit을 수행한다. 로컬 Codex의 기존 수정·초안·운영 데이터를 덮어쓰지 않는다.

## 목표

Android 앱의 UI·인증·수명주기 개발안을 승인받고 읽기·복사의 최소 앱을 별도로 검증한다. 이번 Phase는 아래 작업 체크리스트의 책임만 가진다.

## 선행조건

- [1.1.9 P5](../1.1.9/5phase.md)의 산출물·검증/승인과 실제 최종 SHA 인수.
- 현재 실행 STATUS·Agent/AGENTS·수정 파일 담당자 충돌 확인.
- [품질 게이트](../QUALITY-GATES.md)의 격리 환경·지원 런타임·필수 물리 기기 확보.
- 네이티브 개발안/기술 실험과 실제 구현 승인을 구분한다. 플랫폼별 사용자 승인이 없으면 P2로 진행하지 않는다.

## 포함 범위

`NF-REQ-041`. 아래 작업에서 다루는 현재 패치의 범위만 수행한다. 여러 버전에 걸친 요구는 이 패치의 부분 범위를 검증한 것으로 기록한다.

## 제외 범위

다른 패치의 기능·사용자가 선택하지 않은 Future 아이디어·승인 없는 기술 교체·운영 변경은 제외한다.

## 수정 책임 경로와 인터페이스

- `apps/android (신규 제안)`
- `tests/native/android (신규 제안)`
- `packages/auth/src`
- `docs/adr/ADR-NF-005-android-native.md`

경로는 책임 영역이다. 신규 제안 표시는 아직 생성된 파일이 아니며 실제 이름·runner·package export는 P1 인수에서 확정한다. 디렉터리 전체를 리팩터링하라는 권한이 아니다. **입력**은 선행 계약·source SHA·fixture·권한 문맥이고 **출력**은 현 단계의 코드/설계·실행 증거·후속 호환 계약이다.

## 작업 체크리스트

- [ ] `LC-NF-1.1.10-P1-01` 네이티브 개발안 문서화와 실제 구현 승인을 구분한다. Windows 기술 승인이 Android 선택을 대신하지 않는다.
- [ ] `LC-NF-1.1.10-P1-02` Kotlin/Compose와 필요한 editor/CRDT adapter 후보를 Gboard/Samsung Keyboard·프로세스 복구 실험으로 비교한다.
- [ ] `LC-NF-1.1.10-P1-03` Google 플랫폼 공식 sign-in/시스템 브라우저 인증과 API access를 구분하고 web client secret을 binary에 넣지 않는다.
- [ ] `LC-NF-1.1.10-P1-04` 관련 구현·테스트 경로를 읽고 위 요구/수용 사례를 정상·오류·권한·복구 입력표로 고정한다. 원인 미확정 항목은 가설과 증거 수준을 표시한다.
- [ ] `LC-NF-1.1.10-P1-05` 저장 형식·API·순서·copy·권한 중 변경되는 인터페이스와 호환/되돌림을 결정 문서에 기록하고 최초 소비 전에 승인한다.
- [ ] `LC-NF-1.1.10-P1-06` 각 변경 파일 담당자와 실제 최종 source SHA를 기록한다. 해당 패치 밖의 기능이나 아직 선택하지 않은 아이디어를 섞지 않는다.

- [ ] `LC-NF-1.1.10-P1-07` 웹의 다사용자 협업/presence·사전 제공 경로·무료 폰트/라이선스 계약을 플랫폼 개발안에 포함하고 OS별 미지원/대체 승인 gate를 명시한다.

## 구체적 검증

| 수용 ID | 입력·상황 | 기대 결과 |
|---|---|---|
| `AC-1.1.10-01` | 기술/구현 승인 없음 | 개발안·실험 증거만 남기고 앱 코드를 배포하지 않는다. |
| `AC-1.1.10-02` | 회전/메모리 회수 중 로그인·조회 | 잘못된 계정 세션이 생성되지 않고 상태가 안전하게 복구된다. |
| `AC-1.1.10-03` | 웹/Android 같은 자료 복사 | 출력 계약과 경고 단위가 같다. |
| `AC-1.1.10-04` | 공유 권한 철회/서버 지원 종료 | API/cache 접근이 정책대로 제한되며 안내가 제공된다. |

P1은 위 기대 결과와 실제 구현 가능 경계를 승인하는 단계다. P2/P3은 관련 재현·수정과 사용자 흐름을 실행하며, P4에서 전체 교차 검증하고 P5에서 실제 결과를 인수한다. 표가 있다는 이유로 테스트 완료로 처리하지 않는다.

## 실행·증거 기록

[공통 명령·검증](../QUALITY-GATES.md)을 먼저 읽는다. 기존 runner의 영향받은 검사를 우선 사용하고 필요할 때만 회귀를 보강한다. 지원 환경에서 관련 DB/E2E를 선택하며 동일 변경의 full suite는 로컬/CI 중 한 곳과 필수 게이트만 따른다. native은 승인된 SDK/플랫폼 명령을 기록한다. 없는 도구·실제 IME·물리 기기 검증을 모사 결과로 통과시켰다고 표시하지 않는다. 문서-only Phase는 링크·범위·결정·설계 검토로 별도 인수한다.

## 완료 조건

- [ ] 작업 ID마다 코드/설계·실행/검토 증거·정확한 SHA가 연결되어 있다.
- [ ] 현재 패치의 원문·권한·복구·오류 처리가 정상 동작과 함께 검증되었다.
- [ ] 미실행·남은 결함·외부 차단·보류한 기술 결정이 숨김없이 기록되었다.
- [ ] 현재 상태/담당/변경 파일·관련 문서가 실제 수행 내용과 일치한다.
- [ ] 구현 Phase는 CI·동일 SHA 개발 인수를, 설계-only는 승인 증거를 갖췄다.
- [ ] main·Release·운영 변경은 별도 현재 승인 없이 수행하지 않았다.
