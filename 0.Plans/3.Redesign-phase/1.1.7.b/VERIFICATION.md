# 1.1.7b 계획 작성 검증

이 문서는 최초 **계획 게시 당시**의 문서-only 검증 이력이다. 후속 사용자 요청으로 실제 실행을 시작했으며 P1 완료 증거는 [1phase.md](1phase.md)와 실행 [STATUS.md](../../1.%20Dev-phase/STATUS.md)에 기록한다. 아래 미실행·개수 표기는 최초 계획 게시 시점 기준이며 현재 P1 실행 상태를 덮어쓰지 않는다.

2026-09-23 사용자 요청에 따른 상세 통합 계획이다. 제품 merge/port·VERSION/runtime·migration·서버 변경은 수행하지 않았다.

## 범위·정합성

- 1.1.7b는 **5 Phase·42개 고유 미완료 작업·24개 수용 기준**이다. 18 WC와 최초 통합/분리 작업/후속 담당의 Markdown·JSON 연결을 확인했다.
- 22개 원인의 정적 판정 **미변경 14 / 부분 대응 5 / 해결 후보 3**은 그대로 유지한다. 새 b SHA에서 해결됐다고 표시한 항목은 없다.
- 기존 1.2.0의 5 Phase·30개 작업과 1.2.1~1.2.8의 41 Phase·205개 작업 ID/미완료 상태를 보존했다. 전체는 **10개 버전·51 Phase·277개 작업**이다.
- 실행 current 1.1.7a/P5/complete는 유지하고 다음 계획만 **b → 1.2.0 → 1.2.1~1.2.8**로 갱신했다. 1.2.0의 실제 구현 기준은 향후 인수된 b SHA다.

## 교차 검토 반영

두 검토 담당자가 편집/백엔드 의존성과 운영/버전/DB 계약을 읽기 전용으로 검토했다. WC-11의 현행 UI/코발트 적용 시점, WC-12 reload 보호의 b 선행 인수, WC-18 도구 지원의 b P1 최초 담당을 정렬했다. WC-06/10/18의 분리 작업, WC-06의 후속 P4, D-10의 최초 통합 참조도 수정했다.

중간 Phase의 신규/악화 회귀·필수 수용과 등록된 기존 차단의 담당 단계를 구별했다. 기존 위험을 통제할 수 없으면 중간 Phase도 중단한다. P4/P5의 전체 필수 차단 해소와 1.2.0 진입 금지는 유지했다. DB 세 종류, 이미 적용된 1150 보존, dev 후보/정식 승인 검사 분리, a의 release 예외 비승계를 명시했다.

## 최종 문서 검사

- Markdown **99개**, 로컬 링크 **1468개**의 대상 존재를 확인했다. 작업/수용 ID·JSON 대응과 다음 버전 연결에 오류가 없었다.
- 제품·설정·도구·CI·VERSION/package/lockfile, 보호된 Sketch/Stack/Mock-up, 선정 코발트 목업은 변경하지 않았다. native 보류 계획 **42개 파일**도 직전 게시 기준과 같다.
- 원본 0922 비공개 리뷰 **8개 파일의 SHA-256**을 보존했고 비공개 파일을 게시 대상으로 추가하지 않았다.
- [Future 검수](../../2.Patch-phase/FUTURE-INTAKE.md): 탐색 4문서, 후보 129개 ID, 입력 blob `8f42d20b638e245eb775415ccfdabef56a96f694` 유지.
- 2026-09-23 원격 조회에서 source head `c230c024aeb0297b1c130e3f3e8b507a43a7e871`와 직전 계획 head `e00a3cd62b90741a8bd629dfd669459169a1cbdb`를 확인했다. 이전 source의 CI/PC 인수는 당시 기록이며 이번 제품 검사 PASS로 전용하지 않는다.

문서 변경의 공백/형식 검사와 보호 경로 보존을 확인했다. 실제 앱 검사·production image·필수 CI·개발 서버 인수는 이번 작업에서 **미실행**이다.

## 게시 경계

사용자의 기존 커밋·푸시 요청에 따라 검증된 계획 문서만 `codex/1.1.7b-web-integration-plan`에 `[skip ci]`로 게시한다. Future 검수와 원격 SHA 일치를 확인하며 main·릴리스 branch·tag·서버는 변경하지 않는다. 문서 게시와 제품 Phase 완료를 구별한다.
