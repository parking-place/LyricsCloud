# 1.1.7b — 웹 안정화 선행 통합

**상태: 상세 계획 / 제품 구현 미착수 (`planned`)** · 작성일 2026-09-23.

사용자 지시대로 **1.1.7a → 1.1.7b 웹 안정화 통합 → 1.2.0 코발트 리디자인 → 1.2.1~1.2.8** 순서로 진행한다. 기존 `3.Redesign-phase` 아래에서 관리하며 폴더는 a의 표기 관례와 맞춘 `1.1.7.b`, 제품 표기는 정확히 `1.1.7b`다.

## 이번 버전의 결과

`phase/1.1.8-p4-web-stabilization`의 웹 수정 18묶음을 현재 v1.1.7a 웹 기반에 코드·타입·호출자·회귀 시험까지 통합하고, 새 1.1.7b SHA의 검증과 개발 서버 공개 인수를 마친다. 기존 화면·프로필·공유·데이터를 유지하며 코발트 외형은 1.2.0에서 적용한다. 후보 목록 작성이나 일부 파일 복사만으로 통합을 완료하지 않는다.

기준 제품은 `fc2463cdb47d9fd7d0042779f602c6ddb7d734cf`, 최신 계획 기준은 `e00a3cd62b90741a8bd629dfd669459169a1cbdb`다. 확인한 원격 head는 `c230c024aeb0297b1c130e3f3e8b507a43a7e871`, 실제 기능 SHA는 `0375825fe004fc74869250eefa14add267c4b3ae`다. 2026-09-23 원격 조회에서 이동이 없었다. 실제 착수 때 다시 확인하며 아직 존재하지 않는 통합 SHA를 완료 근거로 쓰지 않는다.

## 통합과 릴리스 경계

사용자가 요청한 합치기는 **웹 동작과 그 의존성의 통합**으로 계획한다. 원격 전체 merge에는 Windows/native API·1150 신규 migration·1.1.8 버전값·이전 계획이 섞이므로 기능 묶음별 선별 통합을 기본으로 한다. 각 제외 사유를 기록하고 웹 수정에 필요한 의존성이 제외될 경우 동등한 웹 구현을 검증한다. 미완료 native 기능을 새로 완성하거나 일괄 활성화하지 않는다.

이번 요청은 **통합 계획 작성**이다. 실제 merge/port·VERSION 변경·서버 배포는 이번 작업에 포함하지 않는다. b의 실제 P1~P5 인수 완료 후 1.2.0에 진입하며, 정식 b tag 발행 자체를 추가 선행 조건으로 만들지 않는다. 정식 main/release branch·tag·공용 image·릴리스 서버 작업은 실행 시점의 명시 승인과 정책을 따른다. 과거 a의 독립 release 예외는 b에 자동 승계되지 않는다.

원문 유실·거짓 저장·권한 확대·복구 불가와 필수 운영 gate는 후속 번호 배정으로 면제하지 않는다. 원격 후보에 없는 최소 수정은 b 범위 변경·담당·회귀 시험으로 명시한다. 큰 CRDT/정책 변경이 필요하면 인수를 `review`로 중단한다. 전체 UX 재설계와 대규모 리팩터링은 후속 계획에 유지한다.
