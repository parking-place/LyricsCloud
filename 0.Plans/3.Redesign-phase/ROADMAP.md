# 1.2.0 이후 버전별 로드맵

2026-09-22 사용자 요청에 따라 0922 코드·UX·UI·운영 리뷰를 **1.2.1~1.2.8**에 배정했다. 새로 올라온 `phase/1.1.8-p4-web-stabilization`과의 차이도 [브랜치 비교·선택 통합 계획](BRANCH-COMPARISON-118-P4.md)에 포함한다. 이 폴더에서 1.2.x 리디자인과 후속 품질 개선을 함께 관리한다.

현재 실행은 **1.1.7a 완료**, 다음 제품 착수는 계속 **1.2.0 코발트 Chroma Dock**이다. 1.1.8~1.1.14 네이티브 계획은 보류하며 웹 안정화 수정의 선별 인수는 네이티브 재개와 구별한다. 이 문서는 계획이며 제품 코드 변경·배포 완료가 아니다.

## 의존성과 중복 제거

| 소비할 계약 | 최초 담당 | 뒤에서 활용하는 버전 |
|---|---|---|
| 코발트 토큰·반응형 셸·기능 도달성·편집 인스턴스 보존 | 1.2.0 | 모든 후속 버전 |
| 휘발성/기기 보관/서버 ACK·readiness·이탈 guard | 1.2.1 | 1.2.2, 1.2.6, 1.2.7, 1.2.8 |
| 부분 연산·IME·태그 raw 수렴·변환 보존 | 1.2.2 | 1.2.5, 1.2.6, 1.2.7, 1.2.8 |
| 세션 응답 수명·receipt/replay·Unicode 확인 | 1.2.3 | 1.2.5, 1.2.7 |
| 백업/프록시·worker/DB 예산 | 1.2.4 | 1.2.7 안내, 1.2.8 검증/구조화 |
| 최신 query·cursor·검색 순서·return anchor | 1.2.5 | 1.2.6 작성/자료 UX |
| 작성/모바일 focus·공유/복구 과제 | 1.2.6~1.2.7 | 1.2.8 회귀와 구조 분리 |

표는 기술 의존성이다. 번호 순서와 별개로 독립 문제 조사·문서 검수는 병행할 수 있지만 구현 Phase를 임의로 동시에 착수하지 않는다. 원인이 같은 ES-05/UI-01, UI-03/M-09 등은 같은 상태 계약과 실패 fixture를 재사용한다. UX 항목의 저장/권한 문제를 화면 문구만 바꿔 해결하지 않는다.

1.2.0 또는 웹 안정화 브랜치에서 선해결된 항목은 `해결 후보 SHA → 의존 변경 → 현재 기준 포팅 → 동일 입력 재검증 → 채택 SHA`로 인수한다. 후보 코드가 있다는 이유로 현재 버전의 구현 체크를 완료하지 않는다. 같은 변경을 다시 만드는 대신 후속 Phase를 잔여 경계·실기기·호환 인수에 집중시킨다. 모든 실질 범위가 먼저 해소된 버전은 근거와 번호 변경을 기록하고 빈 tag/image를 만들지 않는다.

## 1.2.0 출시 차단과 후속 번호의 관계

리뷰의 **우선순위 P1은 Phase 1과 다른 의미**다. BE-01, ES-01/03/05/06/07, UI-02, OPS-01 및 조건부 OPS-02를 [공통 gate](QUALITY-GATES.md)에서 재확인한다. UI-01은 원 리뷰 P2지만 실제 입력 유실이 재현된 경계는 같은 보존 gate를 따른다. UI-08도 코발트 모바일 조작 인수에서 해소해야 한다.

1.2.0 P1에서 현재 후보와 비교 브랜치의 해결 여부·남은 위험을 기록하고 P4/P5에서 재판정한다. 미해결 원문 손실·거짓 저장·권한 문제나 승인된 운영 gate 위반을 1.2.1 이후에 배정했다는 이유로 출시하지 않는다. 필요 최소 수정의 1.2.0 편입은 범위·담당·호환·검증을 PLAN-CHANGE에 기록하고, 후속 버전에는 선해결 증거와 남은 범위만 남긴다. 추가 결정이 필요한 프로토콜/운영 정책 변경은 해당 결정 전 실행하지 않는다.

## 보류·범위 밖

네이티브 1.1.8~1.1.14의 잔여 SDK·패키징·서명·실기기 인수는 자동 재개하지 않는다. Suno 자동 metadata·NAVER 사전은 기존 공식 제공/권리/비용 gate를 유지한다. 새 인증 방식·공유 범위·요금·원격 저장소·관측 서비스와 제품 클릭/검색/창작 행동 telemetry도 이 계획에 자동 포함하지 않는다. 다음 신규 버전은 실제 남은 요구가 있을 때 배정하며 1.2.9 이후를 숫자 채우기로 만들지 않는다.
