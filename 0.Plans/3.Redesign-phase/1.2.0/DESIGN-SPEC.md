# 1.2.0 디자인 명세 — Cobalt Blue Chroma Dock

선택 근거: 2026-09-22 사용자 지정. 구조는 Chroma Dock E, 색 조합은 04 Cobalt다. [실행형 기준](mockup/index.html), [전환 결정](../PLAN-CHANGE.md), [수용 기준](ACCEPTANCE.md)을 함께 사용한다.

광원의 파랑과 버튼의 파랑은 역할이 다르다. 밝은 광원 위에 흰 작은 글자를 직접 올리지 않고 읽기용 강조색을 사용한다. 위험·경고·저장·권한 상태는 의미별 토큰과 문장/아이콘으로 구별한다. 사용자 사진과 노트 지정 색상은 콘텐츠이며 전체 테마 전환으로 덮어쓰지 않는다.

색상 값과 실제 혼합식은 목업의 [palette.js](mockup/palette.js), [color-core.js](mockup/color-core.js), [color-layer.css](mockup/color-layer.css)에 있다. P1은 실제 앱의 기존 토큰 이름과 대응표를 작성하고 P2부터 공통 스타일로 옮긴다. 개별 화면마다 별도 파랑·회색을 추가하지 않는다.

## 유리·배경·입체감

- 바깥 배경에 넓고 부드러운 코발트·민트·살구 그라데이션을 두고, 카드는 바탕보다 더 불투명하게 올린다.
- 도크·짧은 액션·카드 경계에 반사광·채도·다층 그림자를 배치한다. 가사 본문·입력·검색 결과의 판독 영역은 고밀도 표면을 사용한다.
- SVG 굴절은 장식 요소에만 적용한다. 글자, 커서, 선택, 버튼 클릭 영역과 스크린 리더 읽기 순서에 필터를 적용하지 않는다.
- GSAP의 등장·hover/press·도크 반응은 시각 피드백으로 사용한다. 애니메이션 완료를 저장·탐색·복사 성공 조건으로 삼지 않는다.
- `prefers-reduced-motion`, 기존 투명도 감소 설정, forced-colors, backdrop-filter 미지원에서 불투명 면·명확한 경계·정적인 피드백으로 대체한다.
- 목업의 GSAP/Draggable 포함은 디자인 재현용이다. 제품 의존성 채택·번들 크기·라이선스·기존 CSP 및 정리 lifecycle은 P1/P2에서 검토한다. CDN 의존을 새로 만들지 않는다.

## 구조와 반응형

PC는 상단 브랜드/현재 위치/프로필, 작업별 모듈, 하단 도크를 기준으로 한다. 메뉴는 홈·곡·라임 노트·프롬프트·검색·최근·즐겨찾기·템플릿·휴지통·설정의 목적지를 모두 제공한다. 모바일에서 도크에 없는 메뉴는 이름이 있는 더보기로 같은 목적지에 도달한다.

가사 편집기는 좌측 송폼, 중앙 본문, 우측 자료를 유지한다. 자료에는 **다른 곡 / 다른 가사 / 라임 / 프롬프트** 네 탭이 있어야 한다. 좁은 화면에서는 송폼·자료를 보이는 버튼과 시트/펼침 패널로 열며 선택한 탭·필터·스크롤을 가능한 범위에서 보존한다. 숨기기/집중 모드는 기능 제거가 아니다.

320/390/768/1024/1440px와 긴 한글 제목·빈 목록·큰 글꼴을 기준으로 재배치한다. viewport 수치를 장치 종류로 오인하지 않는다. 모바일 safe area·가상 키보드·주소창 높이 변화 뒤에도 저장 상태·편집 커서·닫기/복사 액션이 도크에 가리지 않아야 한다. 터치 주요 액션은 44px 이상을 기본 목표로 하고 좁은 보조 액션은 실제 포커스/누름 범위를 함께 검토한다.

## 제품 이식 경계

- 목업은 합성 데이터와 textarea/localStorage로 시연한다. 실제 앱은 기존 CodeMirror 6, Yjs, 계정/문서별 로컬 복구, 서버 권한/저장 계약을 계속 사용한다.
- 테마·도크·자료 탭·시트·집중 모드 변경 때문에 편집기를 remount하거나 문서·selection·undo·조합 중 IME를 초기화하지 않는다.
- 프로필/표시 설정은 초안·미리보기·저장·취소의 범위를 보존한다. 테마 변경으로 입력 중 닉네임이나 사진 미리보기를 잃지 않는다.
- 모달은 이름, 열기/닫기, Escape, 초점 회수, 배경 접근 제한, 긴 내용 스크롤을 제공한다. 저장 실패나 권한 종료는 색 변화만으로 안내하지 않는다.
- 테마 설정 이행과 이전 UI 복귀 방법은 P1에서 확정한다. rollout/rollback 때문에 창작물·계정 설정·수정 기록을 삭제하는 구조는 허용하지 않는다.

## 검증 원칙

작은 글자 4.5:1, 큰 글자·UI 경계/포커스의 해당 기준을 실제 합성 배경과 상태별로 점검한다. 단일 토큰 대비 계산은 blur·그라데이션 전체의 접근성 통과 증거가 아니다. [기존 성능 게이트](../../2.Patch-phase/QUALITY-GATES.md)를 완화하지 않고 입력 지연·스크롤·전환·GPU 효과 비용을 비교한다. 수치 예산이 없는 새 효과는 P1 기준 측정 뒤 예산을 정하고 P4에서 검증한다.
